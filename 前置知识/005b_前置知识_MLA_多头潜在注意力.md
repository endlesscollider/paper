# MLA：多头潜在注意力——联合压缩 KV 而不砍头数

> **一句话**：多头潜在注意力（Multi-head Latent Attention, MLA）不像 MQA/GQA 那样直接砍掉 K、V 的头数，而是把每个 token 的 Key 和 Value **联合压缩进一个低维的潜在向量**（latent vector），推理时缓存这个小向量，需要参与注意力计算时再用投影矩阵"解压"还原出来。这样既大幅压缩了缓存，又因为压缩/解压是可学习的、信息损失比"直接砍头数"小得多，实测表达力反而能超过标准多头注意力（MHA）。本文讲清楚这个压缩-解压机制具体怎么运作，以及它和 RoPE 位置编码搭配时遇到的一个技术性难题——解耦 RoPE 是怎么绕开这个难题的。

## 一、先想清楚问题出在哪：砍头数这条路的天花板

### 1.1 贯穿全文的例子

延续 [MQA 前置知识](/前置知识/005a_前置知识_MQA_多查询注意力) 里用过的配置，方便直接对比：一个 7B 规模的自回归模型，$L=32$ 层，每层 $H=32$ 个注意力头，每头维度 $d_h=128$（隐藏维度 $d=4096$），处理 $S=2048$ 个 token 的序列，用 bfloat16（2 字节）存储。

在这个配置下，前文已经算过：MHA 的 KV Cache 是 1024 MB，MQA 把它压到 32 MB（缩小 32 倍），但代价是 DeepSeek-V2 论文的消融实验显示 MMLU 掉了 7.3 个百分点、C-Eval 掉了近 13 个百分点。GQA 用分组共享在两者之间找平衡，但依然是同一套"减少独立 K/V 份数"的思路，信息损失的机制没有变。

### 1.2 砍头数路线的根本局限

MQA、GQA 的共同思路是：原本每个 Query 头都能看到自己专属的一份 Key/Value，现在强迫若干个 Query 头共享同一份。这是一种**结构性的裁剪**——被合并到一组的 Query 头之间没有任何缓和地带，它们看到的 K、V 内容完全一样，没有商量的余地。

这就带来一个天然的问题：**有没有办法既大幅压缩缓存，又不用这种"一刀切共享"的方式损失信息？**

DeepSeek-V2 论文（2024）给出的答案是——**不砍份数，而是压缩每一份的维度**。所有 Query 头依然各自独立、各自能看到自己的 Key、Value，只是这份 Key、Value 不再是"直接存下来的原始高维向量"，而是先联合压缩进一个低维空间，缓存这个压缩后的小向量，需要用时再解压回高维。

## 二、核心机制：低秩联合压缩

### 2.1 一句话直觉

> 标准 MHA 里，32 个头各自存一份完整的 Key 向量和 Value 向量，相当于给每个头单独发一份"高清照片"。MLA 的做法是：把这 32 份高清照片打包压缩成**一张缩略图**存起来，等需要用的时候，再用一个专门训练好的"还原滤镜"把缩略图还原成接近原图的样子——还原出来的 32 份 Key/Value 依然各不相同（滤镜给每个头单独还原），但存储的只有那一张缩略图。

### 2.2 压缩：把 K、V 联合投影进潜在向量

设 $\mathbf{h}_t \in \mathbb{R}^d$ 是第 $t$ 个 token 在这一层的输入隐藏向量。MLA 的第一步是把它投影进一个低维的潜在空间：

$$
\mathbf{c}_t^{KV} = W^{DKV} \mathbf{h}_t
$$

**这个公式在做什么**：把这个 token 原本 $d$ 维的隐藏向量，压缩成一个远小于 $H \cdot d_h$ 维的潜在向量——这一个向量以后就是唯一需要存进缓存的东西。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mathbf{h}_t \in \mathbb{R}^d$ | **原始高维信息** | 这一层的输入隐藏向量，包含了这个 token 当前所有的语义信息 |
| $W^{DKV} \in \mathbb{R}^{d_c \times d}$ | **压缩滤镜（下投影矩阵）** | "D" 代表 Down-projection，把 $d$ 维打包压缩成远小的 $d_c$ 维 |
| $\mathbf{c}_t^{KV} \in \mathbb{R}^{d_c}$ | **缩略图 / 潜在向量** | 唯一需要缓存的东西，$d_c \ll H \cdot d_h$ |

**用人话读**："用一个学出来的压缩矩阵，把这个 token 的隐藏向量打包成一个很小的潜在向量，以后要缓存的就是这一个小向量，而不是一堆按头分开的大向量。"

**为什么是这个形式**：这是标准的低秩投影——把一个高维向量映射到低维空间，只保留对后续任务最有用的那部分信息（"最有用"是训练过程中学出来的，不是手工指定的）。之所以能大幅压缩还基本不掉信息，本质原因是 K、V 这类特征往往存在冗余，可以用远低于原始维度的子空间近似表达，这背后的数学直觉可以参见 [矩阵的秩与低秩近似](/前置知识/000z_前置知识_矩阵的秩与低秩近似)。
:::

关键在于：**Key 和 Value 共享同一个压缩结果** $\mathbf{c}_t^{KV}$——这也是"联合压缩"（joint compression）这个名字的来源，压缩这一步不区分 K 和 V，两者用同一份潜在向量表示。

### 2.3 解压：需要用时再还原出 K 和 V

真正做注意力计算时，需要的是完整的 Key 和 Value 向量（并且要按头切分）。MLA 用两个独立的上投影矩阵把潜在向量还原出来：

$$
\mathbf{k}_t^C = W^{UK} \mathbf{c}_t^{KV}, \qquad \mathbf{v}_t^C = W^{UV} \mathbf{c}_t^{KV}
$$

**这个公式在做什么**：从存进缓存的那一个小小的潜在向量，用两个不同的"还原滤镜"分别还原出这个 token 完整的 Key 表示和 Value 表示——注意 Key 和 Value 用的是两个不同的滤镜，虽然它们的原料（潜在向量）是同一份。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mathbf{c}_t^{KV}$ | **缩略图原料** | 上一步压缩出来、存在缓存里的那个小向量 |
| $W^{UK} \in \mathbb{R}^{Hd_h \times d_c}$ | **Key 专用还原滤镜** | "U" 代表 Up-projection，把 $d_c$ 维还原成 $H \cdot d_h$ 维——覆盖全部 $H$ 个头 |
| $W^{UV} \in \mathbb{R}^{Hd_h \times d_c}$ | **Value 专用还原滤镜** | 和 $W^{UK}$ 结构一样，但参数不同，专门负责还原 Value |
| $\mathbf{k}_t^C, \mathbf{v}_t^C$ | **还原出的完整 K / V** | 每个都覆盖全部 $H$ 个头，接下来会像标准 MHA 一样切分成各自的头参与计算 |

**用人话读**："同一份缩略图，一个滤镜还原出完整的 Key（覆盖所有头），另一个滤镜还原出完整的 Value（也覆盖所有头）——两个滤镜看的是同一份原料，但各自学着还原不同的东西。"

**为什么是这个形式**：如果 K、V 共用同一个上投影矩阵，两者还原出来的内容会强行绑定在一起，学习能力受限；用两个独立矩阵能让 Key 和 Value 各自专注于自己该表达的信息（Key 负责"能不能被匹配到"，Value 负责"匹配到后拿什么"），这个分工在标准 MHA 的 $W_K, W_V$ 设计里本来就存在，MLA 只是把它接在压缩步骤之后而不是直接接在原始输入上。
:::

**这里最关键的一点**：还原出来的 $\mathbf{k}_t^C, \mathbf{v}_t^C$ 依然覆盖全部 $H$ 个头，每个头拿到的 Key/Value 切片依然是**各不相同**的（因为 $W^{UK}, W^{UV}$ 是覆盖了全部头维度的大矩阵，不同头对应的输出行本来就不一样）。这正是 MLA 和 MQA/GQA 的本质区别——**MQA/GQA 是从源头上就只生产一份或几份 K/V，MLA 是让所有头都能拿到各自不同的 K/V，只是这份"各不相同"的信息是从一个共享的低维潜在向量里解压出来的**。

### 2.4 推理时的关键优化：不用真的解压

DeepSeek-V2 论文里还指出一个很重要的工程细节：由于矩阵乘法满足结合律，$W^{UK}$ 可以被**提前吸收**进 Query 的投影矩阵 $W^{Q}$ 里，$W^{UV}$ 可以被吸收进输出投影矩阵 $W^{O}$ 里。也就是说，推理时**根本不需要把 $\mathbf{k}_t^C, \mathbf{v}_t^C$ 显式算出来**——原本"缓存的潜在向量 → 解压出 K/V → 和 Query 做点积"这一串操作，可以直接简化成"缓存的潜在向量 → 直接和吸收了 $W^{UK}$ 的新 Query 做点积"。这个合并是纯粹的离线代数操作（提前把两个矩阵乘好），不影响推理时的实际计算量，只是省去了显式还原 K/V 这一步。

## 三、缓存到底存了什么，压缩了多少

### 3.1 缓存内容的对比

| 方案 | 缓存的内容 | 每 token 缓存的元素个数（不含解耦 RoPE 部分） |
|------|-----------|------------------------------------------------|
| MHA | 每层每头独立的完整 $\mathbf{k}_t, \mathbf{v}_t$ | $2 \times H \times d_h$ |
| GQA | 每层每组独立的完整 $\mathbf{k}_t, \mathbf{v}_t$ | $2 \times G \times d_h$ |
| MQA | 每层唯一一份 $\mathbf{k}_t, \mathbf{v}_t$ | $2 \times d_h$ |
| **MLA** | 每层唯一一个低维潜在向量 $\mathbf{c}_t^{KV}$ | $d_c$ |

MLA 缓存的元素个数公式里**没有系数 2**——这是因为 Key 和 Value 共用同一份潜在向量，缓存一份 $\mathbf{c}_t^{KV}$ 就同时覆盖了两者，而 MHA/GQA/MQA 的 K、V 是分别独立存储的两份数据。

### 3.2 DeepSeek-V2 的具体配置和压缩比

DeepSeek-V2 论文里 $d_c$（KV 压缩维度）设为 $4 d_h$。结合下一节要讲的解耦 RoPE 额外开销 $d_h^R = d_h/2$，论文给出了一个非常直观的等效比较：

> MLA 每 token 的 KV Cache 大小，恰好等于 GQA 配置成**只有 2.25 组**时的大小——但 MLA 的实际表达力比标准 MHA（$G=H$，也就是 32 组）还要更强。

论文 Appendix D.2 的实测数据（Table 9）更直观：

| 规模 | 缓存方案 | 激活参数 | KV Cache（元素数/token） | BBH | MMLU | C-Eval | CMMLU |
|------|---------|---------|---------------------------|-----|------|--------|-------|
| Small MoE | MHA | 2.5B | 110.6K | 37.9 | 48.7 | 51.6 | 52.3 |
| Small MoE | **MLA** | 2.4B | **15.6K（仅 14%）** | 39.0 | 50.0 | 50.9 | 53.4 |
| Large MoE | MHA | 25.0B | 860.2K | 46.6 | 57.5 | 57.9 | 60.7 |
| Large MoE | **MLA** | 21.5B | **34.6K（仅 4%）** | 50.7 | 59.0 | 59.2 | 62.5 |

数据来源：DeepSeek-AI, *DeepSeek-V2*, arXiv:2405.04434, Appendix D.2, Table 9。

对照第一节 MQA 那张表（MHA 明显优于 GQA 明显优于 MQA），这里的结果完全反过来：**MLA 用比 MQA 更极端的压缩比例（4%-14% vs MQA 通常在 1/H 量级），换来的却是比 MHA 更好的下游表现**。这正是"压缩维度而非砍头数"这条思路的核心价值——信息没有被结构性地一刀切掉，而是被投影进一个学习出来的低维子空间，训练过程会自动学会保留对任务最有用的那部分变化方向。

### 3.3 DeepSeek-V2 完整模型的实测收益

在完整的 DeepSeek-V2（236B 总参数，21B 激活参数）与前代 DeepSeek 67B 稠密模型的对比中，论文摘要和正文汇报了三个具体数字：

- 训练成本降低 **42.5%**
- KV Cache 降低 **93.3%**
- 单节点 8×H800 GPU 上最大生成吞吐量提升到 **5.76 倍**（超过 50K token/秒，输入侧提示词处理吞吐量超过 100K token/秒）

需要说明的是，93.3% 和 5.76 倍这两个数字，是 MLA 和 DeepSeekMoE（一种降低前馈网络计算成本的稀疏专家架构，本文不展开，可参见 [DeepSeek-V2 MLA 精读](/论文综述/104_DeepSeekV2_MLA多头潜在注意力) 里的完整说明）共同作用的结果，也叠加了 KV Cache 量化（把缓存进一步压到平均 6 bit）等部署优化，并不是 MLA 单独机制贡献的全部——但 MLA 是其中支撑"缓存能被压这么小"的核心结构性改动。

## 四、RoPE 遇到的麻烦：为什么不能直接套用

### 4.1 问题出在哪

DeepSeek-V2 沿用了 [RoPE 旋转位置编码](/前置知识/002k_前置知识_RoPE旋转位置编码) 来注入位置信息。RoPE 的机制是对 Query 和 Key 向量分别乘上一个和位置相关的旋转矩阵，这个旋转矩阵**同时依赖于内容和位置**。

第 2.4 节提到的关键优化——把 $W^{UK}$ 吸收进 $W^{Q}$——依赖于矩阵乘法的结合律：$W_Q^T W^{UK}$ 可以离线算好合并成一个矩阵，不需要在推理时分两步做。但如果直接把 RoPE 套在还原出来的 $\mathbf{k}_t^C$ 上，公式会变成：

$$
\text{RoPE}(\mathbf{k}_t^C) = \text{RoPE}(W^{UK} \mathbf{c}_t^{KV})
$$

**这个公式在做什么**：假设直接把 RoPE 套在解压还原出来的 Key 上会发生什么——这个公式本身就是要被否定的"错误做法"，写出来是为了下一段说明它为什么行不通。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mathbf{c}_t^{KV}$ | **压缩后的潜在向量** | 缓存里存的那个小向量 |
| $W^{UK}$ | **还原滤镜** | 把潜在向量还原成完整 Key 的上投影矩阵 |
| $\text{RoPE}(\cdot)$ | **旋转操作** | 试图直接套在还原出来的 $\mathbf{k}_t^C$ 上，这是问题所在 |

**用人话读**："如果直接对解压出来的 Key 施加 RoPE 旋转，会发现这个旋转操作被夹在了还原矩阵和后面要吸收它的 Query 矩阵之间。"

**为什么是这个形式**：这个公式的作用不是展示一个好的设计，而是暴露矛盾——RoPE 操作本质上是"乘上一个和当前 token 位置相关的旋转矩阵"，这个旋转矩阵会插在 $W^{UK}$ 和后续要吸收它的 $W_Q$ 之间，下一段会具体说明这为什么导致离线合并优化失效。
:::

RoPE 操作本质上是"乘上一个和当前 token 位置相关的旋转矩阵"，这个旋转矩阵夹在 $W^{UK}$ 和后续要吸收它的 $W_Q$ 之间，而**矩阵乘法不满足交换律**——旋转矩阵会随着"当前生成到第几个 token"不断变化，所以它没法被提前离线合并进 $W^{UK}$，也就破坏了 $W^{UK}$ 能被吸收进 $W_Q$ 这件事。后果是：如果坚持给压缩后的 K 直接套 RoPE，推理时就必须对缓存里所有历史 token **重新计算**一遍 $\mathbf{k}_t^C$（因为每次要生成新 token 时，涉及的旋转角度都不同），这正好把 KV Cache 联合压缩省下来的推理效率给抵消掉了。

### 4.2 解决方案：解耦 RoPE

DeepSeek-V2 的解法是**把"携带位置信息"这件事从主体的 K、V 通道里剥离出来，单独开一条小通道专门处理**：

$$
\mathbf{q}_t^R = \text{RoPE}(W^{QR} \mathbf{c}_t^{Q}), \qquad \mathbf{k}_t^R = \text{RoPE}(W^{KR} \mathbf{h}_t)
$$

**这个公式在做什么**：额外单独算一小份带位置信息的 Query 和 Key（维度只有 $d_h^R = d_h/2$，比主体通道小很多），只有这一小份需要套 RoPE，主体的压缩通道完全不碰 RoPE，从而保住了"$W^{UK}$ 可离线吸收进 $W_Q$"这个关键优化。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mathbf{c}_t^{Q}$ | **Query 侧的潜在向量** | 和 KV 侧类似，DeepSeek-V2 对 Query 也做了低秩压缩（主要为了训练时省激活值显存，不影响推理缓存） |
| $W^{QR}, W^{KR}$ | **位置专用小投影** | 各自独立、维度较小的矩阵，专门负责生成"携带位置信息"的那一小部分 Query/Key |
| $\text{RoPE}(\cdot)$ | **旋转操作** | 只施加在这条独立的小通道上，不碰主体的压缩 K/V 通道 |
| $\mathbf{q}_t^R, \mathbf{k}_t^R$ | **位置感知的小尾巴** | 会和主体的 $\mathbf{q}_{t,i}^C, \mathbf{k}_{t,i}^C$（不带位置信息，来自压缩通道）拼接在一起，共同参与打分 |

**用人话读**："不要试图把位置信息塞进那条已经压缩好的主通道，而是单独开一条小通道专门装位置信息，两条通道的结果最后拼在一起用。"

**为什么是这个形式**：这样一来，主体的 $\mathbf{k}_t^C$ 完全不含位置信息，$W^{UK}$ 依然可以安全地离线吸收进 $W_Q$；解耦出来的这一小份 $\mathbf{k}_t^R$ 因为维度小（只有 $d_h/2$），且是**所有 $H$ 个头共享同一份**（不像主体通道每个头都不同），额外的缓存开销很小。这是一种"把问题拆开单独解决"的工程设计：位置编码需要的性质（逐位置变化、不能离线合并）和缓存压缩需要的性质（离线可合并）互相冲突，就不要试图用同一套变量同时满足两者，而是分别开专用通道各自满足各自的约束。
:::

最终每个头的完整 Query、Key 是两条通道拼接（concatenate）起来的结果：

$$
\mathbf{q}_{t,i} = [\mathbf{q}_{t,i}^C; \mathbf{q}_{t,i}^R], \qquad \mathbf{k}_{t,i} = [\mathbf{k}_{t,i}^C; \mathbf{k}_t^R]
$$

**这个公式在做什么**：把"不带位置信息、从压缩潜在向量还原出的主体部分"和"专门携带位置信息的小尾巴"直接拼接成一个更长的向量，作为这个头真正参与注意力打分的完整 Query/Key。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mathbf{q}_{t,i}^C, \mathbf{k}_{t,i}^C$ | **内容主体（不带位置）** | 从压缩通道还原出来的部分，每个头 $i$ 各不相同 |
| $\mathbf{q}_{t,i}^R$ | **位置小尾巴（Query 侧）** | 每个头各自独立的一份，携带位置信息 |
| $\mathbf{k}_t^R$ | **位置小尾巴（Key 侧，不带头下标 $i$）** | 所有头共享同一份——这是它能省缓存的原因 |
| $[\cdot;\cdot]$ | **拼接操作** | 把两段向量首尾相连，变成一个更长的向量 |

**用人话读**："每个头最终用来打分的 Query 和 Key，是'不带位置的内容部分'和'专门带位置的小尾巴'拼在一起——两部分分别来自两条独立的计算通道。"

**为什么是这个形式**：拼接后的向量做点积时，点积会自动拆成两部分的和（内容部分的点积 + 位置部分的点积），效果上等价于"同时考虑内容相关度和位置相关度"，但计算上两条通道完全独立、互不干扰，各自可以用最适合自己的方式优化（内容通道走低秩压缩省缓存，位置通道走 RoPE 保证位置敏感性）。
:::

### 4.3 额外开销小，但不是零开销

解耦 RoPE 这条小通道也需要被缓存（因为 $\mathbf{k}_t^R$ 在生成后续 token 时也要被历史 token 反复查询），所以 DeepSeek-V2 真实的每 token 缓存大小是 $(d_c + d_h^R) \times l$，而不是单纯的 $d_c \times l$——这也是第 3.2 节 "2.25 组" 那个数字里已经包含的部分。但因为 $d_h^R$ 只有主体头维度的一半，且所有头共享同一份，这部分开销相比主体压缩通道省下来的量小得多。

## 五、和 MQA/GQA 的正面对比

| 维度 | MQA | GQA | MLA |
|------|-----|-----|-----|
| 压缩手段 | 砍 KV 头数到 1 | 砍 KV 头数到 $G$ 组 | 联合压缩进低维潜在向量，不砍头数 |
| 每个头能看到的 K/V | 所有头看同一份 | 组内头看同一份 | 每个头看到各不相同的还原结果 |
| 信息损失机制 | 结构性丢弃（一刀切共享） | 结构性丢弃（分组共享） | 有损压缩（可学习地保留主要变化方向） |
| 实测表达力（DeepSeek-V2 数据） | 明显低于 MHA | 介于 MHA 和 MQA 之间 | **持平或超过 MHA** |
| KV Cache 压缩比（本文例子 $H=32$） | 32 倍 | $H/G$ 倍 | 可达数十倍（DeepSeek-V2 等效 2.25 组，约 14 倍） |
| 和 RoPE 的兼容性 | 直接兼容 | 直接兼容 | 需要解耦 RoPE 额外处理 |
| 推理时的额外优化空间 | 无 | 无 | $W^{UK}, W^{UV}$ 可离线吸收进 $W_Q, W_O$ |

MLA 用一个额外的技术代价（解耦 RoPE 的工程复杂度）换来了"压缩比更大、表达力反而更好"的组合，代价是实现复杂度比 MQA/GQA 高出不少——这也是为什么早期大模型架构普遍先采用更简单的 GQA，MLA 是后来才出现的更精细方案。

## 六、总结

| 要点 | 内容 |
|------|------|
| **核心机制** | Key、Value 联合投影压缩进一个低维潜在向量 $\mathbf{c}_t^{KV}$，缓存只存这一个小向量，需要时用 $W^{UK}, W^{UV}$ 解压还原 |
| **和 MQA/GQA 的本质区别** | 不是砍独立 K/V 的"份数"，而是压缩每份的"维度"；解压后每个头依然各不相同 |
| **推理优化** | $W^{UK}$ 可吸收进 $W_Q$，$W^{UV}$ 可吸收进 $W_O$，避免显式还原 K/V |
| **RoPE 的冲突** | RoPE 的旋转矩阵和位置相关，无法被离线吸收进上投影矩阵——直接套用会破坏推理优化 |
| **解决方案** | 解耦 RoPE：单独开一条小通道（维度 $d_h/2$，所有头共享）专门携带位置信息，和主体压缩通道拼接使用 |
| **DeepSeek-V2 实测** | KV Cache 等效 GQA 2.25 组，但表达力持平或超过 MHA；完整模型对比前代降 KV Cache 93.3%，吞吐提升 5.76 倍 |
| **提出背景** | DeepSeek-AI, *DeepSeek-V2*, arXiv:2405.04434, 2024 |
