# 前置知识：DDPG——Deep Deterministic Policy Gradient

> **一句话**：DDPG 是第一个成功将深度学习应用于连续动作空间 RL 的算法。它结合了 DQN 的 replay buffer + target network 技巧和 Actor-Critic 架构，用确定性策略直接输出连续动作。

**前置概念**：
- [Q 函数与 Value 函数](/前置知识/000o_前置知识_Q函数与Value函数) — Q 值的含义和 Bellman 方程
- [策略梯度与 PPO](/前置知识/000a_前置知识_策略梯度与PPO) — Actor-Critic 的基本思想

---

## 贯穿全文的例子

> 一个单摆（Pendulum）需要学习用连续力矩将摆杆竖直并保持平衡。
> - **状态** $s = [\cos\theta, \sin\theta, \dot\theta] \in \mathbb{R}^3$：摆角和角速度
> - **动作** $a \in [-2, 2]$：施加的力矩（连续值）
> - **奖励**：$r = -(\theta^2 + 0.1\dot\theta^2 + 0.001a^2)$（越竖直、越稳定、力矩越小越好）

---

## 一、动机：DQN 不能处理连续动作

### 1.1 DQN 的局限

DQN 通过 $a^* = \arg\max_a Q(s, a)$ 选最优动作。这要求能对所有动作求 max——当动作空间是离散且有限的（如上下左右 4 个方向），可以逐个比较。

但如果动作空间是连续的（如力矩 $a \in [-2, 2]$），$\arg\max$ 就变成了一个连续优化问题——每步决策都要解一次优化，计算上不可行。

### 1.2 DDPG 的解法

DDPG 的思路：**用一个神经网络直接输出最优动作**，不再对 Q 求 max。

$$
\mu_\theta(s) \approx \arg\max_a Q(s, a)
$$

**这个公式在做什么**：不再对 Q 函数逐个动作求 max，而是直接训练一个网络，输入状态就吐出"Q 值最高的那个动作"——把"搜索"变成"预测"。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $Q(s,a)$ | **打分裁判** | 给每个（状态，动作）组合打一个"未来收益"分数 |
| $\arg\max_a Q(s,a)$ | **理想答案** | 遍历所有动作，找出打分最高的那一个——但连续空间下这一步不可行 |
| $\mu_\theta(s)$ | **抢答的学生（Actor）** | 一个神经网络，直接输出它认为分数最高的动作，不用遍历 |
| $\approx$ | **近似替代** | Actor 的输出不保证是真正的最优解，但训练目标是让它逐渐逼近最优 |

**用人话读**："别再一个一个试动作找最好的了，直接训练一个网络，让它看到状态就能猜出最好的动作。"

**为什么是这个形式**：连续动作空间里 $\arg\max$ 是个无限搜索问题，用网络直接参数化这个映射，把"求解优化问题"变成"一次前向传播"，代价是不再保证全局最优。
:::

这个网络叫 **Actor**（策略网络），它输出一个确定性的动作值（不是概率分布）。

## 二、算法核心

### 2.1 四个网络

| 网络 | 符号 | 作用 |
|------|------|------|
| Actor | $\mu_\theta(s)$ | 输入状态，输出确定性动作 |
| Critic | $Q_\phi(s, a)$ | 输入状态+动作，输出 Q 值 |
| Target Actor | $\mu_{\bar\theta}(s)$ | Actor 的慢更新副本 |
| Target Critic | $Q_{\bar\phi}(s, a)$ | Critic 的慢更新副本 |

### 2.2 Critic 更新（学 Q 函数）

目标：让 $Q_\phi(s, a)$ 满足 [Bellman 方程](/前置知识/000o_前置知识_Q函数与Value函数)：

$$
L(\phi) = \mathbb{E}_{(s,a,r,s') \sim \mathcal{B}}\left[(Q_\phi(s,a) - y)^2\right]
$$

**这个公式在做什么**：让 Critic 打的分越来越接近"真实应该打的分"（由 Bellman 目标 $y$ 给出）——这是标准的回归损失，训练目标就是缩小 Critic 预测和目标值之间的差距。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $(s,a,r,s') \sim \mathcal{B}$ | **从记忆库里抽经验** | 从 [Replay Buffer](/前置知识/000r_前置知识_Replay_Buffer_经验回放) 里随机抽一条历史经验（状态、动作、奖励、下一状态） |
| $Q_\phi(s,a)$ | **Critic 当前的打分** | 网络现在认为这个（状态，动作）值多少分 |
| $y$ | **标准答案** | 下面单独讲解的 Bellman 目标，Critic 应该逼近的分数 |
| $(Q_\phi(s,a) - y)^2$ | **打分误差** | 当前打分和标准答案差多少，差得越多 loss 越大 |
| $\mathbb{E}_{(s,a,r,s')\sim\mathcal{B}}$ | **批量平均** | 实际训练中对一个 mini-batch（如 256 条经验）取平均 |

**用人话读**："从记忆库里随机抽一批经验，让 Critic 给出的分数尽量接近'即时奖励 + 未来价值'算出来的标准答案。"

**为什么是这个形式**：这是标准的时序差分（TD）回归——用自举（bootstrapping）的方式让 Q 函数自我一致，不需要等到整条轨迹结束就能更新。
:::

$$
y = r + \gamma \cdot Q_{\bar\phi}(s', \mu_{\bar\theta}(s'))
$$

**这个公式在做什么**：给出 Critic 应该逼近的"标准答案"——这一步的真实奖励，加上用 target 网络估计的下一步价值。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $r$ | **这一步到手的奖励** | 环境给出的即时反馈 |
| $\mu_{\bar\theta}(s')$ | **Target Actor 的猜测** | 用参数变化更慢的 Target Actor，猜下一状态该采取什么动作 |
| $Q_{\bar\phi}(s', \mu_{\bar\theta}(s'))$ | **Target Critic 的估值** | 用同样慢更新的 Target Critic，给"下一状态+猜的动作"打分，估计未来还能拿多少 |
| $\gamma$ | **折扣因子** | 未来的价值打个折（如 0.99），越远的奖励越不确定，权重越小 |
| $y = r + \gamma \cdot Q_{\bar\phi}(\cdots)$ | **Bellman 目标** | 即时奖励 + 打折后的未来价值，合起来就是这一步动作"应该值多少分" |

**用人话读**："这一步的真实收获，加上用慢速更新的目标网络估计出的'未来还能拿多少'，就是 Critic 应该学的目标分数。"

**为什么用 Target 网络而不是当前网络**：如果 $y$ 也用正在快速更新的 $Q_\phi, \mu_\theta$ 计算，目标值会随每一步训练剧烈晃动，导致训练震荡甚至发散。用参数滞后、缓慢移动的 Target 网络计算 $y$，让训练目标更稳定。
:::

### 2.3 Actor 更新（确定性策略梯度）

Actor 的目标：输出使 Q 值最大的动作。

$$
\nabla_\theta J = \mathbb{E}_{s \sim \mathcal{B}}\left[\nabla_a Q_\phi(s, a)\big|_{a=\mu_\theta(s)} \cdot \nabla_\theta \mu_\theta(s)\right]
$$

**一句话**：先问 Critic "Q 值沿哪个方向增大最快"（$\nabla_a Q$），再问 Actor "怎么调参数能让输出往那个方向走"（$\nabla_\theta \mu$）。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\nabla_a Q_\phi(s,a)\big|_{a=\mu_\theta(s)}$ | **Critic 指的方向** | 在 Actor 当前输出的动作点上，Q 值往哪个方向变化增长最快 |
| $\nabla_\theta \mu_\theta(s)$ | **Actor 的调节旋钮** | 网络参数 $\theta$ 变化一点点，会让输出动作往哪个方向移动多少 |
| $\nabla_a Q_\phi \cdot \nabla_\theta \mu_\theta$ | **链式法则接力** | 把"动作该往哪走"的信号，通过链式法则传回"参数该往哪调" |
| $\mathbb{E}_{s\sim\mathcal{B}}$ | **批量平均** | 实际训练中对 mini-batch 里抽到的一批状态取平均梯度 |
| $\nabla_\theta J$ | **Actor 的更新方向** | 汇总后得到的、能让期望 Q 值上升的参数更新方向 |

**用人话读**："Critic 告诉 Actor 现在的动作往哪个方向调能拿更高分，Actor 就顺着这个方向调整自己的参数。"

**为什么是这个形式**：这是确定性策略梯度定理——因为 $\mu_\theta$ 是确定性映射（不是分布），可以直接把 Q 对动作的梯度，通过链式法则传导到 Q 对参数的梯度，不需要像随机策略梯度那样对动作分布做期望采样。
:::

**代入例子**：
- 当前状态：摆杆偏左 30°
- Actor 输出：$\mu_\theta(s) = 0.8$（向右施力 0.8）
- Critic 评估：$Q_\phi(s, 0.8) = -2.5$
- Critic 梯度：$\nabla_a Q|_{a=0.8} = +1.2$（力矩再大一点 Q 值更高）
- Actor 更新：调整参数让 $\mu_\theta(s)$ 朝 $> 0.8$ 的方向变化

### 2.4 探索：OU 噪声

DDPG 的策略是确定性的（$\mu_\theta(s)$ 输出唯一一个值），没有内在的随机性。探索完全靠外部加噪声：

$$
a = \mu_\theta(s) + \mathcal{N}_{\text{OU}}
$$

**这个公式在做什么**：因为 Actor 输出的是唯一确定的动作、本身没有随机性，所以人为在动作上加一点噪声，让智能体愿意尝试"不完全按套路来"的动作，从而探索到更好的策略。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mu_\theta(s)$ | **Actor 的确定答案** | 网络认为当前最好的动作，每次输入同一状态都给出同一个值 |
| $\mathcal{N}_{\text{OU}}$ | **人工加的探索噪声** | Ornstein-Uhlenbeck 过程采样出的一个随机扰动，时间上前后相关（比白噪声更平滑，不会一步一个急转弯） |
| $a$ | **实际执行的动作** | 确定性动作加上噪声后，真正送进环境执行的那个值 |

**用人话读**："让 Actor 先给出它认为最好的动作，再往上加一点平滑的随机抖动，逼着智能体去尝试周围没试过的动作。"

**为什么用 OU 噪声而不是普通高斯白噪声**：连续控制任务（如力矩、速度）需要动作在时间上连贯，白噪声每步独立采样会让动作抖动过于剧烈、不像真实物理动作；OU 噪声有时间相关性，扰动更平滑，更符合惯性系统的探索需求。
:::

### 2.5 Target Network 的软更新

$$
\bar\theta \leftarrow (1 - \tau)\bar\theta + \tau\theta, \quad \tau = 0.001
$$

**这个公式在做什么**：让 Target 网络的参数每一步只往主网络方向"挪一小步"，而不是直接复制主网络——保证计算 Bellman 目标时用的网络足够稳定、不会剧烈跳动。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\theta$ | **主网络参数** | 正在被梯度下降快速更新的 Actor/Critic 参数 |
| $\bar\theta$ | **Target 网络参数** | 用来计算 Bellman 目标 $y$ 的那份"慢半拍"参数 |
| $\tau$ | **混合比例（如 0.001）** | 每次更新只让新参数占很小的权重 |
| $(1-\tau)\bar\theta + \tau\theta$ | **软更新公式** | 旧 target 参数占 99.9%，新主网络参数只占 0.1%，混合成新的 target 参数 |

**用人话读**："Target 网络每一步只朝主网络的方向挪一点点，像温水煮青蛙一样慢慢跟上，而不是一步到位直接复制。"

**为什么要软更新而不是硬更新**：如果 target 网络直接复制主网络（DQN 式的"每 N 步硬更新"），计算 Bellman 目标时用的价值估计会突然跳变，导致训练震荡；软更新让目标值随时间平滑变化，代价是收敛稍慢，但换来了更强的稳定性。
:::

## 三、DDPG 的问题

| 问题 | 表现 | 后续解决方案 |
|------|------|------------|
| Q 值过估计 | Critic 系统性地高估 Q 值，策略被误导 | [TD3](/前置知识/000q_前置知识_TD3) 的双 Q 取最小值 |
| 探索不足 | OU 噪声是无方向的，不知道该往哪探索 | [SAC](/前置知识/000k_前置知识_SAC_Soft_Actor_Critic) 的最大熵目标 |
| 对超参敏感 | 噪声幅度、学习率稍有变化就崩溃 | TD3 的延迟更新 + SAC 的自动温度 |
| 脆弱性 | 不同随机种子结果差异巨大 | TD3/SAC 的多项稳定化技术 |

---

## 四、DDPG 的历史意义

DDPG (Lillicrap et al., 2015) 是连续控制 Deep RL 的**开山之作**。虽然现在已被 TD3 和 SAC 全面取代，但它建立的框架——"Actor 输出连续动作 + Critic 评估 + Replay Buffer + Target Network"——至今仍是所有连续动作 off-policy 方法的骨架。
