# 前置知识：DPO（Direct Preference Optimization）

> **一句话**：把"训练奖励模型 + 用 RL 优化策略"这两步合并成一步——直接从"A 比 B 好"这种偏好对里,用一个分类损失训练出策略,数学上等价于隐式地训练了一个奖励模型再做 RL,但完全不需要真的把奖励模型和 RL 循环写出来。

## 贯穿全文的例子

> **场景**：一个机械臂在学习"把杯子放到托盘上"。给定同一个初始状态 $s$,收集到两条轨迹（或两个动作块）$a^+$ 和 $a^-$：$a^+$ 是杯子被平稳放置的动作,$a^-$ 是杯子被磕到托盘边缘的动作。我们只知道"人类看了两个视频后说 $a^+$ 更好",不知道 $a^+$ 具体值多少分、$a^-$ 具体值多少分。DPO 要解决的问题就是：**只用这种"谁更好"的相对信息,能不能直接训练出一个更好的策略？**

---

## 一、动机：为什么不直接套用 RLHF 的两步流程

### 1.1 标准 RLHF 流程的问题

在 LLM 对齐和机器人偏好学习中,标准做法（RLHF）分两步：

**第一步**：用人类标注的偏好对 $(a^+, a^-)$ 训练一个奖励模型 $r_\phi(s,a)$，让它学会"给好动作打高分"。

**第二步**：把训练好的 $r_\phi$ 当作环境奖励,用 [PPO](/前置知识/000a_前置知识_策略梯度与PPO) 之类的在线 RL 算法去优化策略 $\pi_\theta$，同时用 [KL 惩罚](/前置知识/000j_前置知识_KL散度与策略约束) 防止策略跑飞。

这个流程有三个实际痛点：

| 痛点 | 具体表现 |
|------|---------|
| 训练不稳定 | PPO 需要调 clip 范围、KL 系数、value 函数等一堆超参数,机器人/大模型场景下经常训崩 |
| 计算昂贵 | 需要同时维护策略网络、奖励模型、Value 网络三套参数,还要不断从策略里采样新数据喂给奖励模型打分 |
| 两步分离引入误差 | 奖励模型训练完就冻住,后续 RL 阶段发现的"奖励模型没覆盖到的情况"没法反过来纠正奖励模型 |

**核心问题**：能不能跳过"训练一个显式的奖励模型 + 跑 RL 循环"这两步,直接从偏好对 $(a^+, a^-)$ 一步到位训练出策略？DPO 的答案是：**可以,而且是数学上精确等价的**,不是近似。

### 1.2 直觉：反过来想问题

RLHF 的思路是：先有奖励模型,再推出最优策略。DPO 反过来想：**如果我们已经知道"最优策略"和"奖励模型"之间存在一个固定的数学关系,那为什么不直接把奖励模型用这个关系"替换掉",让损失函数里只剩下策略 $\pi_\theta$？**

这正是 DPO 论文（Rafailov et al., 2023）的核心洞察——它没有发明新的算法,而是发现了 RLHF 目标函数的一个**闭式重参数化**,把"训练奖励模型"这一步用代数运算直接消去了。

## 二、核心公式推导

### 2.1 第一步：RLHF 的最优策略长什么样

标准 RLHF 的优化目标是"最大化奖励,同时不要偏离参考策略太远"：

$$
\max_\pi \; \mathbb{E}_{a \sim \pi(\cdot|s)}\big[r_\phi(s,a)\big] - \beta \, D_{\text{KL}}\big(\pi(\cdot|s) \,\|\, \pi_{\text{ref}}(\cdot|s)\big)
$$

**这个公式在做什么**：这就是 [KL 散度与策略约束](/前置知识/000j_前置知识_KL散度与策略约束) 第 3.1 节讲过的带 KL 惩罚的 RL 目标——一模一样的形式,只是这里的 reward 换成了训练好的奖励模型 $r_\phi$。这个约束优化问题存在解析解（用 Lagrange 乘子法可以严格推出）：

$$
\pi^*(a|s) = \frac{1}{Z(s)} \, \pi_{\text{ref}}(a|s) \, \exp\left(\frac{1}{\beta} r_\phi(s,a)\right)
$$

**逐项拆解**：

| 符号 | 含义 | 直觉 |
|------|------|------|
| $\pi^*(a|s)$ | 上面约束优化问题的最优解 | "在不偏离参考策略太远的前提下,奖励最大化"能达到的最好策略 |
| $\pi_{\text{ref}}(a|s)$ | 参考策略（通常是 SFT 后的策略） | 基准分布,起点 |
| $r_\phi(s,a)$ | 训练好的奖励模型打分 | 这个动作有多好 |
| $\beta$ | KL 约束的松紧程度 | 越大越贴近 $\pi_{\text{ref}}$,越小越激进地追高奖励 |
| $Z(s) = \sum_a \pi_{\text{ref}}(a|s)\exp(r_\phi(s,a)/\beta)$ | 归一化常数（对所有动作求和/积分,只依赖 $s$） | 保证 $\pi^*$ 是合法的概率分布 |

这个形式和 [AWR 前置知识](/前置知识/000u_前置知识_AWR_优势加权回归) 第 2.4 节推出的最优策略形式**完全一样**（都是"参考分布 × 指数化的奖励/advantage"）——这不是巧合,两者都是同一类"KL 约束下的奖励最大化"问题的解。区别在于 AWR 直接拿这个公式当训练目标做加权回归,而 DPO 要往前多走一步：**把 $r_\phi$ 解出来**。

**为什么是这个形式**：这是约束优化问题（用 KL 当约束）的标准 Lagrange 对偶解,和 [KL 散度前置知识](/前置知识/000j_前置知识_KL散度与策略约束) 中"用 $\exp(A/\beta)$ 加权"的推导逻辑同源——本质上都是"指数倾斜"（exponential tilting）这个数学操作在起作用。

### 2.2 第二步：反解出奖励模型的表达式

上面的公式两边同时取对数、整理,可以把 $r_\phi$ 用 $\pi^*$ 和 $\pi_{\text{ref}}$ 表示出来：

$$
r_\phi(s,a) = \beta \log \frac{\pi^*(a|s)}{\pi_{\text{ref}}(a|s)} + \beta \log Z(s)
$$

**这个公式在做什么**：这是 2.1 节公式的代数逆运算——原来是"知道奖励推最优策略",现在反过来"知道最优策略推奖励"。这一步是整个 DPO 推导的关键转折点：**任何一个奖励模型,都可以用它对应的最优策略和参考策略的对数比值来表示**。

**逐项拆解**：

| 符号 | 含义 | 关键点 |
|------|------|--------|
| $\beta \log\frac{\pi^*(a|s)}{\pi_{\text{ref}}(a|s)}$ | 最优策略与参考策略的对数概率比,乘以 $\beta$ | 这一项**依赖动作 $a$**,包含了奖励模型的全部有效信息 |
| $\beta \log Z(s)$ | 一个只依赖状态 $s`、不依赖动作 $a$ 的项 | 这一项在后面的推导中会被**完全消掉** |

### 2.3 第三步：代入 Bradley-Terry 偏好模型,消掉 $Z(s)$

人类偏好数据通常用 **Bradley-Terry 模型**建模："$a^+$ 比 $a^-$ 更受偏好"的概率是两者奖励差的 sigmoid：

$$
p(a^+ \succ a^- \mid s) = \sigma\big(r_\phi(s,a^+) - r_\phi(s,a^-)\big)
$$

**为什么需要这个公式**：人类标注的偏好数据只有"哪个更好"这种相对信息,没有绝对分数。Bradley-Terry 模型是统计学里专门用来把"两两比较的胜负结果"转化为"每个选项背后有一个潜在实力值"的经典工具（最早用于体育比赛排名）——这里把"实力值"换成了"奖励"。

> **一句话直觉**：两个选手的奖励差越大,"奖励高的那个赢"的概率就越接近 1；奖励差为 0 时,谁赢的概率对半分。

**逐项拆解**：

| 符号 | 含义 | 直觉 |
|------|------|------|
| $\sigma(x) = 1/(1+e^{-x})$ | sigmoid 函数 | 把任意实数压缩到 $(0,1)$,当作概率 |
| $r_\phi(s,a^+) - r_\phi(s,a^-)$ | 两个动作的奖励差 | 差值越大,优势越明显 |
| $p(a^+ \succ a^- \mid s)$ | $a^+$ 被偏好的概率 | 训练目标是让这个概率匹配人类实际标注的偏好频率 |

**关键代数技巧**：注意 Bradley-Terry 公式里只出现奖励的**差值** $r_\phi(s,a^+) - r_\phi(s,a^-)$，而 2.2 节里 $\beta \log Z(s)$ 这一项对同一个状态 $s$ 下的 $a^+$ 和 $a^-$ 是**完全相同的常数**。把 2.2 节的 $r_\phi$ 表达式代入奖励差,$Z(s)$ 这一项会被**精确抵消**：

$$
r_\phi(s,a^+) - r_\phi(s,a^-) = \beta \log \frac{\pi^*(a^+|s)}{\pi_{\text{ref}}(a^+|s)} - \beta \log \frac{\pi^*(a^-|s)}{\pi_{\text{ref}}(a^-|s)}
$$

**这一步在做什么**：把两个"奖励=对数比值+常数"的表达式相减,常数项 $\beta\log Z(s)$ 由于对 $a^+,a^-$ 相同而互相抵消,只剩下和策略直接相关的两项。这正是 DPO 之所以能"跳过奖励模型"的代数核心——**归一化常数 $Z(s)$ 从未真正需要被计算**（在 RLHF 里这个 $Z(s)$ 本身几乎不可能算出来,因为要对整个动作空间积分）。

### 2.4 第四步：得到 DPO 最终损失函数

把上一步的奖励差代入 Bradley-Terry 概率公式,再用最大似然估计（让预测概率匹配真实标注的"$a^+$ 更好"这个事实,取负对数得到损失）,就得到 DPO 的最终训练目标：

$$
\mathcal{L}_{\text{DPO}}(\theta) = -\mathbb{E}_{(s,a^+,a^-)\sim\mathcal{D}}\left[\log \sigma\left(\beta \log\frac{\pi_\theta(a^+|s)}{\pi_{\text{ref}}(a^+|s)} - \beta \log\frac{\pi_\theta(a^-|s)}{\pi_{\text{ref}}(a^-|s)}\right)\right]
$$

**Step 1：这个公式在做什么**

**这是一个纯粹的二分类损失（binary cross-entropy）**：把"$a^+$ 比 $a^-$ 更受偏好"当作标签永远为 1 的二分类问题,让模型预测的"偏好概率"逼近 1。整个公式里没有出现任何显式的奖励模型 $r_\phi$——它已经在 2.3 节被代数消去,替换成了策略 $\pi_\theta$ 自身的对数概率比。

**Step 2：逐符号拆解**

| 符号 | 数学含义 | 具体是什么 | 典型值/维度 |
|------|---------|-----------|-------------|
| $(s,a^+,a^-)\sim\mathcal{D}$ | 从偏好数据集采样一个三元组 | 一个状态,一个更好的动作,一个更差的动作（人类或规则标注） | 离线数据,不需要在线交互 |
| $\pi_\theta(a^+\|s)$ | 当前训练中的策略对"好动作"的概率 | 待优化的网络输出 | — |
| $\pi_{\text{ref}}(a^+\|s)$ | 冻结的参考策略对同一动作的概率 | SFT 后的模型,全程不更新 | — |
| $\log\frac{\pi_\theta(a^+\|s)}{\pi_{\text{ref}}(a^+\|s)}$ | 隐式奖励：策略相对参考策略,对好动作的"偏好提升量" | 可以理解成 DPO 隐式学到的 $r_\phi(s,a^+)$（差一个与 $a$ 无关的常数） | — |
| $\beta$ | 温度系数,决定隐式奖励的"陡峭程度" | 和 2.1 节 KL 约束里的 $\beta$ 是**同一个**超参数 | 典型取值 0.01～0.5 |
| $\sigma(\cdot)$ | sigmoid 函数 | 把"好动作隐式奖励 − 差动作隐式奖励"这个差值压成一个 $(0,1)$ 的概率 | — |
| $-\log(\cdot)$ | 负对数似然 | 让 sigmoid 输出的概率尽量接近 1（因为标签就是"$a^+$ 更好"） | 概率越接近 1,loss 越接近 0 |

**每一项在"拉"什么往哪走**：括号内的差值 $\beta\log\frac{\pi_\theta(a^+|s)}{\pi_{\text{ref}}(a^+|s)} - \beta\log\frac{\pi_\theta(a^-|s)}{\pi_{\text{ref}}(a^-|s)}$ 越大,loss 越小。要让这个差值变大,梯度会同时做两件事：**提升** $\pi_\theta(a^+|s)$（相对参考策略）,**压低** $\pi_\theta(a^-|s)$（相对参考策略）——一次梯度更新同时处理好坏两个方向,这正是偏好学习相比单纯 AWR（只处理"好动作多学"）多出的信号。

**Step 3：数值代入**

延续贯穿全文的例子,某个状态 $s$（机械臂拿着杯子悬在托盘上方）,$a^+$ 是平稳放置动作,$a^-$ 是磕碰动作。设 $\beta=0.1$。

参考策略（SFT 模型)给出的概率：$\pi_{\text{ref}}(a^+|s)=0.3$,$\pi_{\text{ref}}(a^-|s)=0.25$（SFT 模型本身对两个动作都还没有强烈偏好,数值上甚至有点反直觉——这正是需要 DPO 来纠正的地方）。

当前训练中的策略（尚未训练好）给出：$\pi_\theta(a^+|s)=0.35$,$\pi_\theta(a^-|s)=0.28$。

逐步计算：
- $\log\frac{0.35}{0.3} = \log(1.167) \approx 0.154$
- $\log\frac{0.28}{0.25} = \log(1.12) \approx 0.113$
- 括号内差值：$\beta \times (0.154 - 0.113) = 0.1\times0.041 = 0.0041$
- $\sigma(0.0041) \approx 0.501$（几乎是 50/50,说明当前策略几乎没有学到"$a^+$ 应该更好"这件事）
- loss $= -\log(0.501) \approx 0.691$（接近 $\log 2 \approx 0.693$,即"完全不确定"时的 loss,符合直觉）

梯度下降会推动 $\pi_\theta(a^+|s)$ 继续上升、$\pi_\theta(a^-|s)$ 继续下降。假设经过若干步训练后变成 $\pi_\theta(a^+|s)=0.6$,$\pi_\theta(a^-|s)=0.1$：
- $\log\frac{0.6}{0.3}=\log2\approx0.693$，$\log\frac{0.1}{0.25}=\log0.4\approx-0.916$
- 括号内差值：$0.1\times(0.693-(-0.916))=0.1\times1.609=0.1609$
- $\sigma(0.1609)\approx0.540$，loss $=-\log(0.540)\approx0.616$，比训练前更小

**梯度方向**：随着训练推进,loss 持续下降,意味着策略越来越自信地把概率质量从 $a^-$ 移向 $a^+$，同时因为 $\pi_{\text{ref}}$ 在分母里全程不变,策略不会无限制地把 $a^+$ 概率推到 1（因为分母固定,分子涨多了 $\beta\log(\cdot)$ 增长会变慢,且还要和 $a^-$ 那一项的下降速度博弈）。

**Step 4：为什么是这个形式**

- **为什么用两个对数比值的差,而不是直接比较 $\pi_\theta(a^+),\pi_\theta(a^-)$**：因为 2.1-2.3 节的推导表明,"策略相对参考策略的对数概率比"正好等价于"隐式奖励"（差一个可以抵消的常数）。如果直接比较 $\pi_\theta(a^+)$ 和 $\pi_\theta(a^-)$ 本身,没有 $\pi_{\text{ref}}$ 做基准,就无法保证学到的是"奖励差"而不是纯粹"哪个动作先验概率更高"。
- **为什么要有 $\pi_{\text{ref}}$ 在分母里**：这正是 KL 约束在起作用——如果 $\pi_\theta$ 试图无限制地抬高 $a^+$ 的概率,分母 $\pi_{\text{ref}}(a^+|s)$ 不变,分子涨得越高,$\log$ 的边际收益递减，这就是"防止策略跑飞"的隐式机制,不需要像 PPO 那样再单独加一个 KL 惩罚项。
- **为什么用 sigmoid + 负对数似然（而不是别的形式）**：因为 Bradley-Terry 模型本身就是用 sigmoid 定义偏好概率的,DPO 只是原封不动地对这个概率模型做最大似然估计——这是统计学里训练二分类/排序模型最标准的做法。

## 三、DPO 训练流程（工程实操）

### 3.1 数据准备

DPO 需要的数据格式极其简单——三元组 $(s, a^+, a^-)$：

```python
# 偏好数据集示例
preference_data = [
    {"state": s1, "action_win": a1_good, "action_lose": a1_bad},
    {"state": s2, "action_win": a2_good, "action_lose": a2_bad},
    # ...
]
```

这些偏好对可以来自：人类直接标注（"这两个视频哪个更好"）、规则打分（如任务成功/失败自动配对）、或者另一个更强模型的排序结果。

### 3.2 训练伪代码

DPO 训练不需要 rollout、不需要 Critic、不需要奖励模型——只需要两次前向传播（$\pi_\theta$ 和 $\pi_{\text{ref}}$ 各跑一次)：

```python
# DPO 训练一步
for batch in dataloader:
    s, a_win, a_lose = batch

    # π_θ 和 π_ref 分别对 win/lose 动作打分（对数概率）
    logp_theta_win  = policy.log_prob(a_win,  s)
    logp_theta_lose = policy.log_prob(a_lose, s)
    with torch.no_grad():  # π_ref 冻结,不需要梯度
        logp_ref_win  = ref_policy.log_prob(a_win,  s)
        logp_ref_lose = ref_policy.log_prob(a_lose, s)

    # 隐式奖励差
    logits = beta * (logp_theta_win  - logp_ref_win) \
           - beta * (logp_theta_lose - logp_ref_lose)

    loss = -F.logsigmoid(logits).mean()

    optimizer.zero_grad()
    loss.backward()   # 梯度只流向 π_θ
    optimizer.step()
```

**代码中的关键点**：`ref_policy` 在整个训练过程中权重完全冻结（`torch.no_grad()`），只用来提供"基准对数概率"，这一点和 [KL 散度前置知识](/前置知识/000j_前置知识_KL散度与策略约束) 第 2.5.1 节讲的 $\pi_{\text{ref}}$ 扮演的角色完全一致。

### 3.3 和 RLHF 两步流程的直接对比

| 维度 | RLHF（奖励模型 + PPO） | DPO |
|------|----------------------|-----|
| 训练阶段数 | 2（奖励模型 → RL） | 1（直接训练策略） |
| 需要环境交互/rollout？ | ✅ 需要（PPO 是在线的） | ❌ 不需要（纯离线） |
| 需要 Critic/Value 网络？ | ✅ 需要 | ❌ 不需要 |
| 需要显式奖励模型？ | ✅ 需要单独训练 | ❌ 隐式包含在策略里 |
| 超参数数量 | 多（PPO clip、KL 系数、GAE λ、value loss 系数……） | 少（主要就是 $\beta$） |
| 训练稳定性 | 容易训崩（RL 特有的不稳定性） | 稳定（本质是监督学习） |
| 数据要求 | 偏好对（训练奖励模型） + 在线 rollout（训练策略） | 只需偏好对 |

## 四、DPO 的局限与何时不适用

1. **无法处理"绝对分数"信号**：DPO 只学"相对偏好",如果奖励是连续的绝对数值（如"这个动作值多少分"）,DPO 需要先把它转成偏好对,可能损失信息。
2. **依赖参考策略的质量**：$\pi_{\text{ref}}$ 太差会限制 $\pi_\theta$ 能达到的上限（因为公式里始终是"相对 $\pi_{\text{ref}}$ 的提升量"）。
3. **偏好对的粒度是轨迹/动作级别的,不是逐步的**：标准 DPO 比较的是整条轨迹或整个动作块的偏好,不天然提供"具体哪一步该怎么改"的信号——这正是本系列 [RedFlow 精读](/论文综述/094_RedFlow_失败重定向为动作级修正) 中提到 DPO 局限性的地方：它只在轨迹层面比较,没有动作级修正目标。

## 六、总结

| 概念 | 核心要点 |
|------|---------|
| DPO 定义 | 直接从偏好对训练策略,跳过显式奖励模型和在线 RL 循环 |
| 数学关系 | RLHF 最优策略的闭式解 $\Rightarrow$ 反解出奖励 $\Rightarrow$ 代入 Bradley-Terry $\Rightarrow$ 归一化常数抵消 |
| 最终形式 | 一个二分类损失,变量只有 $\pi_\theta,\pi_{\text{ref}}$ 的对数概率比 |
| $\beta$ 的双重角色 | 既是隐式奖励的温度系数,也是隐式的 KL 约束强度 |
| 优点 | 纯离线、无需 Critic、训练稳定、超参数少 |
| 局限 | 只有相对偏好信号,通常是轨迹/动作块级别,没有动作级修正目标 |
