# 前置知识：Cal-QL（Calibrated Conservative Q-Learning）校准保守 Q 学习

> **为什么要读这篇**：[CQL](/前置知识/002g_前置知识_CQL保守Q学习) 能把离线 RL 训稳，但它有一个非常具体的后遗症——离线训完切到在线微调时，成功率会先**断崖式下跌**，然后花掉大量环境交互才慢慢爬回来。原因是 CQL 把 Q 值系统性压低了一个未知的量，在线阶段的策略梯度在 Q 值"爬回真实尺度"之前完全是噪声。Cal-QL 用一行改动解决了它：**保守项可以压低 OOD 动作的 Q 值，但不许压到"我已知的一个下界"以下**。这个下界就是数据集里算出来的蒙特卡洛回报。

## 1. 贯穿全文的例子

沿用一个具体任务：**机械臂打开抽屉**。

```text
状态   s：三路相机图像 + 机器人关节状态
动作   a：一段关节轨迹
奖励   r：只有成功打开抽屉的那一刻给 +1，其余全 0（稀疏终局奖励）
γ      = 0.99
数据集 D：50 条人类遥操作演示，其中 40 条成功、10 条失败
阶段一：只用 D 做离线训练（不碰真机 / 不碰仿真）
阶段二：切到在线，边采集边训练
```

这个设定的关键特征是**阶段二的开头**。阶段一结束时我们有一个 Q 网络和一个策略；阶段二第一次策略更新用的就是这个 Q 网络给出的梯度。如果这个 Q 网络的数值是坏的，第一次更新就会把好不容易训出来的策略破坏掉。

## 2. 问题：CQL 训出来的 Q 值"尺度不对"

### 2.1 先算出这个任务里 Q 值应该是多少

奖励只在成功那一刻给 $+1$。如果从状态 $s$ 出发，策略需要 $k$ 个决策步才能成功，那么

$$
Q^\pi(s,a) = \gamma^{k} \times 1 = 0.99^{k}
$$

代入数字：$k=10$ 时 $Q = 0.99^{10} = 0.904$；$k=50$ 时 $Q = 0.605$；$k=200$ 时 $Q = 0.134$。失败的轨迹上 $Q = 0$。

**所以在这个任务里，一切合理的 Q 值都落在 $[0, 1]$ 区间内**。这个观察是理解 Cal-QL 的基础。

### 2.2 CQL 会把 Q 值压到哪里去

**为什么需要这个公式**：[CQL](/前置知识/002g_前置知识_CQL保守Q学习) 训练离线 RL 时，光有 TD loss 是不够的——网络会在训练数据没覆盖到的动作（OOD 动作）上产生虚高的 Q 值估计（因为没有数据纠正它）。CQL 在标准 TD loss 之外加一个正则项，专门用来压低这些 OOD 动作的 Q 值。这一节要看清楚：这个正则项到底往哪个方向使力，力气有多大是谁决定的。

CQL 的保守项是

$$
\mathcal{R}(\theta) = \mathbb{E}_{s\sim\mathcal{D}}\Big[\mathrm{LSE}_\tau\big(Q_\theta(s,\cdot)\big)\Big] - \mathbb{E}_{(s,a)\sim\mathcal{D}}\big[Q_\theta(s,a)\big]
$$

这里 $Q_\theta$ 就是**正在训练的那个 Q 网络**，$\theta$ 是它的参数（权重）。写成 $Q_\theta(s,a)$ 表示"参数为 $\theta$ 的网络，输入状态 $s$ 和动作 $a$，输出一个打分"。之所以特意标出下标 $\theta$，是为了和后面会出现的 $Q^*$（真实的、理论上正确的 Q 函数，不依赖任何参数，训练要逼近的目标）区分开——$Q_\theta$ 是训练过程中的近似值，会随着训练变化；$Q^*$ 是固定不变的"标准答案"。

> **一句话直觉**：拿"网络自己觉得最好的动作能打多少分"减去"数据集里真实动作打多少分"，这个差值就是要在训练中被压小的东西。差值越大，说明网络在瞎猜的动作上给分虚高，正则项就把这些虚高的分数往下拉。

**逐符号拆解**：

| 符号 | 数学含义 | 直觉 | 在打开抽屉例子中 |
|---|---|---|---|
| $s\sim\mathcal{D}$ | 从数据集里采样一个状态 | "看数据集里出现过的某个场景" | 遥操作演示中某一帧的相机图像+关节状态 |
| $Q_\theta(s,\cdot)$ | 固定 $s$，$Q_\theta$ 对**所有**可能动作的打分 | "在这个状态下，网络对每个动作的评价" | 对随机采样出的一批候选关节轨迹分别打分 |
| $\mathrm{LSE}_\tau(\cdot)$ | log-sum-exp，"软最大值"（推导见 [CQL §3.2](/前置知识/002g_前置知识_CQL保守Q学习#3.2-实用形式-用-logsumexp-代替算术平均)） | 近似于"这堆候选动作里，最高的那个打分是多少" | 候选轨迹里 Q 值最高的那一个，代表"网络觉得的最优动作" |
| $\mathbb{E}_{s\sim\mathcal{D}}[\cdots]$ | 对第一项，在所有采样到的状态上取平均 | "这个虚高现象是不是普遍存在，不是只在一个状态上偶然发生" | 对 50 条演示里出现过的所有状态取平均 |
| $(s,a)\sim\mathcal{D}$ | 从数据集里采样"状态-动作对"（不是任意动作，是数据里真实出现过的那个动作） | "这个状态下，人类演示实际做的动作" | 某一帧图像，配上人类当时实际执行的那段关节轨迹 |
| $Q_\theta(s,a)$ | 网络对这个**真实**动作的打分 | "网络怎么评价人类实际做的这个动作" | 对人类真实轨迹的打分 |
| 减号 | 两项之差 | "网络自己瞎猜的最高分" 减去 "网络给真实动作的打分" | 差值越大越说明虚高越严重 |

**为什么减去数据项、不是只压第一项**：如果正则项只有 $\mathrm{LSE}_\tau(Q_\theta(s,\cdot))$ 这一项，网络的最优解是把**所有**动作（包括数据里真实出现的动作）的 Q 值一起压到 $-\infty$——这样第一项自然就小了，但整个 Q 函数塌缩成没用的常数，区分不出好坏动作。减去数据项相当于给数据动作的 Q 值一个"锚"：只有当某个候选动作的分数**明显高于**数据动作时，才会被拉低；数据动作本身的分数不会被这个正则项主动压低（它还受 TD loss 的正常拉升）。

**数值代入**：假设某个状态 $s$，数据里的真实动作 $Q_\theta(s,a_{\mathcal{D}})=0.3$。网络对随机采样出的 4 个候选动作打分分别是 $[-1.0, 0.5, 2.0, -3.0]$（其中 $2.0$ 是一个网络没见过训练数据、纯粹外推出来的虚高分）。取 $\tau=1$，把数据动作也加入候选集合一起算 LSE（这是 CQL 论文的标准写法）：

$$
\mathrm{LSE}_1 = 2.0 + \log\!\left(e^{-1.0-2.0}+e^{0.5-2.0}+e^{0}+e^{-3.0-2.0}+e^{0.3-2.0}\right) = 2.0+\log(0.0498+0.2231+1+0.0067+0.1810)
$$
$$
= 2.0+\log(1.4606)=2.0+0.379=2.379
$$

$$
\mathcal{R}(\theta) = 2.379 - 0.3 = 2.079
$$

这个 $2.079$ 就是要在训练中被压小的量。梯度下降怎么压它？$\mathrm{LSE}_\tau$ 对每个候选动作的梯度权重和它的 softmax 概率成正比——$2.0$ 那个候选拿到的权重是 $1/1.4606\approx0.685$，远高于其他候选，所以梯度几乎全部集中火力去压这一个虚高分数,而 $-1.0,-3.0$ 这类本来就低的候选几乎不受影响（它们的权重只有 $0.034$、$0.005$）。

梯度下降会一直往下压第一项里权重最大的那些候选。这个压低**没有底**——只要还在训练，OOD 动作的 Q 值就会持续下降，把整个 Q 函数往负方向拖。

跑 800 步离线更新之后，典型情况是：数据动作上的 Q 值还留在 $0.3$ 附近（被第二项抬着），但 OOD 动作上的 Q 值已经掉到 $-5$、$-20$ 甚至更低。

**关键点不是"OOD 动作 Q 值低"——那正是我们要的。关键点是"低到了一个完全脱离真实尺度的位置"。**

### 2.3 为什么这会毁掉在线阶段的第一步

在线阶段的 actor 更新目标（以 SAC 为例）是

$$
\mathcal{L}_{\text{actor}} = -\mathbb{E}_{s\sim\mathcal{D}_{\text{online}}}\big[Q_\theta(s, \pi_\phi(s))\big]
$$

策略沿着 $\nabla_\phi Q_\theta(s,\pi_\phi(s))$ 往 Q 值高的方向走。这里唯一重要的是 **Q 函数的局部形状（相对排序和梯度方向）**，绝对数值无关。

这段论证里出现了两个必须先分清楚的符号：

| 符号 | 含义 | 是谁 |
|------|------|------|
| $Q_\theta$ | **网络当前学出来的** Q 函数，$\theta$ 是它的参数 | 就是前面 2.2 节里被 CQL 保守项压低过的那个网络。它是一个近似值，训练没结束之前可能是错的、有偏的 |
| $Q^*$ | **真实的最优** Q 函数 | 理论上的"标准答案"——如果知道每个 $(s,a)$ 到底能换来多少折扣回报，那就是 $Q^*$。它不是网络，是训练要逼近的目标，实际中永远拿不到精确值，这里只是用它来指出 $Q_\theta$ "应该"是什么样子 |

一句话：$Q_\theta$ 是"网络现在觉得的分数"，$Q^*$ 是"客观上正确的分数"。策略更新用的是 $Q_\theta$，但我们真正希望的是策略朝着 $Q^*$ 高的方向走。如果 $Q_\theta$ 和 $Q^*$ 的**排序**一致（哪个动作更好，两者说法相同），那用 $Q_\theta$ 指导策略就没问题，即使两者的绝对数值差很远。Cal-QL 要防的正是排序不一致的情况。

问题在于：在线阶段一开始，新采集的数据进入 buffer，TD loss 开始把 $Q_\theta$ 往真实尺度（$[0,1]$，即 $Q^*$ 所在的量级）拉。这个拉升过程中，$Q_\theta$ 在不同区域的**上升速度是不均匀的**——数据覆盖密的地方拉得快，稀疏的地方拉得慢。于是在拉升期间，$Q_\theta$ 的等高线在剧烈变形，局部梯度方向和真实的 $\nabla Q^*$（真实 Q 函数的梯度方向，也就是"客观上朝哪个方向调整才是对的"）毫无关系。

具体到数字：假设网络当前给出 $Q_\theta(s, a_{\text{好}}) = -18$，$Q_\theta(s, a_{\text{坏}}) = -12$（这两个数值都是被 2.2 节的 CQL 保守项压低后留下的，压低的幅度对两个动作并不相同）。而客观上（$Q^*$，我们假设已知的"标准答案"）$Q^*(s,a_{\text{好}}) = 0.9 > Q^*(s,a_{\text{坏}}) = 0.1$——$a_\text{好}$ 才是真正该选的动作。但网络给出的排序是**反的**：$-18 < -12$，意味着网络认为 $a_\text{坏}$ 分数更高。策略沿着 $\nabla_\phi Q_\theta$ 更新，会朝 $Q_\theta$ 更高的 $a_{\text{坏}}$ 走，而不是朝 $Q^*$ 更高的 $a_\text{好}$ 走。这就是在线阶段初期成功率崩掉的直接原因——策略被一个排序错误的 $Q_\theta$ 带偏了。

排序反了的根源：CQL 对不同 OOD 动作的压低量是不一致的（取决于它们在训练中被采样到多少次、网络的局部拟合能力等），压低量的差异远大于真实 Q 值的差异（$Q^*$ 层面的真实差异只有 $0.8$，但 $Q_\theta$ 上被压低的幅度差异可能有 $6$）。**保守项引入的这种不均匀压低，其噪声幅度远超真实信号的幅度，把排序完全淹没了。**

## 3. Cal-QL 的解法：给保守项一个下界

Cal-QL 的观察是：我们其实**手里有一个免费的、可靠的 Q 值下界**——数据集里每条轨迹的蒙特卡洛回报。

### 3.1 参考值：数据集的蒙特卡洛回报

对数据集里第 $i$ 条轨迹的第 $t$ 个时刻，定义

$$
G_t^{(i)} = \sum_{j=t}^{T_i - 1} \gamma^{\,j-t} \, r_j^{(i)}
$$

**Step 1：这个公式在做什么**

**它算出"从这条轨迹的第 $t$ 步开始，按照这条轨迹实际的走法一路走到底，折扣累加起来实际拿到了多少奖励"**。它不是估计，是**已经发生的事实**。

> **一句话直觉**：这一步之后这条轨迹到底赚了多少，一分不差地记下来。

**逐符号拆解**：

| 符号 | 数学含义 | 直觉 | 在打开抽屉例子中 |
|------|----------|------|------------------|
| $i$ | 轨迹编号 | 第几条演示 | 1 到 50 |
| $t$ | 轨迹内的时刻 | 第几个决策步 | 0 到 $T_i-1$ |
| $T_i$ | 第 $i$ 条轨迹的长度 | 这条演示做了多少步 | 例如 30 |
| $r_j^{(i)}$ | 第 $j$ 步的即时奖励 | 环境给的分 | 成功那一步 $=1$，其余 $=0$ |
| $\gamma^{\,j-t}$ | 折扣权重 | 离当前越远权重越小 | $0.99^{j-t}$ |
| $G_t^{(i)}$ | 折扣回报 | 事实上拿到的总回报 | 见下面的数值 |

**代入数字**：第 3 条轨迹长度 $T_3 = 30$，只有最后一步 $r_{29} = 1$，其余为 0。

- $t = 29$（最后一步）：$G_{29} = 1$
- $t = 20$：$G_{20} = 0.99^{29-20} \times 1 = 0.99^{9} = 0.914$
- $t = 0$：$G_{0} = 0.99^{29} = 0.747$

第 7 条轨迹是失败的（全程 $r=0$）：所有 $t$ 都有 $G_t = 0$。

**为什么 $G_t$ 是一个合理的下界**：$G_t$ 是**行为策略**（采数据的那个策略，这里是人类遥操作）从 $s_t$ 出发实际拿到的回报，也就是 $Q^{\beta}(s_t, a_t)$ 的一个无偏单样本估计。而 RL 的目标是学出**比行为策略更好**的策略 $\pi$，所以

$$
Q^{\pi}(s_t, a) \;\gtrsim\; Q^{\beta}(s_t, a_t) \approx G_t
$$

换句话说：**任何合理的 Q 函数在这个状态上都不应该低于"人类演示实际拿到的分数"**。如果 CQL 把 Q 压到了 $G_t$ 以下，那它压过头了。

### 3.2 Cal-QL 的保守项

$$
\mathcal{R}_{\text{Cal}}(\theta) = \mathbb{E}_{s\sim\mathcal{D}}\Big[\mathrm{LSE}_\tau\Big(\max\big\{Q_\theta(s,a_k),\; G(s)\big\}_{k=1}^{K}\Big)\Big] - \mathbb{E}_{(s,a)\sim\mathcal{D}}\big[Q_\theta(s,a)\big]
$$

**Step 1：这个公式在做什么**

**它在把候选动作的 Q 值送进 logsumexp 之前，先逐个和参考值 $G(s)$ 取 max**——已经低于参考值的候选被"抬"到参考值，于是它们在这一项里的梯度变成 0，不再被继续压低。

> **一句话直觉**：该压的继续压，已经压到底线以下的就放手不管了。

**逐符号拆解**：

| 符号 | 数学含义 | 直觉 | 具体是什么 |
|------|----------|------|-----------|
| $a_k$ | 第 $k$ 个候选动作 | 采样出来的 OOD 候选 | 随机动作 / 策略采样，共 $K$ 个 |
| $G(s)$ | 状态 $s$ 对应的 MC 回报 | 这个状态的"底线价值" | 从数据集预先算好，随 batch 一起取出 |
| $\max\{Q_\theta(s,a_k), G(s)\}$ | 逐元素取大 | 低于底线的抬回底线 | **这是 Cal-QL 相对 CQL 的唯一改动** |
| $\mathrm{LSE}_\tau$ | 软最大值 | 同 CQL | 见 [CQL 3.2 节](/前置知识/002g_前置知识_CQL保守Q学习#3.2-实用形式-用-logsumexp-代替算术平均) |

**梯度方向的分情况分析**（这是理解 Cal-QL 的核心，必须拆开看）：

对某个候选 $a_k$：

- **情况 A：$Q_\theta(s,a_k) > G(s)$**（Q 值还在底线之上）
  $\max$ 选中了 $Q_\theta$，梯度正常通过。这个候选**继续被压低**。CQL 的保守作用完整保留。

- **情况 B：$Q_\theta(s,a_k) \le G(s)$**（Q 值已经跌破底线）
  $\max$ 选中了常数 $G(s)$，而 $G(s)$ 与 $\theta$ 无关，所以 $\partial/\partial\theta = 0$。这个候选**在保守项里彻底不再受力**。

**情况 B 是 Cal-QL 的全部魔法所在。** 一旦某个 OOD 动作的 Q 值被压到 $G(s)$ 以下，保守项就自动"松手"。这个动作的 Q 值之后只受 TD loss 支配，会停留在 $G(s)$ 附近，而不是无止境往负无穷跑。

**代入完整数字**：某个状态 $s$，$G(s) = 0.75$，数据动作 Q 值 $Q_\theta(s,a_{\mathcal{D}}) = 0.80$。4 个候选动作的 Q 值分别是：

| 候选 | $Q_\theta$ | 与 $G(s)=0.75$ 比较 | $\max$ 结果 | 是否受压低梯度 |
|------|-----------|---------------------|-------------|----------------|
| $a_1$ | $2.30$ | 高于 | $2.30$ | 是（这是虚高的 OOD，正是要压的） |
| $a_2$ | $0.90$ | 高于 | $0.90$ | 是 |
| $a_3$ | $0.20$ | 低于 | $0.75$ | **否**（已经压够了） |
| $a_4$ | $-3.10$ | 低于 | $0.75$ | **否**（之前被压过头，现在保护起来） |

logsumexp（$\tau=1$，候选集合再加上数据动作 $0.80$，共 5 项）：

$$
\begin{aligned}
\mathrm{LSE} &= 2.30 + \log\!\left(e^{0} + e^{0.90-2.30} + e^{0.75-2.30} + e^{0.75-2.30} + e^{0.80-2.30}\right) \\
&= 2.30 + \log(1 + 0.2466 + 0.2122 + 0.2122 + 0.2231) \\
&= 2.30 + \log(1.8941) = 2.30 + 0.6388 = 2.939
\end{aligned}
$$

$$
\mathcal{R}_{\text{Cal}} = 2.939 - 0.80 = 2.139
$$

如果用原始 CQL（不做 max 抬升）：

$$
\mathrm{LSE}_{\text{CQL}} = 2.30 + \log(1 + 0.2466 + 0.1225 + 0.0043 + 0.2231) = 2.30 + \log(1.5965) = 2.768
$$

$$
\mathcal{R}_{\text{CQL}} = 2.768 - 0.80 = 1.968
$$

两个数值差别不大（$2.139$ vs $1.968$），但**梯度分配完全不同**：

| 候选 | CQL 的梯度权重 | Cal-QL 的梯度权重 |
|------|----------------|-------------------|
| $a_1 = 2.30$ | $1/1.5965 = 0.626$ | $1/1.8941 = 0.528$ |
| $a_2 = 0.90$ | $0.2466/1.5965 = 0.154$ | $0.130$ |
| $a_3 = 0.20$ | $0.1225/1.5965 = 0.077$ | **0** |
| $a_4 = -3.10$ | $0.0043/1.5965 = 0.003$ | **0** |

$a_3$ 和 $a_4$ 的梯度被完全切断。$a_4$ 本来权重就很小（$0.003$）——因为 logsumexp 对已经很低的值不太敏感——但重点是它现在**永久性地**不会再被压低了。累积几百步之后，这个差别就是"Q 值停在 $0.75$ 附近"和"Q 值滑到 $-30$"的区别。

**为什么是 max 而不是加一个 hinge 惩罚**：也可以写成 $+\lambda\max\{0, G(s) - Q_\theta\}^2$ 这种把 Q 往上拉的形式，但那会引入一个新超参 $\lambda$，而且会**主动**把 Q 值往上推（可能推过 $G$，破坏保守性）。$\max$ 的形式是纯"止损"——只切断向下的力，不额外施加向上的力，不引入新超参。

### 3.3 一行代码

实现上确实只是一行。核心逻辑是：把候选 Q 值张量和参考值做 broadcast 的 `torch.maximum`，其余部分和 CQL 完全一样。

```python
# candidates: [B, K, num_q_heads]  候选动作上的 Q 值
# mc_returns: [B]                  从数据集预计算的 MC 回报

if mc_returns is not None:
    bounds = mc_returns.reshape(-1, 1, 1)          # [B,1,1] 广播到 [B,K,H]
    bound_rate = (candidates < bounds).float().mean()   # 监控用：多少比例被抬升了
    candidates = torch.maximum(candidates, bounds)      # ← Cal-QL 的全部改动

# 下面和 CQL 完全一样
candidates = torch.cat([candidates, q_data.unsqueeze(1)], dim=1)
ood_q = torch.logsumexp(candidates / tau, dim=1) * tau
cql_reg = (ood_q - q_data).mean()
```

`bound_rate` 这个监控量非常重要，第 5 节会展开怎么用它调参。

## 4. 为什么"校准"这个名字

Cal-QL 论文里的理论表述是：Q 函数需要相对某个**参考策略** $\mu$ 保持校准（calibrated），即

$$
Q_\theta(s,a) \ge Q^{\mu}(s,a) \quad \text{对所有 } a
$$

取 $\mu = \beta$（行为策略），$Q^\beta$ 用数据集的 MC 回报估计，就得到了实现里的形式。

"校准"的含义：**Q 函数的数值虽然仍然是保守的（低于 $Q^*$），但它被锚定在一个已知的合理量级上，而不是漂浮在任意的负数区域**。这样在线阶段一开始，Q 函数的局部形状就已经大致正确，策略梯度立刻可用。

论文给出的性质：Cal-QL 保持 CQL 的保守性（仍然是 $Q^*$ 的下界，所以离线阶段依然稳定），同时保证 Q 值不低于 $Q^\beta$，从而把在线微调的次优性收敛速度从 CQL 的"需要先重新学一遍 Q"改善为"直接继续改进"。

## 5. 工程实践要点

### 5.1 MC 回报必须和奖励定义严格一致

$G_t$ 必须用**训练时实际使用的那套奖励函数**重算，而不是数据集里记录的原始环境奖励。如果训练用的是"只有成功终局给 +1"，$G_t$ 就必须按这套算；如果训练时做了 reward shaping，$G_t$ 也要用 shaped reward 算。

不一致会导致下界的量级完全错位——比如奖励做了 $\times 10$ 缩放但 $G_t$ 没跟着缩放，下界就形同虚设（永远压不到）或者过强（一开始就全部触发，保守项直接失效）。

### 5.2 稀疏终局奖励下的下界很松

回到打开抽屉的例子：失败轨迹上 $G_t \equiv 0$。这意味着对失败轨迹采到的状态，Cal-QL 的下界是 $0$——只要 Q 值还在 $0$ 以上就会继续被压。这个保护比成功轨迹（$G_t \in [0.6, 1.0]$）弱得多。

这不是 bug，是稀疏奖励的固有性质：失败轨迹确实没有提供"这个状态至少值多少"的信息。实践中的后果是**数据集里失败样本占比越高，Cal-QL 的校准效果越弱**。如果观察到 Q 值仍然在往负数跑，检查一下 batch 里成功样本的比例。

### 5.3 用 `bound_rate` 判断校准是否生效

`bound_rate` = 候选 Q 值中被抬升的比例。它的读法：

| `bound_rate` 观察 | 含义 | 处理 |
|-------------------|------|------|
| 全程接近 $0$ | Q 值从没跌破下界，Cal-QL 等价于 CQL | 保守强度 $\alpha$ 可能太小，或下界算错了（量级过小） |
| 训练初期 $0$，后期升到 $0.2\sim0.6$ | **理想**：先正常压低，压到底线后自动止损 | 不用动 |
| 一开始就接近 $1$ | 下界过高，保守项从头就不起作用 | 检查 $G_t$ 的计算，或 $\alpha$ 太大导致一步压穿 |
| 剧烈震荡 | Q 值在下界附近抖 | 降低 critic 学习率或 $\alpha$ |

### 5.4 只在离线阶段使用

Cal-QL（以及 CQL）的保守项是为"数据固定、不能再探索"这个约束设计的。切到在线阶段后，新数据会持续修正 OOD 区域的 Q 值，保守项不再必要，而且会拖慢 Q 值上升。所以标准做法是**在线阶段直接关掉 CQL 项，只留标准 TD loss**。

## 6. 三者对比

| 维度 | 标准 TD（无保守项） | CQL | Cal-QL |
|------|---------------------|-----|--------|
| 离线阶段稳定性 | 差，Q 值发散 | 好 | 好 |
| Q 值数值尺度 | 发散到 $+\infty$ | 系统性偏低，量级不可控 | 保守但锚定在 $Q^\beta$ 之上 |
| 离线策略质量 | 很差 | 好 | 好（与 CQL 相当） |
| 切在线后初期表现 | — | **崩溃**，需大量交互恢复 | 平稳，可直接改进 |
| 额外超参 | 无 | $\alpha, N, \tau$ | 与 CQL 相同（$G_t$ 由数据决定，不是超参） |
| 额外计算 | — | $3N$ 倍 Q 前向 | 与 CQL 相同（多一次 `maximum`） |
| 额外数据要求 | 无 | 无 | **需要完整轨迹**才能算 $G_t$（不能只存散装 transition） |

最后一行值得强调：Cal-QL 要求 replay buffer 按 **episode** 存储而不是按 transition 存储，否则算不出 $G_t$。这会影响数据管线的设计。

## 7. 小结

| 要点 | 内容 |
|------|------|
| 解决的问题 | CQL 把 Q 值压到未知的负数区域，导致离线转在线时策略梯度失效、成功率崩溃 |
| 核心手段 | 保守项的候选 Q 值先与 MC 回报 $G(s)$ 取 max，跌破下界的候选梯度归零 |
| 下界为什么合理 | $G(s) \approx Q^\beta(s,a)$，任何合理策略都不该比行为策略更差 |
| 实现成本 | 一次 `torch.maximum` + 数据侧预计算 $G_t$ |
| 数据要求 | replay 必须按 episode 组织（需要完整轨迹算折扣回报） |
| 关键监控量 | `bound_rate`（被抬升的候选比例），理想曲线是"初期 0 → 后期 0.2~0.6" |
| 使用范围 | 只在离线阶段开启，在线阶段关闭 |
