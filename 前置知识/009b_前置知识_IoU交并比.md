# IoU 交并比（Intersection over Union）

> 一句话概括：IoU（Intersection over Union，交并比）是衡量"两块区域重叠得有多好"的一个 0 到 1 的分数——两块区域重合的面积，除以它们合起来占的总面积。1 表示完全重合，0 表示毫无交集。

## 贯穿全文的例子

> **场景**：一个网络预测"图像里物体接触到软垫的那块区域"，输出一张 $240\times240$ 的二值掩码（每个像素 1=接触、0=没接触）。我们手里有真实的接触区域（也是一张二值掩码）。问题是：怎么用一个数客观地说清楚"网络框出来的接触区域，和真实的接触区域，对得有多准"？这正是 IoU 要回答的。

---

## 一、为什么需要 IoU：普通"准确率"在区域问题上会骗人

先说清楚不用 IoU 会怎样。一个直觉的想法是"逐像素算准确率"：预测和真值一致的像素占比。但在我们的例子里，接触区域可能只占整张图的 5%，其余 95% 都是背景（0）。这时哪怕网络**什么都不预测、全输出 0**，逐像素准确率也高达 95%——这个数字完全是背景撑起来的，对"接触区域框得准不准"毫无意义。

IoU 绕开了这个陷阱：它只看两块"前景区域"（预测的和真实的）本身重叠得好不好，完全不受背景面积大小的影响。哪怕背景占 99.99%，IoU 也只在乎那两小块区域的关系。

---

## 二、定义与几何直觉

给定两块区域 $A$（真值）和 $B$（预测），IoU 定义为它们交集的面积除以并集的面积：

$$
\text{IoU}(A, B) = \frac{|A \cap B|}{|A \cup B|}
$$

**这个公式在做什么**：量"两块区域重合的部分"占"两块区域一共覆盖的部分"的比例——重合越多、各自多出来的部分越少，这个比例越接近 1。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $A$ | **真值区域** | 标准答案框出的那块（如真实接触区域） |
| $B$ | **预测区域** | 网络框出的那块 |
| $\lvert A \cap B\rvert$ | **重合面积（交集）** | 两块都覆盖到的部分有多大——"对上的部分" |
| $\lvert A \cup B\rvert$ | **总覆盖面积（并集）** | 两块合起来一共盖住多大 = $\lvert A\rvert + \lvert B\rvert - \lvert A\cap B\rvert$ |
| 相除 | **归一化比例** | 把"对上多少"除以"一共多大"，得到 0–1 的分数 |

**用人话读**："两块区域重合的地方，占它们合起来总面积的多大比例。"

**为什么分母是并集而不是某一块的面积**：如果分母只用真值面积 $\lvert A\rvert$，那网络把预测区域 $B$ 画得巨大（把 $A$ 整个包住）也能得满分——但这明显是"框得太大"的坏预测。用并集当分母，$B$ 画大了会让并集变大、分数下降，$B$ 画小了漏掉 $A$ 又会让交集变小、分数也下降。所以并集分母同时惩罚"框太大"和"框太小"两种错误，这是 IoU 比"重合/真值面积"更公正的关键。
:::

## 三、边界情况：IoU 取值的两个极端

理解一个指标，最快的方式是看它在极端情况下等于多少：

- **完全重合**（$B$ 和 $A$ 一模一样）：交集 = 并集 → IoU $= 1$。这是完美预测。
- **完全不相交**（$B$ 和 $A$ 没有任何重叠）：交集 $= 0$ → IoU $= 0$。这是最差预测。
- **部分重合**：IoU 落在 $(0, 1)$ 之间，重合越多越靠近 1。

正因为两端被牢牢钉在 0 和 1，IoU 是个非常好读的分数：目标检测里常用"IoU > 0.5"当作"这个框算检测对了"的阈值；分割里 IoU 越高说明掩码轮廓贴得越准。

## 四、在二值掩码上怎么算：从面积到像素计数

例子里的"区域"其实是一张 $240\times240$ 的二值掩码（0/1 矩阵），此时"面积"就退化成"值为 1 的像素个数"，交并集用逐元素逻辑运算就能算，非常适合在 GPU 上向量化。核心思路：交集 = 两张掩码都为 1 的像素数（逻辑与再求和）；并集 = 至少一张为 1 的像素数（逻辑或再求和）。

```python
# A_pred, A_gt: 形状 (H, W) 的二值张量（0/1）
inter = (A_pred & A_gt).sum().float()   # 交集：两张都为 1 的像素数
union = (A_pred | A_gt).sum().float()   # 并集：至少一张为 1 的像素数
iou   = inter / (union + 1e-6)          # +1e-6 防止两张全 0 时除零
```

这里 `&`（逻辑与）挑出"两张掩码都命中"的像素，`|`（逻辑或）挑出"任意一张命中"的像素，各自 `.sum()` 就是对应的像素计数。分母加一个极小量 `1e-6` 是工程上的防除零保护：当两张掩码恰好都全是 0（图里根本没有前景）时，避免 $0/0$ 报错。

如果预测不是硬邦邦的 0/1，而是网络输出的连续概率或连续深度值，通常先用一个阈值把它二值化（比如"深度 > 某个值"算作接触区域），再套上面的算法——阈值怎么选取决于具体任务对"多深才算接触"的定义。

## 五、IoU 主要用在哪

| 场景 | IoU 衡量的是 | 说明 |
|------|-------------|------|
| 图像分割 | 预测掩码 vs 真值掩码的重叠 | 最经典用途，也叫 Jaccard 指数 |
| 目标检测 | 预测框 vs 真值框的重叠 | 常用 IoU>0.5 判定"检测正确"；也用于 NMS 去重 |
| 触觉/接触感知 | 预测接触区域 vs 真实接触区域 | 判断"压在哪、压出多大一片"预测得准不准 |

需要点明：IoU 是**评估指标**，不是（默认的）训练损失。它对"预测区域整体形状"敏感、但本身对像素级的小抖动不可导、也不直接给梯度方向，所以训练时一般用逐像素损失（如 [逐像素 MSE / 交叉熵](/前置知识/009a_前置知识_编码器解码器架构#五图像到图像任务怎么训练逐像素回归损失)）来优化，而用 IoU 来最终评估"框/掩码贴得好不好"。（存在可导的近似版本 soft-IoU / Lovász 损失可直接当训练目标，但那是进阶话题，不影响把 IoU 当评估指标理解。）

---

## 六、总结

- **IoU = 交集面积 / 并集面积**，范围 $[0,1]$，1 完美、0 完全错开。
- 分母用**并集**是关键：同时惩罚"框太大"和"框太小"，比"重合/真值面积"更公正。
- 不受背景面积影响，因此在"前景只占一小块"的区域问题上，比逐像素准确率靠谱得多。
- 二值掩码上就是"逻辑与求和 / 逻辑或求和"，天然可 GPU 向量化。
- 它是**评估**指标，训练一般仍用逐像素损失。
