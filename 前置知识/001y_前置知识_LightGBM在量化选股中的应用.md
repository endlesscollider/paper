# 前置知识：LightGBM 在量化选股中的应用

> **一句话**：LightGBM 是梯度提升决策树的高效实现，在量化选股中常作为"打不过就别发论文"的 baseline——结构简单、训练快、不需要 GPU、效果经常碾压 Transformer。

## 贯穿全文的例子

> CSI300（沪深 300）成分股，日频交易。
> - 特征集：Qlib Alpha158（158 维价量因子）
> - 标签：次日收益率（5 日收益率也常用）
> - 目标：每天选出排名前 30 只股票买入，持有 1 天后换仓

## 一、为什么树模型在量化选股中如此强

### 1.1 Qlib 基准的关键数据

Microsoft Qlib 在 CSI300 上用 20 个随机种子做了全面对比（Alpha158 因子集）：

| 模型 | 年化超额收益 | IR | 参数量 |
|------|-------------|-----|--------|
| LightGBM | 8.25% | 1.06 | ~5K 棵树 |
| **DoubleEnsemble** | **11.58%** | **1.34** | ~10K 棵树 |
| GRU | 6.44% | 0.87 | ~100K |
| LSTM | 5.68% | 0.74 | ~100K |
| **Transformer** | **2.73%** | **0.36** | ~500K |
| ALSTM | 7.24% | 0.97 | ~150K |

**关键发现**：
1. 普通 Transformer 在量化选股中**表现最差**——这和 NLP/CV 中的经验完全相反
2. 树模型集成（DoubleEnsemble）是最强的
3. 即使是单 LightGBM 也轻松超过 Transformer

### 1.2 树模型为什么在这个场景强

| 特性 | 对量化选股的影响 |
|------|-----------------|
| **自动处理非线性和交互** | 因子之间的非线性关系（如"高波动 + 低换手 = 特殊信号"）自动捕获 |
| **不需要特征标准化** | 决策树按阈值分裂，不关心特征绝对值 |
| **天然处理缺失值** | 股票停牌、新上市等导致的缺失值不需要填充 |
| **不容易过拟合到噪声** | early stopping + 树深限制提供强正则化 |
| **对异常值鲁棒** | 涨停/跌停（±10%/±20%）不会像梯度那样"爆炸" |
| **快速训练** | CSI300 × 3年 ≈ 22万条样本，LightGBM 几十秒跑完 |

**为什么 Transformer 不行？**
1. 量化数据量太小：CSI300 × 3年 ≈ 22万条，Transformer 需要百万级数据
2. 信噪比极低：股票日频收益的噪声远大于信号，Transformer 容易拟合噪声
3. 没有明显的序列结构优势：截面选股的输入是"一天的所有股票"，不需要 attention 来建模长距离依赖

## 二、LightGBM 的核心原理（极简版）

### 2.1 梯度提升的一句话

单棵决策树的拟合能力有限，容易欠拟合；但如果一次性用一棵很深的树硬拟合所有标签，又会把噪声也学进去（1.2 节已经说过量化数据信噪比极低）。梯度提升的思路是：不追求一棵树就学对，而是让很多棵"弱"树接力，每一棵只负责纠正前面所有树加起来还没纠正掉的那部分误差，逐步逼近真实标签。

梯度提升 = **逐棵树纠正前面所有树犯的错误**。

$$
\hat{y}^{(m)} = \hat{y}^{(m-1)} + \eta \cdot h_m(\mathbf{x})
$$

> 第 $m$ 棵树的预测 = 前 $m-1$ 棵树的累计预测 + 学习率 × 第 $m$ 棵树的输出。

**逐项拆解**：
- $\hat{y}^{(m)}$：前 $m$ 棵树的累计预测值
- $\hat{y}^{(m-1)}$：前 $m-1$ 棵树已经给出的预测
- $\eta$：学习率（通常 0.01~0.1），控制每棵新树的贡献大小。越小越稳但需要更多树
- $h_m(\mathbf{x})$：第 $m$ 棵新树，它拟合的目标是**前 $m-1$ 棵树的残差**（即预测错误）

**数值例子**：

假设真实标签 $y = 3.0\%$，学习率 $\eta = 0.1$：

| 轮次 | 累计预测 | 残差 = $y - \hat{y}$ | 新树拟合残差 | 更新 |
|------|----------|---------------------|-------------|------|
| 0 | 0% | 3.0% | 3.0% | $0 + 0.1 \times 3.0 = 0.3\%$ |
| 1 | 0.3% | 2.7% | 2.7% | $0.3 + 0.1 \times 2.7 = 0.57\%$ |
| 2 | 0.57% | 2.43% | 2.43% | $0.57 + 0.1 \times 2.43 = 0.813\%$ |
| ... | ... | ... | ... | ... |
| 100 | ≈2.65% | ≈0.35% | 0.35% | ... |

每轮缩小 10% 的误差。100 棵树后，预测值逼近真实值。

**为什么是这个形式**：用"加法模型 + 学习率"而不是一步到位拟合真实值，是因为一步到位（$\eta=1$，直接用一棵树拟合全部标签）极易过拟合噪声——量化数据信噪比极低，一棵树就把噪声也学进去了。用小学习率（如 0.1）让每棵树只贡献一小步，相当于给优化过程加了强正则化，代价是需要更多棵树（用训练时间换泛化能力），这正是 3.1 节 `learning_rate=0.05` 和 `num_boost_round=1000` 配合 `early_stopping` 的设计意图。

### 2.2 LightGBM 的加速技巧

LightGBM 在标准 GBDT 基础上加了三个加速：

1. **Gradient-based One-Side Sampling (GOSS)**：梯度大的样本（模型预测错得多的）全保留，梯度小的只随机采样一部分。减少计算量但保留重要样本。
2. **Exclusive Feature Bundling (EFB)**：互斥的特征（不会同时非零的）打包成一个特征，减少分裂计算量。
3. **Histogram-based splitting**：把连续特征离散化为 256 个 bin，分裂时只需遍历 256 个阈值而不是 N 个样本值。

这些加速让 LightGBM 比 XGBoost 快 5-10 倍，在量化场景中意味着可以做更频繁的滚动重训。

## 三、量化选股中 LightGBM 的具体配置

### 3.1 Qlib 中的标准配置

以下是 Qlib Alpha158 + LightGBM 的典型配置，这也是大量论文使用的 baseline：

```python
import lightgbm as lgb

params = {
    "objective": "regression",     # 回归任务（预测收益率）
    "metric": "mse",
    "boosting_type": "gbdt",
    "num_leaves": 128,             # 每棵树的最大叶子数
    "learning_rate": 0.05,         # 学习率
    "feature_fraction": 0.8,       # 每棵树随机选 80% 特征
    "bagging_fraction": 0.8,       # 每棵树随机选 80% 样本
    "bagging_freq": 5,             # 每 5 轮做一次 bagging
    "max_depth": 8,                # 最大深度
    "min_child_samples": 50,       # 叶子节点最少样本数（防过拟合）
    "lambda_l1": 0.1,              # L1 正则
    "lambda_l2": 0.1,              # L2 正则
    "verbose": -1,
}

# 训练
train_set = lgb.Dataset(X_train, y_train)
val_set = lgb.Dataset(X_val, y_val)

model = lgb.train(
    params,
    train_set,
    num_boost_round=1000,          # 最多 1000 棵树
    valid_sets=[val_set],
    callbacks=[
        lgb.early_stopping(50),    # 验证集 50 轮不改善就停止
        lgb.log_evaluation(100),
    ],
)
```

**参数解释**：
- `num_leaves=128`：控制树的复杂度。量化场景中 64~256 都常见。太大过拟合，太小欠拟合
- `feature_fraction=0.8`：类似随机森林的特征采样，增加多样性
- `min_child_samples=50`：防止树在极少样本上做出"自信"的分裂——量化中噪声大，这个值不能太小
- `early_stopping(50)`：在验证集上 50 轮（50 棵树）没有改善就停——这是最重要的正则化手段

### 3.2 Alpha158 因子集

Qlib 提供的 Alpha158 是 158 维的价量因子集，涵盖：

| 因子类别 | 数量 | 示例 |
|----------|------|------|
| 收益率 | 20+ | 1/2/3/5/10/20/60 日收益率 |
| 波动率 | 20+ | 5/10/20/60 日收益标准差 |
| 换手率 | 10+ | 原始换手率、相对换手率 |
| 量价关系 | 30+ | 价格与成交量的相关系数 |
| 技术指标 | 40+ | RSI、MACD、布林带相关 |
| 截面排名 | 30+ | 各因子在当天截面中的分位数 |

**为什么要 158 维这么多？** 因为树模型能自动做特征选择——无用特征会被忽略（分裂增益为 0）。所以可以放心地丢进去一大堆因子，让模型自己挑选。

### 3.3 特征工程 Tips

```python
# 量化选股中常见的特征工程
def make_features(df):
    """输入：单只股票的日频 OHLCV 数据"""
    # 收益率类
    for d in [1, 2, 3, 5, 10, 20, 60]:
        df[f'ret_{d}d'] = df['close'].pct_change(d)
    
    # 波动率类
    for d in [5, 10, 20, 60]:
        df[f'vol_{d}d'] = df['ret_1d'].rolling(d).std()
    
    # 换手率类
    df['turnover_5d_avg'] = df['turnover'].rolling(5).mean()
    df['turnover_relative'] = df['turnover'] / df['turnover_5d_avg']
    
    # 量价背离
    df['vol_price_corr_10d'] = (
        df['close'].rolling(10).corr(df['volume'])
    )
    
    # 截面标准化（在 DataLoader 中按日做）
    # 注意：这一步必须在同一天的所有股票上做，不能只看单股票
    return df
```

## 四、DoubleEnsemble：树模型的进阶版

### 4.1 为什么单 LightGBM 不够

单个 LightGBM 的问题：
1. 某些时段表现好、某些时段表现差（不稳定）
2. 对某些因子过度依赖——市场风格切换时该因子失效就崩了

### 4.2 DoubleEnsemble 的核心思想

DoubleEnsemble 做两件事：
1. **样本加权**（类似 AdaBoost）：前一轮预测错的样本，下一轮给更高权重
2. **特征加权**（特有创新）：评估每个特征在不同时段的有效性，动态调整特征权重

结果是：在 Qlib 基准中年化 11.58%，比单 LightGBM 的 8.25% 提升了 3.3 个百分点。

## 五、LightGBM 的局限性

| 局限 | 说明 | 应对方案 |
|------|------|----------|
| **无法建模股票间关系** | 每只股票独立预测，不知道"A 的涨跌会影响 B" | → [StockMixer](/论文综述/082_StockMixer_轻量截面混合选股)、[MASTER](/论文综述/083_MASTER_市场感知截面选股Transformer) |
| **无法在线适配** | 训练完就固定，不能根据最近数据快速调整 | → [DoubleAdapt](/论文综述/084_DoubleAdapt_分布漂移双重适配) |
| **特征工程依赖人工** | 效果取决于因子集质量 | 深度模型可自动提取特征 |
| **无法利用文本/图数据** | 只能用数值特征 | 深度模型可融合新闻/关系图 |

尽管有这些局限，LightGBM 仍然是**任何新方法必须超过的基线**。如果一个新方法连 LightGBM 都打不过，说明它的复杂性没有带来实际价值。
