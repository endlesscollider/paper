# 前置知识：GLU 门控线性单元与 SwiGLU、GeGLU

> **一句话**：门控线性单元（Gated Linear Unit, GLU）把一次线性变换的输出劈成两半——一半原样当"内容"，另一半过一个 Sigmoid 压成 0~1 之间的"开关"，两者逐元素相乘。开关值高的维度内容被放行，开关值低的维度内容被压制。把开关函数从 Sigmoid 换成 SiLU 就是 SwiGLU，换成 GELU 就是 GeGLU——这两个换了门的版本，是现在几乎所有主流大模型（LLaMA、PaLM、Gemma、DeepSeek 等）前馈网络（Feed-Forward Network, FFN——Transformer 里夹在两次 Attention 之间、对每个 token 独立做特征变换的两层全连接结构）里的标准配置。

**前置概念**：基础线性代数（矩阵乘法）、Sigmoid 函数 $\sigma(x)=\frac{1}{1+e^{-x}}$（把任意实数压缩到 $(0,1)$ 之间）、基础深度学习（全连接层、ReLU 激活函数）。不需要任何论文背景。

---

## 贯穿全文的例子

> 假设我们在设计一个 8 维特征向量的处理层——这个 8 维向量可以是一个 token 在 Transformer 某一层的隐藏状态，也可以是任何其他任务里的一个特征向量。我们想让网络自己学会"这 8 个特征里，哪些该被放大、哪些该被压制"，而不是对所有特征一视同仁地套用同一个激活函数。这正是本文要讲的"门控"要解决的问题。文章后面会用这个具体的 8 维向量反复手算三种门控方式（GLU、SwiGLU、GeGLU）的输出，看它们到底算出了什么、又有什么不同。

## 一、为什么需要"门"：从标准 FFN 的局限说起

### 1.1 标准 FFN 长什么样

Transformer 里每个子层交替是 Attention 和 FFN（前馈网络，Feed-Forward Network——对每个 token 独立做非线性加工的两层全连接结构，为什么 Transformer 需要它、它和 Attention 如何分工，见 [FFN 前馈网络前置知识](/前置知识/005m_前置知识_FFN前馈网络与Transformer的两阶段设计)，本文不再重复讲解，直接从它的标准公式开始）。FFN 的标准形式极其简单：两次线性变换，中间夹一个非线性激活函数（原始论文用 ReLU）：

$$
\text{FFN}(x) = \text{ReLU}(xW_1)\,W_2
$$

**这个公式在做什么**：把输入向量 $x$ 先升维（$W_1$ 把 $x$ 映射到一个更宽的中间空间），过一次 ReLU 只保留正值，再用 $W_2$ 降维投影回原始维度。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $x$ | **输入特征** | 比如某个 token 的隐藏状态向量 |
| $xW_1$ | **升维投影** | 把 $x$ 映射到一个维度更高的中间空间（比如从 768 维升到 3072 维），让网络有更大的"工作台面"去组合特征 |
| $\text{ReLU}(\cdot)$ | **统一门槛过滤器** | 把中间空间里所有负值砍成 0，正值原样保留——这是整个中间空间**唯一**的非线性来源 |
| $W_2$ | **降维投影** | 把过滤后的中间表示压缩回原始维度，作为这一层的最终输出 |

**用人话读**："把特征先摊开到一个更宽的空间，把里面的负数全部清零，再压缩回原来的维度。"

**为什么是这个形式**：两次线性变换之间必须有非线性，否则整个 FFN 退化成一次线性变换（两个矩阵相乘还是一个矩阵），丧失表达能力。ReLU 是最简单的非线性选择，完整的设计动机（为什么 Attention 之外还需要这一步非线性）见上面链接的前置知识文章第二节。
:::

### 1.2 标准 FFN 的局限：非线性对所有维度"一刀切"

ReLU 的过滤规则极其死板：**只看这个数值本身的正负，跟其他维度完全没有关系**。中间空间的第 37 个维度要不要被放行，只取决于第 37 个维度自己算出来是正是负——它没有办法"参考"其他维度的信息来决定。

但很多真实的特征组合逻辑,天然是"条件式"的：比如"这个位置是不是边缘"这件事，理想情况下应该同时参考"这个位置的梯度强不强"和"这个区域纹理够不够丰富"两条信息——只有两者都满足才算数,这是一种"与"（AND）式的组合关系。ReLU 每个维度各自为战,没法表达这种"看别的维度的脸色决定自己要不要通过"的逻辑。

**门控（Gating）机制**正是为了解决这个问题：让"要不要放行"这个决策,由输入的另一部分线性变换算出来,而不是由数值本身的正负决定。

## 二、GLU：把线性层的输出劈成两半，一半当开关

### 2.1 核心公式

门控线性单元（Gated Linear Unit, GLU）2016 年由 Dauphin 等人在卷积语言模型里提出,核心公式是：

$$
\text{GLU}(x) = (xW_1) \otimes \sigma(xW_2)
$$

**这个公式在做什么**：把同一个输入 $x$ 喂给两个**不同**的线性层,一路直接当"内容"送出去,另一路过 Sigmoid 压成 0~1 之间的"开关值",两路逐元素相乘——开关开得越大,对应位置的内容被放行得越多；开关接近 0,内容几乎被完全掐断。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $x$ | **原始输入** | 同一份输入,会被送进两个不同的线性层 |
| $xW_1$ | **内容分支** | 一次独立的线性变换,产出"真正想传递的信息"，这一路**没有任何非线性**,是纯线性投影 |
| $xW_2$ | **门控分支（激活前）** | 另一次独立的线性变换（权重和 $W_1$ 完全不同）,产出"用来决定放行程度"的原始信号 |
| $\sigma(xW_2)$ | **开关阀** | 把门控分支的原始信号压缩到 $(0,1)$,每个维度变成一个独立的"这一路要不要走"的比例阀门 |
| $\otimes$ | **逐元素相乘** | 内容分支和开关阀**逐维度**相乘（不是矩阵乘法）,同一位置的内容乘同一位置的开关值 |

**用人话读**："同一个输入算两遍不同的线性变换，一遍当作要传递的内容，另一遍过 Sigmoid 变成 0 到 1 之间的开关比例，两者按位置对应相乘——开关大就多放行内容，开关小就多截断内容。"

**为什么是这个形式**：Sigmoid 把开关值限制在 $(0,1)$ 是关键——这保证了"开关"只能**削弱**内容（乘以一个 $\le 1$ 的数），不会反转内容的符号，行为符合直觉的"阀门"语义。同时开关值由输入的**另一路**线性变换算出，让"是否放行"可以依赖内容分支之外的其他特征组合，这正是 1.2 节要解决的"条件式过滤"问题的直接答案。
:::

### 2.2 为什么门控比堆叠更多线性层更有效

一个自然的问题：直接堆更多层的 $\text{ReLU}(xW_1)$、$\text{ReLU}(xW_1 W_1')$……能不能达到同样的效果？答案是**不能**，原因在于计算方式的本质区别：

- **堆叠更多线性+ReLU 层**：本质上还是每个维度各自决定"通过"还是"清零"，多堆几层只是让这个决策变得更复杂（组合了更多次线性变换），但**决策方式没有变**——始终是某个中间量的正负决定自己的命运，不存在"一路的数值控制另一路的强度"这种交叉调制。
- **GLU 的逐元素相乘**：是一种**双线性（bilinear）交互**——output 关于 $(xW_1, xW_2)$ 这两个变量是乘积关系,而不是加和关系。乘积操作能表达"A 和 B 都强才输出强"这种"与门"式的组合逻辑,而任意深的纯加和+逐点非线性堆叠,在参数量相同的前提下都难以直接表示出这种乘法交互——每多一层堆叠只是让函数变得"更弯"，不会凭空产生"一个分支的输出去缩放另一个分支"这种结构。

回到 1.2 节的边缘检测例子：用 GLU，可以让 $xW_1$ 那一路学会输出"梯度强度"，$xW_2$ 那一路学会输出"纹理丰富度"经过 Sigmoid 后的门控值——相乘后天然实现"只有纹理丰富的位置，梯度信号才被放大输出"这种条件式逻辑。这种"用一部分网络的输出去控制另一部分网络输出的强度"的设计思想，和 [Zero-Init 门控与渐进式模块注入](/前置知识/002n_前置知识_Zero-Init门控与渐进式模块注入) 里"用一个可学习的门控系数控制新模块对主干的影响程度"是同一类思路的不同应用场景。

近期有理论工作（*The Devil is in the Condition Numbers*，2026）从优化的角度补充分析：GLU 结构会改变网络的神经切线核（Neural Tangent Kernel, NTK——一种刻画神经网络训练动态的理论工具）谱分布，让条件数变小、特征值分布更集中，这在实验上表现为**收敛更快**。这是对"GLU 为什么好用"这一经验现象的一种理论解释角度，不是本文的核心内容，感兴趣可以按需查阅，不影响后面内容的理解。

## 三、换一个门：SwiGLU 与 GeGLU

GLU 的门控函数不是只能用 Sigmoid。把 $\sigma(\cdot)$ 换成别的非线性函数，就得到了一族 GLU 变体。其中最重要的两个是 **SwiGLU** 和 **GeGLU**。

### 3.1 SwiGLU：门换成 SiLU

**SiLU（Sigmoid Linear Unit，也叫 Swish）**——它的定义是 $\text{SiLU}(x) = x \cdot \sigma(x)$，也就是输入本身乘上自己的 Sigmoid。和纯 Sigmoid（输出永远在 $(0,1)$ 之间）不同，SiLU 的输出范围是 $(-0.278, +\infty)$——正输入几乎原样通过，负输入被压得很小但不是硬截断到 0，且在负半轴附近会有一小段轻微为负的区域（这个细节在下面的数值例子里会看到实际影响）。

$$
\text{SwiGLU}(x) = (xW_1) \otimes \text{SiLU}(xW_2)
$$

**这个公式在做什么**：和 GLU 完全一样的骨架，只是门控分支换成了 SiLU——门控值不再被硬性限制在 $(0,1)$，而是可以在 0 附近平滑过渡，甚至在输入为负时取一个很小的负值。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $xW_1$ | **内容分支** | 和 GLU 完全一样，独立的线性投影 |
| $\text{SiLU}(xW_2)$ | **平滑开关阀** | 不再是"硬压到 $(0,1)$"的 Sigmoid，而是一个更平滑、允许轻微为负的门控函数——本质上是 $xW_2$ 自己乘上自己的 Sigmoid |
| $\otimes$ | **逐元素相乘** | 和 GLU 一样，逐维度对应相乘 |

**用人话读**："和 GLU 一样劈成内容和开关两路，只是开关函数换成了 SiLU（自己乘自己的 Sigmoid），门控值的变化更平滑，也不再严格限制在 0 到 1 之间。"

**为什么换成 SiLU**：Shazeer 在《GLU Variants Improve Transformer》（2020，本文姊妹篇 [论文精读](/论文综述/107_GLU_Variants_Improve_Transformer门控线性单元变体) 有完整解读）中做的系统性实验里，把 SwiGLU 用在 Transformer 的 FFN 里，在多项下游任务上取得了最好或接近最好的效果。这是一个**经验发现**，论文本身也坦言没有从理论上完整解释为什么这个特定形式效果好。
:::

### 3.2 GeGLU：门换成 GELU

**GELU（Gaussian Error Linear Unit，高斯误差线性单元）**——定义是 $\text{GELU}(x) = x \cdot \Phi(x)$，其中 $\Phi(x)$ 是标准正态分布的累积分布函数（Cumulative Distribution Function, CDF——描述"随机变量小于等于 $x$ 的概率"，是一个从 0 平滑增长到 1 的 S 形曲线）。GELU 的直觉是"用一个概率化的软阈值替代 ReLU 的硬阈值"：输入越大，被完整保留的概率越高；输入越负，被压制的概率越高，但过渡是平滑的而不是 ReLU 那种在 0 处突然折断。

$$
\text{GeGLU}(x) = (xW_1) \otimes \text{GELU}(xW_2)
$$

**这个公式在做什么**：门控函数换成 GELU——用高斯分布的累积概率给每个位置算一个"平滑保留比例"，而不是 Sigmoid 那种独立设计的压缩函数。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $xW_1$ | **内容分支** | 同上，独立线性投影 |
| $\text{GELU}(xW_2) = xW_2 \cdot \Phi(xW_2)$ | **概率化开关阀** | 门控值等于"原始信号本身"乘以"这个信号在标准正态分布下的累积概率"——数值越大，$\Phi$ 越接近 1，几乎全部通过；数值越负，$\Phi$ 越接近 0，几乎全部截断，但中间过渡完全平滑 |
| $\otimes$ | **逐元素相乘** | 和前两者一样 |

**用人话读**："开关值不是简单套 Sigmoid，而是用'这个数值有多大概率应该被认为是正的'这个思路算出来的平滑保留比例，再乘上内容分支。"

**为什么用 GELU 做门**：GeGLU 和 SwiGLU 一样是 Shazeer 论文测试的变体之一，实验中和 SwiGLU 一起被报告为效果最好的两个变体（具体数字见 [论文精读](/论文综述/107_GLU_Variants_Improve_Transformer门控线性单元变体)）。GELU 本身也是 BERT、GPT 等模型标准 FFN（没有门控、单纯替换 ReLU）里常用的激活函数，GeGLU 相当于把"用 GELU 代替 ReLU"和"引入门控结构"两个改进叠加在一起。
:::

### 3.3 三张门控函数曲线放在一起看

在继续讲数值区别之前，先直观看一眼三种门控函数（Sigmoid、GELU、SiLU）的曲线形状对比：

![Sigmoid、GELU、SiLU三种门控函数曲线对比](/glu_gate_functions_comparison.png)

> 图中蓝色和橙色曲线（GELU、SiLU）在负半轴都有一段明显的"下凹"，会取到略小于 0 的值，随后在更负的区域又逐渐回升趋近 0；灰色曲线（Sigmoid）则始终保持在 0 以上，永不为负。这个可见的形状差异，正是下面 3.4 节表格里"是否会翻转内容符号"这一列结论的直接来源。

### 3.4 三者的关键区别：门控值的取值范围

| 门控函数 | 取值范围 | 输入为大负数时 | 输入为大正数时 |
|---------|---------|---------------|---------------|
| Sigmoid（GLU） | $(0, 1)$ | 趋近 $0$（正的，只是很小） | 趋近 $1$ |
| SiLU（SwiGLU） | $\approx(-0.278, +\infty)$ | 趋近 $0$，中间有一小段**负值** | 趋近输入本身（近似线性通过） |
| GELU（GeGLU） | $\approx(-0.17, +\infty)$ | 趋近 $0$，中间也有一小段**负值** | 趋近输入本身 |

这个区别在数值例子里会看到实际影响：**Sigmoid 门控永远是正数，所以内容分支的符号绝不会被翻转；SiLU/GELU 门控在输入为负但接近 0 的区域会取到一个很小的负值，这意味着 SwiGLU/GeGLU 在某些情况下会把内容分支的符号翻转过来**——这是三者行为上一个容易被忽略但很重要的差异。

## 四、用于 FFN 时如何保持参数量：中间维度的经验公式

### 4.1 问题：GLU 变体多了一个矩阵

标准 FFN 只有两个权重矩阵：$W_1$（$d \times d_{ff}$）负责升维，$W_2$（$d_{ff} \times d$）负责降维，其中 $d$ 是模型的隐藏维度，$d_{ff}$ 是 FFN 中间层的宽度。参数量是：

$$
P_{\text{标准}} = 2 \, d \, d_{ff}
$$

**这个公式在做什么**：数一数标准 FFN 一共有多少个可训练参数——两个矩阵各贡献 $d \times d_{ff}$ 个数。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $d$ | **模型隐藏维度** | Transformer 主干的特征维度，比如 768 或 4096 |
| $d_{ff}$ | **FFN 中间层宽度** | 升维后的临时维度，通常是 $d$ 的若干倍（标准 Transformer 取 $4d$） |
| $2\,d\,d_{ff}$ | **总参数量** | $W_1$ 贡献 $d \times d_{ff}$，$W_2$ 贡献 $d_{ff}\times d$，两者相加 |

**用人话读**："标准 FFN 就两个矩阵，各自的参数个数是输入维度乘中间维度，加起来就是总参数量。"

**为什么要先算这个**：GLU 类的 FFN 用了三个矩阵而不是两个，如果不做任何调整，参数量会直接增加 50%——为了公平比较（不能让"效果变好"简单归功于"参数变多"），必须把中间维度调小，让总参数量对齐。
:::

而 GLU 类 FFN（不管是 GLU、SwiGLU 还是 GeGLU）需要**三个**矩阵：$W_1, W_2$（两路线性投影，各 $d \times d_{ff}'$）以及降维矩阵 $W_3$（$d_{ff}' \times d$），这里 $d_{ff}'$ 是调整后的新中间维度：

$$
P_{\text{GLU}} = 3\, d\, d_{ff}'
$$

**这个公式在做什么**：数一数 GLU 类 FFN 有多少个参数——这次是三个矩阵各贡献一份，形式和 4.1 节几乎一样，只是矩阵数从 2 变成 3、中间维度从 $d_{ff}$ 换成了待求的 $d_{ff}'$。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $d$ | **模型隐藏维度** | 和 4.1 节里的 $d$ 是同一个量，输入输出的维度不变 |
| $d_{ff}'$ | **待求的新中间维度** | GLU 版 FFN 用的中间宽度，暂时是未知量，下一步要解出它 |
| $3\,d\,d_{ff}'$ | **GLU 版总参数量** | $W_1, W_2, W_3$ 三个矩阵各贡献 $d\times d_{ff}'$ 个参数，三份相加 |

**用人话读**："GLU 版 FFN 有三个矩阵，每个都是 $d$ 乘 $d_{ff}'$ 大小，参数总量就是三份加起来。"

**为什么要单独列这个公式**：4.1 节的 $2d\,d_{ff}$ 是"标准版基准"，这里的 $3d\,d_{ff}'$ 是"GLU 版实际开销"——把两者列在一起才能在下一步解出让两者相等的 $d_{ff}'$。
:::

要让参数量对齐（$P_{\text{GLU}} = P_{\text{标准}}$），代入求解：

$$
d_{ff}' = \frac{2}{3}\, d_{ff}
$$

**这个公式在做什么**：解一个简单的方程——已知标准 FFN 用两个矩阵撐出 $2d\,d_{ff}$ 个参数，GLU 版本用三个矩阵，要撑出一样多的参数，中间维度必须缩小到原来的 $2/3$。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $3\,d\,d_{ff}'$ | **GLU 版参数量** | 三个矩阵（$W_1, W_2, W_3$）各贡献 $d\times d_{ff}'$，一共三份 |
| $2\,d\,d_{ff}$ | **标准版参数量（目标值）** | 4.1 节算出来的基准 |
| $d_{ff}' = \frac{2}{3}d_{ff}$ | **调整后的中间维度** | 令两个参数量相等，直接解出 $d_{ff}'$ 是原始 $d_{ff}$ 的 $2/3$ |

**用人话读**："GLU 多了一个矩阵，为了参数总量不变，中间维度就要缩小到原来的三分之二。"

**为什么是精确的 $2/3$ 而不是别的比例**：这不是一个经验拍脑袋的数字，而是纯粹的代数解——三个等宽矩阵要撑出和两个等宽矩阵一样多的参数，唯一解就是把宽度乘 $2/3$。这个结论在 Noam Shazeer 2020 年的论文《GLU Variants Improve Transformer》中被明确使用："我们将隐藏单元数 $d_{ff}$ 缩小 $2/3$，以保持参数量和计算量与两矩阵版本一致"。
:::

### 4.2 具体应用：LLaMA 里的 $8d/3$

标准 Transformer 的 FFN 中间维度惯例取 $d_{ff} = 4d$（把维度先放大 4 倍再缩回来）。如果一个模型沿用这个惯例、同时又想用 SwiGLU，代入 4.1 节的结论：

$$
d_{ff}' = \frac{2}{3} \times 4d = \frac{8}{3}d
$$

**这个公式在做什么**：把 4.1 节推出的通用缩放规则（新维度 = 原维度 $\times \frac{2}{3}$）代入"标准惯例 $d_{ff}=4d$"这个具体数值，算出 LLaMA 实际使用的中间维度。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $4d$ | **代入的具体起点** | 标准 Transformer FFN 惯用的中间维度（$d_{ff}=4d$），这里把它当作 4.1 节公式里的 $d_{ff}$ |
| $\frac{2}{3}\times 4d$ | **套用 4.1 节的缩放规则** | 直接把 4.1 节推出的 $d_{ff}'=\frac{2}{3}d_{ff}$ 代入 $d_{ff}=4d$，纯粹是数值代入，没有新的推导 |
| $\frac{8}{3}d$ | **化简后的最终结果** | $\frac{2}{3}\times 4=\frac{8}{3}$，也就是新的中间维度是模型隐藏维度的 $8/3$ 倍 |

**用人话读**："把'中间维度缩小到 2/3'这条规则套在'标准取 4 倍'这个具体做法上，算出来就是 8/3 倍。"

**为什么单独列出来**：$8d/3$ 是 LLaMA 等主流模型代码里直接写死的数字，把代入过程摆出来能让读者看清这个数字不是凭空来的，而是两条简单规则相乘的结果。
:::

这正是 LLaMA 论文里实际采用的公式。经过与 Meta 官方开源代码（`llama/model.py`）核对，具体计算顺序是：

1. 起始值 `hidden_dim = 4 * dim`（即 $4d$，标准惯例的起点）
2. 乘上 $2/3$：`hidden_dim = int(2 * hidden_dim / 3)`，得到 $8d/3$
3. 如果配置了自定义倍率 `ffn_dim_multiplier`，再乘一次这个倍率（部分规模的 LLaMA/LLaMA 2 模型用这一项做微调）
4. 最后向上取整到 `multiple_of`（默认 256）的整数倍：`hidden_dim = 256 * ceil(hidden_dim / 256)`——这一步是纯粹的工程考量，让中间维度是一个"规整"的数字，方便底层矩阵乘法在 GPU 上做分块并行，跟前面的数学推导无关。

也就是说，"$8d/3$" 本身不是一个独立发明的魔法数字，而是"标准 4 倍扩张惯例" + "4.1 节参数量对齐的 $2/3$ 因子"两条规则直接相乘的结果，最后再套一层面向硬件效率的取整规则。

```mermaid
flowchart LR
    A["起点: d_ff = 4d<br/>(标准FFN扩张惯例)"] --> B["乘 2/3<br/>(参数量对齐,来自4.1节推导)"]
    B --> C["d_ff' = 8d/3"]
    C --> D["向上取整到 multiple_of<br/>(工程考量,与数学推导无关)"]
    D --> E["最终 SwiGLU FFN 中间维度"]
```

> 这张图串起了 $8d/3$ 这个数字的完整来源：它不是凭空定的经验值，而是"标准 4 倍扩张"叠加"三矩阵参数对齐的 $2/3$ 缩放"两条规则的直接乘积，最后再经过一次面向硬件效率的取整。

需要强调的是：$2/3$ 这个缩放因子对**任何**起始 $d_{ff}$ 都适用（只要目标是"参数量对齐两矩阵版本"），$8d/3$ 只是"起始值恰好取 $4d$"这个特例下的结果——如果一个模型选择别的扩张倍率（比如 $d_{ff}=8d$），对齐后的 GLU 版本就应该是 $\frac{2}{3}\times 8d = \frac{16}{3}d$，道理完全一样。

## 五、具体数值例子：$d=8$，手算三种门控的输出

用一个 8 维输入向量，手算 GLU、SwiGLU、GeGLU 三种门控方式的完整计算过程,直观感受 3.4 节提到的"符号翻转"现象。

为了避免把两个 $8\times d_{ff}$ 的权重矩阵完整摊开做矩阵乘法（这只是纯粹的矩阵乘法运算，不影响理解门控机制本身），我们直接给出输入经过两个线性层之后的结果——这一步等价于已经算好了 $xW_1$ 和 $xW_2$：

$$
xW_1 = [\,2,\ -1,\ 3,\ 0,\ 1,\ -2,\ 4,\ 0\,], \qquad xW_2 = [\,1,\ 2,\ -1,\ 0,\ 3,\ -2,\ 0,\ 1\,]
$$

**这个公式在做什么**：给出两条分支的具体数值——$xW_1$ 是内容分支的输出，$xW_2$ 是门控分支在激活函数之前的原始信号，后面所有计算都基于这两组数字展开。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $xW_1$ | **内容分支的 8 个输出值** | 每个位置代表"这个特征原本想传递多少信息" |
| $xW_2$ | **门控分支的 8 个原始信号** | 每个位置将被送进 Sigmoid/SiLU/GELU，算出对应位置的"放行比例" |

**用人话读**："这是两条独立的线性变换算完之后的结果，分别代表内容和门控的原始信号，后面我们直接在这两组数字上验证三种门控函数的区别。"

**为什么跳过矩阵乘法本身**：矩阵乘法只是标准的线性代数运算，跳过它不影响理解门控机制的核心——重点是"两条分支算出来之后如何结合"，而不是"分支本身怎么算出来的"。
:::

**第一步：算门控分支的三种激活值**（对 $xW_2$ 逐元素应用 Sigmoid、SiLU、GELU）：

| $xW_2$ 的值 | $1$ | $2$ | $-1$ | $0$ | $3$ | $-2$ | $0$ | $1$ |
|---|---|---|---|---|---|---|---|---|
| $\sigma(xW_2)$（GLU 门） | $0.731$ | $0.881$ | $0.269$ | $0.500$ | $0.953$ | $0.119$ | $0.500$ | $0.731$ |
| $\text{SiLU}(xW_2)$（SwiGLU 门） | $0.731$ | $1.762$ | $-0.269$ | $0$ | $2.859$ | $-0.238$ | $0$ | $0.731$ |
| $\text{GELU}(xW_2)$（GeGLU 门） | $0.841$ | $1.954$ | $-0.159$ | $0$ | $2.996$ | $-0.046$ | $0$ | $0.841$ |

注意第 3 列（$xW_2=-1$）：Sigmoid 算出 $0.269$（正数），但 SiLU 算出 $-0.269$、GELU 算出 $-0.159$——**都是负数**。这正是 3.4 节提到的关键差异：输入为负但幅度不大时，SiLU 和 GELU 会给出一个小的负门控值，而 Sigmoid 永远只给正数。

**第二步：门控值乘上内容分支**，得到三种方法各自的最终输出：

| 位置 | $xW_1$ | GLU 输出 | SwiGLU 输出 | GeGLU 输出 |
|------|--------|---------|-------------|-----------|
| 1 | $2$ | $2\times0.731=1.462$ | $2\times0.731=1.462$ | $2\times0.841=1.683$ |
| 2 | $-1$ | $-1\times0.881=-0.881$ | $-1\times1.762=-1.762$ | $-1\times1.954=-1.954$ |
| 3 | $3$ | $3\times0.269=0.807$ | $3\times(-0.269)=\mathbf{-0.807}$ | $3\times(-0.159)=\mathbf{-0.476}$ |
| 4 | $0$ | $0$ | $0$ | $0$ |
| 5 | $1$ | $1\times0.953=0.953$ | $1\times2.859=2.859$ | $1\times2.996=2.996$ |
| 6 | $-2$ | $-2\times0.119=-0.238$ | $-2\times(-0.238)=\mathbf{0.476}$ | $-2\times(-0.046)=\mathbf{0.091}$ |
| 7 | $4$ | $4\times0.500=2.0$ | $4\times0=0$ | $4\times0=0$ |
| 8 | $0$ | $0$ | $0$ | $0$ |

**关键观察**（加粗的行）：

- **位置 3**：内容分支 $xW_1=3$ 是正数，GLU 的输出保持正号（$0.807$），但 SwiGLU 和 GeGLU 的输出**变成了负数**（$-0.807$、$-0.476）。原因是这个位置的门控原始信号 $xW_2=-1$ 落在 SiLU/GELU 的"轻微为负"区间——Sigmoid 门永远不会做这种符号翻转，但 SiLU/GELU 门会。
- **位置 6**：反过来，内容分支 $xW_1=-2$ 是负数，GLU 保持负号（$-0.238$），但 SwiGLU 和 GeGLU 把它翻成了正数（$0.476$、$0.091$）——同样是因为门控原始信号在"轻微为负"区间导致的符号翻转。
- **位置 7**：门控原始信号 $xW_2=0$，Sigmoid 在 0 处取值 $0.5$（保留一半），但 SiLU 和 GELU 在 0 处的值都恰好是 $0$——这一位置的信息被 SwiGLU/GeGLU **完全阻断**，GLU 却只是打了个五折。

这组手算清楚地展示了：**换一个门控函数不是简单的"数值大小微调"，而是会在某些区域实质性地改变输出的符号和大小关系**。这也是为什么 SwiGLU、GeGLU 不能简单看作 GLU 的"平滑版替代"，它们在特定输入区间的行为逻辑是真正不同的。

## 六、工程实操：PyTorch 里怎么写

前面的公式和数值例子讲清楚了"门控在算什么"，接下来看真实代码怎么实现——核心思路是：**用一个宽度为 $2 d_{ff}'$ 的线性层一次性算出两条分支，再切成两半分别处理**，这样比分别声明两个独立线性层更省一次矩阵乘法的调度开销。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class SwiGLUFeedForward(nn.Module):
    """
    标准 SwiGLU FFN 实现，对应本文 4.2 节的 d_ff' = 8d/3 缩放规则。
    """
    def __init__(self, dim: int, multiple_of: int = 256):
        super().__init__()
        # 按 4.1/4.2 节推导：从 4d 起步，乘 2/3，再向上取整到 multiple_of 的倍数
        hidden_dim = int(2 * (4 * dim) / 3)
        hidden_dim = multiple_of * ((hidden_dim + multiple_of - 1) // multiple_of)

        self.w_gate = nn.Linear(dim, hidden_dim, bias=False)   # 对应 xW2，门控分支
        self.w_content = nn.Linear(dim, hidden_dim, bias=False)  # 对应 xW1，内容分支
        self.w_out = nn.Linear(hidden_dim, dim, bias=False)      # 降维投影回 dim

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # F.silu 就是本文 3.1 节的 SiLU(x) = x * sigmoid(x)
        gate = F.silu(self.w_gate(x))      # 门控分支，过 SiLU
        content = self.w_content(x)         # 内容分支，纯线性，不过任何激活
        return self.w_out(gate * content)   # 逐元素相乘后再投影回原维度
```

代码里有两个细节值得留意：第一，`w_gate` 和 `w_content` 是**两个完全独立**的线性层，参数互不共享——这对应公式里 $W_1, W_2$ 必须是两个不同的矩阵，不能用同一个矩阵算两次；第二，`gate * content` 是 PyTorch 张量的逐元素乘法（`*` 运算符默认行为），不是矩阵乘法，这正是公式里 $\otimes$ 符号的具体实现。

如果要实现 GeGLU，唯一需要改的是激活函数,把 `F.silu` 换成 `F.gelu`；如果要实现最原始的 GLU，换成 `torch.sigmoid` 即可——三种变体的代码骨架完全一致,只有一行调用的函数不同,这也印证了 3.1~3.2 节反复强调的"公式骨架相同,只是换了门控函数"这个核心结论。

## 七、总结对比表

| 变体 | 门控函数 | 门控值范围 | 是否会翻转内容符号 | 典型使用场景 |
|------|---------|-----------|-------------------|------------|
| **GLU** | $\sigma(x)$（Sigmoid） | $(0,1)$ | 否，永远保号 | 2016 年卷积语言模型（Dauphin et al.） |
| **SwiGLU** | $\text{SiLU}(x)=x\sigma(x)$ | $\approx(-0.278,+\infty)$ | 会，在负值小幅区间翻转 | LLaMA、PaLM、Mistral、DeepSeek 等主流 LLM 的 FFN |
| **GeGLU** | $\text{GELU}(x)=x\Phi(x)$ | $\approx(-0.17,+\infty)$ | 会，在负值小幅区间翻转 | Gemma、T5 v1.1 等模型的 FFN |

三者共享同一个骨架 $(xW_1)\otimes g(xW_2)$，唯一的自由变量是门控函数 $g$。用于 FFN 时都要遵循 4.1 节推导的 $d_{ff}' = \frac{2}{3}d_{ff}$ 缩放规则来对齐参数量。
