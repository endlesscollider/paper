# 数值精度：FP32、FP16、BF16、TF32

> 训练一个 VLA 或世界模型，动辄数十亿参数。如果每个参数都用 32 位浮点数存储和计算，显存和算力根本不够用。解决方案是"降精度"：用更少的 bit 表示每个数字。但降精度不是免费的——精度低了，数值容易溢出或舍入为零。本文讲清楚 FP32、FP16、BF16、TF32 这四种格式的区别，以及为什么现代大模型训练几乎都选 BF16。

## 贯穿全文的例子

> 一个 Transformer 层在做一次矩阵乘法 $Y = XW$，其中 $X$ 的形状是 $(B, L, D) = (8, 256, 4096)$，$W$ 的形状是 $(4096, 4096)$。这一次 matmul 涉及约 $8 \times 256 \times 4096 \times 4096 \approx 34.4 \times 10^9$ 次浮点乘加运算。我们会用这个例子来说明不同精度格式对显存占用和计算吞吐量的影响。

---

## 一、浮点数的三段式结构

一个浮点数由三部分组成：

$$
(-1)^{\text{sign}} \times 2^{\text{exponent} - \text{bias}} \times (1 + \text{mantissa})
$$

**这个公式在做什么**：把一个浮点数拆成"符号（正负）×尺度（大小量级）×精确值（具体数字）"三个独立部分。

::: details 📐 逐符号拆解 + 数值代入（点击展开）
**逐符号拆解**：

| 符号 | 含义 | 具体是什么 |
|------|------|-----------|
| sign | 符号位 | 1 bit，0 表示正数，1 表示负数 |
| exponent | 指数位 | 决定数字的"量级"，相当于科学计数法的 $10^n$ 部分 |
| bias | 指数偏移 | 让 exponent 能表示负数，bias = $2^{E-1} - 1$（E 是 exponent 的 bit 数） |
| mantissa | 尾数位（小数部分） | 决定数字的"精确程度"，bit 数越多，能表示的有效数字越多 |

**数值代入**：以 FP32 为例，表示数字 $0.15625$：
- sign = 0（正数）
- 实际值 = $0.15625 = 1.25 \times 2^{-3}$
- mantissa = $0.25$（二进制 `01000...`，即 $1/4$）
- exponent = $-3 + 127 = 124$（bias = 127）
- 验证：$(-1)^0 \times 2^{124-127} \times (1 + 0.25) = 1 \times 2^{-3} \times 1.25 = 0.15625$ ✓

**为什么是这个形式**：这种"浮动小数点"的表示方法可以用有限的 bit 同时覆盖极大的数（如 $10^{38}$）和极小的数（如 $10^{-38}$），比定点数灵活得多。
:::

关键直觉：**指数位决定"能表示多大/多小的数"（动态范围），尾数位决定"相邻两个可表示数之间的间距"（精度）**。

---

## 二、四种格式的具体布局

| 格式 | 总 bit 数 | 指数位 | 尾数位 | 动态范围 | 精度（有效十进制位） |
|------|-----------|--------|--------|----------|---------------------|
| FP32 | 32 | 8 | 23 | $\sim 10^{\pm38}$ | ~7.2 位 |
| FP16 | 16 | 5 | 10 | $\sim 10^{\pm5}$ | ~3.3 位 |
| BF16 | 16 | 8 | 7 | $\sim 10^{\pm38}$ | ~2.4 位 |
| TF32 | 19 | 8 | 10 | $\sim 10^{\pm38}$ | ~3.3 位 |

画成 bit 布局图：

```
FP32: [1 sign][8 exponent][23 mantissa]  = 32 bits
FP16: [1 sign][5 exponent][10 mantissa]  = 16 bits
BF16: [1 sign][8 exponent][ 7 mantissa]  = 16 bits
TF32: [1 sign][8 exponent][10 mantissa]  = 19 bits（仅用于计算，不用于存储）
```

## 三、FP16 的致命弱点：动态范围太小

FP16 只有 5 位指数，这意味着它能表示的最大值约为 $65504$，最小正规数约为 $6.1 \times 10^{-5}$。

**为什么这在训练中是致命的**：

1. **梯度下溢（underflow）**：深度网络训练中，很多梯度值在 $10^{-5}$ 到 $10^{-8}$ 量级。FP16 的最小正规数是 $6.1 \times 10^{-5}$，比这小的数直接变成 0。梯度变 0 意味着参数不更新——训练就卡住了。

2. **Loss 溢出（overflow）**：如果 loss 值或中间激活值超过 65504，FP16 直接变成 `inf`（无穷大），一旦出现 `inf`，后续所有计算都会被污染。

**具体例子**：假设某一层的梯度值是 $3.2 \times 10^{-6}$：
- FP32 下：正常存储，参与 Adam 更新
- FP16 下：$3.2 \times 10^{-6} < 6.1 \times 10^{-5}$，被舍入为 0 → 这一层不更新

这就是为什么**纯 FP16 训练几乎一定会炸**——要么梯度消失，要么 loss 爆炸。

---

## 四、BF16：保住动态范围，牺牲精度

BF16（Brain Floating Point 16）是 Google Brain 在 2018 年提出的格式。核心设计思路：

> 对训练来说，"能表示多大多小的数"比"数字精确到第几位"更重要。

BF16 把 FP32 的 8 位指数原封不动保留下来，砍掉的是尾数位（从 23 位砍到 7 位）。这意味着：

- **动态范围和 FP32 完全相同**：$\sim 10^{\pm38}$，不存在梯度下溢的问题
- **精度降低**：只有约 2.4 位有效十进制数字（FP32 是 7.2 位）

**精度降低的实际影响**：

$$
\text{相对舍入误差}_{\text{BF16}} \approx 2^{-8} \approx 0.4\%
$$

**这个公式在做什么**：计算 BF16 格式下，任何一个数字因为尾数位不够而产生的最大相对误差。

::: details 📐 逐符号拆解 + 数值代入（点击展开）
**逐符号拆解**：

| 符号 | 含义 | 具体是什么 |
|------|------|-----------|
| $2^{-8}$ | 尾数位的最后一位权重 | BF16 有 7 位尾数，最末一位代表 $2^{-7}$，舍入误差最大为其一半 $= 2^{-8}$ |

**数值代入**：存储数字 $1.0078125$（= $1 + 2^{-7}$）：
- FP32 下：精确表示，无误差
- BF16 下：7 位尾数能表示的最小间距是 $2^{-7} = 0.0078125$，所以 1.0 和 1.0078125 是 BF16 能区分的相邻两个数
- 如果真实值是 $1.003$，BF16 会舍入到 $1.0$，误差 = $0.003/1.003 \approx 0.3\%$

**为什么这个形式可以接受**：
- 梯度下降本身就是一个"大方向对了就行"的过程——每步更新不需要精确到第 7 位有效数字
- SGD 本身有梯度噪声（来自 mini-batch 采样），噪声的量级远大于 0.4% 的舍入误差
- 但如果数字溢出变成 `inf`，那就不是"精度不够"而是"整个计算崩了"，这才是致命的
:::

**和 FP32 的转换极其简单**：BF16 就是 FP32 的前 16 位（砍掉后 16 位尾数）。从 FP32 转 BF16 只需截断，从 BF16 转 FP32 只需在后面补 16 个 0。这让 BF16 的硬件实现非常轻量。

## 五、TF32：NVIDIA 的折中方案

TF32（TensorFloat-32）是 NVIDIA 在 Ampere 架构（A100）中引入的格式。它不是一种"存储格式"，而是一种**计算格式**：

- **存储仍然用 FP32**（32 bit 存储，不省显存）
- **matmul 运算时，硬件内部把 FP32 截断为 19 bit**（8 位指数 + 10 位尾数）来做乘加
- **运算结果仍然以 FP32 存回去**

**TF32 的定位**：在不改代码的情况下，让 FP32 程序"免费"获得接近 BF16 的计算速度。

| 对比维度 | FP32 | TF32 | BF16 |
|----------|------|------|------|
| 存储 | 32 bit | 32 bit | 16 bit |
| 计算精度 | 23 位尾数 | 10 位尾数 | 7 位尾数 |
| 动态范围 | $10^{\pm38}$ | $10^{\pm38}$ | $10^{\pm38}$ |
| A100 Tensor Core 吞吐 | 19.5 TFLOPS | 156 TFLOPS | 312 TFLOPS |
| 省显存？ | ❌ | ❌ | ✅（减半） |

**为什么要了解 TF32**：在 PyTorch 中，当你设置 `torch.backends.cuda.matmul.allow_tf32 = True`（Ampere+ 默认启用），所有 `torch.matmul`/`F.linear` 会自动使用 TF32 加速。你的代码依然写 FP32，但实际计算已经是 TF32 精度了——速度提升 8 倍，精度损失对训练几乎无感。

---

## 六、实际训练中怎么选：BF16 + TF32 组合

现代 VLA / 世界模型训练的标准配置：

```python
import torch

# 启用 TF32（Ampere+ GPU 上默认为 True）
torch.backends.cuda.matmul.allow_tf32 = True      # matmul 用 TF32
torch.backends.cudnn.allow_tf32 = True             # cuDNN（卷积）用 TF32

# 模型参数和前向/反向传播用 BF16
model = model.to(dtype=torch.bfloat16)
```

这段代码做了什么：
1. **模型权重以 BF16 存储**：每个参数只占 2 字节（vs FP32 的 4 字节），显存直接减半
2. **矩阵乘法用 TF32 精度**：即使输入是 BF16，NVIDIA Tensor Core 会在内部把 BF16 数字用 TF32 精度来做乘加（更精确的累加），结果再截断回 BF16
3. **卷积用 TF32 精度**：cuDNN 的卷积内核同理

**为什么不直接全用 FP16？** 因为 FP16 动态范围太小，必须配合 loss scaling 才能正常训练（参见 [混合精度训练](/前置知识/003e_前置知识_混合精度训练AMP与Loss_Scaling)）。BF16 动态范围和 FP32 相同，**不需要 loss scaling**，训练代码更简单、更稳定。

**为什么不全用 FP32？** 因为：
- 显存翻倍 → 能训练的模型尺寸减半
- 计算吞吐低 8~16 倍 → 训练时间翻好几倍
- 对最终模型质量几乎无影响（精度损失在梯度噪声之下）

## 七、显存影响的具体计算

回到我们的贯穿例子。一个 7B 参数的 VLA 模型：

| 存储项 | FP32（每参数） | BF16（每参数） | 7B 模型 FP32 | 7B 模型 BF16 |
|--------|---------------|---------------|-------------|-------------|
| 模型参数 | 4 bytes | 2 bytes | 28 GB | 14 GB |
| 梯度 | 4 bytes | 2 bytes | 28 GB | 14 GB |
| Adam 状态（m + v） | 8 bytes | 8 bytes* | 56 GB | 56 GB* |
| **总计** | **16 bytes** | **12 bytes** | **112 GB** | **84 GB** |

> *注意：Adam 的 m（一阶矩）和 v（二阶矩）通常仍以 FP32 存储，因为它们是移动平均，需要足够的精度来跟踪小的梯度变化。这就是"混合精度"中"混合"的含义——不是所有东西都降精度。

---

## 八、精度对训练稳定性的影响

不同精度下训练可能遇到的问题：

| 问题 | FP16 | BF16 | 解决方案 |
|------|------|------|---------|
| 梯度下溢（小梯度变 0） | 高风险 | 几乎不存在 | BF16 或 loss scaling |
| Loss 溢出（值太大变 inf） | 高风险 | 几乎不存在 | BF16 或 loss scaling |
| 权重更新消失（lr × grad 太小被舍入） | 中等风险 | 低风险 | master weights 用 FP32 |
| 累加误差（长序列 softmax 累加） | 中等风险 | 中等风险 | 局部用 FP32 累加 |

**"master weights"策略**：即使前向/反向用 BF16，优化器更新时保存一份 FP32 的"主权重"。更新流程：

```
FP32 master weights → 截断为 BF16 → 前向/反向 → BF16 梯度
                ↑                                      ↓
                └── FP32 master weights += lr × grad ──┘
```

这样做的原因：如果学习率是 $10^{-4}$，梯度是 $10^{-3}$，更新量 = $10^{-7}$。BF16 的精度是 $2^{-8} \approx 0.004$，对于权重值 = 1.0 的参数，$10^{-7}$ 的更新会被直接舍入为 0。用 FP32 主权重就没这个问题。

## 九、PyTorch 中的精度控制 API

```python
# 方法 1：模型整体转 BF16
model = MyVLAModel().to(dtype=torch.bfloat16)

# 方法 2：用 autocast 做自动混合精度（推荐）
from torch.cuda.amp import autocast

with autocast(dtype=torch.bfloat16):
    output = model(input)
    loss = criterion(output, target)

# autocast 会自动决定：
# - matmul、conv → BF16（快）
# - softmax、layernorm、loss → FP32（稳）

# 方法 3：DeepSpeed / FSDP 中指定混合精度
# DeepSpeed config
{
    "bf16": {
        "enabled": true
    }
}

# FSDP
from torch.distributed.fsdp import MixedPrecision
mp_policy = MixedPrecision(
    param_dtype=torch.bfloat16,    # 前向/反向的参数精度
    reduce_dtype=torch.bfloat16,   # AllReduce 通信精度
    buffer_dtype=torch.bfloat16,   # buffer（如 BN running mean）精度
)
```

## 十、总结与选型建议

| 你的场景 | 推荐精度 | 原因 |
|----------|---------|------|
| A100/H100/H800 训练 VLA/世界模型 | **BF16 + TF32** | 最佳性价比，无需 loss scaling |
| V100（不支持 BF16） | FP16 + loss scaling | V100 只支持 FP16 Tensor Core |
| 推理部署 | FP16 或 INT8/INT4 | 推理不需要梯度，动态范围不是问题 |
| 科学计算/需要高精度累加 | FP32 或 FP64 | 数值精度 > 速度 |
| 只想代码不改就快一点 | 开启 TF32 | `allow_tf32 = True`，0 代码改动 |

**一句话总结**：BF16 是现代大模型训练的默认选择——它用"精度不太重要"换"动态范围不能丢"的设计哲学，完美匹配了深度学习"大方向对就行、别溢出别下溢"的训练特性。
