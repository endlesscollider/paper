# 前置知识：长度外推——位置编码的分布外泛化问题

> **一句话**：长度外推（Length Extrapolation）问的是同一个问题——"一个 Transformer 语言模型在训练时只见过长度不超过 $L_{train}$ 的输入，部署后遇到长度 $L_{test} > L_{train}$ 的输入，还能不能正常工作？"这本质上是一个分布外（out-of-distribution，输入落在训练时从未覆盖的取值范围）泛化问题，而位置编码方案的选择，直接决定了模型面对这种分布外输入时是彻底崩溃、缓慢退化，还是完全无感。

## 贯穿全文的例子

> **场景**：一家公司训练了一个通用文档处理模型，出于显存和训练成本的限制，训练时把所有文档切成不超过 2048 个 token 的片段。上线后，客户上传的合同、技术手册、会议记录经常长达 8000 个 token 甚至更长。模型必须在没有针对这种长度重新训练的情况下，稳定处理这些"从没见过这么长"的输入。本文用"训练 2048、部署 8192"这组具体数字贯穿全文，比较不同位置编码方案在这个场景下的表现。

## 一、长度外推问题的数学本质

### 1.1 先精确定义"外推"在说什么

给定一个用长度为 $L_{train}$ 的序列训练出来的语言模型，长度外推问的是：如果推理时输入长度 $L_{test} > L_{train}$，模型的表现（通常用困惑度 perplexity 衡量，即模型预测下一个词的"意外程度"，数值越低表示预测越准）会怎样变化？

一个具备"良好外推能力"的模型，理想情况下应该满足：$L_{test}$ 增大时，困惑度不明显恶化，甚至因为能利用更长的上下文而进一步降低。一个"不具备外推能力"的模型，困惑度会随着 $L_{test}$ 超过 $L_{train}$ 而急剧上升，模型实质上"失效"了。

### 1.2 为什么这本质上是一个分布外泛化问题

神经网络的训练遵循一个基本假设：训练数据和测试数据来自同一个分布，网络在训练时见过的输入模式，才能保证测试时表现符合预期。这个假设对"内容"（词义、句法）通常没什么问题——训练语料已经覆盖了足够丰富的词汇和句式。但对"位置"这个维度，情况完全不同：

- 训练时，模型的每一次前向传播，输入序列长度都被截断在 $[0, L_{train})$ 这个范围内。也就是说，**位置编码这个输入通道，在训练阶段只被灌注过 $[0, L_{train})$ 范围内的取值**。
- 测试时如果 $L_{test} > L_{train}$，位置编码（或者依赖位置编码的 Attention 计算）必然要处理 $[L_{train}, L_{test})$ 这个从未在训练中出现过的取值区间。

这正是分布外泛化问题的标准形式：**训练分布是 $[0, L_{train})$，测试遇到的却是训练分布之外的 $[0, L_{test})$（$L_{test}>L_{train}$）**。网络对训练分布内的输入有很强的泛化能力（因为见过足够多类似样本），但对训练分布之外的输入，表现完全取决于这个具体计算环节的数学结构——**有没有可训练的参数在处理这部分输入，是解决这个问题的关键分水岭**。

### 1.3 一个关键的区分标准：谁在"处理"分布外的位置信息

不同位置编码方案面对 $L_{test}>L_{train}$ 时表现天差地别，根本原因可以归结为一个问题：**处理"位置"这个信息的环节，是否包含只在 $[0,L_{train})$ 范围内被训练过的可学习参数？**

| 环节是否可训练 | 具体例子 | 面对分布外位置时的表现 |
|---|---|---|
| 是（查表式，直接为每个位置训练一个向量） | 可学习位置嵌入（Learned Absolute PE） | 位置 $\ge L_{train}$ 根本没有对应的训练好的向量，直接失效或报错 |
| 是（间接，位置向量参与后续被训练过的网络层） | 正弦位置编码叠加到 embedding 后，经过若干训练过的 Transformer 层 | 公式本身对任意位置有定义，但处理这个信号的网络层只在训练范围内被调教过，超出范围后行为不可预测 |
| 部分是（相对距离参与训练过的旋转/频率结构，但旋转本身不含可训练参数） | RoPE | 旋转操作本身对任意距离有定义，但网络的其余部分是围绕训练时见过的相对距离分布调教出来的，超出较多后仍会退化，只是比前两种慢 |
| 否（惩罚函数是纯数学公式，不经过任何可训练权重） | [ALiBi](/前置知识/005c_前置知识_ALiBi线性偏置位置编码) | 惩罚直接加在最终 Attention 分数上，不经过任何训练过的参数处理，公式在任意距离下都表现一致 |
| 不适用（完全不显式引入位置信息） | NoPE（No Positional Encoding） | 模型完全依靠因果掩码本身隐含的顺序信息和数据里的统计规律，见第四节详细讨论 |

这张表就是本文接下来所有对比的核心逻辑骨架——下面逐个方案展开。

## 二、四类主流方案的外推能力对比

### 2.1 可学习绝对位置编码：几乎不能外推

可学习位置嵌入（Learned Absolute Positional Embedding，直接给每个整数位置训练一个专属向量，本质是一个查表操作）是最直观的方案，[标量条件编码前置知识第五节](/前置知识/001s_前置知识_标量条件编码_位置编码与时间步嵌入#五另外两条不同的路可学习位置嵌入与rope简要对比)已经指出它的核心缺陷：**这张表只在训练时覆盖到的位置范围内被训练过**。如果训练长度是 2048，这张表就只有 2048 行，遇到第 2049 个位置，模型压根没有对应的向量可用——常见的处理方式是直接报错、截断输入，或者用一个从未训练过的随机/零向量顶替，这几种处理方式无一例外都会让模型在这个位置的表现严重失真。GPT-2、BERT 等早期模型用的都是这类编码，这也是它们几乎不具备任何长度外推能力的原因。

### 2.2 正弦位置编码：理论上能算，实践中很差

正弦位置编码（[标量条件编码前置知识第二节](/前置知识/001s_前置知识_标量条件编码_位置编码与时间步嵌入#二概念阶段之一正弦位置编码transformer的原始方案)）用固定公式而非查表，理论上对任意位置都能算出一个合法的编码向量，不存在"表格用完了"的问题。Vaswani et al. 在 2017 年提出 Transformer 时也确实猜测这种编码方式"可能可以外推到比训练时更长的序列"。

但 [ALiBi 论文](/前置知识/005c_前置知识_ALiBi线性偏置位置编码#12-具体验证alibi论文的实测数据)的实测数据推翻了这个猜测：训练长度 512 时，评估长度刚超过 512 几十个 token 困惑度就开始爬升，到 3512（7 倍训练长度）时困惑度从 20.05 恶化到 178.97，接近失效。问题不在编码公式本身（它对任意位置确实有定义），而在于**编码向量之后要经过若干层训练过的网络参数**——这些参数的训练过程完全没有见过"位置 3000 的编码向量应该被怎样处理"这类样本，行为自然不可预测。这正是第 1.3 节表格里"间接可训练"那一档的典型例子。

### 2.3 RoPE：比前两种好，但仍然有限

[RoPE 前置知识](/前置知识/002k_前置知识_RoPE旋转位置编码#三关键性质验证attention分数只依赖相对距离)证明了一个重要性质：两个 token 经过旋转编码后的 Attention 分数，只依赖它们的**相对距离** $n-m$，不依赖各自的绝对位置。这比正弦编码和可学习嵌入依赖绝对位置要更稳健一些——因为相对距离这个量在序列内部具有一定的平移不变性，某种意义上"压缩"了需要泛化的变量数量。

但 RoPE 的外推能力仍然有限。ALiBi 论文用同样的实验设置测试 RoPE：训练长度 512 时，模型能在评估长度增加约 200 个 token（相当于 $1.4\times$ 训练长度）范围内维持或改善困惑度，超过这个范围后困惑度同样开始明显恶化，只是恶化的转折点比正弦编码晚。原因在于：虽然旋转操作本身对任意相对距离都有明确的数学定义（不需要训练），但**用旋转后的 Query/Key 做点积、并在此基础上训练出来的所有后续网络参数，仍然只见过训练时序列内出现的那个相对距离取值范围**——比如训练长度 512 时，模型最多见过距离为 511 的一对 token；测试时如果序列长度是 5000，会出现从未见过的、距离达到 4999 的 token 对，网络对这么大的相对距离要如何处理，同样是没有训练过的。

**RoPE 频率设计带来的一个额外问题**：[RoPE 前置知识第三节](/前置知识/002k_前置知识_RoPE旋转位置编码#31-为什么要多个频率)讲过，RoPE 用多个不同频率的旋转分量编码不同粒度的位置信息，其中低频分量（转速慢）覆盖的是"长距离、粗粒度"的位置关系。问题是：如果训练序列长度有限，这些低频分量在训练过程中**转过的角度范围也是有限的**——它们从未在训练中转到过对应"超长距离"才会出现的角度值。测试时序列变长，这些低频分量需要转到训练时从未见过的角度，表现自然不可预测。这个观察后续启发了一系列专门针对 RoPE 的外推改进方案。

#### 2.3.1 RoPE 的外推改进：位置插值、NTK-aware 与 YaRN（简述）

工业界已经发展出几种在不重新训练模型的前提下，扩展 RoPE 可用长度的技巧，核心思路都是"想办法让测试时的位置落在训练时旋转角度已经覆盖过的范围内"：

- **位置插值（Position Interpolation, PI）**：思路很直接——如果模型训练时只见过 $[0, 2048)$ 范围内的旋转角度，想在 8192 长度上用这个模型，就把位置编号先压缩 4 倍再喂给 RoPE 公式（比如原来的位置 8000，压缩后变成 2000），这样所有旋转角度都落在训练时见过的范围内。代价是位置信息的"分辨率"被拉稀了——原来相邻两个 token 之间的旋转角度差，现在要摊到 4 个 token 上，模型分辨"紧邻位置"的能力会打折扣，因此这种方法通常需要搭配少量微调才能恢复效果。
- **NTK-aware 插值**：观察到"压缩所有频率"这个做法太粗暴——高频分量（负责区分紧邻 token 的细粒度差异）不应该被压缩太多，否则局部顺序信息会丢失；低频分量（负责粗粒度的远距离关系）可以压缩更多。NTK-aware 插值按频率高低设置不同的压缩比例，只对低频分量做大幅度插值，高频分量基本保持不变，这样既扩展了远距离的覆盖范围，又不牺牲近距离的分辨率。
- **YaRN（Yet another RoPE extensioN）**：在 NTK-aware 插值的基础上进一步优化，把 RoPE 的频率维度显式划分成"高频保持不动""中间频率按 NTK 方式插值""低频线性压缩"三段分别处理，并针对 Attention 分数的整体幅度做一个补偿（因为插值后 Attention 分数的分布会发生微小偏移，需要额外校正）。YaRN 论文的实测结果显示，只需要用远少于从头训练所需的数据量和训练步数（该论文报告约减少一个数量级的 token 消耗和数倍的训练步数）对模型做少量微调，就能把上下文长度扩展到十万 token 量级，同时保持在原始训练长度上的困惑度基本不变。

这三种方法的共同本质，是**承认 RoPE 单靠自身机制无法完全解决外推问题，需要额外的人工干预（重新映射位置编号或微调）**，这和 ALiBi"设计上天生免疫"的思路是不同的解题路径——ALiBi 不需要任何插值或额外微调就能直接外推，代价是引入了较强的"就近偏好"，牺牲了一部分远距离精确建模的能力（见 [ALiBi 前置知识第 4.3 节](/前置知识/005c_前置知识_ALiBi线性偏置位置编码#43-alibi的代价不是没有缺点)）。

### 2.4 ALiBi：外推能力最强的显式位置方案

[ALiBi 前置知识第四节](/前置知识/005c_前置知识_ALiBi线性偏置位置编码#四为什么这个设计天然支持长度外推)已经详细论证过：ALiBi 的惩罚项是一个不经过任何训练参数的纯数学公式，天然对任意距离表现一致。实测数据显示，训练长度 512 的模型外推到 3512（7 倍）时困惑度依然保持 18.40，甚至优于自身在训练长度处的 19.73——这是四类方案里唯一能做到"随长度增加性能不退化甚至改善"的方案。

代价是较强的"就近偏好"（recency bias）——因为惩罚项永远是负的且随距离线性增长，模型结构性地更信任邻近的 token。这在语言建模这种"最近的上下文通常最相关"的任务上是个优点，但换到某些需要精确检索几千 token 之前具体细节的任务上，可能会成为限制。

### 2.5 NoPE：完全不加位置编码，反而外推更好？

一个反直觉的方向是彻底不引入任何显式位置编码——既不加位置向量，也不修改 Attention 分数，模型输入端和 Attention 计算的每一步都和位置无关。这种方案称为 NoPE（No Positional Encoding）。

听起来这样的模型应该完全"看不见"顺序，但事实上一个纯粹的 Decoder-only 架构（每个位置只能看到自己和之前的位置，即因果注意力，见 [Causal Attention 前置知识](/前置知识/001g_前置知识_Causal_Attention因果注意力掩码)）本身就隐含着一定的顺序信息——第 $i$ 个位置能看到的 Key 数量正好是 $i$ 个，这个"能看到的数量"本身就和位置有关，模型理论上可以利用这个隐含线索间接推断出相对位置关系。

Kazemnejad et al., "The Impact of Positional Encoding on Length Generalization in Transformers"（NeurIPS 2023）系统比较了 NoPE 和多种显式位置编码方案在算法推理类任务（要求模型学会的是抽象的位置/计数规律，而不是自然语言的统计模式）上的长度泛化能力，核心结论是：

> **NoPE 在长度泛化任务上的表现，超过了包括 ALiBi、RoPE、可学习绝对位置编码在内的所有测试过的显式位置编码方法，且不需要任何额外计算开销。**

这个结论的直觉解释是：显式位置编码（无论 ALiBi 还是 RoPE）都是研究者手工设计的一种"先验假设"（比如 ALiBi 假设"越近越重要"），这个先验在大多数语言建模场景下有效，但对某些任务未必是最优假设，反而可能限制模型自己去发现更适合当前任务的位置利用策略。NoPE 把这个自由度完全留给模型自己在训练中学习，某些任务上这样反而学到了更好的泛化规律。

需要注意几个重要的限定条件（避免对 NoPE 的结论过度泛化）：

- 这个结论主要建立在**算法推理类的合成任务**上（如复制、排序、加法等需要精确位置计数的任务），在这些任务里"位置泛化"的对错有明确的标准答案，容易严格测量；在更贴近真实场景的自然语言建模任务上，NoPE 是否总能超过 ALiBi 这类专门为语言建模设计的方案，还需要结合具体任务判断。
- 后续研究（如 Wang et al., "Length Generalization of Causal Transformers without Position Encoding", 2024）进一步发现，NoPE 虽然能比显式位置编码方案外推到更长的序列，但**它的外推能力同样存在上限**，超过某个长度之后 NoPE 同样会退化——NoPE 不是"无限外推"的银弹，只是在已测试的范围内相对更稳健。
- NoPE 依赖模型自己从训练数据中隐式学出对位置的利用方式，这通常需要更大的模型规模和更充分的训练才能稳定发挥出优势，在小规模模型或数据不足的场景下，显式位置编码提供的先验信息可能仍然更可靠。

> 图中蓝色实线（ALiBi）是一条严格单调递减的直线，距离越远惩罚越重，且没有振荡；红色曲线（RoPE 理论包络）呈现振荡衰减模式——距离增加时总体呈下降趋势，但会有周期性的波动（这来自多个不同频率旋转分量的叠加）；紫色点线（可学习绝对编码）和绿色虚线（NoPE）都不具备这种"距离决定强弱"的显式结构，它们对距离的响应完全取决于训练数据本身学出的隐式规律，因此图中画成大致平坦（说明"没有内置的先验形状"，不代表实际数值一定是 0）。

再看 ALiBi 和 RoPE 单独对比的曲线（横轴是相对距离，纵轴是各自定义下对 Attention 的影响强度，都做了归一化处理以便比较形状而非绝对数值）：

![ALiBi 严格线性衰减 vs RoPE 振荡式衰减包络对比](/length_extrap_rope_vs_alibi_decay.png)

> ALiBi（蓝色）是一条确定性的直线，任何距离下惩罚力度都可以精确预测；RoPE（红色虚线）的实际点积结果会在包络线（橙色点线）范围内振荡，包络本身随距离衰减但不是严格单调——这种振荡结构一定程度上解释了为什么 RoPE 的外推行为不如 ALiBi 稳定：模型很难学会"振荡衰减"这种更复杂的模式在训练范围之外应该如何延续，而"严格单调直线"这种最简单的模式，天然就不存在"延续到未知范围会怎样"的歧义。

## 四、总结对比表与选型建议

| 方案 | 是否需要训练参数 | 面对分布外位置的鲁棒来源 | 实测外推倍数（相对训练长度） | 额外计算/显存开销 | 典型代表 |
|------|---------------|----------------------|----------------------|------------------|---------|
| 可学习绝对位置编码 | 需要（查表） | 无 | 几乎不能外推（超出训练长度即失效） | 无 | 早期 BERT、GPT-2 |
| 正弦位置编码 | 不需要（固定公式），但后续网络层需要训练 | 公式本身适用范围广，但处理它的网络层只见过训练范围 | 约 1.02-1.1 倍（几十个 token 内） | 几乎没有 | 原始 Transformer |
| RoPE | 不需要（固定公式或简单插值），后续网络层同样只见过训练范围内的相对距离 | 相对距离机制比绝对位置更稳健，但仍受训练时相对距离分布限制 | 约 1.2-2 倍（原生），配合 YaRN/NTK-aware 插值微调可扩展到数十倍 | 需要额外插值/微调策略才能大幅扩展 | LLaMA、Qwen（原生）；配合 YaRN 后可大幅扩展 |
| ALiBi | 不需要，且惩罚计算完全不经过任何训练参数 | 惩罚公式对任意距离数学上表现一致 | 约 6-8 倍（论文实测到 7 倍训练长度仍持续改善） | 几乎没有（0-0.7% 额外显存） | BLOOM、MPT |
| NoPE | 不需要（完全不引入位置信息） | 依赖因果掩码隐含的顺序信息 + 模型自学的隐式规律 | 在算法推理任务上优于以上所有显式方案，但同样存在外推上限 | 无 | 研究性方案，尚未见大规模主流模型采用 |

**实用判断标准**：

- 如果任务是标准语言建模，且部署时序列长度相对训练长度不会超出太多（1-2 倍），RoPE 是当前工业界的默认选择，生态最成熟（[LLaMA、Qwen、GR00T 等几乎所有现代大模型都在用](/前置知识/002k_前置知识_RoPE旋转位置编码#五rope的优势总结)）。
- 如果任务对"训短部署长"有明确需求（如本文开头"训练 2048、部署 8192"的场景），且能接受一定的"就近偏好"，ALiBi 是目前工程上最简单、最可靠的长度外推方案。
- 如果已经用 RoPE 训练好了一个模型，又需要临时扩展上下文长度，NTK-aware 插值或 YaRN 是不重新从头训练的务实选择。
- NoPE 目前更适合研究场景或对"精确位置计数"要求较高的算法推理类任务，在生产级语言模型上还缺乏大规模验证。
