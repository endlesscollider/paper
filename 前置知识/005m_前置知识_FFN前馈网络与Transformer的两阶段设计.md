# 前置知识：FFN 前馈网络——Transformer 为什么需要一个"逐 token 加工站"

> **一句话**：Transformer 的每一层都是"Attention + FFN"两步走。Attention 负责让 token 之间**互相看**、交换信息；FFN（Feed-Forward Network，前馈网络，也常被称为 MLP）负责让每个 token **自己消化**刚拿到的信息——它对每个 token 独立地做"升维展开、非线性加工、再压缩回去"，是 Transformer 里除了 Attention 之外唯一的非线性来源，也是整个模型里参数量占比最大的部分（标准配置下约占每层参数的三分之二）。

**前置概念**：基础线性代数（矩阵乘法、矩阵乘矩阵得到矩阵）、什么是非线性函数（$f(x)$ 不能写成 $ax+b$ 的形式）。不需要任何论文背景。

## 贯穿全文的例子

> 假设我们在处理一句话"猫坐在垫子上"，Transformer 把它切成 token，每个 token 用一个 4 维向量表示（真实模型里这个维度通常是几百到几千，这里用 4 维方便手算）。本文会反复用"垫子"这个 token 的 4 维向量 $x=[1.0, -0.5, 2.0, 0.0]$，演示它在 FFN 里具体经历了什么计算。

## 一、先回顾：Transformer 一层里到底发生了什么

### 1.1 两个子层，缺一不可

Transformer 的每一层（无论是 [标准 Self-Attention](/前置知识/001g_前置知识_Causal_Attention因果注意力掩码) 还是 [Cross-Attention](/前置知识/001e_前置知识_Cross_Attention与交替注意力机制) 变体）都由两个子层顺序堆叠而成：

```mermaid
flowchart LR
    A["输入 token 序列"] --> B["Self-Attention<br/>(token 之间互相看)"] --> C["+ 残差"] --> D["FFN<br/>(每个 token 自己加工)"] --> E["+ 残差"] --> F["输出 token 序列"]
```

第一个子层是 Attention：让每个 token 去看序列里的其他 token，决定"该重点参考谁的信息"，然后把参考到的内容混合进自己的表示。这一步是**跨 token** 的——每个 token 的新表示，依赖于其他 token 的内容。

第二个子层就是本文的主角：**前馈网络（Feed-Forward Network, FFN）**。它对 Attention 输出的每一个 token 向量，独立地做一次"加工"——这一步是**逐 token** 的，即第 3 个 token 的输出只取决于第 3 个 token 自己的输入，和第 5 个 token 完全没有关系，也不会去看任何其他 token。

### 1.2 一个自然的问题：Attention 已经让 token 互相交换信息了，为什么还需要 FFN 单独加工一遍？

这正是本文要讲透的问题。答案分两层：第一，Attention 本身有一个结构性缺陷——它对信息的组合方式是**线性**的（下一节详细展开），缺了 FFN 提供的非线性能力，模型的表达力会大打折扣；第二，FFN 承担着"存储和检索训练时学到的具体模式"这一角色，和 Attention"决定该看谁"的角色是互补的分工，不是重复劳动。

## 二、FFN 解决的第一个问题：Attention 本身不够"非线性"

### 2.1 Attention 的输出，说到底是一堆加权平均

回顾 Attention 的计算方式：对每个 token，用它的 Query 和所有 token 的 Key 算相似度，过 softmax 得到一组权重，再用这组权重对所有 token 的 Value 做**加权求和**。

关键点在这里：不管权重怎么变化，"加权求和"这个操作本身永远是**线性**的——给定权重之后，输出是若干个 Value 向量的线性组合。而且如果去掉 Attention 计算里唯一的非线性来源 softmax，纯粹的 $QK^T V$ 就是三个矩阵连续相乘，数学上等价于一次线性变换。

一个纯粹只堆叠 Attention 层（不含任何 FFN、也不含残差连接）的网络会出现一种叫做**秩坍缩（Rank Collapse）**的现象：随着层数加深，所有 token 的表示会越来越趋于相同，模型区分不同 token 的能力急剧下降。Dong 等人在论文《Attention is Not All You Need》（ICML 2021）中证明了这一点——纯 Self-Attention 网络（去掉残差连接和 FFN）的输出，会以**双指数级的速度**收缩到一个秩为 1 的矩阵，也就是所有 token 的表示都坍缩成同一个方向的倍数。直觉上可以理解为：反复对同一组向量做加权平均，每平均一次，向量之间的差异就被磨掉一部分，磨的次数（层数）越多，差异消失得越快——最终所有 token 都长得一模一样，模型再也分不清"猫"和"垫子"有什么区别。

下图直观展示了这个坍缩速度的差异——横轴是层数，纵轴是"token 表示彼此还有多不一样"（示意曲线，非真实模型实测数据）：

![纯Self-Attention（无FFN无残差）的表示坍缩速度示意，对比标准Transformer结构](/ffn_rank_collapse_illustration.png)

> 红色曲线（纯 Attention，无跳跃连接、无 FFN）随层数增加迅速跌到 0——所有 token 的表示很快趋于完全相同；蓝色曲线（标准 Transformer，带残差连接和 FFN）下降极其平缓，token 之间的差异性在深层网络里依然能保留下来。这张图是示意性的，用来直观传达"结构性缺陷"和"结构性修复"之间量级上的差异，不是某个具体模型的实测曲线。

论文同时证明了：**只要加入残差连接或 FFN（或两者），这种坍缩就会被显著遏制**。这也是本文开篇提到的"FFN 是 Attention 之外唯一的非线性来源"这句话的理论支撑——FFN 内部的非线性激活函数打断了"纯线性组合"这条退化路径，让每个 token 的表示能保留自己独有的信息，而不是被反复平均成大家都差不多的样子。

### 2.2 一个更直观的类比

> 想象一个班级讨论：Attention 相当于"每个同学听取全班同学的发言，按重要程度加权总结出一份笔记"。如果讨论了很多轮（很多层 Attention），但每个人做笔记的方式永远是"简单加权平均别人说的话"，那么讨论到后期，所有人的笔记会变得高度相似——因为大家都在互相抄"平均意见"，个体的独特想法被稀释掉了。
>
> FFN 相当于给每个同学加了一步：**听完别人的发言之后，先自己关起门来，用自己的知识体系重新消化、加工一遍，再把消化后的结果记下来**。这一步是每个人独立完成的（不看别人），而且加工过程是非线性的（不是简单地对听到的内容做平均），这样即使经过很多轮讨论，每个人的笔记依然能保留自己的风格和独特理解。

## 三、FFN 解决的第二个问题：模式记忆与检索

### 3.1 FFN 可以被理解成一个"键值记忆库"

除了补充非线性，FFN 还承担着另一个角色。Geva 等人在论文《Transformer Feed-Forward Layers Are Key-Value Memories》（EMNLP 2021）中提出并验证了一个有启发性的视角：**FFN 的第一个矩阵的每一列，可以被看作一个"模式探测器"（对应"键"）；第二个矩阵对应的那一行，则是"如果这个模式被触发，该往输出里加什么"（对应"值"）**。

具体来说：FFN 的中间层有成百上千个神经元，每个神经元在训练过程中会逐渐"专精"于识别某一类具体的输入模式（比如"这个 token 前面出现过某个特定的语法结构"，或者"这段文本在讨论某个特定主题"）。当输入恰好匹配某个神经元擅长识别的模式时，那个神经元的激活值会变得很大（在 ReLU 的语境下就是"被激活，输出正值"），于是它对应的"值"向量就会被大幅度地叠加进最终输出；不匹配的神经元激活值趋近于 0，对输出几乎没有贡献。

> 回到贯穿全文的例子："垫子"这个 token 经过 Attention 之后，携带了"猫坐在我上面"这个上下文信息。FFN 中间层某些神经元可能专门识别"和坐、躺等动作相关的家具类名词"这种模式——如果"垫子"的表示恰好激活了这些神经元，它们存储的"值"向量（比如某种和"家具/表面"语义相关的方向）就会被叠加进输出，帮助后续层更准确地处理这个 token。这只是一个帮助建立直觉的类比说明，不是某个具体训练好的模型里能验证的真实神经元行为。

这个"键值记忆库"的视角解释了为什么 FFN 占据了 Transformer 里最大比例的参数量（下一节会给出具体数字）——存储大量具体的模式-响应对，天然需要大量的参数容量,这和 Attention"学会该看谁"这个相对轻量的角色形成分工。

### 3.2 两个角色的分工总结

| 子层 | 核心问题 | 信息流动方式 | 主要贡献 |
|------|---------|------------|---------|
| Attention | "该参考谁的信息？" | 跨 token（每个 token 看其他所有 token） | 决定信息如何在 token 之间流动和混合 |
| FFN | "拿到信息后，该怎么加工？" | 逐 token（每个 token 独立处理，互不干扰） | 提供非线性能力 + 存储训练时学到的大量具体模式 |

## 四、FFN 的具体计算：升维 → 非线性 → 降维

### 4.1 标准公式

FFN 的标准形式极其简单：两次线性变换，中间夹一个非线性激活函数（原始 Transformer 论文《Attention Is All You Need》用的是 ReLU）：

$$
\text{FFN}(x) = \text{ReLU}(xW_1 + b_1)\,W_2 + b_2
$$

**这个公式在做什么**：把输入向量 $x$ 先升维（$W_1$ 把 $x$ 映射到一个更宽的中间空间），过一次 ReLU 只保留正值，再用 $W_2$ 降维投影回原始维度。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $x$ | **输入特征** | 某个 token 经过 Attention 之后的隐藏状态向量 |
| $xW_1 + b_1$ | **升维投影** | 把 $x$ 映射到一个维度更高的中间空间（比如从 4096 维升到 16384 维），让网络有更大的"工作台面"去组合特征。$b_1$ 是这一层的偏置项 |
| $\text{ReLU}(\cdot)$ | **统一门槛过滤器** | 把中间空间里所有负值砍成 0，正值原样保留——这是整个 FFN**唯一**的非线性来源 |
| $W_2, b_2$ | **降维投影** | 把过滤后的中间表示压缩回原始维度，作为这一层的最终输出 |

**用人话读**："把特征先摊开到一个更宽的空间，把里面的负数全部清零，再压缩回原来的维度。"

**为什么是这个形式**：两次线性变换之间必须有非线性，否则整个 FFN 退化成一次线性变换（两个矩阵相乘还是一个矩阵），丧失表达能力——这正是第二节论证的"缺了非线性会导致表示坍缩"这一问题的直接解法。ReLU 是最简单、计算最快的非线性选择。
:::

后续研究发现 ReLU 有一个"死神经元"问题（负半轴梯度恒为 0，一旦某个神经元输出恒为负，就再也学不到东西），因此现代大模型的 FFN 大多换用了 GELU、SiLU 等更平滑的激活函数,甚至进一步引入门控结构（[GLU/SwiGLU/GeGLU](/前置知识/005g_前置知识_GLU门控线性单元与SwiGLU_GeGLU)）。这些都是"中间非线性函数怎么选"这一具体问题的后续演进,完整脉络见 [激活函数全景综述](/论文综述/S26_激活函数全景综述),本文只讲最基础的 ReLU 版本,把选型问题留给那两篇文章。

### 4.2 中间维度的惯例：为什么要先"扩张"再"压缩"

标准 Transformer 的惯例是让中间维度 $d_{ff}$ 取模型隐藏维度 $d$ 的 **4 倍**（比如 $d=4096$ 时，$d_{ff}=16384$）。为什么要先扩张 4 倍再压回去，而不是直接在原始维度上做非线性变换？

直觉类似"先把工作台面摆大一点"：如果一直在 $d$ 维空间里操作，非线性函数能表达的模式组合方式会被这个维度本身死死限制住。先投影到一个更宽（4 倍）的空间，相当于给模型更多"独立方向"去分别捕捉不同的模式（呼应第三节"键值记忆库"的视角——中间维度越宽，能存储的独立模式-响应对就越多），做完非线性加工后再压缩回原始维度，既获得了更强的表达力，又保证了输入输出维度对齐、可以直接和残差连接相加。$4\times$ 这个具体倍数没有严格的理论推导，是《Attention Is All You Need》原始论文里凭经验设定并沿用下来的惯例（后续也有模型用 $8/3$ 倍等其他倍数，详见 [GLU 前置知识第四节](/前置知识/005g_前置知识_GLU门控线性单元与SwiGLU_GeGLU#四工程实操pytorch里怎么写) 的具体推导）。

### 4.3 参数量：FFN 是 Transformer 里最"重"的部分

以 $d=4096$、$d_{ff}=4d=16384$ 为例，算一下单层里 Attention 和 FFN 各自占用多少参数：

- **Attention**：$W_Q, W_K, W_V, W_O$ 四个 $d\times d$ 矩阵，共 $4d^2$
- **FFN**：$W_1$（$d\times d_{ff}$）+ $W_2$（$d_{ff}\times d$），共 $2d\,d_{ff} = 8d^2$（因为 $d_{ff}=4d$）

<img src="/ffn_attn_param_split.png" alt="单层Transformer里Attention和FFN的参数量对比柱状图，d=4096" class="img-wide">

> 图中可以直接看到，在 $d_{ff}=4d$ 的标准配置下，FFN 的参数量（134.2M）恰好是 Attention 参数量（67.1M）的 2 倍，占整层总参数的约 **三分之二**。这也是为什么模型 scaling（增大模型规模）时，FFN 往往是参数量增长的主要来源，也是 [LoRA 低秩适配](/前置知识/000x_前置知识_LoRA低秩适配基础) 等参数高效微调方法格外关注 FFN 里的权重矩阵的原因之一。

## 五、具体数值例子：手算一个 4 维 token 的完整 FFN 计算

用贯穿全文的例子——"垫子"这个 token 的向量 $x=[1.0,\ -0.5,\ 2.0,\ 0.0]$，把它升维到 8 维（真实模型是升到 4 倍原始维度，这里同样按 4 倍取整数方便手算），走一遍完整的 FFN 计算。

**第一步：升维投影**，$z = xW_1 + b_1$（$W_1$ 是 $4\times 8$ 矩阵，这里直接给出算好的结果）：

$$
z = [\,2.1,\ -1.7,\ 0.75,\ 1.3,\ -2.6,\ 2.0,\ 2.45,\ -0.8\,]
$$

**这个公式在做什么**：把 4 维的输入向量通过一次线性变换映射到 8 维的中间空间，得到 8 个"候选特征"的原始信号（尚未经过非线性处理）。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $x$ | **"垫子"这个 token 的 4 维表示** | $[1.0,-0.5,2.0,0.0]$，本文贯穿全文的具体例子 |
| $W_1$（$4\times8$） | **升维矩阵** | 把 4 维空间的每个方向，重新组合成 8 维空间里 8 个"候选特征通道" |
| $z=xW_1+b_1$ | **8 个候选特征的原始值** | 每一维代表"这个 token 在某个特定模式通道上的匹配程度"（呼应第三节的键值记忆库视角），正负和大小都还没经过任何筛选 |

**用人话读**："把 4 维向量通过矩阵乘法投影成 8 个数字，这 8 个数字分别是'匹配 8 种不同模式通道'的原始打分。"

**为什么先算这一步**：这一步纯粹是线性代数运算，本身不涉及任何设计选择上的"为什么"——真正的设计决策在下一步，即怎么处理这 8 个原始打分。
:::

**第二步：过 ReLU**，把负值清零：

$$
h = \text{ReLU}(z) = [\,2.1,\ 0,\ 0.75,\ 1.3,\ 0,\ 2.0,\ 2.45,\ 0\,]
$$

**这个公式在做什么**：8 个候选特征里，负值代表"这个模式通道没有被匹配到"，直接清零，不让它污染后面的计算；正值代表"匹配上了，且匹配程度就是这个数值"，原样保留。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $z$ 中的负值（如 $-1.7,-2.6,-0.8$） | **未匹配的模式通道** | 这三个通道对"垫子"这个输入没有响应，ReLU 把它们强制清零，这一步之后它们对最终输出的贡献是 0 |
| $z$ 中的正值（如 $2.1, 0.75, 1.3, 2.0, 2.45$） | **被激活的模式通道** | 这五个通道认为"垫子"这个输入匹配了自己负责识别的模式，数值大小代表匹配强度，原样保留传递到下一步 |
| $h$ | **经过筛选后的 8 维中间表示** | 只有 5 个非零位置真正参与了后续计算，另外 3 个位置形同"关闭" |

**用人话读**："8 个候选打分里，负的直接扔掉变成 0，正的原样保留，得到一个大部分位置是 0、少数位置有值的稀疏向量。"

**为什么是这个形式**：这正是第三节"键值记忆库"视角的具体体现——只有真正被这个输入"点亮"的模式通道才会参与下一步的输出计算,没被点亮的通道完全不干扰结果。下图把这 8 个数字的 ReLU 变换过程画成了函数曲线,可以直观看到每个点落在曲线的哪个位置：

![ReLU函数曲线，标注了本例中4个代表性数值(2.1、-1.7、0.75、-2.6)对应的输入输出关系](/ffn_relu_worked_example.png)

> 图中绿色点（$z=2.1$ 和 $z=0.75$）落在曲线的右半段，原样通过；红色点（$z=-1.7$ 和 $z=-2.6$）落在左半段，无论原始数值大小，输出都被拍平到 0。这正是 ReLU "非负则清零"的判定规则的直接可视化。
:::

**第三步：降维投影回原始维度**，$\text{out} = hW_2 + b_2$（$W_2$ 是 $8\times 4$ 矩阵）：

$$
\text{out} = [\,1.45,\ 2.70,\ 2.20,\ 1.85\,]
$$

**这个公式在做什么**：把经过 ReLU 筛选后的 8 维中间表示，重新压缩投影回 4 维，作为这个 token 经过 FFN 之后的最终输出——注意这一步只有 $h$ 中非零的 5 个位置真正对结果有贡献，为零的 3 个位置乘任何数还是 0。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $h$ 中的非零位置（位置 0、2、3、5、6） | **有效贡献者** | 只有这 5 个"键"被激活，它们对应 $W_2$ 里的 5 行（"值"向量）会被叠加进最终输出 |
| $W_2$ 的对应 5 行 | **每个激活模式对应的"响应内容"** | 呼应第三节的类比——一旦某个模式通道被激活，就把它专属的一段"响应向量"叠加进输出 |
| $hW_2+b_2$ | **加权叠加后的最终输出** | 把 5 个被激活的"响应向量"按各自的激活强度（$h$ 中的数值大小）加权叠加，再加上偏置 |

**用人话读**："8 个中间特征里，只有被 ReLU 保留下来的 5 个真正参与了最后的加权叠加，算出这个 token 经过 FFN 之后的新表示。"

**为什么要验证这一步**：这一步具体印证了第三节的键值记忆库直觉——可以逐项拆开验证,加总所有"激活的键 × 对应的值"确实等于最终输出 $[1.45, 2.70, 2.20, 1.85]$，任何一个被清零的"键"（比如位置 1、4、7）完全不参与这次的输出组成。
:::

最终，"垫子"这个 token 经过 FFN 一轮加工后，从 $[1.0, -0.5, 2.0, 0.0]$ 变成了 $[1.45, 2.70, 2.20, 1.85]$——这个新向量会再经过一次残差连接（加回原始的 Attention 输出），传递给下一层。

## 六、工程实操：PyTorch 里怎么写

前面讲清楚了"FFN 在算什么、为什么这样算"，接下来看真实代码怎么实现。核心思路很直接：**两个 `nn.Linear` 中间夹一个激活函数**，对应第四节的公式骨架。

```python
import torch
import torch.nn as nn

class StandardFFN(nn.Module):
    """
    标准 Transformer FFN，对应本文第四节的公式：
    FFN(x) = ReLU(xW1 + b1) W2 + b2
    """
    def __init__(self, dim: int, expansion: int = 4):
        super().__init__()
        d_ff = dim * expansion  # 中间维度，标准惯例取 4 倍（见 4.2 节）
        self.fc1 = nn.Linear(dim, d_ff)   # 对应 W1, b1：升维投影
        self.act = nn.ReLU()              # 唯一的非线性来源（见 4.1 节）
        self.fc2 = nn.Linear(d_ff, dim)   # 对应 W2, b2：降维投影

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # x 形状: [batch, seq_len, dim]
        # 关键点：fc1/fc2 对最后一维做变换，seq_len 维完全不参与矩阵乘法，
        # 这正是"逐 token 独立处理"的具体实现——batch 和 seq_len 两个维度
        # 里的每一个 token，都是被同一组 W1/W2 独立地各自处理一遍
        return self.fc2(self.act(self.fc1(x)))
```

代码里最值得留意的一点是：`self.fc1`、`self.fc2` 只对输入张量的**最后一维**（特征维度 `dim`）做变换，前面的 `batch` 和 `seq_len` 两个维度会被 PyTorch 自动"广播"处理——也就是说，序列里每一个 token 都会被同一套权重 $W_1, W_2$ 独立地各自算一遍，token 之间完全不发生任何信息交换。这行代码就是本文第一节"逐 token 独立加工"这句话最直接的工程体现，和 Attention 层里 Q/K/V 之间必须做跨 token 的矩阵乘法形成鲜明对比。

一个完整的 Transformer 层，把 Attention 和 FFN 用残差连接串起来，大致是这样：

```python
class TransformerBlock(nn.Module):
    def __init__(self, dim: int, num_heads: int):
        super().__init__()
        self.attn = nn.MultiheadAttention(dim, num_heads, batch_first=True)
        self.ffn = StandardFFN(dim)
        self.norm1 = nn.LayerNorm(dim)
        self.norm2 = nn.LayerNorm(dim)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        # 第一个子层：Attention，token 之间互相看
        attn_out, _ = self.attn(self.norm1(x), self.norm1(x), self.norm1(x))
        x = x + attn_out  # 残差连接

        # 第二个子层：FFN，每个 token 独立加工
        x = x + self.ffn(self.norm2(x))  # 残差连接
        return x
```

两个残差连接（`x = x + ...`）都不可省略——第二节讲过，残差连接和 FFN 一起构成了防止表示坍缩的结构性保障，缺了任何一个，深层堆叠的 Transformer 都会面临 token 表示趋同的风险。

## 七、总结

| 维度 | Attention | FFN |
|------|-----------|-----|
| 信息流动 | 跨 token（互相看） | 逐 token（各自独立） |
| 核心问题 | 该参考谁的信息 | 拿到信息后怎么加工 |
| 非线性来源 | 只有 softmax（作用有限） | ReLU/GELU/SiLU 等（真正的非线性主力） |
| 参数占比（$d_{ff}=4d$ 标准配置） | 约 1/3 | 约 2/3 |
| 缺失后果 | 无法让 token 交换信息 | 表示坍缩（趋于同一个方向），详见第二节 |
| 直觉类比 | 开会听取大家发言 | 关起门来自己消化加工 |

理解了 FFN 的这两重角色（补充非线性 + 存储模式记忆），再去看 [GLU 门控线性单元与 SwiGLU、GeGLU](/前置知识/005g_前置知识_GLU门控线性单元与SwiGLU_GeGLU) 会更清楚：那篇文章讨论的"把 ReLU 换成门控结构"，本质上是在优化本文第四节里"中间那个非线性函数该怎么选"这一个具体环节，FFN 整体的"升维-非线性-降维"骨架和它在 Transformer 里的角色分工完全不变。
