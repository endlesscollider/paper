# Perceiver Resampler：用固定数量的可学习 Query 压缩任意长度的特征序列

> 相关阅读：[Cross-Attention 与交替注意力机制](/前置知识/001e_前置知识_Cross_Attention与交替注意力机制)

## 一、要解决的问题

一个视觉编码器（比如 ViT，或者一个视频生成模型的中间层）输出的特征通常是"跟输入尺寸挂钩"的——图像分辨率越高、视频帧数越多，输出的 token 数量就越多。比如一段视频编码后可能有几千甚至上万个 token。

但下游模块（比如一个决定动作的策略网络）往往只需要一个**固定长度**的表征，原因有二：

1. 下游模块的输入维度必须是固定的，不能随视觉输入尺寸变化而变化（否则每次输入不同分辨率的图像都要重新设计网络结构）
2. 上万个 token 直接喂给下游的 Transformer，自注意力的计算量是 token 数量的平方级增长，代价太大

我们需要一种方法：**把任意长度的视觉特征序列"压缩"成一个固定数量（比如 224 个）的表征，同时尽量保留有用的信息**。直接用平均池化或者线性插值会丢失大量细节信息（等权重平均相当于假设所有 token 同等重要，但实际上不同空间/时间位置的信息量并不均等）。我们希望压缩过程是"可学习"的、能自动分辨"该重点保留什么信息"。

## 二、核心思路：用一组可学习的 Query 去"查询"原始特征

Perceiver Resampler（源自 DeepMind 的 Perceiver 系列工作，后来被 Flamingo 等多模态模型广泛采用）的做法是：

- 定义一组数量固定、可学习的向量，叫做**latent（潜变量）**或者 **query**，比如 224 个
- 用这些 latent 作为 Cross-Attention 里的 Query，去"查询"原始的、任意长度的视觉特征（作为 Key 和 Value）
- Cross-Attention 的输出长度永远等于 Query 的数量（224 个），和输入序列有多长完全无关

直觉上，这 224 个 latent 就像 224 个"提问者"，每个提问者都在问"原始特征里和我相关的信息是什么"，然后把回答汇总成自己的新表征。因为 Query 的数量是固定的超参数，输出长度自然也就固定了。

## 三、Perceiver Attention Layer 的公式拆解

Perceiver Resampler 的核心计算单元是一层特殊的 Cross-Attention，公式如下：

$$
\text{PerceiverAttn}(X, L) = \text{softmax}\left(\frac{Q_L (K_{[X;L]})^\top}{\sqrt{d}}\right) V_{[X;L]}
$$

**这个公式在做什么**：用潜变量 $L$ 生成 Query，去查询"原始特征 $X$ 和潜变量 $L$ 拼接后的序列"，得到一个长度和 $L$ 相同、但信息来自 $X$ 和 $L$ 双方的新表征。

**逐符号拆解**：

| 符号 | 数学含义 | 在这个场景中具体是什么 | 典型维度 |
|------|---------|----------------------|---------|
| $X$ | 原始特征序列（图像/视频编码器的输出） | 比如某个视频 patch 化后的特征 | $(B, N, d)$，$N$ 可能是几千 |
| $L$ | 可学习的潜变量（Query 来源） | 一组随机初始化、参与训练的向量参数 | $(B, M, d)$，$M$ 是固定值，比如 224 |
| $[X; L]$ | $X$ 和 $L$ 沿 token 维拼接 | Key/Value 的来源既包含原始特征，也包含潜变量自身 | $(B, N+M, d)$ |
| $Q_L$ | 用 $L$ 经过线性层 $W_Q$ 得到的 Query | 每个潜变量对应一个 Query 向量 | $(B, M, d)$ |
| $K_{[X;L]}, V_{[X;L]}$ | 用拼接序列经过 $W_K, W_V$ 得到的 Key/Value | 每个原始 token 和每个潜变量都提供一份 Key/Value | $(B, N+M, d)$ |
| $\sqrt{d}$ | 缩放因子，$d$ 是每个注意力头的维度 | 防止点积结果过大导致 softmax 饱和 | 标量 |
| 输出 | 长度固定为 $M$ 的新表征 | 每个潜变量根据自己的 Query 从 $X$ 和 $L$ 中"取"到的加权信息 | $(B, M, d)$ |

**为什么 Key/Value 要同时包含 $X$ 和 $L$（而不是只包含 $X$）**：让潜变量除了从原始特征里取信息，也能互相"看到"对方当前的状态，这样多个潜变量之间可以隐式地分工——比如某个潜变量已经"负责"了某块空间区域的信息，其余潜变量的 Query 在下一层可以据此调整自己的关注点，不会所有潜变量都收敛到抓取同一块最显著的信息。

**为什么 Query 只来自 $L$（不来自 $X$）**：这是"压缩"操作单向性的关键——如果 $X$ 也生成 Query 去查询别的东西，输出长度就会变回 $N$（和 $X$ 一样长），压缩效果就消失了。只让固定数量的 $L$ 生成 Query，天然保证了输出长度恒等于 $M$。

### 数值例子

假设简化到 $d=4$（每个 token 是 4 维向量），$N=3$ 个原始 token，$M=2$ 个潜变量，单头注意力（不缩放为了简化，实际会除以 $\sqrt{d}=2$）：

- $X$ 的 3 个 token：$x_1=[1,0,0,0]$，$x_2=[0,1,0,0]$，$x_3=[0,0,1,1]$
- $L$ 的 2 个潜变量（简化为已经算好的 Query）：$q_1=[1,0,0,0]$（"偏好第一种特征"），$q_2=[0,0,1,0]$（"偏好第三种特征"）
- 假设 Key 就等于原始向量本身（简化），拼接后 Key 集合是 $\{x_1,x_2,x_3,l_1,l_2\}$（这里为简化数值例子，忽略 $L$ 自身的 Key/Value 贡献，只演示 $X$ 部分）

对 $q_1$：点积 $q_1 \cdot x_1 = 1$，$q_1\cdot x_2=0$，$q_1\cdot x_3=0$。softmax 后几乎所有权重集中在 $x_1$ 上（$\approx [0.58, 0.21, 0.21]$，用 $\sqrt{4}=2$ 缩放后 softmax([0.5,0,0])），输出 $\approx 0.58 x_1 + 0.21 x_2 + 0.21 x_3 \approx [0.58, 0.21, 0.21, 0.21]$——主要抓到了 $x_1$ 的信息。

对 $q_2$：点积 $q_2\cdot x_1=0$，$q_2\cdot x_2=0$，$q_2\cdot x_3=1$（因为 $x_3$ 第三维是 1）。同理 softmax 后权重集中在 $x_3$ 上，输出主要抓到 $x_3$ 的信息（包含 $[0,0,1,1]$ 里的两个非零维度）。

这说明：**不同的潜变量会根据自己的 Query 方向，从原始特征里"选择性地"抓取不同的信息**，而不是简单地对所有 token 做平均。这正是 Perceiver Resampler 相比平均池化的优势所在——压缩过程是有选择性的、可学习的。

## 四、堆叠多层：迭代式精炼

单层 Perceiver Attention 只能做一次"查询-汇总"。实际实现中会堆叠多层（比如 6 层），每层结构是：

$$
L \leftarrow L + \text{PerceiverAttn}(X, L), \qquad L \leftarrow L + \text{FFN}(L)
$$

每一层里潜变量 $L$ 都会更新一次（残差连接保留之前积累的信息），然后用一个前馈网络（FFN）进一步处理。多层堆叠让潜变量有机会反复"回看"原始特征、不断精炼自己的表征，类似于人类反复阅读一段材料、每次都注意到不同的细节。

## 五、时间维度的扩展：为什么视频需要"3D"版本

如果输入不是单张图像的特征而是一段视频（多帧），原始的 Perceiver Resampler 需要扩展成"3D"版本，额外处理时间维度：

1. **每帧独立分配潜变量**：给每一帧单独分配一组潜变量（比如 224 个 latent 平分到 16 帧，每帧 14 个），而不是所有帧共享同一组潜变量——因为不同帧的视觉内容不同，需要不同的"提问角度"
2. **时间位置编码**：给每一帧的潜变量加上区分"这是第几帧"的位置编码（`time_pos_emb`），否则模型无法区分不同帧的时间顺序
3. **帧间注意力**：在做完"空间"上的 Perceiver Attention 之后，额外插入一层跨帧的自注意力，让不同帧的潜变量之间能交换信息（比如"这个物体在前一帧的位置，帮助判断它在这一帧往哪运动"）

这三点结合起来，就是 RynnWorld-4D-Policy 里 `Video_Former_3D` 采用的设计：先对每一帧的（RGB+深度+光流三分支拼接后的）特征做空间维度的 Perceiver 压缩，再做一次跨帧的时序注意力，最终把整段视频压缩成一个固定长度（比如 224 个 token）的表征，供下游的动作生成模块使用。具体如何应用在这个模型上，见后续章节展开。

## 六、和其他压缩方式的对比

| 方法 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| 平均/最大池化 | 对所有 token 直接算平均值或最大值 | 无参数、计算极快 | 无法区分不同 token 的重要性，丢失大量信息 |
| 线性投影降维 | 用一个矩阵把 $N \times d$ 映射到 $M \times d$ | 有参数、可学习 | 权重矩阵大小和 $N$ 挂钩，输入长度变化时无法直接复用 |
| Perceiver Resampler | 可学习的固定数量 Query 做 Cross-Attention | 输出长度与输入长度无关，压缩过程可学习、有选择性 | 计算量比池化大（仍是 $O(M \times N)$，但远小于自注意力的 $O(N^2)$） |

Perceiver Resampler 的关键优势在于：**输出长度完全由 Query 数量决定，和输入序列长度解耦**。这使得下游模块可以用一套固定的网络结构去处理任意分辨率、任意帧数的视觉输入,而不需要为每种输入尺寸重新设计接口。

## 七、总结

- Perceiver Resampler 用一组数量固定、可学习的 latent 作为 Cross-Attention 的 Query，去查询任意长度的原始特征序列
- 输出长度恒等于 latent 的数量,和输入长度无关,天然解决了"下游模块需要固定维度输入"和"视觉特征长度随分辨率/帧数变化"这两者之间的矛盾
- Key/Value 同时来自原始特征和潜变量自身,让潜变量之间能隐式分工
- 处理视频时需要扩展成"3D"版本:每帧独立分配潜变量、加时间位置编码、额外插入跨帧注意力
- 相比池化和固定线性投影,Perceiver Resampler 的压缩过程是可学习、有选择性的,能更好地保留重要信息
