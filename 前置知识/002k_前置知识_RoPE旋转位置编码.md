# RoPE：旋转位置编码的完整机制

> Self-Attention 本身对输入顺序不敏感——把序列打乱重排,Attention 的计算结果完全一样。必须显式注入位置信息,模型才知道"谁在谁前面"。RoPE 用一种特别的方式做这件事:不是把位置编码成一个向量加到输入上,而是直接把位置信息"旋转"进 Query/Key 向量里。本文从"为什么需要位置编码"讲到 RoPE 的旋转矩阵、频率设计、以及它如何天然编码相对位置。

## 一、为什么 Self-Attention 需要额外的位置信息

### 1.1 问题:Attention 天生"看不见"顺序

回顾 Attention 的计算公式:

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V
$$

这里的 $Q, K, V$ 都是对输入序列的每个 token 独立做线性变换得到的。如果把输入序列 $[x_1, x_2, x_3]$ 换成 $[x_3, x_1, x_2]$,每个 token 的 Query/Key/Value 值完全不变,只是行的顺序变了——Attention 矩阵的每个元素值也只是被重新排列,数值本身没有任何变化。

用一句话说:**Self-Attention 是关于输入 token 集合的一个置换等变(permutation-equivariant)函数,它本身不携带任何"谁在前谁在后"的信息**。但语言和动作序列显然是有顺序的:"猫追狗"和"狗追猫"意思完全不同;机器人的第 3 步动作和第 8 步动作也不能互换。所以必须有一种机制,把位置信息注入到 Attention 的计算中。

### 1.2 两条主流路线

| 路线 | 做法 | 代表 |
|------|------|------|
| **绝对位置编码** | 给每个位置生成一个独立的向量,加到 token embedding 上 | 原始 Transformer 的正弦编码、BERT 的可学习位置嵌入 |
| **旋转位置编码(RoPE)** | 不额外加向量,而是直接对 Query/Key 向量做一个和位置相关的旋转变换 | LLaMA、Qwen、GR00T、XR0 等几乎所有现代 LLM/VLA |

绝对位置编码的问题在第 1.3 节展开;RoPE 正是为了解决这个问题而设计的。

### 1.3 绝对位置编码的局限:只关心"你在哪",不关心"你们俩差多远"

假设用正弦位置编码,给位置 5 和位置 100 各生成一个编码向量,加到对应 token 的 embedding 上。Attention 分数由 $QK^T$ 计算,其中 $Q,K$ 分别来自"内容 + 位置"的叠加。这样一来,位置信息和内容信息**混在一起**做点积,很难保证"位置 5 和位置 8 之间相差 3"这个相对关系被 Attention 分数干净地捕捉到——尤其是在序列长度超出训练时见过的范围后,这种混合方式很容易失真。

更本质的问题是:语言和动作的语义,很多时候只依赖于"相对距离",而不依赖于"绝对位置"。比如"the cat sat"这个短语,不管它出现在句子的第 3 个词还是第 30 个词,"cat"和"sat"之间的语义关系应该是一样的。绝对位置编码没有天然的机制保证这一点。

RoPE 的目标就是:**设计一种编码方式,让两个 token 的 Attention 分数只依赖于它们的相对距离,不依赖各自的绝对位置。**

## 二、RoPE 的核心思想:用旋转矩阵编码位置

### 2.1 一句话直觉

> 把 Query/Key 向量的每一对维度看成平面上的一个点,按照"位置编号 × 固定角速度"把这个点绕原点旋转一个角度。旋转多少度只取决于位置编号,和 token 的内容无关。

### 2.2 二维情形:最简单的旋转

先看最简单的情况:向量只有 2 维,$\mathbf{x} = (x_1, x_2)$。给定位置 $m$ 和一个固定的角速度 $\theta$,RoPE 定义的位置编码操作是:

$$
f(\mathbf{x}, m) = \begin{pmatrix} \cos(m\theta) & -\sin(m\theta) \\ \sin(m\theta) & \cos(m\theta) \end{pmatrix} \begin{pmatrix} x_1 \\ x_2 \end{pmatrix}
$$

**为什么需要这个公式**:我们希望找到一个函数 $f(\mathbf{x}, m)$,把"内容向量 $\mathbf{x}$"和"位置 $m$"编码在一起,同时要求两个编码后向量的点积 $\langle f(\mathbf{q}, m), f(\mathbf{k}, n) \rangle$ 只依赖于 $\mathbf{q}, \mathbf{k}$ 的内容和相对距离 $m-n$,不依赖 $m, n$ 各自的绝对值。旋转矩阵恰好满足这个性质,因为**旋转是保内积的正交变换**——这是下面要验证的关键。

> **一句话直觉**:给向量乘一个旋转矩阵,就像用一个时钟的指针转动角度来表示位置——转得越多,代表位置越靠后。

**逐项拆解**:

| 符号 | 含义 | 具体是什么 |
|------|------|-----------|
| $\mathbf{x} = (x_1, x_2)$ | 原始的 2 维内容向量 | Query 或 Key 向量的其中一对维度 |
| $m$ | token 的位置编号 | 整数,如第 0、1、2...个 token |
| $\theta$ | 固定角速度(超参数) | 决定"每往后移动一个位置,旋转多少角度" |
| $m\theta$ | 实际旋转角度 | 位置越靠后,旋转角度越大 |
| $\begin{pmatrix}\cos & -\sin\\ \sin & \cos\end{pmatrix}$ | 标准二维旋转矩阵 | 把向量在平面上逆时针转 $m\theta$ 度,长度不变 |

**具体数值例子**:取 $\mathbf{x} = (1, 0)$(单位向量,指向 x 轴正方向),$\theta = 90°$(为了算得直观选一个大角度,实际 RoPE 用的角度远小于此)。

- 位置 $m=0$:旋转角度 $0°$,$f(\mathbf{x}, 0) = (1, 0)$ —— 没有变化
- 位置 $m=1$:旋转角度 $90°$,$f(\mathbf{x}, 1) = (\cos 90°, \sin 90°) = (0, 1)$
- 位置 $m=2$:旋转角度 $180°$,$f(\mathbf{x}, 2) = (\cos 180°, \sin 180°) = (-1, 0)$

同一个内容向量 $(1,0)$,随着位置编号增加,像时钟指针一样不断转动,但**长度始终是 1**(旋转不改变向量长度)。

**为什么是这个形式**:旋转矩阵是正交矩阵,满足 $R(\alpha)^T R(\alpha) = I$,且两个旋转矩阵相乘等于角度相加:$R(\alpha)R(\beta) = R(\alpha+\beta)$。这个性质是整套 RoPE 能够"编码相对位置"的数学基础,下一节具体验证。

### 2.3 关键性质验证:Attention 分数只依赖相对距离

计算位置 $m$ 处的 Query 和位置 $n$ 处的 Key 的点积:

$$
\langle f(\mathbf{q}, m), f(\mathbf{k}, n) \rangle = \mathbf{q}^T R(m\theta)^T R(n\theta) \mathbf{k} = \mathbf{q}^T R(n\theta - m\theta) \mathbf{k} = \mathbf{q}^T R\big((n-m)\theta\big) \mathbf{k}
$$

**这一步在做什么**:验证经过旋转编码后,两个向量的点积(也就是 Attention 分数的核心计算)化简后只剩下一个旋转矩阵 $R((n-m)\theta)$,而这个矩阵**只依赖于位置差 $n-m$**,和 $m,n$ 各自的绝对值无关。

**逐项拆解**:
- $R(m\theta)^T R(n\theta)$:两个旋转矩阵的乘积,用到旋转矩阵的正交性 $R(\alpha)^T = R(-\alpha)$,所以 $R(m\theta)^T = R(-m\theta)$
- $R(-m\theta) R(n\theta) = R(n\theta - m\theta)$:旋转矩阵合成定律,角度直接相加减
- 最终结果 $R((n-m)\theta)$:只是一个关于相对距离 $(n-m)$ 的旋转矩阵,原始的 $m, n$ 已经不再单独出现

**数值验证**:接着上面的例子,取 $\theta=90°$,$\mathbf{q}=\mathbf{k}=(1,0)$。分别验证 $(m,n)=(0,1)$ 和 $(m,n)=(5,6)$——这两组的相对距离都是 $n-m=1$:

- $(m,n)=(0,1)$:$f(\mathbf{q},0)=(1,0)$,$f(\mathbf{k},1)=(0,1)$,点积 $=1\times0+0\times1=0$
- $(m,n)=(5,6)$:$f(\mathbf{q},5)$ 旋转 $450°=90°$(等价),得 $(0,1)$;$f(\mathbf{k},6)$ 旋转 $540°=180°$,得 $(-1,0)$,点积 $=0\times(-1)+1\times0=0$

两组绝对位置完全不同,但相对距离相同(都是 1),点积结果**完全一致**(都是 0)——这正是"只依赖相对距离"的直接验证。

**为什么是这个形式**:这正是设计 RoPE 时刻意追求的性质。如果用绝对位置编码(直接把位置向量加到内容向量上),点积展开后会同时含有内容-内容、内容-位置、位置-位置三种交叉项,无法干净地分离出"只依赖相对距离"的部分。旋转变换通过"作用在向量本身而不是叠加一个额外分量"的方式,让位置信息自然地"消融"进点积运算,只留下相对距离这一个变量。

## 三、从二维扩展到高维:多个频率的旋转

### 3.1 为什么要多个频率

一个二维旋转只能编码一种"节奏"的位置变化——就像只有一个指针的时钟,走一圈(经过若干个位置)后又会回到原来的角度,产生歧义(比如上面例子里 $450°$ 和 $90°$ 视觉上是等价的旋转,如果序列长度超过一圈就分不清位置了)。

解决办法和傅里叶分析的思路一致:**用多个不同频率的旋转叠加,类似"时针、分针、秒针"组合起来才能表示任意精细的时间**。头部维度 $d$ 通常是几十到上百,RoPE 把它两两分组,每一组用不同的角速度 $\theta_i$ 做二维旋转。

### 3.2 完整公式

对一个 $d$ 维向量 $\mathbf{x} = (x_1, x_2, \ldots, x_d)$($d$ 为偶数),两两分组 $(x_1,x_2), (x_3,x_4), \ldots$,第 $i$ 组($i=0,1,\ldots,d/2-1$)用角速度 $\theta_i$ 旋转:

$$
\theta_i = \text{base}^{-2i/d}, \qquad f(\mathbf{x}, m)_{2i:2i+2} = R(m\theta_i) \cdot \mathbf{x}_{2i:2i+2}
$$

**为什么需要这个公式**:单一频率的旋转会出现周期性歧义(转一圈就分不清位置),需要让不同维度组承担不同"分辨率"的位置信息——有的维度组转得快(捕捉近距离的细微位置差异),有的维度组转得慢(捕捉远距离的粗粒度位置差异)。

> **一句话直觉**:把向量切成若干对,每一对用不同的转速转动,像钟表的时针、分针、秒针一起工作,合起来就能不重复地表示很长的时间跨度。

**逐项拆解**:

| 符号 | 含义 | 具体是什么 |
|------|------|-----------|
| $d$ | 向量总维度(如 head_dim) | 例如 128 |
| $i$ | 维度组编号 | $0$ 到 $d/2-1$,共 $d/2$ 组 |
| $\text{base}$ | 基础频率超参数 | 通常取 10000 |
| $\theta_i = \text{base}^{-2i/d}$ | 第 $i$ 组的角速度 | $i=0$ 时最大(转得最快),$i$ 越大转得越慢 |
| $R(m\theta_i)$ | 第 $i$ 组用的旋转矩阵 | 只作用在这一对维度 $(x_{2i}, x_{2i+1})$ 上 |

**具体数值例子**:取 $d=4$(两组),$\text{base}=10000$:

- 第 0 组:$\theta_0 = 10000^{-0/4} = 1$,转速最快
- 第 1 组:$\theta_1 = 10000^{-2/4} = 10000^{-0.5} = 0.01$,转速慢 100 倍

位置 $m=10$ 时:
- 第 0 组旋转角度:$10 \times 1 = 10$ 弧度(约 $573°$,已经绕了 1.6 圈,近距离位置差异靠这组捕捉)
- 第 1 组旋转角度:$10 \times 0.01 = 0.1$ 弧度(约 $5.7°$,几乎没转,远距离位置的整体趋势靠这组捕捉)

**为什么是这个形式**:指数衰减 $\text{base}^{-2i/d}$ 让频率从高到低平滑分布——低维度组(小 $i$)对位置变化极其敏感(转速快,适合分辨相邻 token),高维度组(大 $i$)对位置变化很不敏感(转速慢,几乎覆盖整个序列长度都不会转满一圈,提供一个"粗粒度"的位置基准)。这个设计和正弦位置编码里"不同频率的正弦波叠加"思路是相通的,可以对照阅读[标量条件编码](/前置知识/001s_前置知识_标量条件编码_位置编码与时间步嵌入)。

### 3.3 代码实现中的等价写法

实际实现(包括 XR0 代码库里的 `apply_rotary_pos_emb`)通常不显式构造旋转矩阵,而是用下面这个等价的逐元素公式,计算效率更高:

$$
\mathbf{x}^{\text{rot}} = \mathbf{x} \odot \cos(\mathbf{m}\boldsymbol{\theta}) + \text{rotate\_half}(\mathbf{x}) \odot \sin(\mathbf{m}\boldsymbol{\theta})
$$

其中 `rotate_half` 把向量的后半部分取负号后挪到前面、前半部分挪到后面:$\text{rotate\_half}([x_1,\ldots,x_d]) = [-x_{d/2+1},\ldots,-x_d, x_1,\ldots,x_{d/2}]$。这在数学上等价于把 $d/2$ 个二维旋转矩阵按分块对角矩阵的方式作用在向量上,只是把"分组两两旋转"重新排列成了"前后两半"的形式,方便用矩阵乘法和逐元素乘法一次性算完所有组,不需要写循环。

## 四、多模态位置编码:MRoPE(以 Qwen3-VL 为例)

在纯文本 LLM 中,位置就是 token 在序列中的序号,一维整数就够了。但在视觉-语言模型(如 XR0 用的 Qwen3-VL)中,图像被切成 patch 后展开成一个二维网格(高 × 宽),纯粹的一维序号无法表达"这个 patch 在图像里的空间位置"。

MRoPE(Multimodal RoPE)的做法是把位置编号从一个整数,扩展成一个三元组 $(t, h, w)$:

- $t$(时间/序号维度):文本 token 按顺序编号;图像 token 内部共享同一个 $t$
- $h$(高度维度):图像 patch 在网格中的行号
- $w$(宽度维度):图像 patch 在网格中的列号

RoPE 的 $d/2$ 个频率组被划分成三段,分别只用 $t$、$h$、$w$ 中的一个来计算旋转角度,再拼接在一起。这样图像 patch 的位置编码同时携带了"它在第几帧""它在第几行""它在第几列"三种信息,而文本 token 退化为 $h=w=t$ 的特殊情况,和普通一维 RoPE 一致。这让同一个 Attention 机制能自然处理"文本序列"和"二维图像网格"混合的输入,这也是 XR0 中 Qwen3-VL 骨干网络处理多视角图像的位置编码方案,具体应用见 [XR0 深度解析 - Qwen3-VL 骨干网络](/系列/xr0_deep_dive/03_Qwen3VL骨干_视觉编码与MRoPE)。

## 五、RoPE 的优势总结

| 维度 | 绝对位置编码 | RoPE |
|------|------------|------|
| 编码方式 | 额外向量叠加到 embedding | 旋转变换作用在 Q/K 向量本身 |
| 是否需要训练参数 | 可学习版本需要 | 不需要(固定公式) |
| Attention 分数依赖 | 内容 + 绝对位置混合 | 只依赖内容和相对距离 |
| 长序列外推能力 | 差(超出训练长度容易失效) | 较好(相对距离机制更稳健) |
| 实现复杂度 | 简单(查表或加法) | 稍复杂(需要 cos/sin 和逐元素旋转) |
| 代表模型 | 原始 Transformer、BERT | LLaMA、Qwen、GR00T、XR0 等几乎所有现代大模型 |
