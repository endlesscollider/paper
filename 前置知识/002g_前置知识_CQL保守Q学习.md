# 前置知识：CQL（Conservative Q-Learning）保守 Q 学习

> **为什么要读这篇**：只要你训练的 Q 网络会被"取最大值"或"被策略优化器搜索"，而数据又是固定的一批（不能再和环境交互），那么 Q 网络一定会在数据没覆盖到的动作上给出虚高的估值，策略就会一头撞进这些虚高区域，最后学出一个在真实环境里完全不能用的策略。CQL 是解决这个问题最主流的方法，它的做法直接得近乎粗暴：**训练时额外加一项 loss，主动把"数据里没出现过的动作"的 Q 值往下压**。

## 1. 贯穿全文的例子

整篇文章用同一个极简场景，方便代入数字。

一个机械臂要把杯子推到桌面上的目标位置。为了让数字能手算，我们把它简化成**一个状态、一维动作**：

```text
状态   s：杯子在桌面上的位置（现在固定为 s₀ = 0.3）
动作   a：手推杯子的位移量，取值范围 a ∈ [-1, 1]
奖励   r：推完之后杯子离目标的距离越近奖励越高
数据集 D：某个老策略采集的 4 条数据，动作全部集中在 a ∈ [0.1, 0.3]
```

关键设定是最后一行：**数据集里的动作只覆盖了 $[-1,1]$ 中很小的一段**。这是所有离线 RL 问题的本质结构。$a = 0.9$ 这样的动作在数据里根本没出现过，我们称它为 **OOD 动作**（out-of-distribution action，分布外动作）。

## 2. 问题：Q 网络在 OOD 动作上会虚高，而且错误会自我放大

### 2.1 第一层：神经网络的外推是不可控的

$Q_\theta(s,a)$ 是一个神经网络。训练它的监督信号只来自数据集里出现过的 $(s,a)$ 对——在我们的例子里只有 $a \in [0.1, 0.3]$ 这一段。对于 $a = 0.9$，网络输出的值完全由它的参数化形式和初始化决定，可能是 $-3$，也可能是 $+50$，没有任何数据约束它。

这本身还不致命。致命的是下一步。

### 2.2 第二层：TD target 里的 max 会专门挑出虚高的那个

标准 Q 学习的 TD target 是

$$
y = r + \gamma \max_{a'} Q_\theta(s', a')
$$

**这个公式在做什么**：估计"当前这一步拿到的奖励，加上从下一个状态出发能拿到的最好的未来回报"，用来当作 $Q_\theta(s,a)$ 的回归目标——这一步的价值 = 立刻到手的奖励 + 打折的"以后最好能拿多少"。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $r$ | **到手的分** | 这一步环境直接给的即时奖励，在本例中是"推完之后杯子离目标近了多少" |
| $\gamma \in [0,1)$ | **未来折扣器** | 把未来的奖励打个折再算进来，典型取 $0.99$ |
| $Q_\theta(s',a')$ | **对未来的乐观猜测** | 网络对"下一状态执行 $a'$ 还能拿多少"的估计 |
| $\max_{a'} Q_\theta(s',a')$ | **贪心的乐观算子** | 在整个动作空间里专门挑网络给出最高分的那个 $a'$，只在 $a\in[0.1,0.3]$ 上被真实数据监督过，其余全靠外推 |

**用人话读**："这一步的目标价值 = 立刻拿到的奖励，加上打折后的、网络认为下一状态能拿到的最好未来回报。"

**为什么是这个形式**：$\max$ 本来是 Q 学习的灵魂——它让 Q 收敛到最优价值而不是行为策略的价值。但 $\max$ 是一个乐观算子：它专门去找当前网络输出最大的那个动作。如果网络的误差是随机的，$\max$ 就会系统性地挑出正向误差最大的那一个，这就是过估计（overestimation）的来源。
:::

假设真实的最优未来价值是 $Q^*(s', a'^*) = 5.0$，但网络在 OOD 动作 $a' = 0.9$ 上因为外推给出了 $Q_\theta(s',0.9) = 12.0$。取 $r = 1.0$, $\gamma = 0.99$：

$$
y = 1.0 + 0.99 \times \max_{a'} Q_\theta(s',a') = 1.0 + 0.99 \times 12.0 = 12.88
$$

**这个公式在做什么**：把上一步的抽象公式代入具体数字，展示外推误差如何把 TD target 实实在在地拉高。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $1.0$ | **本例的即时奖励** | 假设推完杯子这一步拿到的真实奖励 |
| $0.99$ | **本例的折扣因子** | 常用取值，未来打 1% 的折 |
| $\max_{a'}Q_\theta(s',a')=12.0$ | **被网络高估的未来价值** | 网络在 OOD 动作 $a'=0.9$ 上外推出的虚高输出，真实最优值其实只有 $5.0$ |
| $y = 12.88$ | **被污染的回归目标** | 这个虚高的数字接下来会被当作"正确答案"去训练 $Q_\theta(s,a)$ |

**用人话读**："把 1.0 的即时奖励，加上 0.99 倍的、被网络虚高估计成 12.0 的未来价值，得到一个虚高到 12.88 的训练目标。"

**为什么是这个形式**：如果真实最优未来价值是 $5.0$，target 本应是 $1.0+0.99\times5.0=5.95$，但因为 $\max$ 挑中了虚高的 $12.0$，target 被高估了 $6.93$，而这个被污染的数字会通过 bootstrap 一轮轮放大。
:::

### 2.3 第三层：误差会通过 bootstrap 循环放大

刚才那个虚高的 $y = 12.88$ 会被用来训练 $Q_\theta(s,a)$，把 $Q_\theta(s,a)$ 也推高到 12 附近。下一轮迭代，$Q_\theta(s,a)$ 又会作为**别人的** TD target 里的 $\max$ 候选……

在**在线** RL 里这个循环是能自己刹住的：策略去执行 $a=0.9$，环境返回真实的低奖励，数据进 replay buffer，$Q_\theta(s',0.9)$ 被真实数据修正。

在**离线** RL 里没有这个刹车。数据集永远不会新增 $a=0.9$ 的样本，所以虚高值永远不会被纠正，只会一轮轮 bootstrap 放大。最终结果是 Q 值发散到 $10^5$ 量级，策略输出的动作全部集中在数据集边缘之外，实际执行时完全失败。

**这就是 CQL 要解决的唯一问题。**

## 3. CQL 的解法：加一项 loss 主动压低 OOD 动作的 Q 值

思路直接：既然网络在 OOD 动作上虚高，那就在 loss 里明确写一项，**让网络在"策略想选的动作"上输出低值、在"数据里真实出现的动作"上输出高值**。

### 3.1 基础形式

$$
\mathcal{L}_{\text{CQL}}(\theta) = \underbrace{\mathcal{L}_{\text{TD}}(\theta)}_{\text{照常拟合 Bellman}} + \alpha \cdot \underbrace{\left( \mathbb{E}_{s \sim \mathcal{D},\, a \sim \mu}\big[Q_\theta(s,a)\big] - \mathbb{E}_{(s,a) \sim \mathcal{D}}\big[Q_\theta(s,a)\big] \right)}_{\text{保守正则项 } \mathcal{R}(\theta)}
$$

**这个公式在做什么**：在标准 TD loss 之外，额外要求"网络在采样动作上的平均 Q 值"减去"网络在数据动作上的平均 Q 值"这个差值越小越好——数据里做过的动作 Q 值给高一点，数据里没做过的动作 Q 值给低一点。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mathcal{L}_{\text{TD}}(\theta)$ | **老实拟合 Bellman** | 标准 TD 均方误差 $\mathbb{E}[(Q_\theta-y)^2]$，让 Q 数值大致准确，不变，照常算 |
| $\mathbb{E}_{a\sim\mu}[Q_\theta(s,a)]$ | **"策略眼里这个状态有多好"** | 对每个状态 $s$ 从采样分布 $\mu$（可以是当前策略 $\pi$，也可以是均匀分布）里采 $N$ 个候选动作，取 Q 值的蒙特卡洛平均 |
| $\mathbb{E}_{(s,a)\sim\mathcal{D}}[Q_\theta(s,a)]$ | **锚点：实际做过的动作有多好** | 直接用 batch 里真实出现的 $(s,a)$ 算 Q 值，防止整体塌陷到 $-\infty$ |
| $\alpha$ | **保守强度旋钮** | 系数越大，两者之间被拉开的间隙越大，典型取 $0.1\sim10$ |
| $\mathcal{R}(\theta)$ | **数据内外的相对落差** | 采样动作的平均 Q 减去数据动作的平均 Q，这个差值就是要被压小的保守正则项 |

**用人话读**："除了照常让 Q 满足 Bellman 方程，还要求"策略想选的动作"和"数据里真实动作"之间的 Q 值落差越小越好——落差大就说明网络在瞎猜的动作上给了虚高分。"

**为什么是"差"而不是只压低采样项**：如果只写 $+\alpha\,\mathbb{E}_{a\sim\mu}[Q_\theta]$，网络会发现"把所有 Q 值一起压到 $-\infty$"是最优解，Q 函数整体塌缩、失去区分能力。减去数据项相当于加了一个锚：数据动作的 Q 值被往上拉，所以整体不会塌陷，被压低的只是数据动作**相对**的那些 OOD 动作，这是一个相对量而不是绝对量。

**期望怎么近似**：两个期望都是靠 mini-batch 近似的。外层 $s\sim\mathcal{D}$ 就是从 replay buffer 采 $B$ 个状态；内层 $a\sim\mu$ 是对每个状态再采 $N$ 个动作（典型 $N=4\sim10$），所以一次前向要算 $B\times N$ 个 Q 值，这也是 CQL 比普通 TD 学习贵的原因。

**每一项的梯度方向**：$\mathcal{L}_{\text{TD}}$ 把 $Q_\theta(s,a)$ 拉向 target $y$；$+\alpha\,\mathbb{E}_{a\sim\mu}[Q_\theta]$ 系数为正，梯度下降会减小它，即把采样动作上的 Q 值往下压；$-\alpha\,\mathbb{E}_{\mathcal{D}}[Q_\theta]$ 系数为负，梯度下降会增大它，即把数据动作上的 Q 值往上抬。TD 项负责"数值大致对"，后两项负责"数据内 vs 数据外的相对高低对"。
:::

设 batch 里一个状态 $s_0$，数据动作 $a_{\mathcal{D}} = 0.2$，网络当前输出 $Q_\theta(s_0, 0.2) = 5.0$。从 $\mu$ 采了 4 个动作 $\{0.9, -0.7, 0.5, 0.15\}$，网络输出 $\{12.0, 8.0, 6.0, 5.2\}$，平均 $= 7.8$。取 $\alpha = 1.0$：

$$
\mathcal{R}(\theta) = 7.8 - 5.0 = 2.8, \qquad \alpha \cdot \mathcal{R} = 2.8
$$

**这个公式在做什么**：把上面的抽象保守项代入具体数字，展示这一项的梯度会怎样具体地压低虚高 Q 值。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $7.8$ | **采样动作的平均虚高分** | 4 个候选动作 $\{0.9,-0.7,0.5,0.15\}$ 的网络输出 $\{12.0,8.0,6.0,5.2\}$ 的平均值 |
| $5.0$ | **数据动作的真实分** | 网络在数据动作 $a_{\mathcal{D}}=0.2$ 上的输出，作为锚点 |
| $\mathcal{R}(\theta)=2.8$ | **本例的落差** | 采样动作比数据动作"看起来好" 2.8 分，这正是要被压小的量 |

**用人话读**："这一批候选动作平均比数据里的真实动作高出 2.8 分，$\alpha=1$ 时这 2.8 分会原样加进 loss 里去压。"

**为什么是这个形式**：这一项给出的梯度会把 $\{12.0,8.0,6.0,5.2\}$ 这四个值整体往下拽（每个各承担 $1/4$ 的梯度），同时把 $5.0$ 往上抬。几步之后，$Q_\theta(s_0,0.9)$ 会从 12 掉到 5 以下，策略就不再有动机去选 $a=0.9$。
:::

### 3.2 实用形式：用 logsumexp 代替算术平均

基础形式里的 $\mu$ 需要人为指定。CQL 论文最终推荐的版本（论文中称 CQL($\mathcal{H}$)）不指定 $\mu$，而是对 $\mu$ 取最坏情况并加一个熵正则，解析求解之后得到一个非常干净的形式：

$$
\mathcal{R}_{\mathcal{H}}(\theta) = \mathbb{E}_{s\sim\mathcal{D}}\left[ \tau \log \sum_{a \in \mathcal{A}_{\text{samp}}} \exp\!\left(\frac{Q_\theta(s,a)}{\tau}\right) \right] - \mathbb{E}_{(s,a)\sim\mathcal{D}}\big[Q_\theta(s,a)\big]
$$

**这个公式在做什么**：用 logsumexp 代替第一项里的"平均"，得到一个"软最大值"——不再压低所有候选动作的平均值，而是专门压低那个 Q 值最高的候选动作，因为它才是策略真正会选的、也是虚高最严重的那一个。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mathcal{A}_{\text{samp}}$ | **候选动作池** | 采样出来的一小批候选动作，通常 = 随机均匀动作 ∪ 当前策略采样 ∪ 下一状态策略采样 |
| $\tau > 0$ | **软硬度旋钮** | 温度参数，$\tau\to0$ 时退化为严格 $\max$，$\tau\to\infty$ 时趋向算术平均，常取 $1.0$ |
| $\exp(Q_\theta(s,a)/\tau)$ | **指数放大器** | Q 值高的候选权重指数级放大，数值上要配合减最大值防溢出 |
| $\tau\log\sum_a\exp(\cdot/\tau)$ | **软最大值 $\mathrm{LSE}_\tau$** | 几乎只挑候选里 Q 值最高的那个，但保留了对所有候选的梯度 |
| $\mathbb{E}_{(s,a)\sim\mathcal{D}}[Q_\theta(s,a)]$ | **数据锚点** | 和 3.1 节一样，防止整体塌陷 |

**用人话读**："在一批候选动作里，用软最大值近似挑出 Q 值最高的那个，减去数据里真实动作的 Q 值，这个差就是要压小的保守项。"

**为什么是这个形式**：CQL 论文最终推荐的版本（论文中称 CQL($\mathcal{H}$)）不需要人为指定 3.1 节里的采样分布 $\mu$，而是对 $\mu$ 取最坏情况并加一个熵正则，解析求解之后正好得到这个 logsumexp 形式——效果是只惩罚真正被高估的那个动作，不去动那些本来估得还行的动作。
:::

设候选 Q 值为 $\{q_1,\dots,q_K\}$，$q_{\max}$ 是其中最大值，把它提出来可以证明 logsumexp 确实是"软 max"：

$$
\tau \log \sum_k e^{q_k/\tau} = q_{\max} + \tau \log \sum_k e^{(q_k - q_{\max})/\tau}
$$

**这个公式在做什么**：把 $q_{\max}$ 从求和里提出来，证明 logsumexp 相比严格 $\max$ 只会多出一个有界的小量。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $q_{\max}$ | **主导项** | 候选里 Q 值最大的那个，被单独提出来 |
| $e^{(q_k-q_{\max})/\tau}$ | **相对权重** | 每一项都 $\le 1$（因为 $q_k \le q_{\max}$），衡量其他候选比最大值差多少 |
| $\tau\log\sum_k e^{(q_k-q_{\max})/\tau}$ | **溢出的小尾巴** | 介于 $\tau\log1=0$ 和 $\tau\log K$ 之间的一个非负修正量 |

**用人话读**："软最大值 = 严格最大值 + 一个由其他候选贡献的、不会超过 $\tau\log K$ 的小尾巴。"

**为什么是这个形式**：这个代数变形直接给出了下面的误差上界，说明 logsumexp 不会离真正的 $\max$ 太远。
:::

$$
q_{\max} \le \mathrm{LSE}_\tau \le q_{\max} + \tau \log K
$$

**这个公式在做什么**：给出软最大值和严格最大值之间误差的确切范围。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $q_{\max}$ | **下界** | 软最大值永远不会比真正的最大值还小 |
| $q_{\max} + \tau\log K$ | **上界** | 软最大值最多比真正的最大值大这么多，$K$ 是候选个数 |

**用人话读**："软最大值永远夹在'真实最大值'和'真实最大值加一个固定上限'之间，不会离谱地偏离。"

**为什么是这个形式**：这个上界在工程实现里很重要——做数值归一化时，减掉 $\tau\log K$ 就能大致抵消这个系统性偏差。
:::

代入具体数字看看这个偏差有多小：$K=4$，候选 Q 值 $\{12.0, 8.0, 6.0, 5.2\}$，$\tau = 1.0$：

$$
\begin{aligned}
\mathrm{LSE} &= 12.0 + 1.0 \times \log\!\left(e^{0} + e^{-4} + e^{-6} + e^{-6.8}\right) \\
&= 12.0 + \log(1 + 0.0183 + 0.00248 + 0.00111) \\
&= 12.0 + \log(1.0219) = 12.0 + 0.0217 = 12.02
\end{aligned}
$$

**这个公式在做什么**：用本例的 4 个候选 Q 值算出具体的软最大值，验证它确实几乎等于严格最大值。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $e^0, e^{-4}, e^{-6}, e^{-6.8}$ | **四个候选的相对权重** | 分别对应 $\{12.0,8.0,6.0,5.2\}$ 减去最大值 $12.0$ 再除以 $\tau=1$ 取指数 |
| $\log(1.0219)$ | **溢出的小尾巴** | 三个非最大候选贡献的修正量，只有 $0.0217$ |
| $\mathrm{LSE}=12.02$ | **本例的软最大值** | 几乎就等于严格最大值 $12.0$ |

**用人话读**："4 个候选里最大值是 12.0，另外三个候选加起来只把软最大值再往上拉了 0.02，几乎可以忽略。"

**为什么是这个形式**：对比 3.1 节算术平均给出的 $7.8$，logsumexp 给出的 $12.02$ 几乎就是最大值——算术平均版本把梯度平摊到 4 个候选上（每个只分到 $1/4$），而 logsumexp 版本把几乎全部梯度都给了 $a=0.9$（权重 $1/1.0219=0.979$），另外三个几乎不动。这正是我们想要的：只惩罚真正被高估的那个动作。$\mathcal{R}_{\mathcal{H}}$ 的完整值是 $12.02-5.0=7.02$。
:::

## 4. 完整训练循环

把上面拼起来，一次 critic 更新长这样。先说清楚每一步在做什么，再看伪代码。

流程是：从固定数据集采一批转移；用 target 网络算 TD target；为每个状态额外采若干候选动作（随机的 + 策略给的）；对候选算 Q 值做 logsumexp；把保守项加到 TD loss 上；一起反向传播。

```python
# 1. 从固定数据集采 batch
s, a, r, s_next, done = dataset.sample(batch_size=B)

# 2. 标准 TD target（用 target 网络，且不回传梯度）
with torch.no_grad():
    a_next = policy.sample(s_next)                  # 策略在下一状态采动作
    q_next = target_critic(s_next, a_next).min(-1)   # twin-Q 取小，抑制过估计
    y = r + gamma * (1 - done) * q_next

# 3. 数据动作上的 Q 值：既进 TD loss，也当保守项的"锚"
q_data = critic(s, a)                                # [B, 2]
td_loss = (q_data - y.unsqueeze(-1)).square().mean()

# 4. 采候选动作。三路来源缺一不可，见下文解释
a_rand = torch.rand(B, N, act_dim) * 2 - 1           # 均匀随机，覆盖整个动作空间
a_pi   = policy.sample(s,      num=N)                # 当前策略在 s 上的采样
a_pi2  = policy.sample(s_next, num=N)                # 当前策略在 s' 上的采样
cand   = torch.cat([a_rand, a_pi, a_pi2], dim=1)     # [B, 3N, act_dim]

# 5. 保守项：logsumexp(候选) - Q(数据动作)
q_cand = critic(s.repeat_interleave(3*N), cand.flatten(0,1)).view(B, 3*N, 2)
ood_q  = torch.logsumexp(q_cand / tau, dim=1) * tau  # [B, 2]
cql_reg = (ood_q - q_data).mean()

# 6. 合并
loss = td_loss + alpha * cql_reg
loss.backward()
```

**为什么候选动作要三路来源**：

- **均匀随机动作**：覆盖整个动作空间，包括策略当前完全没想到的角落。如果只用策略采样，那些"策略暂时不去、但一旦 Q 虚高就会跑过去"的区域永远压不到。
- **当前状态上的策略采样**：这是策略**现在**最想选的动作，是最紧迫的过估计风险点。
- **下一状态上的策略采样**：这些动作会出现在下一轮的 TD target 里（$\max_{a'}$ 那一项）。提前把它们压住，等价于直接抑制 target 的虚高，效果比等它污染完 target 再修正要好。

**候选数怎么选**：$N$ 是每一路的采样数，总候选数是 $3N$（有些实现还会把数据动作本身也放进候选，变成 $3N+1$）。$N$ 越大保守估计越准，但成本线性增长——$N=4$ 时一次 critic 更新要算 $12B$ 个 Q 值，是普通 TD 的 13 倍。实践中 $N=4\sim10$ 是常见区间。

## 5. CQL 的代价：过度保守

CQL 的保守正则是**无条件**的：它不管一个 OOD 动作实际上是好是坏，一律往下压。这带来两个直接后果。

**后果一：错过比数据更好的动作。** 如果数据集是一个平庸策略采的，真正的好动作恰好落在 OOD 区域，CQL 会把它们和真正的坏动作一起压低。学出来的策略上限被数据集的质量锁死。

**后果二：离线转在线时"爬不回来"。** 这是更严重的问题。离线阶段跑完，Q 函数被系统性压低了一个未知的量（可能整体偏低 5，也可能偏低 50，取决于 $\alpha$、$N$、训练轮数）。切到在线阶段后，Q 值需要重新爬升到真实尺度才能给出有意义的策略梯度。在这段"爬升期"里，Q 值的相对排序是混乱的，策略会被随机的梯度带偏——表现就是**在线一开始成功率直接崩掉**，需要很多环境交互才能恢复。

这两个后果里，第二个是 [Cal-QL](/前置知识/002h_前置知识_CalQL校准保守Q学习) 要解决的问题。Cal-QL 的思路只改一行：**压低 OOD 动作的 Q 值，但不允许压到某个参考值以下**。这个参考值用蒙特卡洛回报给出。

## 6. 与其他离线 RL 方法的对比

| 维度 | CQL | [AWR](/前置知识/000u_前置知识_AWR_优势加权回归) | IQL |
|------|-----|-----|-----|
| 是否训练 Q 网络 | 是 | 不训练（只用优势加权） | 是 |
| 是否查询 OOD 动作 | **是**，主动采样并压低 | 否 | 否，用 expectile 隐式最大化 |
| 额外计算成本 | 高（$3N$ 倍 Q 前向） | 低 | 低 |
| 保守程度 | 可调（$\alpha$） | 最保守 | 中等 |
| 主要超参 | $\alpha$、$N$、$\tau$ | 温度 | expectile $\tau$ |
| 主要失效模式 | 压太狠导致 Q 尺度失真 | 上限被数据策略锁死 | expectile 选不好则过于保守 |
| 是否易于转在线 | 差（需 Cal-QL 修正） | 差 | 中等 |

**什么时候选 CQL**：数据集质量不高、需要 Q 网络后续做在线微调、且能承受 $3N$ 倍的 critic 前向成本。如果只做纯离线且不需要在线阶段，IQL 往往更省事。

## 7. 小结

| 要点 | 内容 |
|------|------|
| 解决的问题 | 离线 RL 中 Q 网络在数据外动作上虚高，且经 bootstrap 自我放大 |
| 核心手段 | TD loss 之外加一项：压低采样动作的 Q、抬高数据动作的 Q |
| 实用形式 | 用 $\tau\log\sum\exp(Q/\tau)$ 代替平均，只惩罚 Q 最高的候选 |
| 候选来源 | 均匀随机 + 当前状态策略采样 + 下一状态策略采样 |
| 关键超参 | $\alpha$（保守强度）、$N$（每路候选数）、$\tau$（温度） |
| 主要代价 | 无条件保守 → Q 尺度被系统性压低 → 离线转在线时会崩 |
| 后续改进 | [Cal-QL](/前置知识/002h_前置知识_CalQL校准保守Q学习) 给保守项加一个 MC 回报下界 |
