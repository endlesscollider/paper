# 分组查询注意力 GQA：用更少的 Key/Value 换更快的推理

> 标准多头注意力里,Query、Key、Value 各有相同数量的"头"。GQA 打破了这个对称性:让多个 Query 头共享同一组 Key/Value。本文讲清楚这样做的动机、具体机制,以及它和 KV-Cache 内存开销之间的直接联系。

## 一、先回顾:标准多头注意力(MHA)的开销在哪

### 1.1 多头注意力的基本结构

标准多头注意力(Multi-Head Attention, MHA)把输入的隐藏向量投影成三组张量:

$$
Q = XW_Q, \quad K = XW_K, \quad V = XW_V
$$

**这个公式在做什么**：把输入的隐藏向量 $X$ 分别过三个不同的线性层，得到后续做注意力计算要用的 Query、Key、Value 三组张量。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $X$ | **输入的隐藏向量** | 上一层输出的特征表示，是 Q/K/V 三个投影共同的原料 |
| $W_Q, W_K, W_V$ | **三把不同的钥匙** | 三个独立的线性变换矩阵，把同一个 $X$ 加工成三种不同用途的表示 |
| $Q = XW_Q$ | **提问者** | 代表"我想找什么信息"，后面拿它去和每个 Key 比对相似度 |
| $K = XW_K$ | **索引标签** | 代表"我这里有什么信息"，用来被 Query 检索匹配 |
| $V = XW_V$ | **实际内容** | 匹配成功后真正被加权取用的内容 |

**用人话读**："同一份输入分别过三个不同的线性层，得到'要查什么'（Q）、'能被怎么查到'（K）、'查到后拿什么'（V）三组张量。"

**为什么是这个形式**：Q/K/V 分离是标准注意力机制的通用设计——把"检索的依据"（K）和"检索到后取用的内容"（V）分开，让模型可以学到"关注什么"和"关注后拿什么信息"两件独立的事，而不是耦合在一起。
:::

然后把 $Q, K, V$ 各自沿隐藏维度切成 $H$ 个"头",每个头独立做一次 Attention,最后把结果拼接起来。这里的 $H$(头数)对 $Q, K, V$ 是**完全相同的一个数字**——每个 Query 头都配备了自己专属的一个 Key 头和 Value 头。

### 1.2 推理时的瓶颈:KV-Cache 占用的显存

在自回归生成场景中(比如 LLM 逐词生成,或者 XR0 的 DiT 逐层缓存 VLM 的中间结果),每生成一个新 token 都要用到**之前所有 token 算好的 Key 和 Value**。为了避免重复计算,系统会把每一层、每一个已生成 token 的 $K, V$ 存下来,这就是 KV-Cache(具体机制见 [KV-Cache 与自回归解码](/前置知识/002m_前置知识_KV_Cache与自回归解码))。

KV-Cache 的显存占用和"KV 头的数量"直接成正比。如果一个模型有 32 个 Query 头,标准 MHA 要求配 32 个 Key 头和 32 个 Value 头,序列越长、层数越多,缓存的 K/V 张量就越大,很容易成为推理时显存的主要瓶颈——尤其是在需要长上下文或者大批量并发推理的场景。

**核心问题**:有没有办法减少需要缓存的 K/V 数量,同时不明显损失模型表达能力?

## 二、GQA 的核心思路:分组共享

### 2.1 一句话直觉

> 把 $H$ 个 Query 头分成 $G$ 组,同一组内的多个 Query 头**共享同一对** Key/Value 头——相当于几个"侦察兵"(Query)共用同一份"情报资料"(K/V),而不是每人各配一份。

### 2.2 三种配置的对比

| 配置名称 | Query 头数 | KV 头数 | 关系 |
|---------|-----------|--------|------|
| **MHA**(标准多头注意力) | $H$ | $H$ | 每个 Query 头独享一对 K/V |
| **GQA**(分组查询注意力) | $H$ | $G$($1 < G < H$) | 每 $H/G$ 个 Query 头共享一对 K/V |
| **MQA**(多查询注意力) | $H$ | $1$ | 所有 Query 头共享同一对 K/V(GQA 的极端情况) |

GQA 是 MHA 和 MQA 之间的一个折中方案:MHA 表达力最强但缓存开销最大,MQA 缓存开销最小但表达力损失较多,GQA 通过调节分组数 $G$ 在两者之间找平衡点。

### 2.3 具体计算过程

给定 $H$ 个 Query 头和 $G$ 个 KV 头($H$ 能被 $G$ 整除),定义分组倍数:

$$
n_{\text{rep}} = \frac{H}{G}
$$

**这个公式在做什么**：算出"每一组 KV 头要被多少个 Query 头共享"，这个数字后面重复扩展 K/V 时要用到。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $H$ | **Query 头总数** | 例如 32，Query 的多样性完全保留 |
| $G$ | **KV 组数** | 例如 8，比 $H$ 少，是要压缩缓存的目标 |
| $n_{\text{rep}} = H/G$ | **组内共享人数** | 每一组 KV 头平均分给多少个 Query 头用，例如 $32/8=4$ |

**用人话读**："Query 头数除以 KV 组数，就是每组 KV 要伺候几个 Query 头。"

**为什么是这个形式**：$H$ 必须能被 $G$ 整除才能让每组内共享的 Query 头数一致，$n_{\text{rep}}$ 这个整数直接决定了后面 `repeat_interleave` 要重复几次。
:::

前向传播分三步:

**第一步:分别投影得到数量不对等的 Q、K、V**

$$
Q \in \mathbb{R}^{B \times H \times S \times d_h}, \qquad K, V \in \mathbb{R}^{B \times G \times S \times d_h}
$$

**这个公式在做什么**：说明 Q 和 K/V 张量的形状故意不对等——Query 保留 $H$ 组头的完整多样性，Key/Value 只用 $G$ 组头，这个"少存一份"就是 GQA 省显存的直接体现。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $B$ | **batch 维度** | 一批处理的样本数 |
| $H$（Q 的头数维度） | **Query 的完整阵容** | 每个 Query 头都独立存在，数量不缩水 |
| $G$（K,V 的头数维度） | **被精简的 KV 阵容** | 比 $H$ 少，是需要缓存和存储的部分 |
| $S \times d_h$ | **序列长度 × 每头维度** | Q/K/V 每个头内部张量的具体大小 |

**用人话读**："Query 张量按 $H$ 个头存，Key/Value 张量只按 $G$ 个头存，$G$ 比 $H$ 小，这就是需要缓存的那部分被精简了。"

**为什么是这个形式**：KV-Cache 的显存占用直接由存下来的 K/V 头数决定，让投影层直接只输出 $G$ 组头（而不是先算出 $H$ 组再丢弃），从参数量和存储量两方面同时省下 $n_{\text{rep}}$ 倍开销。
:::

**第二步:把 K、V 重复扩展到和 Q 头数一致**

$$
K^{\text{rep}} = \text{repeat\_interleave}(K, n_{\text{rep}}, \text{dim=heads}), \qquad V^{\text{rep}} = \text{repeat\_interleave}(V, n_{\text{rep}}, \text{dim=heads})
$$

**这个公式在做什么**：为了让 Attention 的矩阵乘法能逐头对齐，临时把只有 $G$ 组的 K/V 沿头维度重复展开成 $H$ 组——这只是计算时的临时展开，真正存储的缓存依然只有 $G$ 组。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $K, V$ | **原始精简版 KV** | 只有 $G$ 组头，是真正存进缓存的那份数据 |
| $n_{\text{rep}}$ | **复制次数** | 等于 $H/G$，决定每组 K/V 要被"克隆"给几个 Query 头用 |
| $\text{repeat\_interleave}(\cdot)$ | **临时展开器** | 沿头维度把每组 K/V 连续重复 $n_{\text{rep}}$ 次，凑够 $H$ 组 |
| $K^{\text{rep}}, V^{\text{rep}}$ | **计算专用的展开版** | 只在做矩阵乘法这一刻存在，用完即丢，不写回缓存 |

**用人话读**："把只有 $G$ 组的 Key/Value，临时复制成和 Query 一样多的 $H$ 组，好让每个头都能对齐着做矩阵乘法，但真正存下来的缓存还是只有 $G$ 组。"

**为什么是这个形式**：标准 Attention 的 softmax、加权求和要求 Q、K、V 头数一一对应才能逐头做矩阵乘法。用临时重复而不是真的存 $H$ 份，是"计算时对齐、存储时精简"这个设计的关键——存储开销才是 GQA 真正要解决的瓶颈，计算时多算几次矩阵乘法的代价远小于显存代价。
:::

**具体数值例子**:取 $H=8$,$G=2$,$n_{\text{rep}}=4$。原始 $K$ 的头编号是 $[k_0, k_1]$(共 2 个头)。重复扩展后:

$$
K^{\text{rep}} = [k_0, k_0, k_0, k_0, k_1, k_1, k_1, k_1]
$$

**这个公式在做什么**：把上面的抽象公式代入具体数字，直观展示重复展开后 8 个 Query 头对应的 K 头分配情况。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $k_0$（前 4 个位置） | **第 0 组 KV** | 被 Query 头 0-3 共享的那一份 Key |
| $k_1$（后 4 个位置） | **第 1 组 KV** | 被 Query 头 4-7 共享的那一份 Key |
| 展开后的 8 个位置 | **和 Q 头数对齐后的序列** | 每个位置正好对应一个 Query 头，方便逐头做矩阵乘法 |

**用人话读**："8 个 Query 头里，前 4 个都用第一组 Key，后 4 个都用第二组 Key——原本 2 个 Key 被复制成了 8 个位置。"

**为什么是这个形式**：`repeat_interleave` 保证同一组内连续的 Query 头（如头 0-3）拿到同一份 K/V，这样分组的"组"在张量布局上是连续的一段，方便实现和索引。
:::

即 Query 头 0-3 共享 $k_0$,Query 头 4-7 共享 $k_1$。

**第三步:标准 Attention 计算**

$$
\text{Attention}(Q, K^{\text{rep}}, V^{\text{rep}}) = \text{softmax}\left(\frac{Q (K^{\text{rep}})^T}{\sqrt{d_h}}\right) V^{\text{rep}}
$$

**这个公式在做什么**：用展开对齐后的 Q、K、V 做一次标准的注意力计算——算相似度、softmax 归一化、再加权求和取值，和标准 MHA 的公式完全一样。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $Q(K^{\text{rep}})^T$ | **相似度打分** | 每个 Query 和它所在组的 Key 做点积，算出"关注程度"的原始分数 |
| $\sqrt{d_h}$ | **缩放因子** | 防止点积数值随维度增大而爆炸，稳定 softmax 的梯度 |
| $\text{softmax}(\cdot)$ | **归一化器** | 把原始分数转成一组和为 1 的权重 |
| $(\cdot) V^{\text{rep}}$ | **加权取值** | 用归一化后的权重对 Value 做加权求和，得到最终输出 |

**用人话读**："每个 Query 头去和自己那组的 Key 算相似度、归一化成权重，再按权重去取对应的 Value——和标准多头注意力一模一样，只是这里的 K/V 是从更少的原始头复制出来的。"

**为什么是这个形式**：GQA 的设计目标就是"计算逻辑完全不变，只精简存储"——所以这一步直接复用标准 Attention 公式，唯一区别是输入的 $K^{\text{rep}}, V^{\text{rep}}$ 来自更少的原始 K、V。
:::

### 2.4 完整数值走查

假设 $H=8$(Query 头数),$G=2$(KV 头数),$d_h=4$(每头维度),序列长度 $S=1$(只看一个 token,方便手算)。

- Query 头 0 的向量:$q_0 = [1, 0, 0, 0]$
- KV 头 0(被 Query 头 0-3 共享):$k_0 = [1, 0, 0, 0]$,$v_0 = [10, 20, 30, 40]$
- KV 头 1(被 Query 头 4-7 共享):$k_1 = [0, 1, 0, 0]$,$v_1 = [50, 60, 70, 80]$

对 Query 头 0(属于第 0 组,用 $k_0, v_0$):
$$
\text{score} = q_0 \cdot k_0 / \sqrt{4} = (1\times1+0+0+0)/2 = 0.5
$$

**这个公式在做什么**：把第三步的抽象 Attention 公式代入具体数值，手算出 Query 头 0 和它所在组的 Key 之间的相似度分数。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $q_0 \cdot k_0$ | **点积相似度** | $[1,0,0,0]$ 和 $[1,0,0,0]$ 逐元素相乘再求和，算出原始相似度 |
| $\sqrt{4}$ | **缩放因子** | 这里 $d_h=4$，除以 $\sqrt{d_h}$ 防止分数过大 |
| $0.5$ | **最终打分** | 缩放后的相似度分数，会被送进 softmax |

**用人话读**："Query 头 0 和它所在组的 Key 算一次点积、除以维度的平方根，得到一个打分 0.5。"

**为什么是这个形式**：这只是把第三步 $\text{softmax}(QK^T/\sqrt{d_h})V$ 公式里的第一步（算 $QK^T$ 再缩放）用具体数字走一遍，验证公式在真实张量上是怎么运作的。
:::

只有一个 KV 对时 softmax 后权重恒为 1,输出 $=v_0=[10,20,30,40]$。

对 Query 头 4(属于第 1 组,用 $k_1, v_1$)即使 $q_4$ 的数值和 $q_0$ 不同,只要它落在第 1 组,就只会和 $k_1, v_1$ 交互,输出会基于 $v_1=[50,60,70,80]$。

**关键结论**:8 个 Query 头最终产生 8 个不同的输出(因为每个头的 Query 向量不同,即使共享同一个 K/V,attention score 也不同),但整个过程只需要存储和计算 2 组 K/V,而不是 8 组——**这就是显存节省的来源**。

## 三、为什么这样做不会让性能损失太多

### 3.1 直觉解释

Attention 的表达力主要来自于:(1)每个头能学到不同的"查询模式"(体现在 $Q$ 的多样性上);(2)不同头能关注序列中不同的信息(体现在 $K, V$ 提取到的特征上)。GQA 保留了 $Q$ 的完全多样性(仍然是 $H$ 个独立的 Query 头),只压缩了 $K, V$ 的多样性。经验上,多个 Query 头共享同一份"被检索的内容"(K/V)但仍能各自算出不同的注意力权重分布,信息损失比想象中小。

### 3.2 分组数 $G$ 的选择是一个权衡

| $G$ 的取值 | 效果 |
|-----------|------|
| $G=H$(即 MHA) | 表达力最强,KV-Cache 最大 |
| $G$ 适中(如 $H/4$) | 表达力小幅下降,KV-Cache 减少到 $1/4$ |
| $G=1$(即 MQA) | KV-Cache 最小,但表达力损失相对更明显 |

实践中 $G$ 通常取 $H$ 的 $1/4$ 到 $1/8$,在几乎不损失下游任务效果的前提下,把 KV-Cache 压缩到很小的比例。

### 3.3 XR0 中的具体配置

XR0(Xiaomi-Robotics-0)的 DiT 动作头里,`DiTAttention` 模块的构造参数是 `hidden_size=1024, head_dim=128, kv_heads=8`,算出 Query 头数为 $1024/128=8$。也就是说在这个具体配置下 $H=G=8$,退化为标准 MHA;但代码框架本身按 GQA 的通用形式实现(`kv_group = num_heads // kv_heads`,当 `kv_heads` 设为比 `num_heads` 更小的值时即可启用真正的分组共享),这样设计是为了在不同规模的模型变体之间复用同一套 Attention 实现,具体细节参见 [XR0 深度解析 - DiT 动作头架构](/系列/xr0_deep_dive/05_DiT动作头架构_AdaLN与GQA跨注意力)。
