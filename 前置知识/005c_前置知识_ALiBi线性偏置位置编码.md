# 前置知识：ALiBi——用线性偏置代替位置编码

> **一句话**：ALiBi（Attention with Linear Biases，线性偏置注意力）不给 token 生成任何位置向量，而是在算 Attention 分数的最后一步，直接给每一对 Query-Key 加上一个"惩罚项"——两个 token 隔得越远，惩罚越重。这个惩罚项是一条固定的直线（线性），不含任何需要训练的参数，却让模型在训练时只见过几百个 token 的情况下，测试时能稳定处理几千个 token。

## 贯穿全文的例子

> **场景**：一个语言模型在训练阶段，每次输入的文本片段固定切成 512 个 token（受显存和训练成本限制，不能无限长）。模型上线后要处理的是真实文档——技术手册、法律合同、长对话记录——长度经常超过 2000 甚至 8000 个 token。模型在训练时"没见过"这么长的输入，但推理时必须应对。本文所有机制都会用"训练用 512 token、推理遇到 2048 token"这个具体场景反复演算。

## 一、要解决的问题：位置编码为什么会在长序列上失效

### 1.1 先回顾问题的起点

[标量条件编码前置知识](/前置知识/001s_前置知识_标量条件编码_位置编码与时间步嵌入#二概念阶段之一正弦位置编码transformer的原始方案) 讲过，Transformer 原始论文用正弦函数给每个位置生成一个固定的编码向量，加到 token 的 embedding 上。这个向量之后会参与 Query/Key 的计算，让 Attention 分数间接携带"这两个 token 隔多远"的信息。

问题出在"间接"这个词上。位置向量和内容向量（token embedding）在输入端就已经**加在一起**，之后这个混合向量要经过若干层的线性变换、非线性激活才能变成最终的 Query 和 Key。位置信息和内容信息从第一层开始就纠缠在一起，网络必须**自己学会**怎么从这个混合信号里分离出"相对距离"这个有用的成分。理论上，因为正弦函数是周期性的、光滑的，网络确实有可能学到这种分离规律，但网络的训练数据只覆盖了 $[0, 512)$ 这个范围内的位置组合——它从来没有见过"位置 3000 和位置 3050 应该表现得和位置 30 和位置 80 类似"这种情况需要外推。

> **一句话说清问题本质**：位置编码是一个函数 $f(\text{pos})$，理论上对任意 $\text{pos}$ 都有定义，但网络用来处理 $f(\text{pos})$ 的那些权重，只在训练时见过的 $\text{pos}$ 范围内被调教过。超出这个范围后，$f(\text{pos})$ 的数值依然存在，可网络对这个数值的**反应**是没有训练过的、不可预测的。

### 1.2 具体验证：ALiBi 论文的实测数据

ALiBi 论文（Press, Smith & Lewis, "Train Short, Test Long: Attention with Linear Biases Enables Input Length Extrapolation", ICLR 2022）在 WikiText-103 数据集上做了直接实验：用正弦位置编码训练一个 16 层、1024 维的 Transformer 语言模型，训练时输入长度固定为 $L=512$ 个 token，之后在验证集上把输入长度 $L_{valid}$ 逐渐加长，观察困惑度（perplexity，语言模型预测下一个词的"意外程度"，数值越低说明模型预测得越准）的变化：

| 评估长度 $L_{valid}$ | 512（等于训练长度） | 612 | 812 | 1512 | 3512 |
|---|---|---|---|---|---|
| 正弦位置编码困惑度 | 20.05 | 20.59 | 30.82 | 76.23 | 178.97 |

数字很直观：刚超过训练长度一点（612 比 512 多 100 个 token），困惑度已经从 20.05 恶化到 20.59；长度翻三倍（1512）时困惑度暴涨到 76；长度翻七倍（3512）时困惑度接近 179——是原来的 9 倍，模型已经基本"看不懂"这么长的文本了。

这不是这一个正弦编码实现的偶然问题。用另一种相对位置编码方案 [RoPE](/前置知识/002k_前置知识_RoPE旋转位置编码) 重跑同一个实验，结果同样会随着序列变长而明显退化，只是退化的起点比正弦编码稍晚一些——具体对比见 [长度外推前置知识](/前置知识/005d_前置知识_长度外推与位置编码分布外泛化) 的第二节表格。**这说明问题不是某个具体公式写错了，而是"把位置信息和内容信息混在一起、再靠网络自己学习外推"这整条路线的通病。**

## 二、ALiBi 的核心设计：把位置信息挪到 Attention 分数上，用直线惩罚代替编码

### 2.1 设计思路的转变

ALiBi 的做法和前面所有方法都不同：**它完全不生成任何位置向量，也不修改 Query/Key 向量本身**。它做的事情只有一件——在算完 Query 和 Key 的点积之后，**直接给这个点积结果加一个数**，这个数只取决于两个 token 的相对距离，越远这个数越负（惩罚越重）。

回顾标准 Attention（[Cross-Attention 前置知识](/前置知识/001e_前置知识_Cross_Attention与交替注意力机制) 有完整推导）中，位置 $i$ 处的 Query 和前面所有 Key 计算相关度分数：

$$
\text{softmax}(\mathbf{q}_i \mathbf{K}^\top)
$$

**这个公式在做什么**：这是标准 Attention 打分的原始形式，只用来做对比基准——纯粹由内容决定相关度，不含任何位置信息。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mathbf{q}_i$ | **当前位置的 Query** | 第 $i$ 个 token 用来"提问"的向量 |
| $\mathbf{K}^\top$ | **所有历史 Key 的转置** | 和 $\mathbf{q}_i$ 做点积，算出和每个历史位置的相关度 |
| $\text{softmax}(\cdot)$ | **归一化** | 把相关度打分转成加起来等于 1 的注意力权重 |

**用人话读**："标准做法里，注意力权重只由内容的相关度决定，完全不看两个 token 隔了多远。"

**为什么要先列出这个公式**：作为下面 ALiBi 改动的参照基准——ALiBi 唯一的改动就是在这个基础上加一项距离惩罚，下面立刻对比。
:::

ALiBi 把这一步改成：

$$
\text{softmax}\big(\mathbf{q}_i \mathbf{K}^\top + m \cdot [-(i-1), \ldots, -2, -1, 0]\big)
$$

**这个公式在做什么**：在原始的相关度分数上，额外加一个"距离越远、惩罚越重"的固定偏置——离得近的 Key（比如就是自己，偏置为 0）几乎不受影响，离得越远的 Key，被加上的负数越大，softmax 之后自然分配到的注意力权重就越小。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mathbf{q}_i \mathbf{K}^\top$ | **原始相关度打分表** | 和标准 Attention 完全一样，纯粹由内容决定"这个 Query 和每个 Key 有多相关"，不含任何位置信息 |
| $[-(i-1), \ldots, -2, -1, 0]$ | **距离量表** | 一个长度为 $i$ 的向量，最后一位是 0（Key 就是自己，距离为 0），从右往左每往前一位距离多 1，绝对值 = 相对距离 |
| $m$ | **每个头独有的惩罚力度旋钮** | 一个固定不变的标量（不是训练出来的），$m$ 越大，同样的距离被扣的分越多，这个头就越"短视" |
| $m \cdot [-(i-1),\ldots,0]$ | **线性惩罚项** | 距离量表乘上惩罚力度，得到这一层这个头对每个位置的具体扣分数值——是关于距离的一次函数（直线） |
| $\mathbf{q}_i\mathbf{K}^\top + m\cdot[\ldots]$ | **打过折扣的相关度** | 原始相关度减去一个和距离成正比的数，越远的 Key 被扣得越惨 |
| $\text{softmax}(\cdot)$ | **归一化成权重** | 和标准 Attention 完全一样，把打过折扣的分数变成加起来等于 1 的注意力权重 |

**用人话读**："算完'这两个 token 有多相关'之后，再看它们隔了多远——隔得越远，就在相关度上扣掉一个和距离成正比的分数，隔得近的基本不扣，隔得远的可能被扣到几乎没有注意力权重。"

**为什么是这个形式**：用"减去一个和距离线性相关的数"而不是"编码一个位置向量再让网络自己学"，是因为这个惩罚项**根本不需要学**——它是一个固定公式，套用到任意长度的序列上都成立，10 个 token 和 10000 个 token 用的是同一条直线规则。网络不需要"记住"训练时见过的位置范围，因为这条规则本来就没有"范围"这个概念，天然对任意距离都有定义、都表现一致。这正是长度外推能力的来源。
:::

### 2.2 和标准 Attention 唯一的区别：加法偏置矩阵

具体到实现层面，ALiBi 修改的地方极小：Transformer 计算因果注意力（causal attention，即每个位置只能看到自己和之前的位置，见 [Causal Attention 前置知识](/前置知识/001g_前置知识_Causal_Attention因果注意力掩码)）时，本来就要用一个"掩码矩阵"把未来位置的分数设为 $-\infty$，softmax 之后自然变成 0。ALiBi 只是把这个掩码矩阵从"只有 0 和 $-\infty$ 两种取值"换成"过去的位置按距离线性递减、未来位置仍是 $-\infty$"。这意味着：

- **不增加任何可训练参数**：$m$ 是提前算好、固定不变的常数，训练过程中从不更新。
- **不增加计算量**：原来就要做加法掩码，现在换一套数字做同样的加法操作，运行速度几乎不受影响。
- **完全不需要位置向量**：输入端的 token embedding 里不再叠加任何位置信息，Query 和 Key 的计算方式和内容本身没有变化。

### 2.3 数值例子：走一遍完整计算

延续本文开头的例子。假设某个头的惩罚力度 $m = 1/8$，当前 Query 在位置 $i=10$，要看前面 4 个 Key（位置 7、8、9、10 自己），原始点积分数（内容相关度）分别是 $[2.0, 1.5, 3.0, 2.5]$：

- 距离量表：位置 10 到位置 7、8、9、10 的距离分别是 $3, 2, 1, 0$
- 惩罚项：$m \times [-3,-2,-1,0] = 1/8 \times [-3,-2,-1,0] = [-0.375, -0.25, -0.125, 0]$
- 加完偏置的分数：$[2.0-0.375,\ 1.5-0.25,\ 3.0-0.125,\ 2.5-0] = [1.625,\ 1.25,\ 2.875,\ 2.5]$
- 过 softmax 之后（近似计算）：权重大约是 $[0.17,\ 0.12,\ 0.53,\ 0.39]$（未归一化前的相对大小关系；实际数值需要对这四个数整体做 softmax 归一化，这里只是说明"扣分之后排序可能变化，但整体上距离近的项在同等内容相关度下更占优）

注意距离为 3 的位置 7，即使内容相关度本身不低（2.0），也被扣掉了 0.375 分；而距离为 0 的位置 10（自己）完全不受影响。这就是"隔得越远，先天就吃亏"这句话的具体体现。

## 三、斜率 $m$ 怎么定：几何序列分配，不是均匀分配

### 3.1 为什么每个头要用不同的斜率

Transformer 的每一层都有多个 Attention 头（比如 8 个头、16 个头），每个头独立计算一套 Attention。ALiBi 给**每个头分配一个不同的 $m$**——有的头 $m$ 大（惩罚陡峭，只关注邻近的 token，像个"近视眼"），有的头 $m$ 小（惩罚平缓，能看到很远的 token，像个"远视眼"）。这样整个模型同时具备"看近处细节"和"看远处大局"的能力，而不是所有头都用同一种视野。

### 3.2 具体公式：几何序列

对于有 $n$ 个头的模型，ALiBi 论文给出的斜率集合是从 $2^{-8/n}$ 开始、公比同样是 $2^{-8/n}$ 的几何序列：

$$
m_k = 2^{-\frac{8k}{n}}, \qquad k = 1, 2, \ldots, n
$$

**这个公式在做什么**：给 $n$ 个头分配 $n$ 个不同的惩罚斜率，这些斜率不是均匀分布（等差），而是按倍数递减（等比）——第一个头的斜率最大（视野最窄），后面每个头的斜率是前一个的固定倍数（越来越平缓，视野越来越宽）。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $n$ | **头的总数** | 比如常见的 8 或 16 |
| $8/n$ | **步长的基准指数** | 决定整个几何序列跨越的范围，$n$ 越大，每一步的间隔越细密 |
| $2^{-8k/n}$ | **第 $k$ 个头的斜率** | $k$ 从 1 数到 $n$，$k$ 越大斜率越小（越平缓） |
| $m_k$ | **这个头专属的惯用视野宽度** | 数值本身在训练前就定好，训练过程中不再改变 |

**用人话读**："把 $n$ 个头的'视野宽度'按照倍数关系（不是等距关系）从窄排到宽——第一个头几乎只看紧邻的几个字，最后一个头能把整段惩罚放得很轻，照顾到很远的位置。"

**为什么用几何序列而不是等差序列**：论文作者做过一轮针对不同斜率组合的实验，发现效果最好的斜率集合有一个共同特征——所有斜率都落在 $(0,1)$ 区间内，并且越靠近 0 的地方，斜率分布得越密集（也就是"平缓型"的头比"陡峭型"的头更多，且相邻平缓头之间的差异很小）。几何序列正好天然满足这个"越靠近 0 越密集"的分布规律。反过来，如果每个头的斜率去训练学出来（而不是固定几何序列），论文的实验显示效果反而不如固定方案——这说明"多头各自负责不同惧远近程度"这个先验设计本身就是有效的，不需要靠数据去学。
:::

**具体数值例子**：8 个头（$n=8$）时，$8/n = 1$，斜率序列就是 $2^{-1}, 2^{-2}, \ldots, 2^{-8}$，也就是 $\frac{1}{2}, \frac{1}{4}, \frac{1}{8}, \frac{1}{16}, \frac{1}{32}, \frac{1}{64}, \frac{1}{128}, \frac{1}{256}$。第一个头（$m=1/2$）距离每远 1 个 token 就扣 0.5 分，扣分速度很快；最后一个头（$m=1/256$）距离远 100 个 token 才扣掉 $100/256 \approx 0.39$ 分，几乎不受距离影响。

下图画出了这 8 个头各自的惩罚曲线（横轴是相对距离，纵轴是被加到 Attention 分数上的偏置值，全部是负数或 0）：

![ALiBi 不同头的线性惩罚曲线——斜率越大惩罚越陡峭](/alibi_linear_bias_slopes.png)

> 图中每条直线对应一个头，斜率从 $1/2$ 到 $1/256$ 按几何级数递减。可以看到最陡的头（红色）在距离 20 左右惩罚就已经把分数拉到 $-10$ 以下（softmax 后几乎不再关注这么远的 token），而最平缓的头（粉色虚线）在距离 128 时惩罚才刚过 $-0.5$，视野覆盖了几乎整段输入。**这种"多头各自负责不同远近尺度"的设计，和 [RoPE 用多个不同频率的旋转组合覆盖不同粒度位置信息](/前置知识/002k_前置知识_RoPE旋转位置编码#31-为什么要多个频率) 的思路是相通的——两者都是用多组参数各自负责不同的"距离尺度"，只是 RoPE 靠旋转频率区分尺度，ALiBi 靠惩罚斜率区分尺度。

## 四、为什么这个设计天然支持长度外推

### 4.1 关键性质：惩罚函数本身没有"训练范围"这个概念

ALiBi 的惩罚项 $m \cdot (i-j)$ 是一个纯粹的数学公式，对任意整数距离 $(i-j)$ 都有定义，不需要查表、不需要经过任何在训练时才调整过的参数。距离为 50 的惩罚和距离为 50000 的惩罚，用的是完全同一条直线公式，唯一的区别是数值大小——距离越大，惩罚越重，这个"越远越不受关注"的**趋势**在任意距离下都成立，不存在"超出这个范围公式就失效"的边界。

对比正弦位置编码：公式本身也对任意位置有定义，但**网络处理这个编码的权重**只在训练时见过的位置范围内被调教过。ALiBi 不需要网络"处理"位置信息——惩罚是直接加在最终分数上的，不经过任何可训练的权重矩阵。**这才是外推能力的真正来源：不是"公式适用范围更广"，而是"压根不存在需要泛化的可训练环节"。**

### 4.2 具体的外推效果数字（已用 web 搜索核实原论文数据）

延续本文开头例子（训练长度 512 token），ALiBi 论文的 WikiText-103 实验实测数据：

| 评估长度 $L_{valid}$ | 512（训练长度） | 1012 | 1512 | 2512 | 3512（7 倍训练长度） |
|---|---|---|---|---|---|
| 正弦位置编码困惑度 | 20.05 | 43.54 | 76.23 | 132.41 | 178.97 |
| ALiBi 困惑度（训练长度 512） | 19.73 | **18.73**（全表最优） | 18.52 | 18.41 | 18.40 |

注意 ALiBi 一栏的困惑度不仅没有随长度增加而恶化，反而在超出训练长度之后**持续下降**，在 7 倍训练长度处依然保持 18.40，明显优于正弦编码在自己训练长度（512）时的 20.05。论文另给出一个更直观的对比：用 ALiBi 训练一个 13 亿参数模型，输入长度只用 1024 token，测试时外推到 2048 token，困惑度和"直接用 2048 token 训练的正弦编码模型"打平，但**训练速度快 11%，显存少用 11%**——因为 ALiBi 模型全程只需要处理长度 1024 的序列，Attention 矩阵天然小一半。

需要说明的是，ALiBi 的性能提升并非无限——论文的分析实验（用滑动窗口评估排除"早期 token 诅咒"这一混杂因素后）发现，ALiBi 在超出训练长度后困惑度持续下降的现象，主要原因是**长序列减少了"序列开头缺乏上文"的预测困难**，而不是模型真的学会了利用比训练时更长的历史依赖关系。换句话说，ALiBi 保证的是"外推时不崩溃、性能稳定甚至略有提升"，但不代表模型能凭空"理解"训练时从未见过的超长距离结构。这个细节在 [ALiBi 论文精读](/论文综述/105_ALiBi_线性偏置位置编码长度外推#五附录分析为什么alibi外推有效) 中有更详细的展开。

### 4.3 ALiBi 的代价：不是没有缺点

- **强烈的"就近偏好"（recency bias）**：因为惩罚项永远是负的且随距离线性增长，模型天然倾向于更关注邻近的 token，这对某些需要精确捕捉远距离依赖的任务（比如要求精确检索几千 token 之前一个具体事实）可能不是最优选择——这也是后续 [NoPE](/前置知识/005d_前置知识_长度外推与位置编码分布外泛化#四nope完全不加位置编码) 等方法探讨的方向。
- **偏置矩阵本身随头数增加占用的显存**：虽然运行时几乎不增加计算量，标准实现下 ALiBi 需要存储一个 $n \times L \times L$ 的偏置矩阵（$n$ 是头数），比原始 attention mask 的 $L \times L$ 略大，论文实测这部分额外显存开销在 0–0.7% 之间，基本可以忽略。
- **外推有一个实际上限**：论文观察到性能通常在大约 2 倍训练长度处达到最佳，之后虽然不崩溃，但也不再持续改善，到几万 token 量级时同样会遇到瓶颈——这属于"长度外推"这个更大问题里"退化速度慢"和"完全不退化"的区别，详见 [长度外推前置知识](/前置知识/005d_前置知识_长度外推与位置编码分布外泛化)。

## 五、工程实操阶段：ALiBi 怎么接入一个标准 Transformer

### 5.1 核心改动只有一处：Attention 里加偏置矩阵

因为 ALiBi 不需要修改 token embedding、不需要修改 Query/Key/Value 的线性投影，接入一个已有的 Transformer 实现只需要在计算 Attention 分数之后、softmax 之前插入一步加法。下面这段代码展示最核心的逻辑——先按 3.2 节的几何公式算出每个头的斜率，再构造一个和"距离"相关的偏置矩阵加到原始分数上：

```python
import torch

def get_alibi_slopes(n_heads: int) -> torch.Tensor:
    """按几何序列计算每个头的斜率 m_k = 2^(-8k/n)，对应本文第 3.2 节公式。"""
    start = 2 ** (-8 / n_heads)
    # ratio 和 start 相同，构成几何序列
    slopes = torch.tensor([start ** (k + 1) for k in range(n_heads)])
    return slopes  # shape: (n_heads,)

def build_alibi_bias(n_heads: int, seq_len: int) -> torch.Tensor:
    """构造形状为 (n_heads, seq_len, seq_len) 的偏置矩阵。
    bias[h, i, j] = -slopes[h] * (i - j)，仅在 j <= i（因果掩码范围内）有意义。
    """
    slopes = get_alibi_slopes(n_heads)                       # (n_heads,)
    # distance[i, j] = i - j，i 是 query 位置，j 是 key 位置
    positions = torch.arange(seq_len)
    distance = positions[:, None] - positions[None, :]        # (seq_len, seq_len)
    distance = distance.clamp(min=0).float()                  # 只惩罚"过去"的 key，未来会被因果掩码单独处理
    bias = -slopes[:, None, None] * distance[None, :, :]      # (n_heads, seq_len, seq_len)
    return bias
```

**代码里值得注意的两行**：`get_alibi_slopes` 里的几何序列写法直接对应第 3.2 节公式 $m_k = 2^{-8k/n}$——用 `start ** (k+1)` 而不是循环乘法，是因为几何序列的第 $k$ 项本来就等于首项的 $k$ 次幂；`build_alibi_bias` 里的 `distance.clamp(min=0)` 是因为标准因果注意力已经会用 $-\infty$ 掩盖掉"未来"的位置（$j>i$），这里只需要确保"过去"的位置（$j\le i$）拿到正确的距离值，不需要额外处理未来位置的距离符号。

### 5.2 接入 Attention 计算的位置

这个偏置矩阵在实际前向传播中，只需要在算完 $\mathbf{q}_i\mathbf{K}^\top$ 之后、做 softmax 之前，直接加到分数矩阵上——和已有的因果掩码加在一起：

```python
def attention_with_alibi(q, k, v, alibi_bias, causal_mask):
    # q, k, v: (batch, n_heads, seq_len, head_dim)
    # alibi_bias: (n_heads, seq_len, seq_len)，第 5.1 节算好的偏置
    scores = q @ k.transpose(-2, -1) / (q.shape[-1] ** 0.5)   # 标准 Attention 打分，见前置知识 001e
    scores = scores + alibi_bias.unsqueeze(0)                 # 加 ALiBi 偏置：本文第二节公式的核心一步
    scores = scores.masked_fill(causal_mask, float('-inf'))   # 标准因果掩码，屏蔽未来位置
    weights = torch.softmax(scores, dim=-1)
    return weights @ v
```

**这一步的关键**：`scores + alibi_bias` 这一行就是整篇文章讲的公式 $\mathbf{q}_i\mathbf{K}^\top + m\cdot(i-j)$ 在代码里的落地——除了这一次加法，`attention_with_alibi` 和标准 Attention 实现（[Cross-Attention 前置知识](/前置知识/001e_前置知识_Cross_Attention与交替注意力机制) 里的代码）没有任何区别，这也是论文强调"几行代码就能接入现有 Transformer"的原因。

### 5.3 推理时如何"外推"到更长序列

因为 `build_alibi_bias` 函数本身接受任意 `seq_len` 作为参数，推理时想处理比训练时更长的输入，只需要用更大的 `seq_len` 重新调用这个函数生成一个更大的偏置矩阵——不涉及任何权重的重新训练或插值操作，这也是 ALiBi 相比 [RoPE 的 NTK-aware/YaRN 插值技巧](/前置知识/005d_前置知识_长度外推与位置编码分布外泛化#32-rope的外推改进ntk-aware与yarn) 简单得多的地方：RoPE 外推需要额外的频率插值策略来缓解性能下降，ALiBi 的偏置公式则是"天生"就对任意长度成立，不需要额外补丁。

## 六、总结对比

| 维度 | 正弦位置编码 | RoPE | ALiBi |
|------|------------|------|-------|
| 位置信息注入方式 | 加到 token embedding 上 | 旋转 Query/Key 向量 | 直接加到 Attention 分数上 |
| 是否需要训练参数 | 不需要 | 不需要 | 不需要 |
| 每层是否重新注入位置信息 | 只在输入端注入一次 | 每层都重新注入 | 每层都重新注入 |
| 是否修改 Value 向量 | 是（间接，通过混合embedding） | 否 | 否 |
| 长度外推能力 | 差（超出训练长度几十个 token 就开始退化） | 中等（可延伸到 2 倍左右训练长度） | 强（可维持到 6-8 倍训练长度不崩溃，且常有性能提升） |
| 额外计算/显存开销 | 几乎没有 | 需要额外的 cos/sin 计算 | 几乎没有（0-0.7% 额外显存） |
| 典型代表 | 原始 Transformer、GPT-2 | LLaMA、Qwen、GPT-J | BLOOM、MPT |
