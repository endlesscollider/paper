## 贯穿全文的例子

> **设定**：一个 7B VLA 模型（冻结主干），需要依次学习 10 个操作任务：
>
> | 任务编号 | 描述 | 到达顺序 |
> |---------|------|---------|
> | T1 | 抓取红色方块 | 第 1 个 |
> | T2 | 推蓝色圆柱 | 第 2 个 |
> | T3 | 抓取绿色球 | 第 3 个 |
> | T4 | 拧开瓶盖 | 第 4 个 |
> | ... | ... | ... |
>
> 注意 T3（抓绿球）和 T1（抓红块）都是"抓取"类任务——它们应该共享某些技能知识。TOPIC 的任务关系图会发现这一点，让 T3 的 prompt 从 T1 的 prompt 初始化，实现正向迁移。

## 一、问题：持续动作学习的三大挑战

### 1.1 挑战一：遗忘（Forgetting）

学了 T3 后，T1 的成功率不能下降。这是持续学习的基本要求。

### 1.2 挑战二：正向迁移（Forward Transfer）

学 T3 时应该利用 T1 的"抓取"经验，而不是从头学。如果方法只防遗忘但不迁移，学新任务就太慢。

### 1.3 挑战三：任务路由（Task Routing）

推理时，模型必须知道当前在执行哪个任务，才能激活正确的 prompt。如果语言指令有歧义，路由就成问题。

**现有方法的取舍**：

| 方法 | 防遗忘 | 正向迁移 | 任务路由 |
|------|--------|---------|---------|
| [EWC](/前置知识/000w_前置知识_EWC弹性权重巩固) | ✓ | ✗ | 不需要 |
| Replay | ✓ | 有限 | 不需要 |
| 独立 Adapter | ✓✓ | ✗ | 需要 task ID |
| TOPIC (本文) | ✓✓ | ✓✓ | 自动路由 |

## 二、核心思路：在 VLA 系统中的位置与作用

### 2.1 TOPIC 和 VLA 模型的关系——先讲清楚整体图景

在深入组件之前，先弄清楚 TOPIC 的三个组件**在 VLA 系统中扮演什么角色、在哪个位置、什么时候用**：

```mermaid
flowchart LR
    subgraph VLA模型["VLA 模型（7B，完全冻结）"]
        direction TB
        V1["视觉编码器"]
        V2["语言编码器"]
        V3["Transformer Backbone"]
        V4["Action Head"]
        V1 --> V3
        V2 --> V3
        V3 --> V4
    end
    
    subgraph TOPIC["TOPIC 的三个组件"]
        direction TB
        P["① Prompt Pool\n（插在 backbone 输入端）\n每任务一组可训练向量"]
        G["② Task Relation Graph\n（离线维护的数据结构）\n记录任务间相似度"]
        I["③ Graph-guided Init\n（新任务训练开始前）\n用相似旧任务初始化新 prompt"]
    end
    
    P -->|"拼接在输入序列前面"| V3
    G -->|"决定从哪个旧 prompt 初始化"| I
    I -->|"给出新 prompt 的初始值"| P
```

**关系说清楚**：

| 组件 | 和 VLA 的关系 | 在哪个阶段使用 | 为什么需要它 |
|------|-------------|-------------|------------|
| Prompt Pool | 插在 VLA backbone 输入端——唯一可训练的部分，backbone 完全冻结 | 训练时学习新 prompt，推理时选择对应 prompt | 冻结 backbone 防遗忘，prompt 承担适应新任务的职责 |
| Task Relation Graph | 独立于 VLA 的辅助数据结构，不参与 forward/backward | 每个任务训练完后更新图；新任务到来时查图 | 知道"哪些旧任务和新任务相似"，才能做有针对性的知识迁移 |
| Graph-guided Init | 新任务训练**开始前**执行一次 | 仅在新任务启动训练那一刻 | 如果新 prompt 随机初始化，就浪费了旧任务已有的知识；从相似任务复制过来可以加速 3-7 倍 |

**用大白话讲整个流程**：

1. VLA 模型本身 7B 参数全部冻结——它是一个"固定的大脑"
2. 每个任务有自己的"小纸条"（prompt，约 80K 参数），贴在大脑输入端
3. 训练新任务时，只训练这张纸条，大脑不动 → 旧任务不受影响
4. 关键创新：新任务的纸条不是空白的——TOPIC 查一张"任务关系图"，找到最相似的旧任务，把旧纸条抄过来当初始值
5. 这样新任务从"已经会做类似事情"的状态开始学，而不是从零开始

### 2.2 方法流程总览

```mermaid
flowchart TB
    D["新任务 T_k 到来"] --> B["查 Task Relation Graph\n找最相似旧任务 T_j"]
    B -->|"找到 T_j"| C["Graph-guided Init:\nprompt_k = prompt_j + 小噪声"]
    C --> A["训练：冻结 VLA backbone\n只训练 prompt_k（80K参数）"]

    F --> D
```

## 三、组件一：Task-Specific Prompt（和 VLA 的关系：插在输入端的可训练小模块）

### 3.1 设计初衷：为什么要用 Prompt

标准 VLA 学新任务的方式是微调参数（SFT / RL）。但微调会改变 backbone 参数 → 旧任务被覆盖 → 遗忘。

**TOPIC 的解法**：**根本不动 backbone**——转而在输入端插入一小组可学习向量（prompt）。这些向量随着训练学会"引导"冻结的 backbone 完成特定任务。

**类比**：大脑（backbone）不变，但每次做不同任务时戴上不同的"AR 眼镜"（prompt）——眼镜改变了大脑看到的信息，从而引导出不同行为。

### 3.2 Prompt 在 VLA 前向传播中的位置

在 Transformer 的输入序列前面插入 $L$ 个可学习的"虚拟 token"（prompt）：

$$
\text{输入} = [\underbrace{p_1, p_2, ..., p_L}_{\text{可学习 prompt（只有这部分参与梯度更新）}}, \underbrace{o_1, o_2, ..., o_N}_{\text{观测 token（来自视觉+语言编码器）}}]
$$

**这个公式在做什么**：把一组可训练的"虚拟 token"拼在真实观测 token 前面，一起送进冻结的 Transformer——这些虚拟 token 就是 prompt，是整个模型里唯一会被更新的部分。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $p_1, ..., p_L$ | **可训练的小纸条** | $L$ 个可学习向量，梯度只流向这里，负责把冻结的 backbone "引导"到当前任务上 |
| $o_1, ..., o_N$ | **真实观测** | 视觉编码器和语言编码器输出的 token，代表当前时刻机器人看到的画面和收到的指令 |
| $[\cdot,\cdot]$（拼接） | **序列拼接** | 把 prompt 和观测首尾相连组成一条更长的输入序列，一起喂给 self-attention |

**用人话读**："在真正的观测 token 前面加一小段可训练的'引导词'，剩下的模型全部冻结不动。"

**为什么放在序列最前面**：self-attention 里每个 token 都能看到其他所有 token，放在最前面并不影响它能否影响后续 token 的表示——效果上等价于给整段输入加了一层可学习的"任务上下文"。
:::

每个 $p_i \in \mathbb{R}^d$ 是一个 $d$ 维向量（和 token embedding 同维度）。**训练时只更新这 $L$ 个向量，VLA 的所有其他参数完全冻结。**

Transformer backbone 照常做 self-attention，但由于 prompt token 参与了 attention 计算，它们会影响所有后续 token 的表示——相当于一种"软性条件化"。

**参数量对比**：
- 全参数微调 7B 模型：7,000,000,000 参数
- LoRA (rank=16)：≈ 10,000,000 参数
- Prompt Tuning (L=20, d=4096)：$20 \times 4096 = 81,920$ 参数

Prompt Tuning 的参数量是 LoRA 的 1/100、全参数的 1/85000。极其轻量。

### 3.3 每任务独立 Prompt——为什么能防遗忘

TOPIC 为每个任务分配独立的 prompt：

$$
\mathcal{P} = \{P_1, P_2, ..., P_T\}, \quad P_k \in \mathbb{R}^{L \times d}
$$

**这个公式在做什么**：给每个任务单独分配一块"专属抽屉"，$T$ 个任务就有 $T$ 组互不共享的 prompt 参数。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mathcal{P} = \{P_1, ..., P_T\}$ | **prompt 仓库** | 存放已学过的所有任务各自的 prompt，一个任务对应一个条目 |
| $P_k \in \mathbb{R}^{L\times d}$ | **任务 $k$ 的专属纸条** | 一个 $L\times d$ 的矩阵，$L$ 个 $d$ 维向量拼在一起，只属于任务 $k$ |

**用人话读**："每个任务都有自己独立的一份 prompt，谁也不共享谁的。"

**为什么要完全独立而不共享参数**：共享参数意味着新任务的梯度会改写旧任务依赖的那部分参数，导致遗忘；完全独立的 prompt 让不同任务的更新在参数空间里"物理隔离"，天然零遗忘。
:::

推理时用任务 $k$ 的 prompt：

$$
a = f_{\theta_{\text{frozen}}}([P_k; o])
$$

**这个公式在做什么**：推理时把当前任务的 prompt 拼在观测前面，喂给冻结的 VLA，直接输出动作。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $f_{\theta_{\text{frozen}}}$ | **冻结的大脑** | VLA 的视觉编码器、语言编码器、backbone、action head，全部参数固定不动 |
| $[P_k; o]$ | **本次输入** | 任务 $k$ 的 prompt 和当前观测 $o$ 拼接后的完整输入序列 |
| $a$ | **输出动作** | 模型给出的动作，唯一依赖的可变量就是选用了哪个 $P_k$ |

**用人话读**："把当前任务的专属纸条贴在观测前面，喂给固定不变的大脑，就能得到这个任务该做的动作。"

**为什么这样就能切换任务**：因为 backbone 完全冻结，模型的"行为"完全由输入决定——换一张 prompt 纸条就等于换了一套任务设定，不需要改任何权重。
:::

**好处**：
- 任务间完全不干扰（不同 prompt 不共享参数）→ 零遗忘
- 每个任务只需存一个小 prompt（~320KB）

**坏处**：
- 没有正向迁移——每个新 prompt 随机初始化，从零开始学
- 这是 TOPIC 要解决的主要问题

### 3.3 数值例子

假设 $L = 10$, $d = 4096$:

- 任务 1 的 prompt：$P_1 \in \mathbb{R}^{10 \times 4096}$，随机初始化后训练收敛
- 任务 2 的 prompt：$P_2$ 随机初始化 → 需要从零学习所有技能

如果任务 2 和任务 1 高度相似，$P_2$ 应该从 $P_1$ 出发（warm start），只需微调差异部分。

## 四、组件二：Task Relation Graph

### 4.1 图的定义

任务关系图 $\mathcal{G} = (\mathcal{V}, \mathcal{E}, W)$：
- 节点 $\mathcal{V} = \{T_1, T_2, ..., T_k\}$：已学任务
- 边 $\mathcal{E}$：任务对之间的连接
- 权重 $W_{ij} \in [0, 1]$：任务 $i$ 和 $j$ 的相似度

### 4.2 相似度的计算

TOPIC 使用两种信号计算任务相似度：

**语义相似度**（从语言指令计算）：

$$
\text{sim}_{\text{lang}}(T_i, T_j) = \cos\left(\text{LLM}(\text{instruction}_i), \text{LLM}(\text{instruction}_j)\right)
$$

**这个公式在做什么**：把两个任务的语言指令各自编码成向量，用夹角余弦衡量它们语义上有多接近。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\text{LLM}(\text{instruction}_i)$ | **指令翻译器** | 把任务 $i$ 的自然语言指令（如"抓取红色方块"）编码成一个固定维度的语义向量 |
| $\cos(\cdot,\cdot)$ | **相似度计量表** | 计算两个向量夹角的余弦值，值域 $[-1,1]$，越接近 1 说明语义越像 |
| $\text{sim}_{\text{lang}}(T_i,T_j)$ | **语义相似度打分** | 最终输出的一个标量，代表任务 $i$、$j$ 在语言层面有多相关 |

**用人话读**："把两个任务的指令各自变成一个向量，量一下两个向量的夹角有多小，越小说明这两个任务说的是同一类事。"

**为什么用语言指令而不是别的**：语言指令在任务开始前就有，不需要任何训练数据就能算出相似度，天然适合"新任务刚到来、还没学过"这个时间点使用。
:::

**代入数字**：
- $\text{instruction}_1$ = "抓取红色方块" → embedding $e_1 \in \mathbb{R}^{768}$
- $\text{instruction}_3$ = "抓取绿色球" → embedding $e_3 \in \mathbb{R}^{768}$
- $\cos(e_1, e_3) = 0.87$（都是"抓取"）

- $\text{instruction}_2$ = "推蓝色圆柱" → embedding $e_2 \in \mathbb{R}^{768}$
- $\cos(e_1, e_2) = 0.42$（"抓取" vs "推"，有些共性但不高）

**行为相似度**（从 prompt 向量计算）：

$$
\text{sim}_{\text{prompt}}(T_i, T_j) = \cos\left(\text{mean}(P_i), \text{mean}(P_j)\right)
$$

**这个公式在做什么**：不看语言描述，直接看两个任务学出来的 prompt 参数本身像不像——如果模型为两个任务学出了相近的"引导词"，说明它们在行为层面也相关。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\text{mean}(P_i)$ | **任务 $i$ 的行为摘要** | 把 $L\times d$ 的 prompt 矩阵沿 $L$ 维取平均，压成一个 $d$ 维向量，代表这个任务学到的"引导方向" |
| $\cos(\cdot,\cdot)$ | **相似度计量表** | 同上，衡量两个行为摘要向量的夹角余弦 |
| $\text{sim}_{\text{prompt}}(T_i,T_j)$ | **行为相似度打分** | 从已训练好的参数里读出来的相似度，反映两个任务实际需要的"引导方式"有多接近 |

**用人话读**："看两个任务已经学出来的引导向量像不像，像就说明它们需要模型做类似的事情。"

**为什么语言相似度不够，还要加这一项**：语言表述接近不代表底层动作技能接近（比如"打开瓶盖"和"打开抽屉"语言上都含"打开"，但动作差异很大），行为相似度直接从已学参数里验证这一点，弥补纯语言匹配的盲区。
:::

**综合相似度**：

$$
W_{ij} = \gamma \cdot \text{sim}_{\text{lang}} + (1-\gamma) \cdot \text{sim}_{\text{prompt}}
$$

**这个公式在做什么**：把语言相似度和行为相似度按权重加权平均，得到任务关系图上这条边的最终权重。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\gamma \cdot \text{sim}_{\text{lang}}$ | **语言这一票** | 语言相似度乘上权重 $\gamma$，代表"任务描述像不像"这一因素的贡献 |
| $(1-\gamma) \cdot \text{sim}_{\text{prompt}}$ | **行为这一票** | 行为相似度乘上剩余权重，代表"已学参数像不像"这一因素的贡献 |
| $W_{ij}$ | **边权重** | 两票加权求和后的结果，写入任务关系图，作为任务 $i$、$j$ 之间边的权重 |

**用人话读**："语言像不像和已学参数像不像各占一半票，加起来就是这两个任务的最终相似度。"

**为什么两个信号各占一半（$\gamma=0.5$）**：语言相似度在任务刚出现、还没训练时就能用，行为相似度要等训练完才有意义——两者互补，均分权重是没有先验偏好时最简单的折中选择。
:::

$\gamma = 0.5$ 为默认值。

### 4.3 图的增量构建

每学完一个新任务，图就增长一个节点：

$$
\mathcal{G}^{(k)} = \mathcal{G}^{(k-1)} \cup \{T_k\} \cup \{(T_k, T_j, W_{kj}) : j < k\}
$$

**这个公式在做什么**：学完第 $k$ 个任务后，把它作为新节点加入图中，并把它和所有旧任务之间算好的相似度边一起补上。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\mathcal{G}^{(k-1)}$ | **旧图** | 学完前 $k-1$ 个任务后的任务关系图 |
| $\{T_k\}$ | **新节点** | 刚学完的任务 $k$，作为一个新节点加进去 |
| $\{(T_k, T_j, W_{kj}): j<k\}$ | **新增的边** | $T_k$ 和每个已有旧任务 $T_j$ 之间的相似度边，权重就是前面算出来的 $W_{kj}$ |
| $\mathcal{G}^{(k)}$ | **新图** | 加完节点和边之后的最新任务关系图，供下一个任务查询用 |

**用人话读**："每学完一个任务，就往图里加一个新点，并把这个新点和所有旧点之间的相似度连线画好。"

**为什么是增量式而不是每次重新算全图**：任务是逐个到来的，旧任务之间的相似度不会变，只需要计算新任务与已有任务的边，图的构建代价随任务数线性增长而不是重复计算。
:::

```mermaid
flowchart LR
    subgraph 学完T1后
        T1_1["T1: 抓红块"]
    end
    subgraph 学完T2后
        T1_2["T1: 抓红块"] ---|"0.42"| T2_2["T2: 推蓝柱"]
    end
    subgraph 学完T3后
        T1_3["T1: 抓红块"] ---|"0.42"| T2_3["T2: 推蓝柱"]
        T1_3 ---|"0.87"| T3_3["T3: 抓绿球"]
        T2_3 ---|"0.38"| T3_3
    end
```

## 五、组件三：Graph-guided Prompt Initialization

### 5.1 从最相似任务初始化

当新任务 $T_k$ 到来时：

1. 计算 $T_k$ 与所有已有任务的相似度
2. 找到最相似的任务 $T_{j^*} = \arg\max_j W_{kj}$
3. 用 $T_{j^*}$ 的 prompt 初始化 $T_k$ 的 prompt

$$
P_k^{(0)} = P_{j^*} + \epsilon, \quad \epsilon \sim \mathcal{N}(0, \sigma^2 I)
$$

**这个公式在做什么**：新任务的 prompt 不从零开始，而是直接抄最相似旧任务的 prompt，再加一点小噪声避免完全重复。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $P_{j^*}$ | **最相似旧任务的纸条** | 图中权重最高的旧任务 $T_{j^*}$ 已经训练好的 prompt |
| $\epsilon \sim \mathcal{N}(0,\sigma^2 I)$ | **小扰动** | 从零均值高斯分布里采样的噪声，防止新任务的初始 prompt 和旧任务完全一样导致训练陷入局部结构 |
| $P_k^{(0)}$ | **新任务的起跑点** | 新任务 $T_k$ 的 prompt 在训练开始前的初始值 |

**用人话读**："把最像的旧任务的纸条抄一份，加一点小随机扰动，作为新任务的起点。"

**为什么要加噪声而不是直接复制**：直接复制会让新 prompt 一开始就和旧 prompt 完全重合，梯度更新的方向可能被"卡"在旧任务的局部结构里；加一点噪声打破这种对称性，同时几乎不损失热启动带来的加速效果。
:::

**代入数字**（我们的例子）：

新任务 T3（抓绿球）到来：
- $W_{3,1} = 0.87$（和 T1"抓红块"最相似）
- $W_{3,2} = 0.38$（和 T2"推蓝柱"不太像）
- 选择 $j^* = 1$
- $P_3^{(0)} = P_1 + \epsilon$（从"抓红块"的 prompt 出发）

这意味着 T3 已经"知道"怎么抓取了，只需学习适应绿色球的形状差异。

### 5.2 加权聚合初始化（可选增强）

如果多个旧任务都相关，可以用加权平均：

$$
P_k^{(0)} = \sum_{j: W_{kj} > \tau} \frac{W_{kj}}{\sum_{j'} W_{kj'}} P_j
$$

**这个公式在做什么**：不只抄一个最相似的旧任务，而是把所有相似度超过阈值的旧任务 prompt 按相似度权重混合，作为新任务的初始值。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\{j: W_{kj}>\tau\}$ | **入围名单** | 所有和新任务 $T_k$ 的相似度超过阈值 $\tau$ 的旧任务集合，太不相关的任务被排除在外 |
| $\frac{W_{kj}}{\sum_{j'}W_{kj'}}$ | **投票权重** | 把入围任务的相似度归一化成加起来等于 1 的权重，相似度越高投票权越大 |
| $\sum_j (\cdot) P_j$ | **加权拼合** | 用归一化权重对入围任务的 prompt 做加权平均 |
| $P_k^{(0)}$ | **融合起跑点** | 融合了多个相关旧任务知识的新任务初始 prompt |

**用人话读**："把所有和新任务比较像的旧任务的纸条，按相似度高低加权混合成一张新纸条。"

**为什么比只用最相似的一个更好**：单一最相似任务可能只覆盖新任务的一部分技能（比如只覆盖"抓取"但不覆盖"识别橙色"），融合多个相关任务能让初始 prompt 同时继承更多有用的知识片段。
:::

**代入数字**（阈值 $\tau = 0.5$）：

假设任务 T5（抓橙色三角形）：
- $W_{5,1} = 0.82$（和"抓红块"类似）
- $W_{5,3} = 0.79$（和"抓绿球"类似）
- $W_{5,2} = 0.31$（和"推蓝柱"不像，低于阈值）

$$
P_5^{(0)} = \frac{0.82}{0.82+0.79} P_1 + \frac{0.79}{0.82+0.79} P_3 = 0.509 P_1 + 0.491 P_3
$$

**这个公式在做什么**：把上面加权聚合公式代入具体数字，算出任务 T5（抓橙色三角形）的初始 prompt 是 T1 和 T3 的 prompt 各占约一半的混合。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\frac{0.82}{0.82+0.79}=0.509$ | **T1 的投票权** | 相似度 $W_{5,1}=0.82$ 归一化后占的比例，略高于一半 |
| $\frac{0.79}{0.82+0.79}=0.491$ | **T3 的投票权** | 相似度 $W_{5,3}=0.79$ 归一化后占的比例，略低于一半 |
| $0.509P_1+0.491P_3$ | **最终混合结果** | T5 的初始 prompt，几乎是 T1、T3 两个抓取任务 prompt 各半混合 |

**用人话读**："T5 和 T1、T3 的相似度差不多，所以它的初始纸条几乎是两者各拿一半拼起来的。"

**为什么权重接近 0.5/0.5**：因为原始相似度 $0.82$ 和 $0.79$ 本身就很接近，归一化之后自然也接近对半——如果某个旧任务明显更相似，权重会明显偏向那一个。
:::

融合了两个抓取任务的知识。

### 5.3 为什么 Warm Start 有效

Prompt 空间中，相似任务的最优 prompt 通常相近：

$$
\|P_i^* - P_j^*\| \propto \frac{1}{\text{sim}(T_i, T_j)}
$$

**这个公式在做什么**：说明任务越相似，它们各自训练收敛后的最优 prompt 在参数空间里离得越近——这是 warm start 有效的理论前提。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $P_i^*, P_j^*$ | **两个任务各自的终点** | 任务 $i$、$j$ 分别独立训练到收敛后得到的最优 prompt |
| $\|P_i^*-P_j^*\|$ | **终点间的距离** | 两个最优 prompt 在参数空间里的欧氏距离 |
| $\text{sim}(T_i,T_j)$ | **任务相似度** | 前面定义的语言/行为综合相似度 |
| $\propto \frac{1}{\text{sim}}$ | **反比关系** | 相似度越高，距离越小；相似度越低，距离越大 |

**用人话读**："两个任务越相似，它们各自训练出来的最优纸条就越接近；越不相似，两个最优纸条离得越远。"

**为什么这条关系是 warm start 起作用的前提**：如果这条关系不成立（相似任务的最优 prompt 反而离得很远），那么从相似旧任务初始化就没有意义——正是因为这个反比关系大体成立，从最相似任务出发才能让优化器少走很多路。
:::

从 $P_{j^*}$ 初始化相当于给优化器一个好的起点，减少了需要的训练步数：

| 初始化方式 | 到 90% 成功率的步数 | 最终成功率 |
|-----------|-------------------|-----------|
| 随机初始化 | 2000 步 | 91.2% |
| 从最相似任务初始化 | 600 步 | 93.5% |
| 加权聚合初始化 | 450 步 | 94.1% |

训练步数减少 70%，且最终效果更好（正向迁移）。

## 六、推理时的任务路由

### 6.1 问题：推理时不给 Task ID

训练时我们知道"当前是任务 $k$"，但部署时机器人收到一个指令"抓那个东西"——如何决定用哪个 prompt？

### 6.2 方案：语言指令匹配

利用已构建的任务关系图：

$$
k^* = \arg\max_k \text{sim}_{\text{lang}}(\text{current instruction}, \text{instruction}_k)
$$

**这个公式在做什么**：推理时把当前收到的指令和所有已学任务的指令逐一比较相似度，挑相似度最高的那个任务，用它的 prompt。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\text{current instruction}$ | **当前收到的指令** | 部署时机器人实时收到的自然语言指令，事先不知道属于哪个任务 |
| $\text{sim}_{\text{lang}}(\cdot,\cdot)$ | **语义匹配器** | 复用前面定义的语言相似度函数，逐个和已学任务的指令比较 |
| $\arg\max_k$ | **选择器** | 在所有已学任务里，找出相似度最高的那个任务编号 |
| $k^*$ | **路由结果** | 最终选中的任务编号，决定推理时用哪个 prompt |

**用人话读**："把当前指令和所有学过的任务指令一个个比一比，哪个最像就用哪个任务的纸条。"

**为什么可以用语言匹配来做路由**：因为任务关系图本身已经维护了每个任务的语言指令表示，路由复用同一套相似度计算，不需要额外训练一个专门的路由网络。
:::

**代入数字**：

新指令："pick up the green sphere"
- 与 T1 "grab the red cube" 的 $\cos$ 相似度：0.72
- 与 T2 "push the blue cylinder" 的 $\cos$ 相似度：0.35
- 与 T3 "grasp the green ball" 的 $\cos$ 相似度：0.94

选择 T3 的 prompt → $P_3$。

### 6.3 多 Prompt 融合（应对新颖指令）

如果指令和所有已有任务都不太匹配（最大相似度 < 0.6），说明遇到了**未见过的任务**。此时可以：

$$
P_{\text{fused}} = \sum_k \text{softmax}(\text{sim}_k / \tau) \cdot P_k
$$

**这个公式在做什么**：当新指令和所有旧任务都不太像时，不强行选一个，而是把所有旧任务的 prompt 按相似度做 softmax 加权混合，拼出一个"临时应急"的 prompt。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\text{sim}_k$ | **和任务 $k$ 的相似度** | 当前指令与已学任务 $k$ 指令的语言相似度 |
| $\text{softmax}(\text{sim}_k/\tau)$ | **温度调节投票权** | 把所有任务的相似度转成一组加起来为 1 的权重，$\tau$ 控制分布是"接近均匀"还是"只偏向最像的几个" |
| $\sum_k(\cdot)P_k$ | **加权混合** | 用得到的权重对所有旧任务的 prompt 做加权求和 |
| $P_{\text{fused}}$ | **临时应急 prompt** | 融合了所有相关旧任务知识的组合 prompt，用来应对没见过的新指令 |

**用人话读**："如果新指令跟谁都不太像，就把所有旧任务的纸条按各自的像不像程度混在一起，凑一张临时的纸条应急用。"

**为什么用 softmax 而不是硬性 arg max**：硬性选择要求至少有一个旧任务足够相似才可靠，而 softmax 允许在没有明显最相似任务时，仍然给出一个由多个部分技能组合出的合理近似，避免推理时因为路由失败而完全无法工作。
:::

用所有 prompt 的加权混合，希望组合已有技能来应对新情况。

## 八、局限性

### 8.1 Prompt 容量有限

每个 prompt 只有 $L \times d \approx 80K$ 参数。对于非常复杂的任务，可能表达力不足。

**对比**：LoRA (rank=16) 有 ~10M 参数，是 Prompt 的 125 倍。

### 8.2 假设任务边界清晰

TOPIC 假设训练时知道"现在在学哪个任务"（task boundary 已知）。在无边界的持续学习设定中不直接适用。

### 8.3 路由错误的级联效应

如果推理时选错了 prompt，性能会骤降。对于语义相近但行为不同的任务（如"把杯子放左边" vs "把杯子放右边"），纯语言匹配可能犯错。

## 九、总结

| 贡献 | 意义 |
|------|------|
| Task-Specific Prompt | 零遗忘 + 极低参数开销 |
| Task Relation Graph | 捕获任务间相似性，自动聚类 |
| Graph-guided Initialization | 实现正向迁移，新任务训练加速 3-7 倍 |
| 语言路由 | 推理时无需 task ID |

**核心信息**：在持续学习中，"防遗忘"和"促迁移"同样重要。TOPIC 通过任务关系图将已有知识主动迁移到新任务，让持续学习不只是"不忘"，更是"越学越快"。
