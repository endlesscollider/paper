## 贯穿全文的例子

设想在评测一个双臂机器人策略执行"把桌上的三朵花依次插进花瓶"这个任务。四条 rollout 录像被送去评测：

- **策略 A**：一路顺畅地把进度从 0 推到 1，没有任何倒退。
- **策略 B**：进度先冲到 0.72，中途手滑把插好的花碰掉，跌到 0.28，之后重新捡起来慢慢爬回 0.67，但视频结束时任务还没做完。
- **策略 C**：进度冲到 0.54 之后就卡住不动了，反复调整姿势但毫无进展。
- **策略 D**：一路磕磕绊绊——中途也摔了一次跟头，但最终还是把三朵花都插好了。

如果只看"成功/失败"这一个二值标签，A 和 D 都是"成功"，B 和 C 都是"失败"——四条完全不同的执行过程被压成了两种结果。PRM-as-a-Judge 要解决的，正是这种信息塌陷。下文会反复回到这四条曲线，用它们对照每一个指标的计算方式。

## 一、为什么成功率不够用

### 1.1 二值标签抹掉了什么

机器人操作的评测长期以来依赖**成功率**（Success Rate, SR）：跑 N 次 rollout，数有多少次达到了任务终止条件，除以 N。这个指标简单、可比、跨基准通用，但它天生只回答一个问题——"完成了吗"，回答不了另外三个同样重要的问题：

- **走到哪了**：一次失败是"差一步就成功"还是"刚开始就崩了"？
- **走得稳不稳**：一次成功是"一气呵成"还是"来回试错、反复纠正"？
- **哪里出了问题、能不能恢复**：失败发生在哪个阶段？是持续退步，还是卡住不动，还是退步后又爬回来了？

论文用一句话概括这个问题：**"用成功率评判一场交响乐，等于只听它的最后一个音符"**。上面例子里的 B 和 C 都是"失败"，但 B 达到过 0.72 的进度，C 只到过 0.54；A 和 D 都是"成功"，但 A 中途从未后退，D 有一次明显的倒退。二值标签让这些区别全部消失，留下来的只有一个 0 或 1。

### 1.2 已有的替代方案为什么不够

论文在相关工作里把已有的评测方式分成三类，各自的局限也很清楚：

| 评测方式 | 做法 | 局限 |
|---|---|---|
| 二值成功率 | 判断是否达到终止条件 | 抹掉过程信息，近乎成功和早期崩溃打同一个分 |
| 人工规则打分 | 人工给每个任务设计分阶段规则和权重 | 每个任务都要重新设计规则，人工标注不同评委间还会不一致 |
| 依赖特权状态的指标 | 用仿真器里的物体位姿、关节角、接触力等"上帝视角"信息算路径长度、平滑度等 | 只能在仿真里用，真机部署时没有这些特权信息，任务一换又要重新写逻辑 |

PRM-as-a-Judge 想要的是一种**只需要任务描述和 rollout 视频**、不依赖人工规则、不依赖仿真器特权状态的评测方式——这样它才能同时用在仿真和真实机器人上，用在任何任务和任何本体上。

## 二、核心思路：把评测问题变成"给每一帧打分"

### 2.1 进度势 Φ：一个统一的度量尺

论文的解法是引入一个**任务条件下的进度势**（progress potential）$\Phi(x) \in [0, 1]$：给定任务指令和当前观测 $x$（可以是一帧图像，也可以是多帧组成的一段状态），$\Phi$ 输出一个 0 到 1 之间的数，表示"当前状态距离完成任务还有多远"。$\Phi=0$ 代表任务刚开始，$\Phi=1$ 代表任务已经完成。

一次执行（rollout）就是一串观测 $\tau = (x_0, x_1, \ldots, x_T)$，把每一帧丢进 $\Phi$，就得到一条**进度曲线** $\Phi(x_0), \Phi(x_1), \ldots, \Phi(x_T)$。这条曲线就是后面所有指标的唯一输入——它不区分策略是 VLA（Vision-Language-Action，视觉-语言-动作模型）还是 WAM（World-Action Model，世界动作模型），也不区分任务是插花还是拧瓶盖，只要能录到视频、能给出任务描述，就能生成一条曲线。

```mermaid
flowchart LR
    A["任务指令 + rollout 视频"] --> B["Process Reward Model<br/>逐帧/逐时刻打分"]
    B --> C["原始进度曲线<br/>Φ_raw"]
    C --> D["异常值剔除 + 加权平滑"]
    D --> E["处理后曲线<br/>Φ_processed"]
    E --> F["OPD 指标套件<br/>MP / PPL / CRA / STR / DRR / FNS / SQS"]
    F --> G["模型级 / 任务级评测报告"]
```

> 图中最容易被忽略的一步是"异常值剔除 + 加权平滑"——后面第五节会展示这一步如何直接影响回退（drawdown）能不能被指标捕捉到。

### 2.2 一个合格的"过程裁判"需要满足什么条件

不是随便一个打分函数都能当这个角色。论文提出两个必要条件：

**宏观一致性（macro-consistency）**：把一段执行任意切开再拼起来，总进度不应该变。用公式表达就是 $S(x_{t_0}, x_{t_2}) = S(x_{t_0}, x_{t_1}) + S(x_{t_1}, x_{t_2})$——直觉上，"从开始到结束的进度"应该等于"从开始到中间"加上"从中间到结束"，不能因为你在哪里切开了轨迹而得到不同的总量。

**微观分辨率（micro-resolution）**：两帧之间哪怕差异很小，只要物理上有意义的变化，$\Phi$ 就应该给出不为零的差值，即 $|\Phi(x_{t+\Delta}) - \Phi(x_t)| > 0$。如果一个裁判对"手指刚碰到物体"和"手指已经抓稳"这种细微但关键的状态变化毫无反应，它就没法分辨真实的进展、退步和停滞，只会把这些全部拍扁成一条几乎不变的直线。

要同时满足这两个条件，论文给出的构造方式很直接：**把两帧之间的进度定义为它们各自进度势的差** $S(x_i, x_j) = \Phi(x_j) - \Phi(x_i)$。只要每一帧都能在同一个 $[0,1]$ 量表上打分，宏观加性自动满足（差值的差值必然可加），微观分辨率就取决于这个打分函数本身够不够敏感——这也是为什么论文后面专门做了 RoboPulse / RoboPulse++ 基准去检验候选 PRM 是否真的具备这种敏感度（见第六节）。

## 三、OPD 指标体系：把一条曲线拆成三层信号

有了曲线，接下来的问题是"从曲线里读出什么"。论文把这件事组织成 **OPD**（Outcome-Process-Diagnosis，结果-过程-诊断）三层框架：Outcome 回答"走到哪了"，Process 回答"走得直不直"，Diagnosis 回答"哪里出了问题、有没有恢复"。1.0 版本给出 5 个指标，1.5 版本在失败、恢复、成功三种情形下各加了一个"条件指标"，扩到 9 个。

下面结合本文开头定义的四条曲线（A 平滑成功、B 回退后恢复但未完成、C 早期卡死、D 磕磕绊绊的成功）逐个说明，所有数值都用仓库 `eval/prm_judge/metrics.py` 的真实实现重新算过一遍，不是从论文摘抄。

### 3.1 Outcome 层：MP 和 MC@q，回答"走到哪了"

**MP（Max Progress，最大进度）** 就是整条曲线的最高点：

$$
MP(\tau) = \max_{t \in [0, T]} \Phi(x_t)
$$

**这个公式在做什么**：不管中途有没有回退，只看这次执行**曾经**达到过的最深处。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\Phi(x_t)$ | **某一帧的进度势读数** | 告诉你"这一帧看起来完成了百分之多少" |
| $\max_{t}$ | **只认最高分** | 哪怕后面摔了、退步了，也不影响这次执行"曾经冲到过哪里"这个事实 |

**用人话读**："这次执行这辈子最高光的时刻，进度冲到了多少。"

**为什么用 max 而不是最后一帧**：如果直接看最后一帧，策略 B 中途冲到 0.72、结尾却停在 0.67，会显得比"从没冲那么高但结尾恰好停在 0.70"的策略更差——但这明显不合理，B 已经证明自己有能力达到 0.72 这个水平。MP 只承认"曾经达到的最深处"，不因为收尾时机不巧而惩罚策略。
:::

**MC@q（Milestone Coverage，里程碑覆盖率）** 是 MP 的二值化版本，检查 MP 是否越过某个门槛 $q \in \{25\%, 50\%, 75\%, 100\%\}$：

$$
MC@q(\tau) = \mathbb{1}\left[MP(\tau) \geq \frac{q}{100}\right]
$$

**这个公式在做什么**：把连续的 MP 切成几个"及格线"，方便统计一批 rollout 里有多大比例冲过了 25%、50%、75%、100%。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $q/100$ | **及格线** | 25%、50%、75% 或 100%，四条预设的高度标尺 |
| $\mathbb{1}[\cdot]$ | **及格判定** | 冲过了记 1，没冲过记 0 |

**用人话读**："这次执行有没有冲过 25%（或 50%、75%、100%）这条线。"

**为什么要分成四档而不是只看 MP 的平均值**：单看 MP 的平均值容易被极端值带偏，也看不出"卡在哪个阶段的最多"。分成四个里程碑之后，一批模型在 MC@25 都很高、但 MC@75 骤降的现象（论文管这个叫"最后一米幻觉"，见第五节），只有分档统计才能看出来。
:::

代入四条曲线：A 的 MP=1.00（M25=M50=M75=1，SR=1，判为成功）；B 的 MP=0.673（M25=M50=1，M75=0，SR=0，判为失败）；C 的 MP=0.540（M25=M50=1，M75=0，SR=0，判为失败）；D 的 MP=1.00（全部里程碑达标，SR=1，判为成功）。光看这一层就已经能分出 B 比 C 走得更深——尽管二者在成功率上是同一个"0"。

### 3.2 Process 层：PPL，回答"走得直不直"

**PPL（Path-weighted Progress Length，路径加权进度长度）** 衡量"到达最高点这一路走得有多绕"：

$$
PPL(\tau) = \frac{MP(\tau)^2}{\sum_{t=1}^{T} |\Phi(x_t) - \Phi(x_{t-1})| + \varepsilon}
$$

**这个公式在做什么**：拿"最终冲到的高度"去除"沿途走过的总里程"——高度不变的前提下，绕的路越多，分数越低。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $MP(\tau)^2$ | **应得的高度（平方）** | 分子用平方而不是一次方，让"冲得更高"这件事在分数里占更大权重 |
| $\sum_t \lvert \Phi(x_t)-\Phi(x_{t-1}) \rvert$ | **实际走过的总路程** | 每一步的进度变化量取绝对值再累加——前进算路程，后退也算路程，反复拉锯会让这个数越滚越大 |
| $\varepsilon$ | **防止除零的垫底值** | 曲线完全不动（分母为 0）时不让公式报错，直接给 0 分 |

**用人话读**："冲得越高、走的弯路越少，分数越高；同样冲到 0.7，一路直冲的比来回拉扯十次才冲到的分数高得多。"

**为什么分子要用 $MP$ 而不是最终帧的进度**：论文原本的 1.0 版本用的是"最终进度的平方"（记作 $PPL_{old}$），后来发现这样对最后几帧特别敏感——如果策略在收尾时因为松手、镜头抖动或轻微调整而使进度掉了一点点，$PPL_{old}$ 会被这个无关紧要的尾部波动大幅拉低。换成 $MP$ 之后，只要曾经达到过的高度足够高，短暂的尾部波动不会拖累这个指标，而分母的路径长度依然会照实惩罚反复拉锯的行为。
:::

代入四条曲线（用后处理曲线计算）：A 一路单调上升，路径长度约等于 $MP$ 本身，$PPL \approx 1.00$；D 中途有一次明显下坠又爬回来，路径长度被拉长，$PPL \approx 0.96$——虽然两者都"成功"，PPL 已经能看出 D 走得没有 A 干净。B 的 $PPL \approx 0.471$，反映出它那次深度回退让路径长度远超它实际达到的高度。

### 3.3 Diagnosis 层：CRA 和 STR，回答"卡在哪、退步多严重"

**CRA（Cumulative Regret Area，累计后悔面积）** 衡量整条曲线"跌破历史最高点"的严重程度和持续时间：

$$
CRA(\tau) = \frac{1}{(T+1)\cdot MP(\tau)} \sum_{t=0}^{T} \left( \max_{0 \le i \le t} \Phi(x_i) - \Phi(x_t) \right)
$$

**这个公式在做什么**：在曲线和它自己的历史最高水位线之间画出一块"后悔面积"，面积越大、维持越久，说明退步越严重、恢复得越慢。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\max_{i \le t} \Phi(x_i)$ | **历史最高水位线** | 到当前时刻为止，这条曲线曾经达到过的最高点（只会不断刷新，不会下降） |
| $\max_{i\le t}\Phi(x_i) - \Phi(x_t)$ | **当前的"亏损"** | 现在的进度比历史最高点低了多少；曲线在涨的时候这一项恒为 0 |
| $\sum_t (\cdot)$ | **把每个时刻的亏损累加起来** | 亏损维持得越久（不只是跌得深），这个总和就越大 |
| $\frac{1}{(T+1)\cdot MP}$ | **按时长和量级归一化** | 除以步数让长视频和短视频可比，除以 $MP$ 让不同高度的执行可比 |

**用人话读**："这次执行有多少时间在跌破自己曾经的最好状态，跌得多深、跌了多久，两者相乘再平均。"

**为什么要除以 $MP$**：同样是"跌了 0.1"，对一个最高只冲到 0.2 的策略和一个冲到 0.9 的策略含义完全不同——前者几乎跌回起点，后者只是一次小幅波动。除以 $MP$ 把"跌了多少"换算成"相对于自己巅峰状态跌了多少比例"，这样不同水平的策略之间才能公平比较。
:::

**STR（Stagnation Ratio，停滞比率）** 衡量曲线"几乎不动"的时间占比：

$$
STR(\tau) = \frac{1}{T} \sum_{t=1}^{T} \mathbb{1}\left[ |\Phi(x_t) - \Phi(x_{t-1})| < \epsilon \right]
$$

**这个公式在做什么**：数一数整条曲线里有多少步的变化幅度小到可以忽略（默认阈值 $\epsilon=0.005$），这个比例越高，说明策略越经常"卡住不动"。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\lvert \Phi(x_t)-\Phi(x_{t-1}) \rvert$ | **相邻两步的变化量** | 这一步相对上一步，进度到底动了多少 |
| $\epsilon$ | **"算不算动了"的门槛** | 默认 0.005，小于这个幅度的波动被当成噪声，不计入真实变化 |
| $\mathbb{1}[\cdot < \epsilon]$ | **停滞判定** | 变化幅度小于门槛就记一次"停滞" |
| $\frac{1}{T}\sum_t$ | **停滞步数占全部步数的比例** | 全程有多大比例的时间在原地打转 |

**用人话读**："这次执行有百分之多少的时间，进度几乎完全没有变化。"

**为什么 CRA 和 STR 要分开算，而不是合并成一个"失败严重度"**：因为它们对应完全不同的失败机制，需要不同的修复方案。CRA 高、STR 低说明策略**动得很欢但方向经常错**（抓取失败又重新尝试导致反复回退）——需要更强的错误纠正能力；STR 高、CRA 低说明策略**几乎不退步但也不前进**（末端执行器悬在物体上方不敢下手）——需要更好的接触建立能力。合并成一个数会让这两种截然不同的问题变得无法区分。
:::

代入四条曲线：C 的 STR=0.500——一半的采样步几乎不动，这正是"早期卡死"最直接的数值证据；A 和 D 的 STR 都是 0，说明它们全程都在真实地移动。B 的 CRA=0.060，反映出那次深度回退留下的痕迹；A 的 CRA=0，因为它从未跌破过历史最高点。

<img src="/prm_judge_metric_geometry.png" alt="PPL、CRA、STR、DRR 在同一条回退曲线上分别对应哪块几何区域" class="img-full">

> 用策略 B 的曲线把四个过程指标画成图上可见的面积或线段：PPL 看的是"蓝色路程条的总长度 vs 冲到的高度"，CRA 看的是曲线和红色历史最高水位线之间的"后悔面积"，STR 看的是有没有几乎不动的灰色阴影步，DRR（下面第 3.4 节）看的是跌落箭头和爬回箭头的长度比。

### 3.4 1.5 版本新增的三个条件指标：给"失败""恢复""成功"分别开一张诊断单

1.0 版本的 5 个指标对所有 rollout 一视同仁地计算，但论文在 1.5 版本里意识到：**有些诊断只对特定结果的 rollout 才有意义**。对一个已经成功的 rollout 谈"离成功还有多近"没有意义，对一个从未回退过的 rollout 谈"恢复了多少"也没有意义。于是 1.5 版本引入三个**条件指标**，各自只在满足条件的子集上计算。

**FNS（Failure Near-Success，失败迫近度）**，只在**失败**的 rollout 上计算：

$$
FNS(\tau) = 0.5 \cdot MP(\tau) + 0.3 \cdot MC@75(\tau) + 0.2 \cdot MC@50(\tau)
$$

**这个公式在做什么**：给失败的执行也分出"差一点成功"和"完全没戏"两种档次，而不是让所有失败都得零分。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $0.5 \cdot MP$ | **主干分数：最终到底冲多高** | 权重最大的一项，直接反映这次失败停在了多深的地方 |
| $0.3 \cdot MC@75$ | **加分项：有没有摸到最后阶段** | 冲过 75% 里程碑额外加分，奖励"已经接近完成"的失败 |
| $0.2 \cdot MC@50$ | **加分项：有没有走过半程** | 冲过 50% 里程碑再加一点分 |

**用人话读**："这次失败到底有多接近成功——主要看冲到的最高点，再看有没有越过后两个里程碑线加分。"

**为什么权重是 0.5/0.3/0.2 而不是平均分配**：$MP$ 是连续量，能精确区分"冲到 0.60"和"冲到 0.65"这种细微差别；$MC@75$、$MC@50$ 是二值量，只能告诉你"过没过线"。把最大权重给连续量，让 FNS 保留足够的分辨率,同时用两个里程碑指标做粗粒度的校正，防止 $MP$ 里一次异常的尖峰单独决定整个分数。
:::

**DRR（Drawdown Recovery Ratio，回撤恢复比率）**，只在**发生过真实回退**的 rollout 上计算。先定义"回撤"：$t$ 时刻的回撤 $d_t = \max_{i \le t}\Phi(x_i) - \Phi(x_t)$（当前比历史最高点低多少），$t^\star$ 是回撤最大的那个时刻。

$$
DRR(\tau) = \min\left(1,\ \frac{\max_{t^\star \le t \le T} \Phi(x_t) - \Phi(x_{t^\star})}{d_{t^\star}}\right), \quad d_{t^\star} > 0
$$

**这个公式在做什么**：找到整条曲线上跌得最深的那一次，看看之后策略能把这次跌幅"追回来"多少。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $d_{t^\star}$ | **最大跌幅（分母）** | 整条曲线上，历史最高点和随后最低点之间的最大落差 |
| $\max_{t^\star \le t \le T}\Phi(x_t) - \Phi(x_{t^\star})$ | **谷底之后的最佳反弹（分子）** | 从跌到最低的那一刻起，之后曲线曾经回升到的最高点，减去谷底本身 |
| $\min(1, \cdot)$ | **封顶** | 反弹幅度可能超过原来的跌幅（比如跌了 0.1 又冲到比原来更高），但恢复程度最多算"完全恢复"，不额外加分 |

**用人话读**："摔得最狠的那一下，后来爬回来了多少比例——完全没爬起来是 0，原样爬回或者爬得更高都算 1。"

**为什么只在"有真实回退"的子集上算，而不是对所有 rollout 都算**：如果一条曲线从头到尾单调上升，分母 $d_{t^\star}$ 就是 0，公式除零无意义；工具箱的实现里进一步用一个数值容差（$10^{-12}$）过滤掉浮点误差造成的"伪回退"，只有跌幅真实超过这个容差才计入统计，避免把噪声当成需要恢复的事件。
:::

**SQS（Success Quality Score，成功质量分）**，只在**成功**的 rollout 上计算：

$$
SQS(\tau) = 0.5 \cdot PPL(\tau) + 0.3 \cdot (1-CRA(\tau)) + 0.2 \cdot (1-STR(\tau))
$$

**这个公式在做什么**：给已经贴上"成功"标签的执行再打一次细分——同样是成功，走得干净利落的和一路磕磕绊绊的应该拿到不同的分数。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $0.5 \cdot PPL$ | **主干分：路径效率** | 权重最大，奖励"直冲到底"而不是绕远路 |
| $0.3 \cdot (1-CRA)$ | **稳定性加分** | CRA 越低（退步越少），这一项越接近 0.3 满分 |
| $0.2 \cdot (1-STR)$ | **流畅性加分** | STR 越低（停滞越少），这一项越接近 0.2 满分 |

**用人话读**："同样是成功，走得越直、退步越少、停顿越少，分数越高。"

**为什么三项都要用"1 减"的形式**：$CRA$ 和 $STR$ 本身是"越低越好"的指标，而 $SQS$ 整体设计成"越高越好"，用 $1-CRA$、$1-STR$ 把方向统一，才能直接相加成一个单一分数,不需要读者再心算一次方向转换。
:::

代入例子：A 全程无回退无停滞，$SQS \approx 1.00$；D 中途有一次回退但最终仍成功，$SQS \approx 0.98$——两个"成功"在质量分上被清楚地区分开。B 和 C 都是失败，$FNS$ 分别约为 0.536 和 0.470，量化出"B 比 C 更接近成功"这个直觉。四条曲线在完整指标体系下的最终对比：

| 策略 | 二值结果 | MP | PPL | CRA | STR | DRR | FNS | SQS |
|---|---|---|---|---|---|---|---|---|
| A 平滑成功 | 成功 | 1.000 | 1.000 | 0.000 | 0.000 | — | — | 1.000 |
| B 回退-恢复-未完成 | 失败 | 0.673 | 0.471 | 0.060 | 0.000 | 1.000 | 0.536 | — |
| C 早期卡死 | 失败 | 0.540 | 0.540 | 0.000 | 0.500 | — | 0.470 | — |
| D 磕磕绊绊的成功 | 成功 | 1.000 | 0.960 | 0.002 | 0.000 | 1.000 | — | 0.979 |

> "—" 表示该指标在这条曲线上不适用（DRR 只算有真实回退的曲线，FNS 只算失败的曲线，SQS 只算成功的曲线）。这张表就是 OPD 体系最终想要交付的东西：**同一个"失败"或"成功"标签下面，藏着完全不同的执行质量，而这些差异现在都有了数字。**

## 四、Robo-Dopamine：怎么把"打分"这件事真正做出来

前三节讲的是"曲线应该满足什么性质、曲线能读出什么指标"，都建立在"已经有一条曲线"的前提上。这一节讲曲线从哪来——具体来说是工具箱默认绑定的 PRM 后端 **Robo-Dopamine**（一个 8B 参数的视觉语言模型，经过专门训练用于判断机器人操作进度）怎么产出这条曲线。

### 4.1 三种配对模式：拿哪两帧去比

Robo-Dopamine 是一个**成对式**（pair-wise）裁判：它每次接收"之前"（BEFORE）和"之后"（AFTER）两组图像（每组包含主视角 + 左右手腕视角），输出一个 $[-100\%, +100\%]$ 的整数百分比，表示 AFTER 比 BEFORE 是更接近还是更远离任务完成。要把一整段视频转成一条曲线,需要决定"每次拿哪两帧去比"——工具箱提供三种模式：

<img src="/prm_judge_dopamine_modes.png" alt="incremental / forward / backward 三种配对模式，以及同一批打分累积成的三条不同曲线" class="img-full">

- **incremental（增量模式，默认）**：比较相邻两个采样帧，模型输出被当作"这一步相对上一步的变化量"。
- **forward（前向模式）**：始终拿第 0 帧（起始状态）当 BEFORE，当前帧当 AFTER，模型输出被直接当作"绝对进度"。
- **backward（回溯模式）**：拿一张目标图像（goal image，展示任务完成后的样子）当 BEFORE，当前帧当 AFTER，模型输出被转换成"距离目标还差多少"。

三种模式对同一批模型原始打分的累积方式完全不同（代码来自 `dopamine_inference.py` 的 `run_pipeline`）：

| 模式 | 累积公式 | 直觉 |
|---|---|---|
| incremental | 若打分 $s\ge0$：$p \leftarrow p + (1-p)s$；若 $s<0$：$p \leftarrow p + p\cdot s$ | 正向变化只能吃掉"剩余空间"的一部分，负向变化只能吃掉"已有进度"的一部分——保证曲线自然停在 $[0,1]$ 附近 |
| forward | $p = s$ | 模型的每次输出就是当前的绝对进度，不需要累积 |
| backward | $p = 1 + s$ | 模型说"比目标差 30%"（$s=-0.3$），换算成绝对进度就是 0.7 |

incremental 模式的累积规则值得多说一句：它不是简单的 $p \leftarrow p + s$，而是用 $(1-p)$ 或 $p$ 分别缩放正负打分。这保证了即使模型连续给出"+50%"这样的大幅正向打分，$p$ 也只会不断逼近 1 而不会超出上界；同理连续给出很大的负向打分,$p$ 也只会逼近 0 而不会跌成负数。

**该选哪种模式**：incremental 适合捕捉局部的细粒度变化，是大多数常规批量评测的默认选择；forward 适合"从起点到当前的变化比到目标的距离更容易判断"的场景；backward 需要一张可靠的目标图像，适合有明确终态参照的任务。文档特别提醒：**backward 模式绝不能用被评测 rollout 自己的最后一帧当目标图像**——如果那次 rollout 本身就是失败的，等于让模型拿"失败状态"当"成功标准"去打分,会系统性地夸大进度。

### 4.2 多视角输入：为什么要看手腕摄像头

Robo-Dopamine 每次比较用的不是一张图，而是三张图（主视角 + 左手腕 + 右手腕）。论文给出的设计理由是分工明确的：**主视角**（第三人称或俯视）负责判断全局布局、物体位姿、抓取路径这些"看得远"才能看清的信息；**手腕视角**负责判断抓取器闭合程度、接触位置、有没有打滑或误碰这些"看得近"才能看清的细节。当两个视角给出的信号冲突时（比如主视角看起来物体已经被抓稳，但手腕视角显示手指其实没有真正夹住)，手腕视角的判断优先——因为抓取是否成立、有没有意外碰撞，这类决定任务成败的细节往往只有近距离视角才能看清楚。单臂机器人只有一个手腕摄像头时，工具箱会把这同一段视频复制填进两个手腕输入槛位；如果连手腕视频都没有，则退化成三个槛位都用主视角画面填充。

### 4.3 从曲线到指标之间还有一步：后处理

第三节讲的所有指标公式，实际使用的输入并不是模型的原始打分,而是经过两步后处理的曲线：

1. **异常值剔除**：用滑动窗口内的局部中位数替换掉偏离阈值（默认 0.35）过大的孤立尖峰,清理模型偶尔的误判。
2. **加权窗口平滑**：用一个五点加权窗口（默认权重 $[0.1, 0.2, 0.4, 0.2, 0.1]$，中心权重最大）对曲线做平滑，压低高频抖动。

这一步平滑不是没有代价的。回到本文开头的策略 B：它原始曲线里那次"从 0.72 跌到 0.28"的深度回退，在平滑之后被削去了大半——处理前的最高点是 0.71、CRA 是 0.101、STR 是 0；处理后的最高点变成了 0.673，CRA 反而降到了 0.060。平滑在压制模型误判造成的噪声的同时,也会不可避免地压低真实回退的可见幅度。这也是为什么工具箱把 `progress_raw`（原始曲线）和 `progress_processed`（处理后曲线）都完整保留在输出里——诚实地承认平滑不是免费的，需要给使用者留一条能回头核对原始信号的路。

## 五、大规模评测揭示的现象：RoboDojo 上的五个发现

1.5 版本用 Robo-Dopamine（forward 模式）作为默认裁判，在 **RoboDojo**（一个覆盖真实机器人和仿真环境的统一基准）上评测了真实世界赛道的 9 个模型和仿真赛道的 16 个模型，覆盖 VLA 和 WAM 两大技术路线。这里选取三个最值得记住的发现。

**发现一：VLA 整体上比 WAM 表现更好。** 把仿真赛道 16 个模型按 11 项指标的综合排名统计，Top-3、Top-5、Top-10 里 VLA 的占比都明显高于 WAM——这是跨多个维度的排名统计，不是靠单一指标得出的结论。

**发现二：模型越大不代表越强。** 把参数量和 11 项指标的平均排名画成散点图，没有观察到正相关——不少参数量较小的模型排名反而更靠前，一些参数量很大的模型排名却落后。

**发现三："最后一米幻觉"依然存在。** 在多个任务上,几乎所有基线模型的 MC@25（越过 25% 里程碑的比例）都很高，但 MC@100（真正做完）骤降到接近于零。这类模型不是"没学会做这个任务"，而是**反复卡在最后收尾这一步**——这正是只看成功率完全看不出来、只有分档统计里程碑覆盖率才能暴露的现象。

同一批评测还确认了一件容易被忽略的事：**仿真表现和真机表现只有弱到中等的正相关**（Spearman 相关系数在 0.18 到 0.58 之间），而且九个共享模型在真机上的最大进度普遍低于仿真——尤其是需要精确对齐和复杂接触的任务（比如把管子插进插座、把杯子挂上挂钩），仿真到真机的差距最大。这提醒一个朴素但重要的结论：**仿真排名不能替代真机验证**，尤其是在评估接触密集型操作能力时。

## 六、RoboPulse++：给裁判本身找一个及格线

前面所有指标都建立在"PRM 的打分是可信的"这个假设上。如果裁判本身经常判错方向——把退步看成前进、把停滞看成进展——那么再精巧的指标体系也只是在放大噪声。为了检验这件事，论文构造了 **RoboPulse++**：700 条真实和仿真轨迹、275 个任务条目、17,052 帧、2,244 个人工标注的时间区间，每个区间被标成"上升"（Rising，任务相关状态在朝目标推进）或"下降"（Falling，在远离目标或撤销已完成的进展）。选择"方向"而不是"绝对完成度百分比"作为标注目标，是因为不同机器人、不同任务之间根本不存在一个统一的绝对进度刻度，但"这一段是在变好还是变差"是可以稳定判断的相对信号。

评测协议区分**成对式**（Pair Style，只看相邻两帧）和**序列式**（Sequence Style，看一整段有序的观测序列）两类裁判,并统一换算成 Rising/Falling 的方向预测,用 Macro-F1 和整体准确率打分。

<img src="/prm_judge_robopulse_rising_falling.png" alt="RoboPulse++ 上各裁判的 Rising F1 vs Falling F1 对比，以及 Falling 的精确率-召回率拆分" class="img-full">

结果里有两条清晰的规律：

**规律一：专用 PRM 明显强于通用视觉语言模型。** 表现最好的 Robo-Dopamine（forward 模式）拿到 Macro-F1 0.77、准确率 0.84；表现最好的通用模型 Gemini 3.1 Pro（成对式）只有 0.58 和 0.63。这说明专用裁判的优势不在于"看懂图里有什么"这种粗粒度的语义理解，而在于对物理演变过程的敏锐捕捉——这恰好呼应了第二节提出的"微观分辨率"要求。

**规律二：所有裁判都在"看跌"上明显弱于"看涨"。** 最好的 Falling F1 只有 0.63，而最好的 Rising F1 有 0.92。把 Falling 拆成精确率和召回率会发现,差距主要来自**召回率**——裁判不是把"上升"误判成"下降"，而是大量真实发生的退步**根本没被识别出来**。论文对 155 个抽样的 Falling 区间做了错误分析：78.1% 属于"物体交互失败"（比如抓取滑脱、放置错位），21.9% 属于"任务顺序错误"（做错了步骤顺序）。这提示训练数据里"退步"样本的稀缺是根本原因——成功轨迹和专家演示天然更容易采集,失败和退步的轨迹更难收集、标注也更难达成一致。

论文还专门比较了成对式和序列式裁判在"依赖历史上下文才能判断"的场景（比如一个子目标先完成又被撤销）下的表现：序列式的 RoboMeter 在这类样本上的 Falling 准确率达到 0.901，远高于成对式 Robo-Dopamine（forward）的 0.408。这说明只看两帧有一个结构性的盲区——**如果退步的意义依赖于更早之前的状态，两帧比较是天生看不出来的**，需要更长的时间上下文。

## 七、这套工具在真实使用中长什么样

理解了指标背后的设计,这一节简单说明工具箱怎么落地使用——这部分不涉及新的方法论,只是把前面讲的曲线和指标接到一个可复现的评测流程上。

### 7.1 输入：一份 JSONL 清单，而不是固定的目录结构

用户不需要把视频按某种约定的目录结构摆放，只需要写一份 JSONL 格式的清单，每行描述一个 rollout：

```json
{"case_id": "case_001", "task": "put the can into the basket", "video": "videos/case_001.mp4"}
```

需要更丰富信息时可以加上手腕视角、目标图像、已知标签、来源基准和策略名称：

```json
{"case_id": "case_004", "task_name": "arrange_flowers", "task": "arrange the flowers in the vase",
 "video": "h.mp4", "wrist_video": "w.mp4", "goal_image": "goal.png",
 "label": "success", "benchmark": "RoboTwin", "model": "pi0"}
```

`goal_image` 只在有可靠的成功状态参照（比如一次人工验证过的成功演示的最后一帧）时才填，并且**绝不能用被评测视频自己的最后一帧**（第 4.1 节已经解释过原因）。`label` 是可选的人工标注结果，默认情况下工具箱用 $MP \ge 0.99$ 这条规则自动判定成功/失败，但当基准自带了可靠标签时，可以用 `--success-source label` 切换成直接使用人工标签——这在成功判定阈值对某些任务不适用、或者需要和基准官方成功率对齐时很有用。

### 7.2 一条命令跑完整流程

```bash
MANIFEST=eval/examples/manifest_demo_cases.jsonl \
PRM_PATH="$PRM_PATH" \
VISUALIZE=1 \
bash eval/run_eval.sh
```

跑完之后，`eval/results/run_YYMMDD_HHMMSS/` 目录下会生成一份完整的评测产物：`per_case.jsonl`（每条 rollout 的原始曲线、处理后曲线和全部指标）、`metrics.xlsx`（按 Case / 任务 / 模型均值 / 模型中位数四张表汇总）、以及一个交互式 HTML 报告——报告里可以把 rollout 视频和它的进度曲线同步播放，拖动时间轴时曲线和视频画面联动，直接看到"这一帧对应曲线上的哪一个点、当前是在上升区、回退区还是停滞区"。

### 7.3 想接入自己的 PRM，只需要实现一个接口

工具箱把"曲线怎么来"和"指标怎么算"两件事彻底解耦：任何 PRM 后端只要能返回一个 $[0,1]$ 区间的绝对进度序列，就能直接接入现成的指标和报告流程,不需要重新实现任何统计逻辑：

```python
from prm_judge.prm.base import BasePRMAdapter
from prm_judge.schema import EvalCase, ProgressTrace

class MyAdapter(BasePRMAdapter):
    def predict(self, case: EvalCase, output_dir):
        scores = run_my_model(case.videos, case.task, case.goal_image)
        return ProgressTrace(
            case_id=case.case_id,
            progress=scores,
            source_scale="0_1",
            source_type="absolute",
        )
```

如果模型原生输出的是 $[0,100]$ 刻度或者逐步的增量而不是绝对进度，用 `--normalize` 和 `--source-type` 两个参数声明清楚，工具箱会在指标计算之前统一换算，不需要在适配器代码里手写转换逻辑。仓库里除了 Robo-Dopamine，还内置了 **RoboMeter**（序列式，通过 HTTP 服务调用，适合需要更长时间上下文的重复性或强上下文依赖任务）和 **recorded**（直接读取已经算好的曲线，用来在不跑模型的情况下单独调试指标和报告逻辑）两个后端可以参考。

## 八、局限性

论文在结论和讨论部分坦率列出了几个尚未解决的问题，值得单独强调：

- **成对式裁判的时间盲区**：Robo-Dopamine 这类只看两帧的裁判,天生难以判断"重复动作循环"和"真实持续进展"的区别——第六节的实验已经证明,这类场景下序列式裁判有明显优势，未来更自然的方向是让基础裁判本身具备更长的时间上下文，而不只是靠事后的多帧投票来弥补。
- **负向监督的稀缺**："退步"样本天然比"成功"样本更难收集、标注共识也更难达成，这直接导致所有裁判在 Falling 方向上系统性地弱于 Rising 方向。
- **低成本适配新场景**：新任务、新视角、新本体会不断出现，一个实用的基础裁判需要支持轻量适配，而不是每次都要重新全量训练。
- **评测-数据-训练的闭环还没打通**：论文明确把"用诊断出的失败模式反过来指导数据收集和训练目标设计"列为未来方向,但目前发布的还只是评测工具，这个闭环尚未在论文里完整验证。

## 九、总结

PRM-as-a-Judge 做的事情可以用一句话概括：**用一个能看懂视频的过程裁判,把"完成没有"这一个比特,换成一条能读出走到哪、走得稳不稳、卡在哪、能不能爬起来的进度曲线**。它的贡献分三层：概念层提出了进度势 $\Phi$ 和宏观一致性/微观分辨率这两个约束，把"什么是一个合格的过程裁判"讲清楚；指标层用 OPD 体系把一条曲线拆成结果、过程、诊断三种互补的信号,1.5 版本又补上了失败迫近度、恢复比率、成功质量分三个条件指标；工程层发布了一套可以直接跑起来的开源工具箱,把"喂视频进去、跑一条命令、拿到交互式报告"这件事变成了几分钟就能完成的操作。

对项目里已经出现过的知识点做一次串联：PRM 这个模型本身在 [过程奖励模型前置知识](/前置知识/000n_前置知识_Process_Reward_Model) 里作为**训练时的密集奖励**出现过；这里它换了一个身份，变成**评测时的密集裁判**——同一类模型架构，一个用来指导策略怎么学,一个用来诊断策略学得怎样。如果你在做 VLA 或 WAM 的强化学习后训练，看完 [VLA RL 奖励信号设计方法综述](/论文综述/S15_VLA_RL奖励信号设计方法综述) 会发现,训练阶段用 PRM 当奖励和评测阶段用 PRM 当裁判面临的是同一类风险——奖励黑客（reward hacking）在训练里意味着策略学会欺骗奖励函数,而评测里的对应风险是策略学会"看起来在进步"却没有真正解决任务，这也是为什么 RoboPulse++ 这类"给裁判本身打分"的基准同样重要。
