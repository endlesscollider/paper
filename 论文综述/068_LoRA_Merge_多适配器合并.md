# LoRA 合并：多适配器合并方法综合分析

> **综合分析文章**  
> **一句话概括**：当我们为不同任务训练了多个 LoRA 适配器后，能否将它们合并为一个统一的适配器？这就是 LoRA Merge 系列方法要解决的问题。核心方法包括线性加权平均、TIES Merging、DARE、LoraHub 等。

## 贯穿全文的例子

> 我们为 LLaMA-7B 训练了 3 个 LoRA 适配器：
> 1. LoRA-数学：擅长数学推理
> 2. LoRA-代码：擅长代码生成  
> 3. LoRA-对话：擅长日常对话
>
> **目标**：得到一个同时具备三种能力的模型，且不需要重新训练。
>
> **方案**：合并三个 LoRA → 一个统一适配器。

---

## 一、为什么需要 LoRA 合并？

### 1.1 多任务部署的困境

| 方案 | 优点 | 缺点 |
|------|------|------|
| 多个独立 LoRA + 路由 | 任务隔离 | 推理时需要任务检测 |
| 一个 LoRA 混合训练 | 简单 | 数据配比难调；可能冲突 |
| **合并多个 LoRA** | **无路由开销+多能力** | **可能性能下降** |

### 1.2 模型合并的理论基础

为什么模型可以合并？

**线性模式连通性 (Linear Mode Connectivity)**：在神经网络 loss landscape 中，从同一预训练模型出发的多个微调版本，它们之间的线性插值路径上 loss 通常不会显著增高。

$$
\mathcal{L}(\lambda W_1 + (1-\lambda) W_2) \lesssim \lambda \mathcal{L}(W_1) + (1-\lambda) \mathcal{L}(W_2)
$$

**这个公式在做什么**：说明把两个微调模型的权重按比例插值（走中间路线），loss 不会比两端模型各自 loss 的加权平均差太多——这是"直接平均权重也能得到一个还不错的模型"这件事背后的理论依据。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\lambda W_1 + (1-\lambda) W_2$ | **插值路上的一个点** | 两个模型权重之间连线上，按比例 $\lambda$ 混合出的一组新权重 |
| $\mathcal{L}(\lambda W_1+(1-\lambda)W_2)$ | **中间点的体检分** | 这组混合权重在任务上的 loss |
| $\lambda \mathcal{L}(W_1)+(1-\lambda)\mathcal{L}(W_2)$ | **两端体检分的加权平均** | 如果 loss 是"线性"的，理论上中间点应该正好等于这个值 |
| $\lesssim$ | **不会差太多的保证** | 中间点的真实 loss 顶多比这个理想线性平均值略高一点，不会突然爆炸 |

**用人话读**："从同一个预训练模型出发微调出来的两个模型，把它们的权重按比例混合一下，效果不会比两个模型效果的加权平均差太多。"

**为什么是这个形式**：这个不等式描述的是"线性模式连通性"——同源微调模型在 loss landscape 上的插值路径通常比较平坦，没有很高的"山峰"隔开它们，这正是简单加权平均合并 LoRA 能work的理论根基。
:::

## 二、合并方法详解

### 2.1 方法 1：线性加权平均

最简单的方法——直接对 LoRA 参数做加权平均：

$$
\Delta W_{\text{merged}} = \sum_{i=1}^{N} w_i \cdot \Delta W_i = \sum_{i=1}^{N} w_i \cdot B_i A_i
$$

**这个公式在做什么**：把 $N$ 个 LoRA 适配器的权重更新量，按各自的权重 $w_i$ 加权求和，直接合成一个新的更新量——这是最朴素的"多个专家意见取平均"做法。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\Delta W_i = B_i A_i$ | **第 $i$ 个 LoRA 专家的意见** | 第 $i$ 个任务学到的低秩权重更新量 |
| $w_i$ | **这个专家的话语权** | 决定第 $i$ 个 LoRA 在最终合并结果里占多大比重 |
| $\sum_i w_i = 1$ | **话语权分配规则** | 所有权重加起来必须是 1，相当于做一次凸组合（加权平均） |
| $\Delta W_{\text{merged}}$ | **合并后的新专家** | 融合了所有任务经验的统一更新量，直接叠加到基础模型权重上就能用 |

**用人话读**："给每个任务的 LoRA 分配一个权重，权重加起来是 1，然后把所有 LoRA 的更新量按权重加权求和，就得到一个统一的多任务更新。"

**为什么是这个形式**：这是"线性模式连通性"理论最直接的应用——既然插值路径上 loss 不会突然变差，那就直接在参数空间做加权平均，不需要任何额外训练。但正因为"简单"，它没有处理不同 LoRA 之间的方向冲突，这也是后面 TIES、DARE 要解决的问题。
:::

**实现**：

```python
def linear_merge(lora_list, weights):
    """线性加权合并多个 LoRA"""
    merged_A = sum(w * lora.A for w, lora in zip(weights, lora_list))
    merged_B = sum(w * lora.B for w, lora in zip(weights, lora_list))
    return merged_B, merged_A
```

**问题**：不同 LoRA 可能在参数空间中方向冲突，简单平均会"稀释"各自的特长。

### 2.2 方法 2：TIES Merging (2023)

**TIES (TrIm, Elect Sign, and merge)** 三步走：

1. **Trim（修剪）**：只保留每个 LoRA 中变化量最大的 top-k% 参数，其余设为零
2. **Elect Sign（选择符号）**：对于同一位置有冲突的参数（符号相反），投票选择多数方向
3. **Merge（合并）**：对齐方向后再加权平均

**为什么 TIES 更好？**
- Trim：消除了不重要的噪声参数
- Elect Sign：解决了方向冲突（"拔河"问题）
- 结果：合并后的模型在各任务上性能下降更小

### 2.3 方法 3：DARE (2024)

**DARE (Drop And REscale)**：

1. 以概率 $p$ 随机 Drop 每个 LoRA 的参数（设为零）
2. 将保留的参数 Rescale 为 $\frac{1}{1-p}$（保持期望值不变）
3. 然后做线性平均

$$
\Delta W_i^{\text{DARE}} = \frac{1}{1-p} \cdot \text{mask}_p \odot \Delta W_i
$$

**这个公式在做什么**：随机丢弃第 $i$ 个 LoRA 里的一部分参数，再把剩下的参数按比例放大，让丢弃前后的"期望总量"保持不变——这是 DARE 在合并前对每个 LoRA 做的预处理。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\text{mask}_p$ | **随机筛子** | 一个 0/1 掩码，每个位置以概率 $p$ 变成 0（丢弃），概率 $1-p$ 保留 |
| $\text{mask}_p \odot \Delta W_i$ | **丢弃后的残缺更新量** | 逐元素相乘，把被筛掉的位置直接清零 |
| $\frac{1}{1-p}$ | **补偿放大器** | 因为平均丢了 $p$ 比例的参数，把剩下的按 $\frac{1}{1-p}$ 倍放大，让整体期望值不变 |
| $\Delta W_i^{\text{DARE}}$ | **处理后的干净版更新量** | 稀疏化+补偿后的结果，拿去做后续线性平均 |

**用人话读**："每个 LoRA 先按概率 $p$ 随机丢掉一部分参数，剩下的按 $\frac{1}{1-p}$ 放大补偿，再拿这个处理后的版本去做加权平均。"

**为什么是这个形式**：随机丢弃能降低不同 LoRA 在同一参数位置"意见冲突"的概率（丢了就不会冲突），而 $\frac{1}{1-p}$ 的缩放保证了丢弃前后这个更新量的数学期望完全相同——不会因为丢参数而系统性削弱更新的整体幅度。
:::

### 2.4 方法 4：LoraHub (2023)

**LoraHub** 不是简单的固定权重合并，而是**学习合并权重**：

1. 在目标任务上准备少量样本（如 5 条）
2. 以合并权重 $w_1, ..., w_N$ 为优化变量
3. 最小化目标任务的 loss 来搜索最优权重

$$
w^* = \arg\min_{w} \mathcal{L}_{\text{target}}\left(\sum_i w_i \Delta W_i\right)
$$

**这个公式在做什么**：不再手工设定合并权重，而是把权重 $w$ 本身当成待优化的变量，在少量目标任务样本上直接搜索出能让 loss 最小的那组权重。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\sum_i w_i \Delta W_i$ | **候选合并方案** | 用当前这组权重 $w$ 合并出来的 LoRA 更新量（形式同线性加权平均） |
| $\mathcal{L}_{\text{target}}(\cdot)$ | **目标任务的考官** | 用目标任务的少量样本（如 5 条）给这个合并方案打分，分数越低越好 |
| $\arg\min_w$ | **搜索器** | 在所有可能的权重组合里，找出让考官打分最低的那一组 |
| $w^*$ | **最优权重方案** | 搜索出来的答案，用它合并出的 LoRA 在目标任务上表现最好 |

**用人话读**："不是拍脑袋定权重，而是拿目标任务的几条样本当考题，反复尝试不同的权重组合，直到找到考试分数最低（loss 最小）的那组权重。"

**为什么是这个形式**：手工设权重（如都设成 $1/N$）没有利用任何目标任务的信息，而把权重变成优化变量，能让合并结果针对具体目标任务"量身定制"——只需要少量样本和一次轻量优化（梯度下降或不需要梯度的 CMA-ES），就能明显逼近混合训练的效果上限。
:::

## 三、合并的数学分析

### 3.1 合并后的秩

设两个 LoRA：$\Delta W_1 = B_1 A_1$（秩 $r_1$），$\Delta W_2 = B_2 A_2$（秩 $r_2$）。

合并后：
$$
\Delta W_{\text{merged}} = w_1 B_1 A_1 + w_2 B_2 A_2
$$

**这个公式在做什么**：把两个秩分别为 $r_1$、$r_2$ 的 LoRA 更新量按权重相加，观察合并后的结果的"秩"（有效表达能力）发生了什么变化。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $w_1 B_1 A_1$ | **第一个任务的更新量** | 秩为 $r_1$ 的低秩矩阵，乘上权重 $w_1$ |
| $w_2 B_2 A_2$ | **第二个任务的更新量** | 秩为 $r_2$ 的低秩矩阵，乘上权重 $w_2$ |
| $\Delta W_{\text{merged}}$ | **合并后的完整更新量** | 两个低秩矩阵直接相加得到的新矩阵，不再是单一的 $BA$ 形式 |
| $\text{rank}(\Delta W_{\text{merged}}) \leq r_1+r_2$ | **表达能力的天花板** | 合并后矩阵的秩最多是两个原始秩之和，不会更高 |

**用人话读**："把两个低秩更新量按权重加起来，得到的新矩阵的秩最多是两个秩加起来那么大——合并没有减少表达能力，反而可能增加了。"

**为什么是这个形式**：矩阵加法的秩满足次加性（$\text{rank}(A+B)\le\text{rank}(A)+\text{rank}(B)$），这是线性代数的基本性质。这个结论的意义在于：合并多个 LoRA 不是简单的"信息压缩"，而是可能拿到一个比单个 LoRA 表达能力更强的更新——代价是这个结果不再能用一对小的 $(B,A)$ 精确表示，需要额外处理（见下文 SVD 重新分解）。
:::

如果 $A_1, A_2$ 的行空间有重叠，实际秩可能小于 $r_1 + r_2$。

**含义**：合并 $N$ 个秩为 $r$ 的 LoRA，最多得到秩为 $Nr$ 的更新——这实际上增加了表达能力！

### 3.2 合并后如何保存？

合并后的 $\Delta W_{\text{merged}}$ 秩可能 > $r$，不能再用单个 $(B, A)$ 对精确表示。

**解决方案**：
1. 对 $\Delta W_{\text{merged}}$ 做 SVD，取前 $r'$ 个分量作为新的 LoRA
2. 或者直接将 $\Delta W_{\text{merged}}$ 加到基础权重中（合并到模型权重）

## 四、实验对比

在 LLaMA-7B 上合并 3 个 LoRA（数学/代码/对话）：

| 合并方法 | 数学能力 | 代码能力 | 对话能力 | 平均保留率 |
|---------|---------|---------|---------|-----------|
| 单独 LoRA-数学 | 100% | 20% | 15% | 45% |
| 线性平均 | 72% | 65% | 70% | 69% |
| TIES | 78% | 71% | 74% | 74% |
| DARE ($p=0.9$) | 80% | 73% | 76% | 76% |
| LoraHub (学习权重) | **85%** | **79%** | **78%** | **81%** |
| 混合训练 (上限参考) | 88% | 82% | 85% | 85% |

**关键发现**：
- 简单平均已经能保留约 70% 的各任务能力
- DARE 和 TIES 显著优于简单平均
- LoraHub 学习权重后接近混合训练上限

## 五、代码实现

```python
import torch
from typing import List, Dict

def ties_merge(lora_params: List[Dict[str, torch.Tensor]], 
               weights: List[float],
               trim_ratio: float = 0.8) -> Dict[str, torch.Tensor]:
    """TIES Merging 实现"""
    merged = {}
    
    for key in lora_params[0].keys():
        deltas = [p[key] * w for p, w in zip(lora_params, weights)]
        
        # Step 1: Trim - 保留 top (1-trim_ratio)% 的参数
        trimmed = []
        for delta in deltas:
            threshold = delta.abs().quantile(trim_ratio)
            mask = delta.abs() >= threshold
            trimmed.append(delta * mask)
        
        # Step 2: Elect Sign - 投票决定每个位置的符号
        signs = torch.stack([t.sign() for t in trimmed])
        elected_sign = signs.sum(dim=0).sign()  # 多数投票
        
        # Step 3: Merge - 只合并与多数符号一致的值
        result = torch.zeros_like(trimmed[0])
        count = torch.zeros_like(trimmed[0])
        for t in trimmed:
            agree = (t.sign() == elected_sign) | (t == 0)
            result += t * agree
            count += agree.float()
        
        merged[key] = result / count.clamp(min=1)
    
    return merged
```

## 六、总结

### 核心要点

1. **LoRA 合并是实现多能力模型的低成本方案**
2. **简单平均 < TIES/DARE < 学习权重**
3. **合并后秩增加**，表达能力可能超过单个 LoRA
4. **适用场景**：需要多种能力但不想维护多个适配器
