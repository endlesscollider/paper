# LifeLong-RFT：用可验证过程奖励做 VLA 持续强化微调

> **论文**: *Towards Long-Lived Robots: Continual Learning VLA Models via Reinforcement Fine-Tuning*<br>
> **作者**: Yuan Liu, Haoran Li, Shuai Tian, Yuxing Qin, Yuhui Chen, Yupeng Zheng, Yongzhen Huang, Dongbin Zhao<br>
> **版本**: arXiv:2602.10503v2, 2026-05-16<br>
> **项目页**: https://yuan-liu-lifelong-rft.github.io/<br>
> **综述上下文**: [持续/终身 VLA 强化学习综述](./S07_持续终身VLA强化学习综述)

## 一、它解决什么问题

VLA 通常通过专家示教做 SFT。当机器人需要用少量新示教持续学习新任务时，SFT 存在两个问题：

1. 对新任务的数据需求高。
2. 新任务的监督梯度可能覆盖旧任务能力。

LifeLong-RFT 将专家示教中的 observation/instruction 当作起点，从当前 VLA 采样多个 action chunk，再根据它们与参考动作的一致性构造可验证奖励，用 GRPO 做 chunk-level reinforcement fine-tuning。

需要准确理解的是：

- 它的奖励来自**专家动作标签与格式检查**，不是机器人在环境中完成任务后的 online success reward。
- 它不需要在训练期间与环境交互，也不需要额外预训练 reward model。
- 它仍然依赖已标注的参考轨迹，因此更接近“用 RL 目标改造的示教后训练”，不是无示教的纯在线 RL。

## 二、Chunk-level GRPO

对一个 observation $o$ 和语言指令 $l$，从旧策略采样 $G$ 个 action chunk：

$$
\{a_i\}_{i=1}^{G}\sim\pi_{\theta_{old}}(\cdot\mid o,l).
$$

**这个公式在做什么**：对同一个观测和指令，用旧策略采样出一组（$G$ 个）不同的 action chunk，作为后续打分和比较的候选集合。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\pi_{\theta_{old}}(\cdot\mid o,l)$ | **旧策略的动作分布** | 更新前的 VLA 策略，在给定观测 $o$ 和指令 $l$ 下会输出的动作分布 |
| $a_i$ | **第 $i$ 个候选动作块** | 从这个分布里采样出来的一个 action chunk（一段连续动作序列） |
| $\{a_i\}_{i=1}^G$ | **一组候选** | 一共采样 $G$ 次，得到 $G$ 个不同的候选动作块，供组内互相比较打分 |

**用人话读**："让旧策略针对同一个场景和指令，重复采样 $G$ 次，得到 $G$ 份不同的动作方案，留着接下来打分对比。"

**为什么要采样一组而不是一个**：GRPO（Group Relative Policy Optimization，组内相对策略优化）的核心思想是不需要额外训练 critic，而是靠"组内互相比较"来估计相对好坏，所以必须先采出一组候选。
:::

每个 chunk 得到可验证奖励 $r_i$，组内标准化得到 advantage：

$$
A_i=\frac{r_i-\operatorname{mean}(r_1,\ldots,r_G)}
{\operatorname{std}(r_1,\ldots,r_G)}.
$$

**这个公式在做什么**：把每个候选动作块的原始奖励，减去组内平均再除以组内标准差，变成一个"相对组内水平是好是差"的标准化优势分。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $r_i$ | **原始奖励** | 第 $i$ 个候选动作块拿到的可验证奖励分数 |
| $\operatorname{mean}(r_1,\ldots,r_G)$ | **组内平均水平** | 这一组 $G$ 个候选的平均分，作为参照基准 |
| $\operatorname{std}(r_1,\ldots,r_G)$ | **组内波动幅度** | 这一组分数的标准差，用来把差值缩放到统一尺度 |
| $A_i$ | **标准化优势** | 减去均值、除以标准差之后的结果，正代表比组内平均好，负代表比组内平均差 |

**用人话读**："看这个动作块的分数比同组其他候选平均分高出多少个标准差，高就是好动作，低就是差动作。"

**为什么不需要训练 critic**：因为基准（均值）和尺度（标准差）都直接从同一组采样里统计出来，不需要额外网络去预测"平均水平应该是多少"，这正是 GRPO 相比传统 PPO 省显存的原因。
:::

优化目标采用 GRPO/PPO 式 clipping，并加入参考策略 KL 正则，限制策略过度偏移。不训练显式 critic，因此比大型 VLA 的 actor-critic PPO 更省显存。

## 三、三维可验证过程奖励

论文 v2 中的三个奖励是 **QACR、CTAR 和 FCR**，而不是环境进度、安全性和效率奖励。

### 3.1 QACR：量化动作一致性

Quantized Action Consistency Reward 比较预测动作 token $a$ 与参考 token $\tilde a$ 在各个位置是否匹配：

$$
R_{\mathrm{QACR}}=
\frac{\sum_{k=1}^{\min(U,V)}\mathbb{I}(a_k=\tilde a_k)}
{\max(U,V)}.
$$

**这个公式在做什么**：逐个位置比较预测的动作 token 和参考动作 token 是否完全一致，算出一个"逐字符匹配率"作为奖励。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $a_k$、$\tilde a_k$ | **预测 token / 参考 token** | 第 $k$ 个位置上，模型预测的动作 token 和专家参考的动作 token |
| $\mathbb{I}(a_k=\tilde a_k)$ | **逐位裁判** | 这个位置预测对了记 1 分，错了记 0 分 |
| $\min(U,V)$ | **可比较长度** | 预测序列长度 $U$ 和参考序列长度 $V$ 中较短的一个，避免越界比较 |
| $\max(U,V)$ | **归一化分母** | 用较长的那个长度做分母，长度不一致本身也会拉低分数 |

**用人话读**："把预测的动作 token 序列和参考序列逐位对齐比较，算对了几个位置，再除以两者中较长的长度，得到一个 0 到 1 之间的匹配率。"

**为什么用 $\max(U,V)$ 而不是 $\min(U,V)$ 做分母**：如果预测序列比参考序列短或长，说明输出本身有问题，用较长的长度做分母会自动惩罚长度不一致的情况，而不是只看重叠部分。
:::

无法通过 Fast+ tokenizer 格式检查的输出直接得 0 分。

### 3.2 CTAR：连续轨迹对齐

Continuous Trajectory Alignment Reward 先将 action token 解码回连续 action chunk，然后同时比较 pose 和 gripper：

$$
d_t=\frac{1}{D}\lVert y_t^{pose}-\tilde y_t^{pose}\rVert_1,
\qquad r_t^{pose}=\exp(-\alpha d_t),
$$

**这个公式在做什么**：先算出预测姿态和参考姿态之间的平均绝对误差，再把这个误差通过指数函数转换成一个"越接近越接近满分 1"的奖励。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $y_t^{pose}$、$\tilde y_t^{pose}$ | **预测姿态 / 参考姿态** | 第 $t$ 步解码出的连续动作姿态，以及专家参考姿态 |
| $\lVert y_t^{pose}-\tilde y_t^{pose}\rVert_1$ | **总偏差** | 两者各维度差值的绝对值之和（L1 距离） |
| $\frac{1}{D}(\cdot)$ | **按维度摊平** | 除以维度数 $D$，得到平均每维的偏差，避免维度越多惩罚越重 |
| $d_t$ | **平均姿态误差** | 归一化后的每步姿态偏差 |
| $\exp(-\alpha d_t)$ | **误差转奖励** | 误差为 0 时输出 1（满分），误差越大输出越接近 0，$\alpha$ 控制衰减速度 |

**用人话读**："算出预测姿态和参考姿态平均每维差多少，再用指数函数把这个差值压成一个 0 到 1 之间的分数，差得越少分越高。"

**为什么用指数衰减而不是直接用 $-d_t$**：直接用负误差当奖励，数值范围不固定、可能是很大的负数，训练不稳定；指数变换把奖励限制在 $(0,1]$ 区间，且误差为 0 时恰好取到最大值 1，数值上更适合和其他奖励项相加。
:::

$$
r_t^{grip}=\mathbb{I}(y_t^{grip}=\tilde y_t^{grip}),
$$

**这个公式在做什么**：夹爪状态是离散的开/合，直接比较预测和参考是否一致，一致给满分，不一致给零分。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $y_t^{grip}$、$\tilde y_t^{grip}$ | **预测夹爪状态 / 参考夹爪状态** | 第 $t$ 步预测的夹爪开合状态和专家参考状态 |
| $\mathbb{I}(\cdot)$ | **是非裁判** | 两者相等输出 1，不相等输出 0 |
| $r_t^{grip}$ | **夹爪奖励** | 这一步夹爪动作是否判断正确 |

**用人话读**："夹爪只有开和合两种状态，预测对了给 1 分，预测错了给 0 分，没有中间地带。"

**为什么姿态用连续奖励、夹爪用二值奖励**：姿态是连续量，差一点也算"接近对"，适合用连续衰减打分；夹爪是离散动作，开合状态错了就是彻底错了（比如该合的时候开着会导致抓空），不存在"部分正确"，所以用严格的 0/1 判断。
:::

$$
R_{\mathrm{CTAR}}=\frac{1}{H}\sum_{t=1}^{H}
\left[\beta r_t^{pose}+(1-\beta)r_t^{grip}\right].
$$

**这个公式在做什么**：把整个 action chunk 里每一步的姿态奖励和夹爪奖励按权重合并，再对所有步取平均，得到这一整段轨迹的连续对齐总分。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\beta r_t^{pose}$ | **姿态分量** | 姿态奖励乘上权重 $\beta$，决定姿态对齐在总分里占多大比重 |
| $(1-\beta) r_t^{grip}$ | **夹爪分量** | 夹爪奖励乘上剩余权重，两者权重加起来正好是 1 |
| $\frac{1}{H}\sum_{t=1}^H(\cdot)$ | **逐步平均** | 把 chunk 里 $H$ 步的每步合并分数加起来再取平均，得到整段的总体表现 |
| $R_{\mathrm{CTAR}}$ | **连续轨迹对齐总分** | 这一整个 action chunk 与参考轨迹的综合相似度 |

**用人话读**："每一步先把姿态分和夹爪分按权重加起来，再把这一整段动作块里所有步骤的分数取平均，得到这段动作和参考轨迹有多像。"

**为什么要对时间步取平均而不是只看最后一步**：机器人操作是连续过程，每一步的姿态和夹爪状态都会影响最终结果，只看终点会漏掉中途的错误（比如路径对了但中途姿态飘忽），逐步平均能更全面反映整体轨迹质量。
:::

这一项是论文最重要的奖励。消融实验中去掉 CTAR 后，LIBERO 平均成功率从 95.6% 降到 4.7%。

### 3.3 FCR：格式合规

Format Compliance Reward 是二值奖励：

$$
R_{\mathrm{FCR}}=\mathbb{I}[\text{action chunk 尺寸和动作维度合法}].
$$

**这个公式在做什么**：检查模型输出的动作块是不是能被正常解码成合法的动作格式，格式不对直接判 0 分。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| "action chunk 尺寸和动作维度合法" | **格式校验条件** | 检查输出的动作块长度、每个动作的维度数是否和预期一致，能不能被 tokenizer 正常解码 |
| $\mathbb{I}[\cdot]$ | **合法性开关** | 条件成立输出 1（格式正常），不成立输出 0（格式损坏） |
| $R_{\mathrm{FCR}}$ | **格式合规奖励** | 这个二值分数，用来兜底防止自回归模型生成乱码动作 |

**用人话读**："检查这段动作输出是不是长度、维度都对得上、能被正常解码，能就给 1 分，不能就给 0 分。"

**为什么需要单独一个格式奖励**：自回归模型生成 token 序列时偶尔会输出损坏或不完整的序列，这类输出无法解码成有效动作，QACR 和 CTAR 都无法评估，所以需要一个前置的格式检查兜底。
:::

它防止自回归 VLA 生成不可解码的动作 token 序列。

### 3.4 总奖励

$$
r=\omega R_{\mathrm{QACR}}
+(1-\omega)R_{\mathrm{CTAR}}
+\lambda R_{\mathrm{FCR}}.
$$

**这个公式在做什么**：把三个维度的可验证奖励（token 匹配率、连续轨迹对齐、格式合规）按权重加权求和，得到最终喂给 GRPO 的总奖励。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $\omega R_{\mathrm{QACR}}$ | **离散匹配分量** | token 级逐位匹配率乘上权重 $\omega$，衡量"字面上"预测对了多少 |
| $(1-\omega) R_{\mathrm{CTAR}}$ | **连续对齐分量** | 连续轨迹对齐分乘上剩余权重，衡量解码后的真实动作有多接近参考 |
| $\lambda R_{\mathrm{FCR}}$ | **格式合规分量** | 格式合规奖励乘上一个较小的独立权重 $\lambda$，作为兜底加分项 |
| $r$ | **最终总奖励** | 三部分加权求和后的标量，直接用来计算 GRPO 的组内标准化优势 |

**用人话读**："总奖励 = token 匹配率占 70%的权重 + 连续轨迹对齐占剩下的权重 + 格式合规再额外加一点分。"

**为什么 QACR 和 CTAR 用互补权重（$\omega$ 与 $1-\omega$）而 FCR 独立加权**：QACR 衡量离散 token 层面、CTAR 衡量解码后连续动作层面，两者是对同一件事（预测准不准）的两种互补视角，用互补权重保证总权重不超标；FCR 只是格式兜底检查，性质不同，所以单独给一个小权重 $\lambda$ 而不占用前两者的份额。
:::

论文使用 $\omega=0.7$ 和 $\lambda=0.1$。

## 四、持续学习设置

LifeLong-RFT 的 LIBERO continual learning 实验遵循 LOTUS 设定：

1. 在每个 LIBERO suite 的前 6 个任务上做 base-task 训练，每任务 50 条示教。
2. 后 4 个任务依次到来，每个新任务只用 10 条示教。
3. 对每个已学任务保留 5 条示教做 Experience Replay。
4. 每学完一个新任务，评估所有已学任务，计算 FWT、NBT 和 AUC。

因此，LifeLong-RFT 并不是 replay-free continual learning，也没有在 50 个顺序任务上验证。它解决的是“有少量旧示教和少量新示教时，如何用 RFT 提高适应效率并减少遗忘”。

## 五、实验结论

### 5.1 联合多任务学习

以 NORA-Long 为 backbone，LifeLong-RFT 在 LIBERO Object/Spatial/Goal/Long 上的成功率分别为 99.2%、98.2%、95.8% 和 89.0%，平均 95.6%；对应 SFT baseline 平均为 91.8%。

### 5.2 持续学习

在四个 LIBERO suite 的 6+4 设定中，LifeLong-RFT 相对 NORA-Long SFT 同时改善了 FWT、NBT 和 AUC。其中 LIBERO-Goal 的 AUC 提升 35.9 个点。

论文摘要中的“平均成功率提升 22%”是指 continual LIBERO 实验中相对 SFT 的总体改善，不应解读为已在 50 任务上证明了 22% 收益。

### 5.3 真实机器人

在 Pick Banana、Pick Bread、Pull Drawer 和 Hang Chinese Knot 四个任务上，RFT 平均成功率为 87.5%，对应 NORA-Long SFT 为 78.8%。持续设定中，新任务使用 20 条示教，每个旧任务保留 5 条示教。

## 六、优点、局限与正确定位

| 维度 | 评价 |
|---|---|
| 核心贡献 | 把动作 token 正确性、连续控制误差和格式合法性统一为 chunk-level 可验证奖励 |
| 数据效率 | 对新任务仅使用标准 SFT 数据量的 20% |
| 训练成本 | 无 critic，无训练期环境交互，但论文实验仍使用 8 张 NVIDIA H20 |
| 防遗忘机制 | 小量 Experience Replay + 参考策略 KL + RFT 的选择性更新 |
| 主要局限 | 奖励依赖参考动作；continual 阶段只有 4 个新任务；不能替代真正环境奖励的在线自我改进 |

LifeLong-RFT 最适合的场景是：已有预训练离散动作 VLA 和少量示教，希望在不重新访问环境的条件下，比普通 SFT 更有效地适应新任务。如果研究问题是 50 个任务的长期 on-policy RL，它应作为有限 replay 基线，而不是已完成的最终解法。
