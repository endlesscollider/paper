## 贯穿全文的例子

> **场景**：你拿手机对着家里的厨房台面拍了一段 10 秒的视频——台面上有一个杯子、一个碗、一个抽屉柜。你希望：(1) 电脑能把这段视频自动变成一个物理仿真里的场景,杯子能被抓起来、抽屉能被拉开；(2) 不只是原样复刻这个场景，还能自动生成"同一个抽屉柜，但换了一个杯子的样子""同一个杯子，但摆在略微不同的位置""同样的场景，但任务变成把碗叠在杯子上面而不是把杯子放进碗里"这些变体，用来训练一个更鲁棒的机器人操作策略——而这一切都不需要你手动做任何 3D 建模或物理参数标注。这正是 SimFoundry 要做到的事。

## 一、这篇论文解决什么问题

### 1.1 "数字孪生"这条路线本身还不够

[RialTo](./114_RialTo_数字孪生RL策略学习) 已经验证了"把真实场景重建进仿真、在仿真里用 RL 打磨鲁棒性"这条 Real-to-Sim-to-Real 路线是可行的。但 RialTo 的重建环节依赖用户在交互式界面里**手动标注**——给可移动部件打刚体标签、给铰接部件手动加关节约束、手动对齐坐标系。这个标注步骤虽然比从零手工建模快得多，但仍然需要人工介入，扩展到大量不同场景时是一笔持续的人力成本。

更进一步的问题是：即便一个场景被精确重建成了数字孪生，这个数字孪生**只有一个**——它精确复刻了拍摄时刻的那一个具体场景配置（那一个杯子、那一个抽屉位置）。而机器人策略要在真实世界里应对的场景，几乎不可能和采集数据时刻的场景完全一致——真实世界里的杯子每次摆放位置都会有细微差异，甚至可能换成另一个杯子。只在这一个精确的数字孪生里训练，策略的鲁棒性提升是有边界的。

### 1.2 SimFoundry 的两个核心目标

SimFoundry 同时针对上面两个问题给出方案：

1. **全自动化重建**：输入只是一段普通的真实世界视频，输出是一个"仿真就位"（sim-ready）的可交互数字孪生——不需要任何人工标注环节。
2. **数字"表亲"（Digital Cousins）生成**：在重建出的数字孪生基础上，自动生成大量"保留了几何/语义可操作性，但和原场景略有不同"的变体场景——这些变体不是原样复制,而是像"表亲"一样和原场景有家族相似性但各自独立。

**"数字表亲"这个概念的来源**：这个概念最早由 Stanford 团队在 [ACDC](https://arxiv.org/abs/2410.07408)（Automated Creation of Digital Cousins, 2024）这篇工作中提出，核心洞察是——如果只在"数字孪生"（和真实场景一模一样的单一副本）里训练，策略学到的鲁棒性范围局限于这一个具体场景；而"数字表亲"（同类但不同的场景变体，比如换一个不同形状的杯子、换一个不同尺寸的抽屉）提供的是一个**场景分布**而不是单点，用一个分布去训练，策略自然获得了更好的泛化能力。SimFoundry 把这个概念从 ACDC 针对单张图片的原型系统，扩展成了一整套模块化、自动化、支持视频输入的完整生产管线。

### 1.3 三个层次的"表亲"变化

SimFoundry 把"数字表亲"细分成三个独立的变化维度，对应真实世界里策略需要应对的三种不同类型的分布偏移：

| 表亲类型 | 变化的对象 | 具体含义 | 举例 |
|---------|-----------|---------|------|
| Object Cousin（物体表亲） | 场景中某个具体物体的外观/几何 | 保留物体的功能可操作性（比如仍然是"可以被抓起的杯子形状"），但换成不同的具体样式 | 原场景的白色马克杯 → 变体场景里换成一个蓝色带把手的陶瓷杯 |
| Scene Cousin（场景表亲） | 整体场景布局/背景 | 保留物体之间的空间关系和可操作性，但改变背景、光照、场景整体风格 | 原场景是白色橱柜厨房 → 变体场景换成木质橱柜厨房 |
| Task Cousin（任务表亲） | 需要完成的任务目标本身 | 同一个场景和物体集合，但要求达成的目标状态不同 | 原任务是"把杯子放进碗里" → 变体任务是"把碗倒扣在杯子上" |

**回到我们的例子**：厨房台面的那段视频重建出数字孪生之后，Object Cousin 会自动生成"同一个抽屉柜，但杯子换了个样子"的变体；Scene Cousin 会生成"同样的物体摆放关系，但整体厨房风格换了"的变体；Task Cousin 会生成"同一个场景和物体，但目标任务从'放进'变成'叠放'"的变体。三者可以独立组合，构成一个远比单一数字孪生丰富得多的训练场景分布。

## 二、SimFoundry 的三阶段模块化管线

SimFoundry 的系统架构被设计成三个顺序执行的阶段——**Extraction（提取）→ Generation（生成）→ Augmentation（增强）**——每个阶段内部由多个可独立替换的模块组成。这种模块化设计的好处是：任何一个环节用到的具体技术（比如分割模型、深度估计模型）未来有更好的替代品出现时，只需要替换对应模块，不需要重新设计整个系统——论文里称这个特性为"随基础模型进步而自动变强"。

```mermaid
flowchart LR
    A["输入：单段<br/>真实世界视频"] --> B["阶段一：Extraction<br/>逐物体提取<br/>分割掩码/深度信息"]
    B --> C["阶段二：Generation<br/>2D→3D生成模型<br/>产出物体网格<br/>+ 3DGS背景重建"]
    C --> D["阶段三：Augmentation<br/>标注物理参数<br/>物理仿真器合理性检查<br/>组装成sim-ready场景"]
    D --> E["数字孪生<br/>Digital Twin"]
    E --> F["Object/Scene/Task<br/>Cousin 编辑"]
    F --> G["大规模数字表亲<br/>场景分布"]
```

### 2.1 阶段一：Extraction——从视频里"认出"场景中有哪些独立物体

给定输入视频，第一阶段负责识别视频里出现的每一个独立物体，并为每个物体提取后续阶段需要的基础视觉信息：**分割掩码**（这个物体在画面里对应哪些像素）、**深度信息**（这个物体离相机有多远，帮助恢复三维空间关系）。这一步依赖成熟的开放词汇分割和单目/多目深度估计基础模型，把一段连续的视频流，拆解成"场景里有哪几个物体，每个物体在画面里的轮廓和大致空间位置是什么"这样一份结构化的中间表示。

### 2.2 阶段二：Generation——把每个物体和背景分别变成 3D 表示

第二阶段针对上一步识别出的**每个独立物体**，用 2D 到 3D 的生成模型（这类模型接收物体的图像片段，输出对应的三维网格），单独生成该物体的三维几何和外观模型。物体和背景被分开处理有一个重要的工程意义：物体网格是独立的、可以在后续被单独挪动/替换/编辑的资产，而**背景部分**则用[3D Gaussian Splatting](/前置知识/007a_前置知识_3D_Gaussian_Splatting三维场景重建)整体重建成一个连续的高保真视觉场景——因为背景（墙面、地面、固定家具背板等）通常不需要被单独操作或编辑，用椭球群整体重建视觉逼真度更高、更快。

**为什么要把前景物体和背景分开处理**：如果整个场景（物体+背景）都用一整块 3DGS 椭球群表示，虽然视觉效果好,但后续无法把某个物体单独"拿出来"编辑（比如换成另一个物体，或者移动到新位置）——因为椭球群是一个整体，没有物体级别的语义边界。分开处理之后，物体是独立的、语义清晰的网格资产（可以单独替换、移动），背景是一整块连续的视觉背景（不需要编辑，只需要好看），两者各取所长。

### 2.3 阶段三：Augmentation——补全物理属性，组装成可用的仿真场景

第三阶段把前两步产出的几何和视觉资产,转换成物理仿真器真正能运行的"活"场景：

- **标注物理参数**：给每个物体标注质量、摩擦系数、碰撞体形状等物理属性，给需要开合的部件（抽屉、柜门）标注关节类型和限位。
- **物理仿真器合理性检查**（sanity check）：把标注好的场景放进物理仿真器里跑一遍,自动检测是否存在明显的物理错误——比如物体悬空没有支撑、碰撞体互相穿插、关节轴方向标注错误导致部件运动异常。检测到问题的场景会被自动标记或修正，而不需要人工逐个检查。

这一整套自动化流程，最终产出一个**sim-ready**（仿真就位）的数字孪生——一个可以直接被物理仿真器加载、支持碰撞检测、支持机器人策略与之交互的可交互场景，全程不需要任何人工标注介入。

### 2.4 数字表亲的编辑机制

有了结构化的、物体级别可编辑的数字孪生之后，生成三类数字表亲变成了对已有资产的**编辑**操作，而不需要重新走一遍整个重建管线：

- **Object Cousin**：对场景里某个具体物体，检索/生成一个功能相似但外观不同的替代资产，替换进场景里同一个位置。
- **Scene Cousin**：调整背景的视觉风格（材质、光照、纹理），保持物体的空间布局关系不变。
- **Task Cousin**：基于同一批物体资产，重新指定目标状态（不同的谓词组合,比如"in"变成"on"，"open"变成"closed"）,生成新的任务定义。

三种编辑各自独立，可以自由组合，理论上从一段输入视频出发，可以自动衍生出数量巨大的场景+任务变体组合。

## 三、评测方法论：怎么验证"仿真里训出来的策略真的能预测真实表现"

Real2Sim 工作流最容易被质疑的一点是：即使重建出的场景视觉上很逼真，仿真里的物理行为和评测结果,能不能真的预测真实世界的表现？如果不能，那整套 real2sim2real 的价值就要打问号。

### 3.1 实验设置

论文在 7 个操作任务、5 种不同的策略架构上（涉及多步骤操作、铰接物体交互、双臂协调等有难度的任务类型）系统性地对比：**同一个策略在 SimFoundry 重建的仿真场景里评测出的成功率，和在真实世界里评测出的成功率，两者相关性有多强**。

### 3.2 核心结果：强相关性

结果显示，SimFoundry 仿真评测和真实世界表现之间的**平均 Pearson 相关系数达到 0.911**（皮尔逊相关系数衡量两组数值线性相关的强弱，取值范围 $[-1,1]$，越接近 1 说明两者变化趋势越一致），同时平均最大排名违背程度（衡量"仿真里排名靠前的策略，是否在真实世界里也排名靠前"这个顺序一致性）低至 0.018。作为对比,论文中提到的基线方法（[PolaRiS](https://polaris-evals.github.io/)）在同样的评测设置下相关系数明显更低。这个结果说明：**在 SimFoundry 重建的场景里做策略评测和筛选，可以相当可靠地预测这些策略部署到真实世界后的实际表现**——这对于"先在仿真里筛选策略、再挑最好的部署真机"这种研发流程具有直接的工程价值,可以大幅减少不必要的真机测试次数。

### 3.3 数字表亲对零样本迁移的具体提升幅度

论文进一步测量了三类数字表亲各自对策略泛化能力的贡献——用仅包含数字孪生（无表亲变体）训练的策略作为基线，分别加入 Object、Scene、Task 表亲训练后,在真实世界零样本部署的平均任务成功率提升：

| 数字表亲类型 | 平均成功率提升 |
|-------------|--------------|
| Object Cousin | +17% |
| Scene Cousin | +21% |
| Task Cousin | +40% |

**Task Cousin 提升幅度最大的原因**：物体外观变化（Object Cousin）和场景风格变化（Scene Cousin）主要帮助策略提升的是**视觉鲁棒性**（认出略微不同的物体、适应不同的背景），而任务目标变化（Task Cousin）帮助策略学习的是**更泛化的操作逻辑**本身——理解"in"和"on"这类不同空间关系谓词具体要求末端执行器做什么样的动作序列，这类更抽象的能力一旦具备，往往能迁移到更广泛的真实场景变化中,而不仅仅是视觉层面的鲁棒性,这也解释了为什么它的提升幅度明显超过另外两种表亲类型。

## 四、和相关工作的关系

### 4.1 和 RialTo 的对比：自动化程度与表亲生成能力

| 维度 | RialTo | SimFoundry |
|------|--------|------------|
| 输入 | 手机扫描/专用 3D 重建工具 | 单段普通视频 |
| 标注方式 | 交互式界面人工标注刚体/关节/物理参数 | 全自动（分割+深度+2D-3D生成+物理合理性检查） |
| 背景重建技术 | 传统网格重建工具 | 3D Gaussian Splatting |
| 变体生成能力 | 仅支持位姿/干扰物/外力扰动（同一批资产内的数值扰动） | 支持 Object/Scene/Task 三个维度的资产级"表亲"编辑 |
| 鲁棒性来源 | 仿真内 PPO 扰动训练 | 数字表亲提供的场景分布 + 仿真内策略训练 |
| 系统评测能力 | 论文未系统评测仿真-真实相关性 | 明确测量并报告 0.911 的 Pearson 相关系数 |

SimFoundry 可以看作是在 RialTo 验证的"Real-to-Sim-to-Real 整体范式可行"基础上，把重建环节的自动化程度和场景多样性生成能力都往前推进了一大步——用生成式 AI（2D-3D 生成模型、开放词汇分割）替代了人工标注环节，用"表亲"编辑替代了单纯的数值扰动。

### 4.2 和 DreamGen 的对比：两条并行但互补的数据规模化路线

[DreamGen](./131_DreamGen_视频世界模型生成机器人训练数据) 用视频生成模型在像素空间"想象"新场景的视频，完全绕开物理仿真；SimFoundry 走的是相反方向——先把真实场景重建成一个**真正带物理引擎的**可交互仿真环境,再在这个物理精确的环境里生成变体和训练策略。两者的核心取舍不同：

- DreamGen 不需要任何物理建模，能覆盖仿真难以精确建模的接触密集型任务，但生成视频的物理合理性无法保证，且提取的伪动作标签有噪声。
- SimFoundry 需要完整的物理重建流程，但换来的是精确的碰撞检测、可靠的强化学习训练环境，以及论文中验证过的、能够预测真实表现的评测能力。

两条路线可以视作互补：物理仿真擅长的任务（刚体操作、精确的几何交互）用 SimFoundry 这类方法，仿真难以覆盖的任务（柔性体、高频接触）可以用 DreamGen 这类方法补充。

### 4.3 和 ACDC 的关系：从原型到生产级系统

SimFoundry 的"数字表亲"概念直接继承自 [ACDC](https://arxiv.org/abs/2410.07408)（Dai, Wong et al., 2024），但做了几个关键扩展：ACDC 的输入是单张 RGB 图像，SimFoundry 支持视频输入（能获取多视角信息，重建质量更高）；ACDC 是一个相对聚焦的研究原型，SimFoundry 是一整套模块化的生产级系统，支持三种不同类型的表亲编辑（ACDC 主要聚焦物体级别的变化）；SimFoundry 额外提供了系统性的仿真-真实相关性验证。

## 五、局限性

1. **依赖上游基础模型的质量**：分割、深度估计、2D-3D 生成这几个环节都依赖现成的基础模型，任何一个环节的质量瓶颈（比如分割模型对遮挡严重的物体表现不佳）都会传递到最终重建质量上。
2. **物理参数标注仍是近似**：自动标注的质量、摩擦系数等物理属性是基于视觉外观的估计或默认经验值，不是精确测量，这决定了重建场景的物理精度存在上限（这一点和 [DrEureka](./115_DrEureka_LLM引导域随机化与奖励设计)、[ASAP](./116_ASAP_对齐仿真与真实物理的Delta动作模型) 等专门解决物理参数/动力学精确对齐的方法形成互补关系）。
3. **柔性体和液体建模仍然受限于物理仿真器本身的能力**：这一局限是继承自底层物理仿真器的通用限制，不是 SimFoundry 本身的设计问题。
4. **数字表亲的"合理性"依赖生成模型的常识**：比如 Object Cousin 替换物体时，需要生成/检索模型判断"什么样的替代物体仍然保留原有的可操作性"，这一步的质量同样受限于当前生成式 AI 模型的能力水平。

## 六、总结

SimFoundry 把 Real-to-Sim-to-Real 这条工作流推进到了一个新的自动化程度——**输入仅仅是一段普通视频，输出是一个物理仿真就位、且能自动衍生出大量场景/物体/任务变体的可交互环境**，整个过程不需要任何人工标注。它的核心贡献可以归纳为两点：

1. **用模块化的三阶段管线（Extraction-Generation-Augmentation）实现了全自动的 real2sim 重建**，且这种模块化设计使系统能随着上游基础模型（分割、深度估计、3D 生成）的进步自动变得更强，不需要重新设计。
2. **系统性地验证了"仿真评测能否预测真实表现"这件事**——0.911 的 Pearson 相关系数为整个 real2sim2real 范式的可信度提供了具体的实证支撑，这是此前很多同类工作缺失的一环。

结合 [数字表亲](https://arxiv.org/abs/2410.07408) 这个概念——用一个场景分布而不是单一数字孪生去训练策略——SimFoundry 展示了 Object/Scene/Task 三个独立可控的变化维度分别能带来多大的真实世界泛化收益，其中 Task Cousin（改变任务目标本身）的贡献最为显著，提示了"多样化任务目标"可能是提升策略泛化能力里被低估的一个杠杆。
