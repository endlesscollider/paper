# 写作前置调研工具（强制第一步）

## 背景

`writing-rules.md` 要求写任何新文章前，必须先确认三件事：(1) 相关概念项目里是否已经写过、
该链接到哪里，(2) 新文章该用什么文件名编号和 `order` 值，(3) 目标应该归入哪个目录类型。

在没有专用工具之前，这三件事需要靠反复调用 `grep_search` / `list_directory` / `read_file`
拼凑出来，一次任务往往要花十几次工具调用才能摸清现状，纯属浪费。现在这些信息由脚本一次给出。

## 使用方法

**在开始写任何新文章（前置知识/论文精读/综述/工程项目/系列）之前，第一步永远是先跑：**

```bash
node scripts/prep_writing.mjs <关键词1> <关键词2> <关键词3> ...
```

关键词填写本次要写的主题涉及的核心概念/项目名/论文简称/模型名（英文优先，命中率更高）。
比如要写"NVIDIA real2sim 工作流系列"，就跑：

```bash
node scripts/prep_writing.mjs real2sim MimicGen DreamGen SimFoundry "GR00T-Mimic" "3D Gaussian Splatting"
```

脚本会一次性打印：

1. **关键词覆盖检查**：每个关键词在 前置知识/论文综述/工程项目/工程实践/系列 中命中的文件、
   标题、order、命中次数——用来判断"这个概念是否已经写过、该复用哪篇文章、该链接到哪里"。
2. **编号与命名规范**：前置知识/论文精读/综述/工程项目/系列 各自当前用到的最大编号和 order，
   以及新文章建议使用的编号，避免和现有文章冲突。
3. **固定规范提示**：文章类型判断标准、写前必查项、系列 index.md 的必填字段等静态规则速览。

## 之后仍需人工做的事（脚本不能替代）

- 脚本只做**关键词字符串命中**，不做语义判断——命中列表里哪些文章真正相关、该不该链接，
  仍需要读一下对应文件确认，尤其是判断"深度是否够、要不要新写而不是复用"。
- 如果关键词覆盖检查发现某个概念完全没有前置知识文章覆盖，按 `writing-rules.md` 的知识
  自包含原则，要在写正文之前先建好那篇前置知识文件（哪怕只是骨架）。
- 综述类文章仍需人工确认分类逻辑（按方法论 vs 按历史演进），脚本不判断内容组织方式。
- 涉及外部最新信息（如某公司最新发布的技术栈、最新论文列表）时，仍需要 `web_search`/`web_fetch`
  补充调研——这一步无法脚本化，但应该和 `prep_writing.mjs` 的项目内检查**并行**执行，
  而不是先查完外部再查内部（省时间）。

## 维护

如果新增了内容目录（比如新的 `硬件基础` 子分类、新的编号格式），需要同步更新
`scripts/prep_writing.mjs` 里的 `CONTENT_DIRS` 和对应的 `scan*Numbering()` 函数，
否则脚本给出的编号建议会过时。
