# 锚点链接规范（自定义 Slugify 规则）

## ⚠️ 核心规则

本项目在 `.vitepress/config.mts` 中配置了**自定义 slugify**（不是 VitePress 默认的 `encodeURIComponent` 版本）。规则如下：

```javascript
slugify(str) {
  return str.trim().toLowerCase()
    .replace(/[、，。：；！？…""''（）【】《》"']/g, ' ')  // 中文标点和引号 → 空格
    .replace(/\u2014+/g, ' ')                              // 全角破折号 ——  → 空格
    .replace(/\s+/g, '-')                                  // 空格 → 连字符
    .replace(/-{2,}/g, '-')                                // 合并连续连字符
    .replace(/^-+|-+$/g, '')                               // 去首尾连字符
}
```

**效果**：中文标点被替换为 `-`（空格），英文字母小写，`.`/`_`/`:` 等 ASCII 符号**原样保留**。

## 写锚点的规则

### 规则 1：中文标点变 `-`

标题中的 `、`、`：`、`——`、`""` 等中文标点会变成 `-`。

```markdown
<!-- 标题：## 三、异步模式：不再互相等待 -->
<!-- slug：三-异步模式-不再互相等待 -->
[链接](./file#三-异步模式-不再互相等待)
```

### 规则 2：`.` 和 `_` 保留原样

```markdown
<!-- 标题：### 4.2.4 QC 的完整 TD Loss -->
<!-- slug：4.2.4-qc-的完整-td-loss -->
[链接](./file#4.2.4-qc-的完整-td-loss)
```

### 规则 3：不要加 `_` 前缀

```markdown
<!-- ❌ 错误 -->
[链接](./file#_6-1-主要对比)

<!-- ✅ 正确 -->
[链接](./file#6.1-主要对比)
```

### 规则 4：不要在标题中使用括号 `()`

Markdown 链接语法 `[text](url#anchor)` 中的 `)` 会被解析器当作链接结束符。如果标题中有 `()`，锚点链接无法正确书写。

```markdown
<!-- ❌ 避免这种标题 -->
### 4.1 no_sync()：暂停梯度同步

<!-- ✅ 正确写法 -->
### 4.1 no_sync 暂停梯度同步
```

### 规则 5：空格变 `-`，英文变小写

```markdown
<!-- 标题：## 五 Flow Policy 把 Flow Matching 用作机器人策略 -->
<!-- slug：五-flow-policy-把-flow-matching-用作机器人策略 -->
```

## 快速对照表

| 标题字符 | slug 中变成 |
|----------|-------------|
| 空格 | `-` |
| `、` `，` `。` `：` `；` | `-`（空格） |
| `——`（全角破折号） | `-` |
| `""` `''`（中文引号） | `-` |
| `"` `'`（ASCII引号） | `-` |
| `（）`（中文括号） | `-` |
| `.` | `.`（保留） |
| `_` | `_`（保留） |
| `:` | `:`（保留） |
| 英文大写 | 小写 |
| 中文汉字 | 原样保留 |

## 验证工具

项目根目录有检查脚本：
```bash
node check_anchors_v2.mjs
```
写完含锚点链接的文章后务必运行一次确认。

## 最佳实践（写新标题时）

1. **避免中文标点**——用空格代替 `、`、`：`、`——`
2. **避免括号**——`no_sync()` 写成 `no_sync`
3. **数字编号用 `.`**——`4.2.4` 而不是 `4-2-4`
4. **先写标题，立刻在脑中算 slug，确认链接能正确写出**
