# 物体解算器从零实现

> 从一个只有位置和速度的小球开始，逐步实现物理仿真中最核心的“解算器”：先理解一行积分代码，再加入碰撞、接触、摩擦、关节约束和多刚体系统，最后回到 Newton 的 GPU 实现。

## 系列定位

物理引擎最容易让初学者迷失的地方，是一上来就面对 `ModelBuilder`、碰撞管线、关节坐标、Warp kernel 和各种求解器名称。这个系列采用相反的学习顺序：每次只增加一个物理问题，并先用一个可以独立运行、可以打印中间状态的最小程序验证它。

这里的“物体解算器”指的是：给定当前状态、外力、几何和约束，计算一个时间步之后物体应该处于什么状态的数值算法。渲染器只负责画出来，碰撞检测只负责发现可能接触的位置，解算器负责把这些信息转换成下一时刻的位置和速度。

## 学习方式

每一章都建议按三个层次阅读：先运行仓库里的最小脚本，观察状态如何变化；再阅读公式和手算表格，确认算法的每一步；最后对照 Newton 的 API 或源码，理解生产级引擎增加了哪些数据结构、并行化和工程保护。

本系列不会把“能跑起来”当成“理解了”。每加入一个组件，都会回答它在仿真循环中的位置、它修改了哪些状态、它解决了什么数值问题，以及它没有解决什么问题。
