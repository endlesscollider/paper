## 一、完整时间步

把一帧物理更新展开，可以得到下面的流水线：

~~~mermaid
flowchart LR
    A[Model 几何与质量] --> B[State 当前状态]
    B --> C[累计外力与重力]
    C --> D[半隐式 Euler 预测速度]
    D --> E[积分位置与姿态]
    E --> F[Broad phase]
    F --> G[Narrow phase SAT]
    G --> H[Contact 点 法线 穿透]
    H --> I[位置修正]
    I --> J[法向顺序冲量]
    J --> K[切向摩擦冲量]
    K --> L[下一 State]
    L --> B
~~~

这张图是独立实现时的总目录。每个箭头都对应一个可以单独打印、单独测试的中间数据，而不是一团 solver magic。

## 二、教学版代码的模块边界

| 模块 | 教学版函数或字段 | 独立实现时的责任 |
|------|------------------|------------------|
| 数学 | Vec2、rotate、cross | 向量运算、坐标变换、叉乘 |
| 刚体模型 | RigidBody | 质量、惯性、姿态、速度和力 |
| 几何 | world_vertices、SAT | 生成候选接触 |
| 接触 | Contact | 保存点、法线、穿透和累计冲量 |
| 位置求解 | correct_positions | 清理已有几何误差 |
| 速度求解 | solve_velocity_constraints | 法向、摩擦和恢复 |
| 场景循环 | World.step | 固定顺序推进所有阶段 |

这个边界比类名更重要。你可以把 SAT 换成 GJK，把 PBD 换成 XPBD，把顺序冲量换成其他迭代法，但只要模块之间的数据契约稳定，场景循环不必重写。

### 先说明网页程序的边界

下面的交互程序不是把 `rigid2d.py` 全部复制进浏览器。它只用两个旋转矩形展示“预测状态、检测地面、位置校正、速度响应、生成画面”的总顺序：地面高度使用旋转矩形在竖直方向上的真实支撑范围，但接触响应仍是直接反射竖直速度并衰减水平速度和角速度。

它**没有**执行物体之间的 SAT、接触点有效质量、累计顺序冲量和摩擦锥。因此两个矩形互相穿过并不代表完整教学解算器失效；网页右上角明确标记 `simplified ground demo`，完整实现应运行 `scripts/newton_solver_from_zero/rigid2d.py`。

| 网页循环阶段 | 当前程序做法 | 完整 `rigid2d.py` 做法 |
|--------------|--------------|------------------------|
| 几何 | 只计算矩形最低点到质心的竖直距离 | 对所有凸多边形执行 SAT |
| 接触对象 | 矩形与静态地面 | 动态-动态、动态-静态刚体对 |
| 位置响应 | 把质心抬到支撑高度 | 沿接触法线按逆质量分配修正 |
| 速度响应 | 恢复竖直速度并经验衰减 | 用有效质量求法向与摩擦冲量 |
| 目的 | 看清完整时间步的控制顺序 | 验证真正的教学刚体解算器 |

## 三、从零实现的自测顺序

不要一开始就创建一百个刚体。按下面的最小实验顺序，每一步都记录位置、速度、法线、穿透和冲量：

| 阶段 | 场景 | 必须验证 |
|------|------|----------|
| 1 | 单方块自由落体 | 半隐式 Euler 更新顺序 |
| 2 | 单方块撞静态地面 | 法线方向、位置修正、静态逆质量 |
| 3 | 单方块反弹 | 恢复目标速度 |
| 4 | 两个方块正碰 | 动量分配和相对速度 |
| 5 | 偏心碰撞 | 接触点力矩和角速度 |
| 6 | 水平滑动方块 | 摩擦上限和切线方向 |
| 7 | 四方块堆叠 | 多接触顺序迭代 |
| 8 | 倾斜方块落地 | 接触点近似和旋转稳定性 |

如果第 2 阶段就穿透，不要跳到第 7 阶段调迭代次数；后面的现象可能只是前面法线或接触点错误的放大。

## 四、最小不变量清单

### 4.1 几何不变量

- 法线长度接近 1
- 法线方向约定固定
- 接触点在两个形状附近，而不是远处包围盒角点
- 穿透深度非负

### 4.2 动力学不变量

- 静态刚体逆质量和逆惯量为 0
- 内部冲量对总线性动量成对抵消
- 没有外力时，完全弹性碰撞不应凭空创造能量
- 约束冲量增量通过累计量计算，不能每轮重复施加总量

### 4.3 数值不变量

- dt 固定或有明确的子步策略
- 分母接近零时跳过约束
- 接触消失时清除对应缓存
- 迭代次数改变时，结果应能解释为求解精度变化

## 五、和 Newton 的对象逐项对照

Newton 把生产级系统拆成多个对象。可把教学版映射为：

| 教学版 | Newton | 关键差别 |
|--------|--------|----------|
| RigidBody 的静态形状、质量、惯性 | ModelBuilder 构建后得到的 Model | Newton 使用 Warp/GPU 数组并支持更多几何类型 |
| RigidBody 的位置、姿态、速度 | State | Newton 状态通常是批量数组并支持双缓冲 |
| detect_contacts | CollisionPipeline | Newton 支持 broad phase、网格、SDF、接触归约 |
| Contact | Contacts | Newton 用批量接触结构承载多个世界和多个接触 |
| World.step | Solver.step 外部循环 | Newton 把不同求解策略实现成独立 solver |
| correct_positions | XPBD/接触位置处理 kernel | 生产实现有更多稳定性和并行处理 |
| solve_velocity_constraints | 接触/关节求解 kernel | Newton 处理更多约束类型和 GPU 并行布局 |

Newton 源码中最值得先读的是 newton/_src/solvers/solver.py 的积分 kernel，以及 solver_semi_implicit.py 的 step 组织。先对应本系列的 World.step，再看 Warp kernel 中数组索引和并行化细节。

## 六、Newton 的自由落体对照

本系列第 1 章的手写状态有 position 和 velocity；Newton 版本则由 ModelBuilder 声明粒子或刚体，model.state 分配动态状态，SolverSemiImplicit.step 处理时间推进：

~~~python
# ModelBuilder 声明不随时间步改变的粒子属性
builder = newton.ModelBuilder(gravity=(0.0, -9.81, 0.0))
builder.add_particle(pos=wp.vec3(0.0, 5.0, 0.0),
                     vel=wp.vec3(0.0, 0.0, 0.0),
                     mass=1.0)
model = builder.finalize()
solver = newton.solvers.SolverSemiImplicit(model)

# 两份 State 分别作为本步输入和输出，避免原地覆盖
state_0 = model.state()
state_1 = model.state()

for _ in range(100):
    # 每步先清除上一步残留力，再推进固定的 0.01 s
    state_0.clear_forces()
    solver.step(state_0, state_1, None, None, 0.01)

    # 输出状态成为下一步输入，旧缓冲区留作下一次输出
    state_0, state_1 = state_1, state_0
~~~

这段代码的核心不是 API 记忆，而是双缓冲：state_0 是本步输入，state_1 是本步输出；步结束后交换引用。它与并行 kernel 的读写边界相容，也让前一状态可以保留用于差分、渲染或梯度计算。

## 七、生产级实现还要增加什么

完成本系列的教学版后，距离生产级刚体引擎还有一段工程工作：

| 生产问题 | 需要增加的技术 |
|----------|----------------|
| 物体数量大 | AABB broad phase、空间划分、并行 pair 生成 |
| 高速物体穿透 | 连续碰撞检测、time of impact、子步 |
| 复杂网格 | GJK/EPA、SDF、接触流形和归约 |
| 堆叠很多 | 岛分解、并行约束调度、warm starting |
| 约束很硬 | XPBD、隐式求解、预条件迭代 |
| 3D 姿态 | 四元数、世界惯性张量、角动量更新 |
| 机器人关节 | 广义坐标、最大坐标、关节限制和执行器 |
| GPU 批量仿真 | Warp kernel、数组布局、多 world 并行 |
| 可微训练 | 保留计算图、接触近似和梯度稳定性 |

这些不是“本系列前面没讲好”，而是从教学实现进入生产引擎时自然出现的新边界。Newton 系列的[五件套数据模型](/系列/newton_engine_deep_dive/02_五件套核心数据模型_ModelBuilder_Model_State_Control_Contacts)、[多世界并行](/系列/newton_engine_deep_dive/07_多世界并行与RL训练_Worlds机制)和[可微仿真](/系列/newton_engine_deep_dive/08_可微仿真_梯度怎么传回控制输入)分别对应这些工程扩展。

## 九、系列总复习

可以把刚体解算器记成下面五层：

~~~text
状态层：位置、姿态、线速度、角速度
动力学层：力、力矩、质量、惯性
几何层：形状、碰撞检测、接触点和法线
约束层：位置投影、有效质量、冲量和摩擦
工程层：迭代、缓存、并行、稳定性和调试
~~~

前四层回答“物理上应该发生什么”，第五层回答“如何在有限时间和有限计算量下稳定地近似它”。理解 Newton 的关键不是记住某个 solver 名字，而是能把源码中的每个 kernel 放回这五层。

## 结业检查

当你能独立回答以下问题，基本就从“会调用物理引擎”进入“能实现刚体解算器”了：

1. 为什么半隐式 Euler 要先更新速度再更新位置？
2. 碰撞检测输出的 Contact 至少需要哪些字段？
3. 为什么位置修正不能替代速度冲量？
4. 接触点偏离质心时，为什么会改变角速度？
5. 有效质量为什么包含逆质量、逆惯量和力臂平方？
6. 为什么法向累计冲量必须限制为非负？
7. 摩擦上限为什么依赖法向冲量？
8. 多接触为什么需要顺序迭代？
9. 2D 角度迁移到 3D 时，为什么惯性从标量变成张量？
10. 关节为什么可以复用 ConstraintRow？

如果其中任何一题只能背结论，回到对应章节运行小实验并打印中间变量。真正的独立实现能力来自能追踪一笔冲量如何从 Contact 走到两个刚体的速度和角速度。

## 总结

本系列从一个自由落体小球出发，逐步构造了一个教学版刚体解算器。它没有试图隐藏复杂性，而是把复杂性拆成可验证的阶段：积分、几何、约束和迭代。你现在可以以 rigid2d.py 为参考，从空文件重写一遍，再逐步接入 Newton 的 GPU 数据模型和求解器。
