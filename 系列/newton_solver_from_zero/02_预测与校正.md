# 预测与校正

> 系列第 2 章。我们把上一章的自由落体循环拆成两个阶段：先按动力学预测自由运动，再根据约束把不合法的状态校正回来。

## 前情提要

上一章的最小解算器只有一条信息来源：重力。它会正确地让小球加速下落，却不知道“地面”这个几何事实，所以小球会穿过 $y=0$。本章不急着实现完整碰撞，而是先建立物理引擎最重要的时间步结构。

相关阅读：[最小自由落体解算器](./01_最小自由落体解算器)、[数值积分与能量稳定性](/前置知识/006c_前置知识_物理仿真数值积分_辛积分与能量稳定性)、[PBD](/前置知识/006f_前置知识_基于位置的动力学PBD)。

## 一、一个时间步里到底发生什么

把物体当前的状态记为 $s_t$。解算器不会直接猜“最终位置”，而是先假设这一小段时间里没有约束阻挡物体，让外力推进出一个自由状态；这个自由状态可能穿透地面，但它很有用，因为它告诉我们外力本来想把物体带到哪里。

然后，约束阶段读取自由状态，检查哪些条件被违反，并分别产生位置修正和速度修正。最后把修正后的状态交给渲染器，开始下一个时间步。

~~~mermaid
flowchart LR
    A[状态 s_t] --> B[清空并累计外力]
    B --> C[动力学预测<br/>积分速度与位置]
    C --> D[碰撞检测与约束]
    D --> E[位置校正<br/>消除当前穿透]
    E --> G[速度校正<br/>阻止继续钻入]
    G --> F[状态 s_t+dt]
    F --> A
~~~

> 图中两次校正缺一不可：位置校正回答“这一帧已经穿进去多少”，速度校正回答“下一帧还会不会继续向里运动”。

这里有一个容易混淆的词：**预测不是错误的最终答案，而是约束求解器的输入**。如果没有预测，接触求解器不知道外力把物体推向哪里；如果没有校正，积分器又不会自动知道几何约束。

## 二、预测阶段只做自由动力学

本章沿用半隐式 Euler。对一个质点，先用加速度更新速度，再用新速度更新位置。这个公式在第 1 章已经出现过，这里不重复建设它的理论背景；它在本章的角色是“产生一个暂时允许违反约束的候选状态”。

$$
v^\mathrm{p}=v_t+a_t\Delta t,\qquad y^\mathrm{p}=y_t+v^\mathrm{p}\Delta t
$$

**这个公式在做什么**：从当前状态出发，忽略地面等约束，预测本时间步结束时的位置和速度。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $v_t+a_t\Delta t$ | **自由速度预测** | 让重力或其他外力先改变运动速度 |
| $y_t+v^\mathrm{p}\Delta t$ | **自由位置预测** | 按刚更新好的速度推进竖直位置 |
| 上标 $\mathrm{p}$ | **预测状态标签** | 提醒这个状态还没有经过接触约束修正 |

**用人话读**：先假设没有墙和地面，看看外力会把物体带到哪里。

**为什么先允许暂时穿透**：接触响应需要知道穿透量或接近速度；预测状态正好提供这两个量。关键不是永远允许穿透，而是要在同一个时间步内及时校正。
:::

本章小程序把 `position` 定义为球心高度 $y$，球半径为 $r$，所以合法条件不是 $y\ge 0$，而是 $y\ge r$：球心最低只能落到一个半径的高度。预测值低于 $r$ 并不表示最终结果必须在地下，只表示重力在没有地面的情况下会让球底穿过地面。

## 三、校正阶段是在满足什么

先给结论：**本章的小程序在校正阶段既修正位置，也修正速度。** 位置被放回地面，向下的法向速度被改为零；因此它模拟的是完全无反弹的地面接触。

对半径为 $r$ 的小球，地面约束是球心高度不能低于 $r$。预测没有穿透时，位置和速度都直接接受；预测穿透时，球心被放回 $r$，同时把向下速度钳为零：

$$
\left(y_{t+\Delta t},v_{t+\Delta t}\right)=
\begin{cases}
\left(y^\mathrm{p},v^\mathrm{p}\right), & y^\mathrm{p}\ge r \\
\left(r,\max(0,v^\mathrm{p})\right), & y^\mathrm{p}<r
\end{cases}
$$

**这个公式在做什么**：预测合法时原样接受；预测穿透时同时消除已有的几何重叠和继续钻入地面的速度。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $y^\mathrm{p}\ge r$ | **合法分支** | 球底仍在地面上方，预测位置和速度都不用改 |
| $y^\mathrm{p}<r$ | **接触分支** | 球底已经越过地面，必须执行校正 |
| $y_{t+\Delta t}=r$ | **位置校正器** | 把球心放回恰好接触地面的高度 |
| $v_{t+\Delta t}=\max(0,v^\mathrm{p})$ | **速度校正器** | 保留向上的离开速度，删除向下的钻入速度 |

**用人话读**：没撞地就接受预测；撞地后不仅把球拿回地面，还要取消它继续向下的速度。

**为什么速度用零而不是反向**：本章把恢复系数设为零，只讲静止接触。如果要反弹，应把入射法向速度按恢复系数反向；第 3 章会实现这一步。
:::

### 用一个时间步看清两次校正

取小程序中的 $\Delta t=0.02\text{s}$、重力 $-9.81\text{m/s}^2$、半径 $r=0.25\text{m}$。假设某一步开始时球心高度为 $0.255\text{m}$、速度为 $-0.4\text{m/s}$，这一时间步的数据变化如下：

| 顺序 | 状态 | 数值 | 含义 |
|------|------|------|------|
| 1 | 预测速度 | $-0.5962\text{m/s}$ | 重力让向下速度继续增大 |
| 2 | 预测位置 | $0.243076\text{m}$ | 小于半径，球底穿入地面 $0.006924\text{m}$ |
| 3 | 校正位置 | $0.25\text{m}$ | 把已经发生的 $6.924\text{mm}$ 穿透清掉 |
| 4 | 校正速度 | $0\text{m/s}$ | 删除向下速度，表示无反弹接触 |

如果只执行第 3 步而保留 $-0.5962\text{m/s}$，下一时间步仍会带着很大的向下速度开始预测，位置会反复穿透再被硬拉回来。画面可能勉强停在地上，但状态本身不满足接触速度约束，后续加入反弹、摩擦或多个物体后就会出错。

## 四、位置修正和速度修正的职责

| 阶段 | 读取什么 | 修改什么 | 解决什么 |
|------|----------|----------|----------|
| 动力学预测 | 当前状态、外力、时间步 | 预测位置和速度 | 外力本来会怎样运动 |
| 位置校正 | 穿透深度、几何约束 | 位置、必要时姿态 | 已经发生的重叠 |
| 速度校正 | 接触点相对速度 | 线速度、角速度 | 下一步继续靠近或反弹 |

这个分工也解释了为什么“把物体位置直接钳到地面”只是教学起点。它能让画面看起来不穿透，却没有告诉系统碰撞传递了多少动量；在堆叠和旋转刚体中，单纯钳位置很容易出现能量损失、抖动或物体互相穿插。

~~~mermaid
flowchart LR
    A[预测状态<br/>yᵖ 小于 r 且 vᵖ 小于 0] --> B[位置分支<br/>y 设为 r]
    A --> C[速度分支<br/>v 设为 0]
    B --> D[当前帧<br/>没有几何穿透]
    C --> E[下一帧<br/>不携带旧的钻入速度]
~~~

> 两条分支修正的是同一接触的不同部分。位置修正不能自动改变速度；速度修正也不能把已经穿入地面的球搬出来。

## 五、固定时间步不是可选的装饰

如果渲染帧时间忽快忽慢，直接把每帧时间传给求解器，接触检测和迭代误差也会随之变化。更稳妥的结构是渲染线程累计真实时间，物理线程用固定 $\Delta t$ 反复推进；一帧显示多个物理步的最终状态。

~~~python
# 渲染帧只负责提供经过了多少真实时间
accumulator += frame_time
while accumulator >= fixed_dt:
    # 物理始终以相同的 fixed_dt 推进，必要时一帧执行多步
    world.step(fixed_dt)
    accumulator -= fixed_dt

# 渲染读取最后一个完成的物理状态
render(world)
~~~

这段代码的关键不是循环写法，而是把“显示频率”和“数值积分步长”分开。Newton 的示例同样会在外部循环中明确传入 dt，而不是让求解器从 GPU 计时器猜物理时间。

## 六、把本章结构放进 Newton

在 Newton 中，Model 保存几何、质量和拓扑等相对稳定的数据；State 保存本时间点的动态状态；SolverSemiImplicit.step 先处理力和约束，再调用积分 kernel。这个分层可以和[Newton 五件套数据模型](/系列/newton_engine_deep_dive/02_五件套核心数据模型_ModelBuilder_Model_State_Control_Contacts)对照阅读。

概念上可以写成：

~~~text
state_in -> force/constraint evaluation -> integration -> state_out
~~~

在教学代码中，World.step 直接对应这个过程：先 integrate_forces，再 integrate_velocity，接着 detect_contacts、correct_positions 和 solve_velocity_constraints。代码刻意把阶段写成独立函数，方便下一章逐行观察。

## 七、把可运行小程序从头到尾拆开

页面里的编辑器运行的是一段独立 Python 程序，不依赖 Newton，也不调用隐藏的物理库。它自己完成 180 个固定时间步，并把每一步的圆和地面保存进 `frames`；Python 结束后，页面组件只负责重放这些帧。

程序的核心循环可以压缩为下面几行。这里的 `*_pred` 只保存自由预测，`*_next` 才是会交给下一时间步的最终状态：

~~~python
for step in range(180):
    # 1. 预测：暂时忽略地面，只计算重力造成的自由运动
    velocity_pred = velocity + gravity * dt
    position_pred = position + velocity_pred * dt

    # 2. 检测：球心低于半径，等价于球底穿过 y = 0
    touching = position_pred < radius

    if touching:
        # 3. 位置校正：把已经穿入地下的球放回接触边界
        position_next = radius

        # 4. 速度校正：恢复系数为 0，删除向下速度而不产生反弹
        velocity_next = max(0.0, velocity_pred)
    else:
        # 没有违反约束，直接接受预测状态
        position_next = position_pred
        velocity_next = velocity_pred

    # 5. 写回：校正后的状态成为下一固定时间步的输入
    position, velocity = position_next, velocity_next
~~~

这五步中，真正的物理计算到“写回”就结束了。后面的 `objects`、`metrics` 和 `simulation` 都属于可视化协议：

| 字段 | 谁产生 | 谁读取 | 是否参与物理计算 |
|------|--------|--------|------------------|
| `objects` | Python | Canvas 动画 | 否，只描述地面和圆怎么画 |
| `metrics` | Python | 动画右上角面板 | 否，只展示预测值与校正值 |
| `frames` | Python | 页面播放器 | 否，保存要按顺序重放的画面 |
| `simulation` | Python | `PhysicsPlayground` 组件 | 否，约定边界、帧率和帧列表 |

这张数据流图说明浏览器中究竟是谁在做计算、谁在做显示：

~~~mermaid
flowchart LR
    A[Python 固定步循环] -->|计算| B[预测状态]
    B -->|接触约束| C[位置与速度校正]
    C -->|写入| D[frames 与 metrics]
    D -->|程序结束后交给| E[PhysicsPlayground]
    E -->|逐帧重放| F[Canvas 动画与数值面板]
~~~

> 关键边界是 `frames`：左边已经完成物理求解，右边只负责显示。因此修改 `fill` 只会换颜色，修改 `gravity`、`dt` 或速度校正才会改变运动。

### 原程序里的速度重建是什么

旧版本曾使用 `velocity_next = (position_next - position) / dt`，即根据校正后的位移反推平均速度。它不是“完全没有修正速度”，而是一种位置型速度重建；[基于位置的动力学（Position-Based Dynamics, PBD）](/前置知识/006f_前置知识_基于位置的动力学PBD)经常采用这种思路。

但它与本章要强调的接触速度约束不是一回事。首次撞地时，只要球在这一时间步内还向下移动了一小段，反推速度仍可能为负；因此本章改成显式删除向下法向速度，把“位置修正”和“速度修正”清楚地写成两行。第 4 章会再系统讲解[约束投影与 PBD](./04_约束投影与PBD)。

## 八、亲手验证两种校正

先直接运行下面的小程序。球第一次接触地面时，右上角会同时显示 `y predicted`、`y corrected`、`v predicted` 和 `v corrected`：红球是穿透后的预测位置，绿球是校正后的最终位置。

第一次加载 Python 运行环境可能需要等待；加载完成后，程序会在浏览器内执行。可以直接修改左侧代码再运行，不需要安装本地依赖。

建议做两个对照实验：

1. 把 `velocity_next = max(0.0, velocity_pred)` 改成 `velocity_next = velocity_pred`。动画仍会靠位置钳制停在地面，但 `v corrected` 会持续积累成越来越大的负数，这证明只改位置没有得到合法速度。
2. 恢复代码，再把它改成 `velocity_next = -0.8 * velocity_pred`。小球会反弹，因为这行保留了 80% 的入射速度并反向；这就是恢复系数的最小版本。

## 总结

本章最重要的心智模型是：

1. 预测阶段忠实地执行外力，不负责理解几何约束
2. 校正阶段把预测状态拉回合法状态，并修正下一步的速度趋势
3. 位置修正和速度修正是两个不同问题，不能用一个替代另一个
4. 固定时间步把数值稳定性从渲染帧率中隔离出来
