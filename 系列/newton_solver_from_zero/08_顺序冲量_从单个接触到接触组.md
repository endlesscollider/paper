# 顺序冲量

> 系列第 8 章。单个接触可以一次求准；多个接触共享物体时，一处速度写回会改变另一处的输入，因此求解器必须按顺序反复修正。

## 单接触模型的边界

[第 7 章](./07_碰撞冲量_有效质量与速度写回)已经闭合一个纯平动接触：由当前法向速度、固定目标和有效逆质量求出冲量，再把它按逆质量写回双方。本章仍不引入旋转，只增加“同一个物体同时参与多个接触”。

## 一个接触的答案会改变另一个接触

三个质量均为 $1\,\mathrm{kg}$ 的物体 A、B、C 紧挨着排在一条直线上。A 以 $6\,\mathrm{m/s}$ 向右运动，B、C 静止。接触 $C_1$ 位于 A 与 B 之间，接触 $C_2$ 位于 B 与 C 之间，两个接触都取完全非弹性目标 $v_n^\star=0$。

~~~mermaid
flowchart LR
    A["A<br/>v = 6"] -->|"接触 C1"| B["B<br/>v = 0"]
    B -->|"接触 C2"| C["C<br/>v = 0"]
~~~

> B 同时属于两个接触。$C_1$ 改写 B 的速度后，$C_2$ 读到的输入已经变化；$C_2$ 再改写 B，又会让 $C_1$ 先前的结果失效。

若每个接触只算一次，按 $C_1\rightarrow C_2$ 的顺序会得到：

| 处理时刻 | A 速度 | B 速度 | C 速度 | 当时满足的接触 |
|----------|--------|--------|--------|----------------|
| 初始 | $6$ | $0$ | $0$ | 无 |
| 解 $C_1$ | $3$ | $3$ | $0$ | $C_1$ |
| 解 $C_2$ | $3$ | $1.5$ | $1.5$ | $C_2$ |

最后一行中，$C_1$ 的相对速度重新变成 $1.5-3=-1.5\,\mathrm{m/s}$，A 又在撞向 B。每个局部公式都算对了，错误来自“只遍历一轮”这个全局流程。

需要的不是另一条单次碰撞公式，而是一个反馈循环：每次都读取最新速度，修正一个接触，把新速度立即暴露给其余接触；多轮遍历后，所有接触的残差共同缩小。

~~~mermaid
flowchart LR
    S["一轮开始"] --> C1["读取最新速度<br/>修正 C1"]
    C1 --> C2["读取 C1 写回后的速度<br/>修正 C2"]
    C2 --> Q{"迭代次数足够<br/>或残差足够小?"}
    Q -- "否" --> C1
    Q -- "是" --> O["输出速度"]
~~~

> 箭头回到 $C_1$ 是算法成立的关键。顺序冲量不是把同一笔完整冲量重复施加，而是根据最新残差增补或撤回局部冲量。

## 每轮求的是冲量增量

每个接触在创建时保存固定目标 $v_n^\star$。某轮访问该接触时，$v_n$ 是从双方**当前速度**测得的值，可能已经被其他接触修改；$K_n=w_A+w_B$ 是当前这对平动物体的有效逆质量。此轮的候选冲量增量为：

$$
\Delta j=\frac{v_n^\star-v_n}{K_n}
$$

**这个公式在做什么**：读取其他接触已经修改过的当前速度，测量本接触还剩多少速度误差，再把这段残差换算成本轮需要增补或撤回的冲量。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $v_n$ | **当前测量值** | 每次访问接触时重新从最新速度计算，不是最初撞击速度 |
| $v_n^\star$ | **固定目标** | 接触创建时确定，在本次求解过程中保持不变 |
| $v_n^\star-v_n$ | **当前残差** | 正值要求增加推开冲量，负值表示先前推得过多，需要撤回一部分 |
| $1/K_n$ | **局部换算器** | 把当前速度残差变成冲量增量 |
| $\Delta j$ | **候选增量** | 允许为正或负，还不能直接作为无条件写回量 |

**用人话读**：每次轮到这个接触时，重新看它离目标还差多少，只修正眼前这一小段误差。

**为什么不用最初的 $v_n^-$**：最初速度没有包含其他接触已经产生的影响。反复使用它会在每轮重复计算同一笔完整冲量，速度会持续增长而不是收敛。
:::

这个增量与第 7 章的单次冲量形式相同，改变的是状态语义：第 7 章从“碰撞前旧状态”一次求出总冲量；本章从“本轮当前状态”求出增量。区分旧快照、当前读数和固定目标，才能避免迭代代码把三种量混在一起。

## 单边接触必须裁剪累计冲量

接触可以推开物体，不能拉住物体。因此每个接触保存一个累计法向冲量 $j_{\mathrm{acc}}\ge0$。新接触的累计值初始化为零；若使用跨帧预热，可以从上一帧匹配到的持久接触恢复缓存值，但恢复后必须把对应冲量预先写入速度。

一次访问接触时，累计状态按以下次序更新：

$$
j_{\mathrm{old}}=j_{\mathrm{acc}},
\qquad
j_{\mathrm{acc}}\leftarrow\max(0,j_{\mathrm{old}}+\Delta j),
\qquad
\delta j=j_{\mathrm{acc}}-j_{\mathrm{old}}
$$

**这个公式在做什么**：保存访问前的累计历史，把候选增量加入总量并投影到非负区间，最后只把新旧累计值的真实差额 $\delta j$ 写回双方速度。

::: details 📐 公式详解（点击展开）

| 子表达式 | 它是谁 | 它在干嘛 |
|---------|--------|---------|
| $j_{\mathrm{old}}$ | **旧历史快照** | 保存本轮访问前该接触已经贡献了多少冲量 |
| $j_{\mathrm{old}}+\Delta j$ | **候选新总量** | 允许增加冲量，也允许因其他接触的影响而撤回一部分 |
| $\max(0,\cdot)$ | **单边边界** | 禁止累计值变成负数，因而禁止接触产生拉力 |
| $j_{\mathrm{acc}}$ | **更新后的历史状态** | 留给本轮其余接触和下一轮使用 |
| $\delta j$ | **本轮实际写回量** | 只施加累计值真正改变的部分，避免重复施加历史总量 |

**用人话读**：记住以前推了多少，本轮可以多推或少推，但总推力不能反向变成拉力；速度只接收这次真正变化的差额。

**为什么裁剪累计值而不是裁剪 $\Delta j$**：其他接触可能让历史冲量显得过大，此时 $\Delta j$ 必须为负，才能撤回一部分。若把每轮增量裁成非负，过量冲量永远无法减少，接触链会被越推越开。
:::

一个最小反例能说明差别。假设某接触已累计 $j_{\mathrm{old}}=3$，最新速度表明应该撤回 $1$，于是 $\Delta j=-1$。正确结果是新累计量 $2$、实际写回 $-1$。若错误地计算 $\max(0,\Delta j)=0$，累计量仍是 $3$，求解器无法消除过量响应。

## 完整状态转移

顺序冲量是状态算法，不只是一个循环外壳。每个接触必须具有清晰的初始化、读取、计算、主状态更新和历史更新：

~~~mermaid
flowchart LR
    I["初始化<br/>j_acc = 0<br/>保存固定目标"] --> R["读取当前状态<br/>v_A v_B"]
    R --> V["计算 v_n 与 Delta j"]
    V --> H["更新历史<br/>裁剪 j_acc<br/>得到 delta j"]
    H --> W["更新主状态<br/>写回 v_A v_B"]
    W --> N["访问下一个接触"]
    N --> Q{"完成一轮?"}
    Q -- "否" --> R
    Q -- "是且需继续" --> R
    Q -- "是且已收敛" --> O["输出当前速度<br/>保留接触缓存"]
~~~

> `j_acc` 是每个接触自己的历史，速度是多个接触共享的主状态。访问一个接触时，两类状态都要更新；只保存其中一类都无法得到正确迭代。

严格的执行顺序如下：

1. **初始化或重置**：新接触令 $j_{\mathrm{acc}}=0$，并从撞击快照建立固定目标 $v_n^\star$。
2. **读取当前状态**：从 A、B 读取可能已被其他接触修改的速度，计算当前 $v_n$。
3. **计算候选增量**：用当前残差和 $K_n$ 得到允许正负的 $\Delta j$。
4. **更新历史状态**：保存旧累计值，更新并裁剪 $j_{\mathrm{acc}}$，求出实际差额 $\delta j$。
5. **更新主状态**：A 写入 $-w_A\delta j\mathbf n$，B 写入 $+w_B\delta j\mathbf n$。
6. **迭代接触组**：访问其余接触，多轮重复第 2 到第 5 步。

这里把历史更新写在速度更新之前，是为了先确定合法的实际增量；两项发生在同一次接触访问中。不能用未经裁剪的 $\Delta j$ 写速度，再仅对历史值做裁剪，否则主状态和历史状态会立即不一致。

## 三物体算例如何收敛

对 A、B、C 的例子继续按 $C_1\rightarrow C_2$ 扫描。每次局部求解都让当前接触的两侧速度暂时相等，随后另一接触又会改变 B：

| 完成轮数 | A 速度 | B 速度 | C 速度 | 最大接近残差 |
|----------|--------|--------|--------|--------------|
| 0 | $6$ | $0$ | $0$ | $6$ |
| 1 | $3$ | $1.5$ | $1.5$ | $1.5$ |
| 2 | $2.25$ | $1.875$ | $1.875$ | $0.375$ |
| 3 | $2.0625$ | $1.96875$ | $1.96875$ | $0.09375$ |
| 收敛 | $2$ | $2$ | $2$ | $0$ |

最终共同速度为 $2\,\mathrm{m/s}$，总动量仍是 $1\times6=6\,\mathrm{kg\,m/s}$。每轮都只做局部二体计算，但共享速度把信息沿接触链传播；更多迭代意味着影响传播得更充分。

处理顺序会影响有限轮数下的中间误差，却不应改变充分收敛后的合法结果。生产求解器会结合固定迭代次数、残差阈值、接触排序和预热，在速度与开销之间取舍。

## 最小实现

代码只翻译上一节已经完整列出的状态转移。每个 `Contact1D` 保存参与物体索引、法线方向的固定目标和累计冲量；所有接触共享 `velocities`，因此一次写回会立刻成为下一个接触的输入。

~~~python
from dataclasses import dataclass


@dataclass
class Contact1D:
    a: int
    b: int
    target_speed: float = 0.0
    accumulated_impulse: float = 0.0


def solve_contacts(velocities, inv_masses, contacts, iterations=8):
    for contact in contacts:  # 新时间步的接触历史初始化
        contact.accumulated_impulse = 0.0

    for _ in range(iterations):
        for contact in contacts:
            a, b = contact.a, contact.b
            current_speed = velocities[b] - velocities[a]
            effective_inv_mass = inv_masses[a] + inv_masses[b]
            if effective_inv_mass == 0.0:
                continue

            candidate_delta = (
                contact.target_speed - current_speed
            ) / effective_inv_mass

            old_total = contact.accumulated_impulse
            new_total = max(0.0, old_total + candidate_delta)
            actual_delta = new_total - old_total
            contact.accumulated_impulse = new_total

            velocities[a] -= inv_masses[a] * actual_delta
            velocities[b] += inv_masses[b] * actual_delta
~~~

对贯穿算例可用 `velocities=[6.0, 0.0, 0.0]`、`inv_masses=[1.0, 1.0, 1.0]` 和接触 `(0, 1)`、`(1, 2)`。把 `iterations` 从 1 增加到 8，三个速度应逐步接近 2；若速度持续增长，通常是把累计总量当成本轮增量重复写回了。

代码把跨帧预热留在范围之外。加入预热时，不应在每帧无条件清零持久接触；需要匹配上一帧的接触，把缓存的累计冲量预写入速度，然后从该历史值继续迭代。

## 单次撞击和持续接触的边界

顺序冲量同时服务于两类状态，但目标来源不同：

| 接触状态 | 目标来源 | 累计冲量的作用 |
|----------|----------|----------------|
| 新碰撞 | 保存撞击速度，用恢复系数建立分离目标 | 在本时间步产生停止与反弹 |
| 持续接触 | 通常使用零法向目标，并配合重力与位置偏差 | 持续阻止物体互相穿入 |

若把持续接触每帧都当作全新撞击，微小数值速度会不断触发反弹；若完全丢弃累计历史，堆叠需要更多迭代才能重新建立支撑。接触持久化和低速恢复阈值解决的是这两个不同问题。

## 总结

多个接触把单次碰撞公式变成了迭代状态机：

1. 一个接触写回共享速度后，会改变其余接触的输入，一轮遍历通常不能同时满足所有约束。
2. 每轮根据当前速度计算冲量增量，而不是重复使用最初撞击速度计算完整冲量。
3. 累计冲量允许局部增量为负，但总量必须保持非负，表达“接触能推不能拉”。
4. 实际写回量必须是新旧累计值之差，历史状态与主速度状态必须同步更新。

碰撞求解器概览与两章冲量模型形成了清楚的职责链：第 6 章给出输入、输出和方法地图，第 7 章闭合单个接触，第 8 章处理接触之间的耦合。

## 法向响应之外还有切向滑动

法向顺序冲量只阻止继续穿透，不会限制接触面上的滑动。[摩擦与恢复系数](./09_摩擦与恢复系数)在同一个纯平动框架中增加切向速度和摩擦上限；偏心接触产生的旋转、力臂和转动惯量则属于完整刚体响应。
