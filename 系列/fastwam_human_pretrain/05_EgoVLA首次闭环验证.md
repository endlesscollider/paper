# fast-WAM 在 EgoVLA 的首次闭环验证

> 把 fast-WAM 接入 EgoVLA 仿真环境，在 12 个桌面操作任务上做首次闭环测试。短任务平均 62%，但长任务几乎全部 0%——这一章详细记录首次实验的设置、结果和初步分析。

## 前情提要

前四章完成了 Wan2.2 base model 的架构理解和 LoRA 微调对齐。现在 fast-WAM（即 Wan2.2 Video DiT + Action Expert 联合训练的完整模型）要正式在仿真环境中接受闭环评估了。

---

## 1. EgoVLA 仿真环境介绍

### 1.1 什么是 EgoVLA？

EgoVLA 是一个基于 Isaac Lab 的**桌面双臂操控仿真环境**，配备灵巧手。它提供：
- 第一视角 (ego) 的相机观测
- 12 个标准化的操控任务
- 闭环仿真评测框架（模型输出 action → 仿真执行 → 返回下一帧观测）

### 1.2 12 个评测任务

分为**短任务**（单一动作）和**长任务**（多步骤序列）：

**7 个短任务：**

| 任务 | 描述 | 难度 |
|------|------|------|
| Stack-Can | 把一个罐子堆叠到另一个上 | 中 |
| Push-Box | 把盒子推到标记位置 | 中 |
| Open-Drawer | 打开抽屉 | 中 |
| Close-Drawer | 关闭抽屉 | 低 |
| Flip-Mug | 把倒着的杯子翻正 | 中 |
| Pour-Balls | 把杯中球倒入碗中 | 高 |
| Open-Laptop | 打开笔记本电脑 | 中 |

**5 个长任务：**

| 任务 | 描述 | 步骤数 |
|------|------|--------|
| Insert-And-Unload-Cans | 插入两个罐子再取出 | 4 步 |
| Stack-Can-Into-Drawer | 把罐子放进抽屉再关门 | 3 步 |
| Sort-Cans | 把罐子按位置分类 | 2 步 |
| Unload-Cans | 从插槽取出罐子 | 2 步 |
| Insert-Cans | 把罐子插入插槽 | 2 步 |

### 1.3 评测协议

- 每个任务运行 **27 次**（不同随机初始化位置）
- 成功率 = 成功次数 / 27 × 100%
- 使用**并行化仿真**（1 server + 多 client）加速评测

## 2. 数据处理

### 2.1 Data-Fix：首批数据清洗

原始 EgoVLA 训练数据存在问题，做了以下修正：

1. **去掉失败案例**：原始数据中包含执行失败的 episode，这些数据会给模型错误的监督信号
2. **去掉重复数据**：部分 episode 被重复存储
3. **平衡数据量**：不同任务的 episode 数量差异较大，做了初步平衡

### 2.2 动作表示

首批实验使用的动作表示：

| 维度 | 含义 | 坐标系 |
|------|------|--------|
| 前 6 维 | 末端执行器位姿 (ee) | **世界坐标系** |
| 后 12 维 | 关节位置 (qpos) | 关节空间 |
| 总计 | 18 维 | - |

> 注：后续实验（微调-2）会将 ee 从世界系切换到相机系——这是一个重要的改进。

## 3. 训练配置

### 3.1 三个训练变体

| ID | 历史帧 | 动作表示 | 训练步数 |
|-----|--------|---------|---------|
| fast-WAM_eeqpos | 无 | world ee + qpos12 | 5 epoch, ~11k steps |
| fast-WAM_eeqpos_long | 无 | world ee + qpos12 | 30k steps |
| fast-WAM-his_eeqpos | 3 帧历史 | world ee + qpos12 | 30k steps |

### 3.2 训练超参

- 图像输入：单相机，384×384 分辨率
- 学习率：1e-4
- 混合精度训练

### 3.3 训练曲线

四个关键指标在训练过程中的表现：
- `train/grad_norm`：训练初期波动大，后期稳定
- `train/loss`：快速下降后趋于平稳
- `train/loss_action`：动作预测的 FM loss，稳步下降
- `train/loss_video`：视频预测的 FM loss，下降后基本持平

观察：`loss_action` 的下降速度比 `loss_video` 更快——这说明对于仿真数据中的这些任务，action 比 video 更容易学习。

## 5. 结果分析

### 5.1 关键发现

1. **短任务平均 62%，低于 EgoVLA 的 78% 但仍有一定水平**
2. **长任务几乎全部 0%**——这是致命的差距
3. **去掉时序平滑 (temporal smoothing) 后效果反而更好**
4. **加长训练步数（30k vs 11k）没有提升，反而略有下降**
5. **加入 3 帧历史也没有帮助**

### 5.2 为什么长任务全部失败？

长任务需要**按正确顺序执行多个子动作**（如 Stack-Can-Into-Drawer: 抓罐子 → 放进抽屉 → 关门）。失败原因：

1. **没有历史记忆**：当前 fast-WAM 每步只看当前帧，不知道之前做了什么。到第二步时，模型不知道"罐子已经放进去了，该关门了"
2. **文本描述歧义**：任务描述是一整句话（"打开抽屉，放入罐子，关上抽屉"），模型在每一步都看到同一段文本，无法区分该执行哪一步
3. **动作精度累积误差**：即使单步成功率不低，多步串联后误差累积导致后续步骤基础不稳

### 5.3 时序平滑为什么有害？

`temporal smoothing` 是对连续帧的动作输出做移动平均。直觉上它应该让动作更丝滑，但实际上：
- fast-WAM 的动作输出本身就是多帧预测（一次出多步 action）
- 再做平均会**模糊掉动作的起止时机**——机器人该"快速伸手"的时候被平滑成"慢慢伸手"
- 结果：抓取不到位、动作延迟

### 5.4 训练更长为什么不好？

30k steps 时 train loss 已经很低了，但 val loss（从闭环结果间接反映）没有继续改善。可能原因：
- 训练数据量有限（data-fix 后），30k steps 已经过拟合
- 视频分支学到的"先验"不够好，action 分支只靠记忆

---

## 6. 本章小结

| 结论 | 影响 |
|------|------|
| 短任务 ~62%，证明 fast-WAM 基本可行 | 继续在此基础上优化 |
| 长任务 ~0%，说明多步推理能力缺失 | 需要任务拆分或加入历史/状态信息 |
| temporal smoothing 有害 | 后续实验全部去掉 |
| 更长训练和加历史都无效 | 瓶颈不在训练时长和输入信息量 |
