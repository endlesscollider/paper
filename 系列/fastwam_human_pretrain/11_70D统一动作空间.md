# 70D 统一手部动作空间：设计、可逆映射与验证

> 人类手（MANO 模型，连续曲面）和机器人灵巧手（Inspire，12 个关节角）的动作表示完全不同。要让人类数据和机器人数据在同一个模型中训练，需要设计一个统一的动作空间。本章记录 70D 统一空间的完整设计、可逆映射流程、以及初步验证结果。

## 前情提要

上一章所有优化尝试都未能突破瓶颈。新方向确定：用大规模人类手部数据（EgoVerse）做 pretrain 来建立物理先验。但首先要解决一个基础问题——人类手和机器人手的动作空间不同，需要统一。

---

## 1. 问题定义

### 1.1 两种手部数据的动作表示

| 数据源 | 手部模型 | 原始表示 | 维度 |
|--------|---------|---------|------|
| **EgoVerse**（人类） | MANO 参数化手模型 | 手腕位姿 + MANO pose params | 高维连续 |
| **EgoVLA**（机器人） | Inspire 灵巧手 | 12 个关节角 (qpos12) | 12D per hand |

直接把两种表示塞进同一个模型显然不行——维度不同、语义不同、数值范围不同。

### 1.2 设计目标

1. **统一**：人类和机器人数据用同一套 70 维表示
2. **语义一致**：相同的维度在两种数据中表达相同的物理含义（如"食指弯曲程度"）
3. **可逆**：从 70D 空间可以无损地恢复出机器人的 qpos12（因为 EgoVLA 对 qpos 误差很敏感）

---

## 2. 70D 统一空间定义

### 2.1 总体结构

```
总共 70D = wrist_pose18 + left_hand_z26 + right_hand_z26
```

分为三部分：

| 范围 | 名称 | 含义 |
|------|------|------|
| 0:18 | wrist_pose18 | 左右手腕位姿 |
| 18:44 | left_hand_z26 | 左手 26 维指部描述 |
| 44:70 | right_hand_z26 | 右手 26 维指部描述 |

### 2.2 手腕位姿 (wrist_pose18)

| 维度 | 含义 |
|------|------|
| 0:3 | 左手腕 xyz 位置 |
| 3:6 | 右手腕 xyz 位置 |
| 6:12 | 左手腕 6D 旋转 |
| 12:18 | 右手腕 6D 旋转 |

使用 6D 旋转表示（rotation 矩阵的前两列），而非欧拉角或四元数——因为 6D 表示是连续的、无奇异点的，更适合神经网络学习。

### 2.3 每只手的 hand_z26 定义

| 维度 | 名称 | 含义 |
|------|------|------|
| 0:3 | tip_thumb_xyz | 拇指指尖在 palm frame 下的 xyz |
| 3:6 | tip_index_xyz | 食指指尖 xyz |
| 6:9 | tip_middle_xyz | 中指指尖 xyz |
| 9:12 | tip_ring_xyz | 无名指指尖 xyz |
| 12:15 | tip_pinky_xyz | 小指指尖 xyz |
| 15 | curl_thumb | 拇指弯曲程度 |
| 16 | curl_index | 食指弯曲程度 |
| 17 | curl_middle | 中指弯曲程度 |
| 18 | curl_ring | 无名指弯曲程度 |
| 19 | curl_pinky | 小指弯曲程度 |
| 20 | spread_thumb | 拇指侧向张开角 |
| 21 | spread_index | 食指侧向张开角 |
| 22 | spread_middle | 中指侧向张开角 |
| 23 | spread_ring | 无名指侧向张开角 |
| 24 | spread_pinky | 小指侧向张开角 |
| 25 | thumb_opposition | 拇指对掌程度（越大 = 越接近捏合状态）|

### 2.4 为什么这样设计？

设计原则：**选择人类和机器人都能自然表达的物理量**。

- **指尖 xyz**：无论是 MANO 手模型还是 Inspire 灵巧手，都有明确的指尖位置（通过前向运动学计算）
- **curl（弯曲）**：人和机器人的手指都能弯曲，程度可以统一量化
- **spread（侧摆）**：手指的横向张开角
- **thumb_opposition**：拇指和其他手指的接近程度——这是抓取动作的核心特征

这些量都定义在 **palm frame（手掌坐标系）** 下——消除了手腕位置/朝向的影响，只描述手指本身的形态。

## 3. EgoVLA 的可逆映射

### 3.1 为什么需要可逆？

EgoVLA 的闭环控制最终需要的是 **qpos12**（12 个关节角）。模型在 70D 空间预测输出后，需要**精确恢复**回 qpos12 来驱动仿真。

如果这个转换有误差——即使只有 0.01 弧度的关节角偏差——都可能导致抓取失败。因此必须设计一个**数学上严格可逆**的编码-解码流程。

### 3.2 编码流程（qpos12 → 70D）

```
1. raw72 → qpos12（提取有效关节）
2. qpos12 → URDF FK → fingertips 位置 + 运动链
3. FK 结果 → physical_hand_z26（物理意义的 26 维）
4. 用 codec decoder 估计 q_pred = z_phys @ A + b
5. residual = q_target - q_pred（目标和预测的残差）
6. delta_z = residual @ P（残差投影到 z 空间）
7. enc_z = physical_hand_z + delta_z（注入残差）
8. action70 = wrist18 + left_enc_z26 + right_enc_z26
```

### 3.3 解码流程（70D → qpos12）

```
1. 从 action70 提取 enc_z26
2. q_recon = enc_z @ A + b（线性解码）
3. 得到 qpos12
```

### 3.4 关键设计：残差注入

为什么不直接 `physical_z → A → qpos`？因为线性映射 $q = zA + b$ 的精度有限——physical_z 是从 FK 计算出来的物理量，不能完美线性映射回所有关节角。

**残差注入**解决了这个问题：

$$
\text{enc\_z} = \text{physical\_z} + \underbrace{\Delta z}_{\text{补偿残差}}
$$

- $\Delta z$ 编码了"线性映射预测不到的部分"
- 解码时 $q = \text{enc\_z} \cdot A + b$ 就能精确恢复 qpos
- 数学上严格可逆（$\Delta z$ 是由 $A$ 和 $P$ 的逆关系保证的）

### 3.5 每根手指独立处理

不同手指的关节数不同：
- **拇指**：4 个关节 (yaw, pitch, intermediate, distal) ↔ 6 维 z (xyz + curl + spread + opposition)
- **食指-小指**：各 2 个关节 (proximal, intermediate) ↔ 各 6 维 z (xyz + curl + spread)

每根手指有独立的 $A$, $b$, $P$ 矩阵。

## 4. 分布验证

### 4.1 EgoVerse vs EgoVLA 的指尖分布对比

将两种数据都转换到 70D 空间后，对比各维度的分布：

| 维度 | EgoVerse (MANO) | EgoVLA (Inspire) | 差异 |
|------|----------------|-----------------|------|
| 指尖 x/y | 分布范围类似 | 分布范围类似 | 较小 |
| **指尖 z（法向）** | **范围更大** | 范围较小 | **较大** |
| curl | 分布更广 | 分布集中 | 中等 |
| spread | 有一定差异 | - | 中等 |

核心发现：**人类手的自由度（尤其是 z 方向/法向）确实比 Inspire 灵巧手大很多**。这意味着人类数据能覆盖机器人数据的分布，反过来不行。

### 4.2 编码空间 vs 物理空间对比

encoded_hand_z（注入残差后）和 physical_hand_z（纯物理计算）的差值：
- 对大多数维度，差值集中在一个很小的范围内
- 说明线性映射 $A$ 已经捕捉了大部分变化，残差只是"微调"

---

## 5. 统一归一化

两种数据的数值范围不同，需要统一的归一化策略：

| 策略 | 做法 | 适用场景 |
|------|------|---------|
| EgoVLA stats | 用 EgoVLA 数据的 mean/std 归一化 | 只训练 EgoVLA |
| **Fuse stats** | 用两种数据的混合统计量归一化 | 联合训练（pretrain + finetune）|

Fuse stats 的计算方式：从 EgoVerse + EgoVLA 的混合数据中计算全局 mean 和 std。

## 6. 初步训练结果

### 6.1 基于 70D 空间的 EgoVLA 训练

| 方案 | xyz loss weight | 成功率趋势 |
|------|----------------|-----------|
| 70D, weight=1 | 1 | 比直接 qpos 略低 |
| 70D, weight=2 | 2 | 略有改善 |
| 70D, weight=10 | 10 | 进一步改善但仍不如直接 qpos |

### 6.2 当前问题

> 70D 动作空间训练后，比直接学习 qpos 有**明显抖动**，精度有一定下降，导致成功率降低。

原因排查中：
- 可能是转换过程中的数值精度问题
- 可能是归一化策略不够好（EgoVLA stats vs Fuse stats 的差异）
- 可能是 xyz 维度的 loss 权重需要进一步调整

### 6.3 EgoVerse 大规模训练效率

| Batch size | GPU | Global BS | 速度 | 2 epoch 用时 |
|-----------|-----|-----------|------|-------------|
| 8 | 32 | 256 | 117.6 samples/s | 181.5h |
| 4 | 64 | 256 | 185.3 samples/s | 115.1h |
| 16 | 32 | 512 | 131.6 samples/s | 162.1h |
| **16** | **64** | **1024** | **259.0 samples/s** | **82.4h** |

结论：效率最高的方式是增大 global batch size + 增加 GPU 并行。gbs=1024, 64 卡时约需 82 小时完成 2 epoch。
