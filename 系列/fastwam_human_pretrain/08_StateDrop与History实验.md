# State Drop 与 History：排除 Shortcut 假设

> 如果模型只是从 state (qpos) 直接预测 action，而完全忽略视频信息，那 fast-WAM 的"视频辅助动作预测"设计就失去了意义。本章通过 state drop 消融实验验证这个假设——结论是 state 对 action 预测的贡献几乎为零。

## 前情提要

上一章证明了数据配比不是瓶颈。接下来的问题是：**模型到底在利用什么信息来预测动作？** 是图像观测？视频预测？还是纯粹的 state (qpos) 信号？

---

## 1. 假设与实验动机

### 1.1 State Shortcut 假设

fast-WAM 的输入包含：
- **图像观测**（通过 VAE 编码为 video latent token）
- **文本指令**（通过 T5 编码为 text token）
- **State**（当前 qpos12，编码为 state token）

如果 state token 已经包含了足够的信息直接预测下一步 action（比如"当前手臂角度 → 下一步手臂角度"的简单映射），那模型可能会**跳过视频理解这条难路径**，直接用 state → action 的 shortcut。

如果这个假设成立，说明视频分支根本没有起作用——fast-WAM 退化成了一个简单的 state-to-action 模型。

### 1.2 实验设计

在训练时**随机丢弃 state token**（用零向量替换），强迫模型不能依赖 state：

| 实验 | State drop rate | 含义 |
|------|----------------|------|
| Baseline | 0（不 drop）| 标准训练 |
| Drop 0.1 | 10% 的样本 state 被置零 | 轻微扰动 |
| Drop 0.5 | 50% 的样本 state 被置零 | 中等扰动 |
| Drop 1.0 | **100% state 被置零** | 完全不给 state |

另外加入一个**带 history 的变体**：

| 实验 | State drop rate | History |
|------|----------------|---------|
| History + Drop 0.1 | 10% | 3 帧历史图像 |

---

## 2. 训练曲线对比

### 2.1 核心发现

> **不同 drop rate 下，train loss 和 val loss 的曲线几乎完全重合。**

具体指标：
- `train/loss_action`：四种 drop rate 下的曲线几乎无法区分
- `train/loss_video`：同样重合
- `train/grad_norm`：无显著差异
- 验证集指标：同样无差异

### 2.2 这意味着什么？

如果 state 对 action 预测有重要贡献，那么：
- drop=0（有 state）时 loss 应该更低
- drop=1.0（完全没 state）时 loss 应该明显更高

但实际上 loss 完全相同 → **state 对 action 预测的贡献接近零**。

模型在预测动作时，主要依赖的是**图像观测 + 文本条件**，state (qpos) 几乎不提供额外信息。

---

## 3. 闭环仿真验证

训练曲线一致后，闭环测试也印证了这个结论：

> 不同 state drop rate 下的闭环仿真成功率也没有显著差别。

包括加入 3 帧 history 的版本，也没有带来明显改善。

---

## 4. 为什么 State 不起作用？

### 4.1 信息冗余

在 EgoVLA 的设置中：
- **图像观测**已经隐式包含了手臂的位置信息（从画面中能看到手在哪里）
- **qpos12** 提供的关节角信息是精确的，但模型选择不用它

这说明 DiT 从图像 token 中提取的视觉信息已经**涵盖了 state 能提供的空间位置信息**。

### 4.2 State 维度太低

qpos12 只有 12 个浮点数——相对于数千个 video token，state token 在注意力计算中的权重非常小。模型可能在训练过程中自然地学会了忽略这个"微弱信号"。

### 4.3 不存在简单的 state → action 映射

如果任务只有一种物体初始位置、一种固定轨迹，那 state → action 的映射可能很简单。但 EgoVLA 的初始位置是随机的——同一个 qpos 可能对应"物体在左边"或"物体在右边"，动作完全不同。所以 state → action 的映射本身就不是单射，模型学不到 shortcut。

---

## 5. History 帧为什么也没用？

加入 3 帧历史图像的目的是给模型"运动方向"的信息——当前帧看不出手正在往哪走，但连续 3 帧可以推断运动趋势。

但实际无效，可能原因：
1. fast-WAM 是**单步预测**（给当前帧预测动作），不需要"推断运动方向"——它需要的是"知道目标在哪、该往哪走"
2. 视频生成分支本身就在做多帧预测（预测未来视频），已经隐式包含了运动方向信息
3. 3 帧历史的信息增量相对于首帧的丰富视觉信息来说太小

---

## 6. 排除了什么？确认了什么？

### 排除的假设

| 假设 | 结论 |
|------|------|
| "模型通过 state shortcut 预测 action" | ✗ 排除——state drop=1.0 时效果不变 |
| "加入历史帧能提高精度" | ✗ 排除——history 无效果 |
| "state 信息是 action 预测的关键输入" | ✗ 排除——state 贡献接近零 |

### 确认的事实

| 事实 | 含义 |
|------|------|
| 模型主要依赖视觉信息预测动作 | fast-WAM 的视频→动作信息通道确实在工作 |
| state drop 不影响训练 | 可以安全地在后续实验中去掉 state 输入 |
| 瓶颈不在输入信息量 | 加更多信息（state, history）都不帮助 |

---

## 7. 本章小结

本章的实验简洁但结论清晰：

1. State (qpos) 对 fast-WAM 的动作预测**不提供有意义的贡献**
2. 模型不存在 state → action 的 shortcut
3. 历史帧也不提供有效的额外信息
4. **瓶颈在模型本身的动作预测精度**——不是缺信息，而是"有信息但用不好"

这进一步把问题定位到了 fast-WAM 的视频生成质量——如果视频分支生成的"未来视频"物理上不合理，那它传递给动作分支的信息就是错误的，动作精度自然不好。
