# 第二章：分布式价值函数：网络结构与训练

> 上一章：[仓库全景与 Pipeline 总览](./01_仓库全景与Pipeline总览)

## 前情提要

上一章画出了全局地图。本章深入 pipeline 的第一个核心环节：**训练一个分布式价值函数（Value Function, VF）**——它是一个神经网络，输入当前的图像观测和机器人状态，输出一个标量估计"从这一刻到任务完成还有多远"。后续章节用这个估计来计算优势（advantage）、决定每个动作是 "high"（好于预期）还是 "low"（差于预期）。

---

## 一、网络结构：ResNet-50 + 3 层 MLP → 201 个 softmax logits

核心代码在 `src/psi/recap/distributional_vf.py`：

```python
class DistributionalValueFn(nn.Module):
    def __init__(self, config):
        # 1. 图像编码器：冻结的 ImageNet 预训练 ResNet-50，去掉最后的全连接层
        resnet = models.resnet50(weights=models.ResNet50_Weights.DEFAULT)
        resnet.fc = nn.Identity()          # pool5 输出 2048 维
        for p in resnet.parameters():
            p.requires_grad = False         # 完全冻结，不训练
        self.img_encoder = resnet

        # 2. MLP head：(state_dim + 2048) → hidden → hidden → 201 logits
        self.net = nn.Sequential(
            nn.Linear(32 + 2048, 256),      # 2080 → 256
            nn.LayerNorm(256),
            nn.ReLU(),
            nn.Linear(256, 256),            # 256 → 256
            nn.ReLU(),
            nn.Linear(256, 201),            # 256 → 201 (NUM_VALUE_BINS)
        )

        # 3. 预计算 201 个 bin 的中心值，用于把分布期望还原成标量
        self.bin_values = torch.linspace(-1.0, 0.0, 201)  # [-1.0, -0.995, ..., 0.0]
```

**信息流**：输入一帧 $(s_t, \text{img}_t)$，ResNet-50 把 224×224 图像编码成 2048 维向量（冻结，不回传梯度），和 32 维的本体状态拼接后过 MLP，输出 201 个 logits。

**推理时怎么拿到标量 $V(s_t)$**：

```python
def expected_value(self, state, img):
    probs = torch.softmax(self(state, img), dim=-1)  # (B, 201) 概率分布
    return (probs * self.bin_values).sum(dim=-1)      # 加权求和 → 标量 ∈ [-1, 0]
```

这正是 [分布式值函数与类别化回报预测](/前置知识/002q_前置知识_分布式值函数与类别化回报预测) 里讲的"分类交叉熵训练 + 期望还原"。

### 1.1 和原文的架构差异

| 维度 | π\*₀.₆ 原文 | Psi0-Recap |
|------|-------------|-----------|
| 图像骨干 | Gemma-670M（和策略共享架构的 VLM） | ImageNet ResNet-50（冻结） |
| 骨干参数量 | ~670M | ~25M（全部冻结） |
| 骨干是否训练 | 从 VLM 预训练初始化，微调 | 完全冻结，零梯度 |
| 语言输入 | 有（任务指令通过 VLM 编码） | **无**（只看图像 + 状态） |
| MLP head | 未公开具体结构 | 3 层，hidden=256，LayerNorm + ReLU |
| bin 数量 | 201 | 201 ✓ |
| 归一化区间 | $(-1, 0)$ | $(-1, 0)$ ✓ |

**最大的差异是没有语言输入**：原文的价值函数和策略共享 VLM（Vision-Language Model，视觉语言模型）骨干，天然能看到任务指令文本，所以同一个价值函数可以处理"叠衣服"和"做咖啡"两种不同任务。Psi0-Recap 只跑一个任务（bendpick），不需要区分任务语义，所以省略了语言输入不影响功能——但如果要扩展到多任务，这一块是必须补回来的。

## 二、训练标签：从 success/n_steps 推导逐帧 return

VF 训练的核心问题是：每个决策帧的"正确答案"（训练标签）是什么？

答案在 `npz_dataset.py` 的 `compute_returns()` 函数里：

```python
def compute_returns(t_obs: int, success: bool, n_steps: int) -> np.ndarray:
    # 失败轨迹：所有帧的 return 都是 V_MIN = -1
    if not success:
        return np.full(t_obs, V_MIN, dtype=np.float32)

    # 成功轨迹：假设 t_obs 个查询点均匀分布在 n_steps 步中
    # 第 i 个查询点的"剩余步数" = (n_steps-1) * (1 - i/(t_obs-1))
    # 归一化到 (-1, 0)：除以 MAX_EPISODE_STEPS-1
    i = np.arange(t_obs, dtype=np.float32)
    steps_remaining = (n_steps - 1) * (1.0 - i / (t_obs - 1))
    return (-steps_remaining / (MAX_EPISODE_STEPS - 1)).astype(np.float32)
```

**逻辑拆解**：

- **失败**：不管走了多少步，所有帧的 return 一律设为 $-1$。这对应原文中"失败惩罚 $-C_{\text{fail}}$ 足够大，归一化后直接饱和到 $V_{\text{MIN}}$"的设计。
- **成功**：最后一帧 return = 0（刚成功），第一帧 return ≈ $-n_{\text{steps}}/600$（离成功最远）。中间帧线性插值。
- **更快的成功 = 更高的 early return**：同样是第一帧，180 步完成的轨迹 return ≈ $-0.30$，而 590 步完成的轨迹 return ≈ $-0.98$。VF 学到的就是"这类状态通常还要走多久"。

**数值例子**：`t_obs=6, success=True, n_steps=180`（6 个查询点，180 步成功）

| 查询点 $i$ | steps_remaining | return |
|------------|----------------|--------|
| 0 | $179 \times (1 - 0/5) = 179$ | $-179/599 = -0.299$ |
| 1 | $179 \times (1 - 1/5) = 143.2$ | $-143.2/599 = -0.239$ |
| 2 | $179 \times (1 - 2/5) = 107.4$ | $-107.4/599 = -0.179$ |
| 3 | $179 \times (1 - 3/5) = 71.6$ | $-71.6/599 = -0.120$ |
| 4 | $179 \times (1 - 4/5) = 35.8$ | $-35.8/599 = -0.060$ |
| 5 | $179 \times (1 - 5/5) = 0$ | $0/599 = 0.0$ |

最后一帧恰好是 0，第一帧约 $-0.30$——比那些 590 步才成功的轨迹高得多（它们的第一帧接近 $-0.98$）。

### 2.1 离散化：连续 return → bin 索引

```python
BIN_EDGES = np.linspace(-1.0, 0.0, 202)  # 202 条边界 → 201 个 bin

def discretize_return(r: float) -> int:
    idx = np.searchsorted(BIN_EDGES[1:-1], r)
    return int(np.clip(idx, 0, 200))
```

每个 bin 宽度 = $1/201 \approx 0.005$。这意味着 VF 的分辨率是"能区分相差约 3 步的两条轨迹"（在 600 步任务中）。

## 三、训练循环：episode 级分层 split + 交叉熵

训练脚本 `scripts/recap/train_distributional_vf.py` 的核心逻辑：

```python
# 1. 加载数据：每个 NPZ 展开成逐帧样本
dataset = TrajectoryDataset(data_dir)
# 输出示例：loaded 847 decision points from 98 episodes (71 successes)

# 2. Episode 级分层划分：保持 train/val 中成功/失败比例一致
train_eps, val_eps = train_test_split(
    range(n_episodes),
    test_size=0.1,
    stratify=dataset.episode_labels,  # [1, 0, 1, 1, ...] per episode
    random_state=42,
)

# 3. 标准 Adam + CrossEntropy 训练 50 epochs
optimizer = torch.optim.Adam(model.parameters(), lr=3e-4)
criterion = nn.CrossEntropyLoss()

for epoch in range(50):
    train_loss = train_epoch(model, train_loader, optimizer, criterion, device)
    val_loss, val_mse = val_epoch(model, val_loader, criterion, device)
    # 保留 val_loss 最低的 checkpoint
```

**为什么按 episode 切分而不是按 frame 切分**：如果按 frame 随机切分，同一条 episode 的不同帧可能同时出现在 train 和 val 中——由于同一 episode 内相邻帧高度相关（状态只差一个动作块的执行），这会导致验证集泄漏，validation loss 虚假地低。按 episode 切分保证 train/val 看的是完全不同的轨迹。

**分层（stratify）的目的**：确保 train 和 val 中成功/失败的比例一致。如果 val 里全是成功轨迹（return 都是平滑的线性下降），而 train 里有很多失败轨迹（return 都是 $-1$），那 val loss 就不能真实反映价值函数对混合数据的拟合能力。

### 3.1 验证指标

训练循环里跟踪两个指标：

1. **val_loss**（交叉熵）：价值函数预测的分布和真实 bin 的匹配程度。这是 checkpoint 选择的标准。
2. **val_mse**：价值函数的标量输出 $\hat{V}(s_t)$（分布期望）和真实 return 之间的均方误差。这是一个更直观的"预测准不准"的指标，但由于离散化本身有量化误差，MSE（Mean Squared Error，均方误差）不会趋近于 0。

## 四、评测脚本：逐帧 MSE 与 episode-level AUC 的深度分析

训练完价值函数之后，`scripts/recap/eval_distributional_vf.py` 独立运行，报告两个指标。这两个指标各自能说明什么、不能说明什么、在什么场景下会失效，需要逐个辨析。

### 4.1 逐帧均方误差（Step-level MSE）

```python
@torch.no_grad()
def step_level_mse(model, loader, device) -> float:
    model.eval()
    all_v_hat, all_returns = [], []
    for state, img, _bin_idx, returns in loader:
        state, img = state.to(device), img.to(device)
        # model.expected_value() 输出标量 V_hat(s_t) ∈ [-1, 0]
        all_v_hat.append(model.expected_value(state, img).cpu().numpy())
        all_returns.append(returns.numpy())
    v_hat = np.concatenate(all_v_hat)
    returns = np.concatenate(all_returns)
    return float(np.mean((v_hat - returns) ** 2))
```

**做了什么**：遍历验证集里的**所有决策帧**（包含轨迹开头、中间、结尾各个阶段的帧），对每一帧计算价值函数预测 $\hat{V}(s_t)$ 和真实归一化回报 $R_t$ 之间的均方误差（Mean Squared Error, MSE），然后对所有帧取平均。

**能说明什么**：

- 价值函数在各种进度阶段的预测是否准确——轨迹开头的帧（$R_t$ 很负，比如 $-0.8$）和接近成功的帧（$R_t$ 接近 $0$），价值函数对它们的估值是否都在合理范围内
- 如果 MSE 很低（比如 < 0.01），说明价值函数确实学到了"从图像+本体状态 → 推断任务进度"的映射能力

**不能说明什么**：

- MSE 低不等于 advantage 信号有用。极端情况：如果价值函数对**所有帧**都输出训练集 return 的均值（比如固定输出 $-0.5$），MSE 等于 return 的方差——可能不算特别高，但这样的价值函数算出来的 advantage $A_t = R_t - (-0.5)$ 完全等价于直接按 $R_t$ 排序，价值函数没有提供任何**超越已知 return 的额外信息**
- MSE 不区分"系统性偏差"和"随机噪声"：价值函数可能整体偏高 0.1（所有帧都多估了 0.1），这时候 advantage 的**正负号**仍然是对的（因为减去的是同一个偏移量），但 MSE 会被这个偏差撑高。所以 MSE 稍高不一定意味着 advantage 不可用

**真正的用途**：比较两个不同配置训出来的价值函数时，MSE 更低的那个在逐帧预测上更精细——对后续 advantage 的信噪比有直接帮助。

### 4.2 Episode-level AUC：一个需要非常谨慎解读的指标

```python
@torch.no_grad()
def episode_level_auc(model, data_dir: str | Path, device) -> float:
    model.eval()
    paths = sorted(glob.glob(f"{data_dir}/**/*.npz", recursive=True))
    scores, labels = [], []
    for p in paths:
        data = np.load(p, allow_pickle=True)
        # ⚠️ 关键：只取每条轨迹的第一帧 (t=0)
        state0 = torch.from_numpy(data["obs_states"][0].astype(np.float32)).unsqueeze(0).to(device)
        img0 = IMG_TRANSFORM(data["obs_images"][0]).unsqueeze(0).to(device)
        scores.append(model.expected_value(state0, img0).item())
        labels.append(int(bool(data["success"])))
    try:
        return float(roc_auc_score(labels, scores))
    except ValueError:
        return float("nan")
```

**做了什么**：对数据集里的每条 episode，**只看第一帧**的 $V(s_0)$ 作为"评分"，然后用 ROC AUC（Receiver Operating Characteristic 曲线下面积）衡量这个分数能否将最终成功的轨迹和最终失败的轨迹区分开。AUC = 1.0 表示完美区分，AUC = 0.5 表示和随机猜没有区别。

**⚠️ 核心问题：第一帧的初始状态真的有区分度吗？**

这取决于任务环境的初始化设定——SIMPLE bendpick 任务在每次 reset 时是否做了域随机化（物体位置、朝向的随机扰动）。分两种情况讨论：

**情况 A：初始状态几乎完全相同（弱随机化或固定 reset）**

如果每条 episode 开始时机器人姿态和物体位置都差不多（SIMPLE 的很多任务是 motion-planning 生成的数据，初始配置可能变化很小），那么：

- 所有 episode 的第一帧图像和本体状态几乎一样
- 价值函数对所有第一帧输出的 $V(s_0)$ 也应该几乎相同（因为输入几乎相同）
- ROC AUC ≈ 0.5——**这不是价值函数的错，而是"第一帧本身就不含成败信息"**
- **这种情况下 AUC ≈ 0.5 是完全正常的，不应被解读为"价值函数没训好"**

为什么初始状态相同但最终结局不同？因为策略本身有随机性（flow matching 采样的噪声），同样的起点可能因为中间某一步的微小差异而走向完全不同的结局。这种"初始相同、结局不同"的轨迹，价值函数在第一帧**应该**给出相同的估值（因为它看到的输入确实一样），所以 AUC 低是合理的。

**情况 B：初始状态有明显随机化**

如果每次 reset 时物体位置有较大变化（比如放在桌面的随机位置），那么：

- 有些初始配置天然更容易成功（物体正好在手附近），有些天然更难（物体在桌子边缘）
- 价值函数可能从初始图像里"看到"这个难度差异，给出不同的 $V(s_0)$
- AUC 高说明**价值函数学会了判断"这个初始布局的固有难度"**

但注意：这衡量的是"状态的固有难度"，**不是"策略的决策质量"**。一条从困难初始状态出发但最终成功的轨迹，恰恰是策略做得好的证据——但 AUC 的计算逻辑会把它归为"分数低却成功"的反例。

**所以 episode AUC 到底在量化什么？**

它量化的是一个复合量："初始状态的随机化幅度 × 价值函数从首帧图像中提取环境布局信息的能力"。它**不直接衡量**价值函数对 RECAP advantage 信号的贡献——因为 advantage 是在**每一帧**（包括轨迹中段和后段）计算的，而价值函数在状态已经分化之后的预测能力，才是 advantage 信号的主力来源。

**那为什么这个指标还在代码里？**

作为一个快速的 sanity check（健全性检查）：
- AUC 明显 > 0.5 → 价值函数至少具备从图像中提取环境状态的能力（不是全盲的）
- AUC ≈ 0.5 → 两种可能：(a) 初始状态无区分度（正常）或 (b) 价值函数完全没学到东西（有问题）

要区分 (a) 和 (b)，需要结合 step MSE：如果 step MSE 低但 episode AUC ≈ 0.5，说明是情况 (a)——价值函数在轨迹中后段预测得好，只是初始状态确实没有区分力。如果 step MSE 高且 episode AUC ≈ 0.5，才说明价值函数可能真的没训好。

### 4.3 更有诊断价值的评测方式（原代码没做，值得二次开发时补充）

上面两个指标是这个课程项目里有的。如果要更深入地评估价值函数对 RECAP 的实际贡献，以下几个分析更有诊断价值：

**1. 逐帧散点图：$\hat{V}(s_t)$ vs $R_t$**

把验证集所有帧的（预测值, 真实值）画成散点图，看 Pearson 相关系数。如果点紧密分布在 $y=x$ 对角线附近（相关系数 > 0.9），说明价值函数的**排序能力**很强——这意味着 advantage 的正负号是可信的。

**2. Advantage 在成功/失败轨迹上的分布分离度**

分别画两个直方图：成功轨迹所有帧的 advantage 分布，和失败轨迹所有帧的 advantage 分布。理想情况下两个分布应该有清晰的分离——成功轨迹的帧多数有正 advantage，失败轨迹的帧多数有负 advantage。如果两个分布完全重叠，说明价值函数提供的 advantage 信号几乎没有区分力，后续二值化无论怎么设阈值都效果有限。

**3. 成功轨迹内的单调性检验**

对一条成功轨迹，价值函数的输出序列 $V(s_0), V(s_1), \ldots, V(s_T)$ 应该大致单调递增（越接近成功，"离成功的距离"越短，$V$ 越接近 0）。可以用 Kendall's tau 或简单的"相邻帧 $V$ 递增的比例"来量化。如果很多成功轨迹里价值函数的输出忽高忽低（单调性差），说明它对"进度"的感知不一致——虽然整体 MSE 可能还行，但逐帧的优势信号会非常嘈杂。

**4. 阈值敏感性分析**

固定价值函数，改变二值化的百分位阈值（20%、30%、40%、50%），观察被标为 "high" 的帧中来自成功轨迹的比例变化。如果这个比例对阈值极其敏感（小幅改动阈值就导致标签质量剧变），说明 advantage 的分布在阈值附近非常密集，价值函数没有把"好"和"差"拉开足够的间隔。

## 五、训练超参数

| 超参 | 取值 | 来源/说明 |
|------|------|----------|
| 学习率 | 3e-4 | Adam 默认偏大，但 MLP head 只有 ~53 万可训参数 |
| batch size | 256 | frame 级 batch |
| epochs | 50 | 足够在 ~800 个 frame 的数据上收敛 |
| hidden dim | 256 | MLP 隐层宽度 |
| validation split | 10% | episode 级分层 |
| seed | 42 | 固定 |
| wandb | 可选 | `--no_wandb` 关闭 |

由于 ResNet-50 完全冻结，**实际可训练参数只有 MLP head 的 3 个 Linear 层**：

- Linear(2080, 256)：532,736 参数
- Linear(256, 256)：65,792 参数
- Linear(256, 201)：51,657 参数
- LayerNorm(256)：512 参数
- **总计**：~65 万可训参数

这意味着训练极快（单 GPU 几分钟），不需要分布式训练。
