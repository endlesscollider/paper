# 第三章：优势计算与标签生成

> 上一章：[分布式价值函数：网络结构与训练](./02_分布式价值函数_网络结构与训练)
> 下一章：[Advantage Conditioning 接入 Ψ₀ 训练](./04_Advantage_Conditioning接入训练)

## 前情提要

上一章训练好了分布式价值函数 $V_\phi(s_t)$——给定一帧观测，它能预测"从这一刻到成功还要走多远"。本章讲如何用这个 VF 给每一帧打上 "high" / "low" 的二值标签，供后续策略微调消费。

---

## 一、优势的计算公式：纯 Monte Carlo

核心代码在 `src/psi/recap/advantages.py`：

```python
def compute_advantage(actual_return, expected_value):
    """A_t = R_t - V(o_t)"""
    return actual_return - expected_value
```

就这一行。Psi0-Recap 使用的是**纯 Monte Carlo 优势**：

$$
A(s_t, a_t) = R_t(\tau) - V_\phi(s_t)
$$

**这个公式在做什么**：拿这条轨迹里第 $t$ 帧的真实回报（从 `compute_returns()` 算出来的那个归一化数值），减去 VF 对这一帧的预期——正数表示"比 VF 以为的要好"，负数表示"比 VF 以为的要差"。

::: details 📐 逐符号拆解 + 数值代入（点击展开）
**逐符号拆解**：

| 符号 | 含义 | 这里具体是什么 |
|------|------|--------------|
| $R_t(\tau)$ | 真实回报 | 上一章 `compute_returns()` 的输出值，是个已知数字 |
| $V_\phi(s_t)$ | VF 的预测 | `model.expected_value(state, img)` 的输出 |
| $A(s_t, a_t)$ | 优势 | 两者之差 |

**数值代入**：假设某帧的真实 return 是 $R_t = -0.30$（成功轨迹的一个 early frame），VF 对这帧的预测是 $V_\phi = -0.45$（VF 以为会更慢）：

$$
A = -0.30 - (-0.45) = +0.15
$$

正值！说明这条轨迹在这一帧**比 VF 预期的要快**。这帧有资格被标记为 "high"。

再看一个：真实 return $R_t = -0.60$，VF 预测 $V_\phi = -0.40$：

$$
A = -0.60 - (-0.40) = -0.20
$$

负值。这帧比 VF 预期的要差，会被标为 "low"。
:::

### 1.1 和原文的差异：纯 MC vs N 步展开

| 维度 | π\*₀.₆ 原文（目标任务微调） | Psi0-Recap |
|------|---------------------------|-----------|
| 公式 | $A = \sum_{i=0}^{N-1} r_{t+i} + V(s_{t+N}) - V(s_t)$ | $A = R_t - V(s_t)$ |
| N | 50 | 等效于 $N = T$（展开到轨迹结束） |
| bootstrap | 有（$V(s_{t+N})$ 用 VF 估计未来） | 无（直接用真实回报） |
| 偏差 | 有偏（VF 不精确→bootstrap 引入偏差） | 无偏（但方差更大） |

Psi0-Recap 直接用完整轨迹的真实回报，不做 bootstrap——这其实对应的是**原文的预训练阶段**（原文在预训练阶段也用 $N=T$），而不是目标任务微调阶段（那里用 $N=50$）。

**为什么这个简化在这里合理**：
1. 数据已经是完整的 episode（不是正在跑的在线数据），真实 return 直接可算
2. 只跑一个任务一轮，不需要 bootstrap 带来的低方差优势
3. 实现简单——不需要在 label 阶段维护一个"向前看 N 步"的滑窗

**关键设计：先算完所有帧的优势，再统一做百分位阈值。** 不是逐 episode 各自取百分位，而是把所有 episode 的所有 frame 的优势值放到同一个数组里，全局取 top 30% 作为 "high"。这意味着：

- 成功轨迹的 frame 会整体偏向 "high"（因为真实 return 本身就高）
- 失败轨迹的 frame 几乎全是 "low"（return = $-1$，很难超过 VF 的预期）
- 成功轨迹中"比平均还快"的那些特别好的帧，才是真正的 top 30%

## 三、百分位二值化的具体机制

```python
def label_from_advantage(advantage, threshold=0.0, percentile=None):
    if percentile is not None:
        # percentile=30 → 取第 70 百分位数作为阈值（top 30% 超过它）
        used_threshold = np.percentile(advantage, 100.0 - percentile)
    labels = np.where(advantage > used_threshold, "high", "low")
    return labels, used_threshold
```

**`percentile=30` 的含义**：让恰好 30% 的帧被标记为 "high"。实现方式是取全部优势值的第 70 百分位数作为阈值——超过这个阈值的恰好是 top 30%。

**数值例子**：假设 100 个帧的优势值排序后如下：

```
[-0.8, -0.7, ..., -0.1, 0.0, 0.05, ..., 0.3, 0.4, 0.5]
                                              ↑ 第 70 百分位
```

阈值被设在约 0.3 的位置，超过 0.3 的 30 个帧被标为 "high"，其余 70 个标为 "low"。

### 3.1 为什么是 30%

这直接对应原文 Section F 的描述："approximately 30% of the demonstration data has positive advantage"。原文在预训练阶段用的就是 30%。目标任务微调阶段可能调到 40% 或更低的 10%（取决于数据质量和优化目标），但 Psi0-Recap 作为课程项目只实现了固定的 30%。

## 四、输出格式：Parquet 标签文件

标签最终存储为一个 Parquet 文件，结构如下：

| 列名 | 类型 | 含义 |
|------|------|------|
| `episode_id` | str | 如 "episode_0042" |
| `frame_id` | int | episode 内的帧索引（0-based） |
| `advantage` | float32 | 原始连续优势值 |
| `advantage_label` | str | "high" 或 "low" |
| `expected_v` | float32 | VF 的预测 $V_\phi(s_t)$ |
| `actual_return` | float32 | 真实回报 $R_t$ |
| `threshold` | float32 | 实际使用的阈值 |

同时输出一个 `label_summary.json`：

```json
{
  "count": 847.0,
  "fraction_high": 0.30,
  "mean_advantage": -0.012,
  "std_advantage": 0.18,
  "threshold": 0.042,
  "mean_expected_v": -0.38,
  "mean_actual_return": -0.39,
  "num_episodes": 98
}
```

**为什么用 Parquet 而不是 JSON 或 CSV**：
- 列式存储，读取特定列很快
- 原生支持 pandas DataFrame 的 round-trip
- 文件小（二进制压缩）
- 下游的 `AdvantageLabelStore` 直接用 `pd.read_parquet()` 加载，查询效率高

## 五、AdvantageLabelStore：微调时的标签查询接口

标签文件生成之后，策略微调阶段需要一个高效的查询接口——给定 `(episode_id, frame_id)` 或 `(episode_index, frame_index)`，立即返回对应的 "high" / "low"。

```python
class AdvantageLabelStore:
    def __init__(self, labels_path):
        self.df = pd.read_parquet(labels_path)
        # 建立 hash map 索引
        self._by_episode_frame = {}
        for row in self.df.itertuples():
            self._by_episode_frame[(str(row.episode_id), int(row.frame_id))] = row.advantage_label

    def lookup(self, episode_id=None, frame_id=None, ...):
        return self._by_episode_frame.get((episode_id, frame_id))
```

这个 store 在微调开始时一次性加载到内存，之后每个 training step 查表的时间复杂度是 O(1)（字典 lookup），不会成为训练的瓶颈。

## 六、单元测试：保证标签逻辑的正确性

`tests/test_recap_value_function.py` 中和标签相关的关键测试：

```python
def test_label_from_advantage_top_30_percent():
    """percentile=30 should label ~30% of frames 'high'."""
    adv = np.random.normal(size=1000)
    labels, threshold = label_from_advantage(adv, percentile=30.0)
    frac_high = (labels == "high").mean()
    assert 0.25 < frac_high < 0.35  # 允许小误差
    assert (adv > threshold).mean() == frac_high

def test_compute_advantage_sign():
    actual = np.array([0.0, -0.1, -0.5])
    expected = np.array([-0.2, -0.1, -0.4])
    adv = compute_advantage(actual, expected)
    assert adv[0] > 0    # return 超出预期 → positive
    assert abs(adv[1]) < 1e-6  # 恰好匹配 → ~zero
    assert adv[2] < 0    # return 低于预期 → negative
```

这些测试验证了两个关键属性：
1. 百分位阈值确实让约 30% 的帧被标为 "high"
2. 优势的正负号符合直觉：return 超出 VF 预期 → positive

## 七、本章小结

| 维度 | 实现细节 |
|------|---------|
| 优势公式 | $A = R_t - V_\phi(s_t)$（纯 Monte Carlo，无 bootstrap） |
| 二值化方式 | 全局取 top 30% 百分位阈值 |
| 输出格式 | Parquet + JSON summary |
| 查询接口 | `AdvantageLabelStore`（内存 hash map，O(1) lookup） |
| 和原文的差异 | 纯 MC 而非 N 步展开；固定 30% 百分位而非 per-task 调整 |
