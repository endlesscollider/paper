# 网络架构大盘点：四个网络长什么样

> 前情提要：上一章搞清楚了数据从哪来、长什么样——统一格式是 `observations`/`actions`/`rewards`/`terminals`/`masks`。这一章看接收这些数据的网络架构：动作是怎么被生成的（flow matching 网络）、动作的好坏是怎么被打分的（Critic），以及如果观测是图像，怎么先过一层视觉编码器。

## 一、这个项目一共用到几种网络结构

不管是 QC、QC-FQL 还是 RLPD-AC、QC-RLPD，翻来覆去用到的网络结构其实只有三类：

1. **动作生成网络**——QC/QC-FQL 用 `ActorVectorField`（flow matching），RLPD-AC/QC-RLPD 用 `TanhNormal`（高斯策略）
2. **价值网络（Critic）**——`utils/networks.py` 里的 `Value`，或 `rlpd_networks` 里的 `StateActionValue` + `Ensemble` 组合，本质都是"输入状态+动作，输出一个标量打分"的 MLP
3. **视觉编码器（可选）**——只有观测是图像时才需要，`ImpalaEncoder`，把图像压缩成一个向量，之后接入前两种网络

这一章先讲第 1、2 类（低维状态任务的核心网络），第三节再讲图像编码器怎么接进来。

## 二、`ActorVectorField`：QC/QC-FQL 共用的核心网络结构

```python
class ActorVectorField(nn.Module):
    hidden_dims: Sequence[int]
    action_dim: int
    layer_norm: bool = False
    encoder: nn.Module = None
    use_fourier_features: bool = False
    fourier_feature_dim: int = 64

    def setup(self) -> None:
        self.mlp = MLP((*self.hidden_dims, self.action_dim), activate_final=False, layer_norm=self.layer_norm)
        if self.use_fourier_features:
            self.ff = FourierFeatures(self.fourier_feature_dim)

    @nn.compact
    def __call__(self, observations, actions, times=None, is_encoded=False):
        if not is_encoded and self.encoder is not None:
            observations = self.encoder(observations)
        if times is None:
            inputs = jnp.concatenate([observations, actions], axis=-1)
        else:
            if self.use_fourier_features:
                times = self.ff(times)
            inputs = jnp.concatenate([observations, actions, times], axis=-1)
        v = self.mlp(inputs)
        return v
```

**这个网络在做什么，用自然语言先讲清楚**：它本质上就是一个普通的 MLP，输入是"状态 + 动作（+ 可选的时间）"拼接起来的向量，输出一个和动作维度相同的向量。这个输出向量的含义会随着调用方式的不同而变化——如果传了 `times`，输出被解读成"flow matching 里某个时刻的速度场"；如果没传 `times`，输出被直接解读成"一个动作"。这种"一个网络结构、两种解读方式"的设计，正是它能同时充当多步 flow 和单步映射网络的原因。第 3 章先只讲 `actor_bc_flow` 在 QC 基础流程中的职责；第 4 章再单独引入 `actor_onestep_flow`，第 5 章对应具体代码。

**逐个参数看**：

| 参数 | 含义 |
|------|------|
| `hidden_dims` | MLP 隐藏层宽度序列，比如 `(512, 512, 512, 512)` |
| `action_dim` | 输出维度——注意这里是**动作块**的维度（单步动作维度 × chunk 长度 $h$），不是单步动作维度 |
| `encoder` | 可选的视觉编码器，观测是图像时用（第三节细讲） |
| `use_fourier_features` | 是否用傅里叶特征给时间 `t` 编码（而不是直接把 `t` 这个标量拼进去） |

**为什么需要傅里叶特征编码时间**：直接把 `t`（一个 0 到 1 之间的标量）拼进输入向量,网络很难学会"时间对结果的影响是非线性、多频率的"——这是扩散/flow 模型训练里的常见技巧，用一组不同频率的正弦/余弦函数把标量时间映射成一个高维向量,让网络更容易学到不同时间尺度上的变化模式。这不是本项目独有的技巧,而是"怎么把一个标量变成网络能用的向量"这个通用问题的一种解法,和 Transformer 的位置编码、扩散模型的时间步嵌入本质上是同一类方法的不同变体，完整的原理推导、多种编码方式的对比,详见 [标量条件编码：位置编码、时间步嵌入与随机傅里叶特征](/前置知识/001s_前置知识_标量条件编码_位置编码与时间步嵌入)。`FourierFeatures` 类的实现：

```python
class FourierFeatures(nn.Module):
    output_size: int = 64
    def __call__(self, x):
        half_dim = self.output_size // 2
        f = jnp.log(10000) / (half_dim - 1)
        f = jnp.exp(jnp.arange(half_dim) * -f)
        f = x * f
        return jnp.concatenate([jnp.cos(f), jnp.sin(f)], axis=-1)
```

这是标准的正弦位置编码公式——用不同频率（由 `jnp.exp(jnp.arange(half_dim) * -f)` 生成的一组指数衰减频率）分别对时间标量做 cos/sin 变换，拼接成一个 `output_size` 维的向量。

## 三、`Value`：Critic 网络的结构

```python
class Value(nn.Module):
    hidden_dims: Sequence[int]
    layer_norm: bool = True
    num_ensembles: int = 2
    encoder: nn.Module = None

    def setup(self):
        mlp_class = MLP
        if self.num_ensembles > 1:
            mlp_class = ensemblize(mlp_class, self.num_ensembles)
        self.value_net = mlp_class((*self.hidden_dims, 1), activate_final=False, layer_norm=self.layer_norm)

    def __call__(self, observations, actions=None):
        if self.encoder is not None:
            inputs = [self.encoder(observations)]
        else:
            inputs = [observations]
        if actions is not None:
            inputs.append(actions)
        inputs = jnp.concatenate(inputs, axis=-1)
        v = self.value_net(inputs).squeeze(-1)
        return v
```

**这个网络在做什么**：同样是一个 MLP，输入"状态 + 动作"，输出维度固定为 1（一个标量打分），最后 `.squeeze(-1)` 去掉多余的维度。真正有意思的部分是 `num_ensembles` 这个参数和 `ensemblize` 函数——这是"critic ensemble"这个技巧的实现方式。

**为什么要 ensemble（训练多个 Critic）**：回顾 [Q-Chunking 精读第 6.2 节](/论文综述/071_QChunking_RL与动作分块#6.2-消融:chunk-长度-critic-ensemble-utd-的影响) 提到的实验结论——增大 critic ensemble 数量（$K=2 \to K=10$）能明显提升性能。这是标准的 Double-Q / 多重 Q 学习技巧：单个 Critic 网络在训练早期容易对某些动作的价值估计产生系统性偏差（过高估计），用多个独立初始化的 Critic 一起训练，取它们的最小值或平均值作为最终目标，能有效压制这种过估计偏差。

**`ensemblize` 怎么用一份代码同时训练多个网络**：

```python
def ensemblize(cls, num_qs, in_axes=None, out_axes=0, **kwargs):
    return nn.vmap(
        cls, variable_axes={'params': 0, 'intermediates': 0},
        split_rngs={'params': True}, in_axes=in_axes, out_axes=out_axes,
        axis_size=num_qs, **kwargs,
    )
```

**这行代码在做什么，用自然语言讲清楚**：`nn.vmap` 是 Flax 提供的"给一个模块自动加一个批处理维度"的工具。`variable_axes={'params': 0}` 的意思是——把这个 MLP 的参数**复制 `num_qs` 份**，并把这些副本堆叠在一个新的维度（第 0 维）上；`split_rngs={'params': True}` 保证这 `num_qs` 份参数用**不同的随机种子**初始化（否则复制出来的网络会完全一样，起不到 ensemble 的作用）。效果上等价于同时创建了 `num_qs` 个独立的 MLP，但因为用了 `vmap`（向量化映射），前向计算时可以把它们当成"一个网络"一起跑，不需要写 Python 循环逐个调用——这是一个典型的 JAX 工程技巧：把"多个独立的相同结构模型"通过 `vmap` 压成一个"带批处理维度的单个计算"，充分利用 GPU/TPU 的并行能力。

**这解释了 `acfql.py` 里 critic 输出的形状**：`self.network.select('critic')(obs, actions)` 返回的不是一个标量，而是形状为 `(num_qs,)` 的向量（每个 ensemble 成员各给一个打分）。第 5 章会看到 `next_qs.min(axis=0)` 或 `next_qs.mean(axis=0)` 这样的代码——就是在这 `num_qs` 个打分上聚合，得到一个最终标量。

## 四、`ActorVectorField` 和 `Value` 需要哪些初始化信息

回到 `acfql.py` 的 `create()` 函数，看这两个网络具体是怎么被实例化的：

```python
critic_def = Value(
    hidden_dims=config['value_hidden_dims'],   # 例如 (512, 512, 512, 512)
    layer_norm=config['layer_norm'],
    num_ensembles=config['num_qs'],             # 默认 2
    encoder=encoders.get('critic'),
)

actor_bc_flow_def = ActorVectorField(
    hidden_dims=config['actor_hidden_dims'],
    action_dim=full_action_dim,                 # 注意：是 action_dim * horizon_length
    layer_norm=config['actor_layer_norm'],
    encoder=encoders.get('actor_bc_flow'),
    use_fourier_features=config["use_fourier_features"],
    fourier_feature_dim=config["fourier_feature_dim"],
)
actor_onestep_flow_def = ActorVectorField(
    hidden_dims=config['actor_hidden_dims'],
    action_dim=full_action_dim,
    layer_norm=config['actor_layer_norm'],
    encoder=encoders.get('actor_onestep_flow'),
)
```

**这里有一处很容易被忽略但很关键的细节，值得单独拎出来**：`full_action_dim` 是怎么算出来的？往前翻几行：

```python
if config["action_chunking"]:
    full_actions = jnp.concatenate([ex_actions] * config["horizon_length"], axis=-1)
else:
    full_actions = ex_actions
full_action_dim = full_actions.shape[-1]
```

`action_chunking=True` 时，`full_action_dim = action_dim * horizon_length`——也就是说,网络从设计上就直接把"$h$ 步动作块"当作一个扁平的高维向量来处理,没有专门为"时间序列结构"设计任何特殊的网络层（比如 RNN 或 Transformer）。**这是一个值得注意的工程简化**：[Q-Chunking 精读第二节](/论文综述/071_QChunking_RL与动作分块#2.2-q-chunking-的解法:改变-动作-的定义) 里"动作块" $\mathbf{a}_{t:t+h}$ 在数学上是一个有时间顺序的序列，但代码实现上就是把它拉平拼成一个长向量（比如单步动作 5 维,$h=5$ 时就是 25 维），直接喂给一个普通 MLP。网络不会显式知道"前 5 维是第一步、接下来 5 维是第二步"，这个时间结构完全靠训练数据里的统计规律隐式学到。

## 五、图像观测怎么接入：`ImpalaEncoder`

如果任务的观测是图像（`config['encoder']` 不是 `None`），网络结构会多一层视觉编码器：

```python
encoders = dict()
if config['encoder'] is not None:
    encoder_module = encoder_modules[config['encoder']]
    encoders['critic'] = encoder_module()
    encoders['actor_bc_flow'] = encoder_module()
    encoders['actor_onestep_flow'] = encoder_module()
```

**注意这里的一个设计选择**：`critic`、`actor_bc_flow`、`actor_onestep_flow` 各自拿到一份**独立**的编码器实例（分别 `encoder_module()` 调用了三次）——它们不共享视觉特征提取的参数。这是保守但常见的做法：共享编码器能省参数、加快训练，但也可能让 Critic 的梯度污染 Actor 的视觉表征（或者反过来），分开训练更稳妥，代价是训练更慢、参数量更大。

`ImpalaEncoder` 的结构（`utils/encoders.py`）：

```python
class ImpalaEncoder(nn.Module):
    width: int = 1
    stack_sizes: tuple = (16, 32, 32)
    num_blocks: int = 2

    def __call__(self, x, train=True, cond_var=None):
        x = x.astype(jnp.float32) / 255.0        # 归一化到 [0, 1]
        conv_out = x
        for block in self.stack_blocks:            # 依次通过若干个 ResNet 风格的卷积块
            conv_out = block(conv_out)
        conv_out = nn.relu(conv_out)
        out = conv_out.reshape((*x.shape[:-3], -1)) # 展平成向量
        out = MLP(self.mlp_hidden_dims, activate_final=True)(out)
        return out
```

**这个编码器在做什么，用自然语言讲清楚**：这是 IMPALA（一个经典的分布式 RL 算法）论文里提出的卷积网络结构——若干层带残差连接的卷积块（`ResnetStack`，每个块内部是"卷积→ReLU→卷积→加回输入"的标准残差结构），逐步把一张原始像素图（数值范围 0-255）压缩成一个低维、语义丰富的特征向量,最后再过一层 MLP 调整到需要的输出维度。之后这个特征向量会被当作普通的"状态观测"，拼接到动作/时间向量上，送进 `ActorVectorField` 或 `Value` 的 MLP 主体里——**图像编码器的输出和低维状态输入在后续网络里被一视同仁地对待**，不存在任何图像特有的处理逻辑,这是"先编码成向量、后续统一用 MLP 处理"这套范式的典型体现。

`encoder_modules` 字典还提供了几个不同规模的变体：`impala_small`（更少的残差块，跑得快）、`impala_large`（更宽的卷积层，表达力更强），本项目论文实验主要用的是低维状态任务（OGBench/RoboMimic 的 low-dim 版本），图像编码器这条路径在论文主实验里不是主角，但代码层面是完整支持的。

## 六、`TrainState` 与 `ModuleDict`：所有网络怎么被打包管理

最后补一个贯穿全项目的工程细节——这些网络实例（`actor_bc_flow`、`actor_onestep_flow`、`critic`、`target_critic`）不是分散的四个独立对象，而是被统一装进一个 `ModuleDict`：

```python
network_info = dict(
    actor_bc_flow=(actor_bc_flow_def, (ex_observations, full_actions, ex_times)),
    actor_onestep_flow=(actor_onestep_flow_def, (ex_observations, full_actions)),
    critic=(critic_def, (ex_observations, full_actions)),
    target_critic=(copy.deepcopy(critic_def), (ex_observations, full_actions)),
)
networks = {k: v[0] for k, v in network_info.items()}
network_def = ModuleDict(networks)
network_params = network_def.init(init_rng, **network_args)['params']
network = TrainState.create(network_def, network_params, tx=network_tx)
```

`ModuleDict`（`utils/flax_utils.py`）把这四个（或更多）网络包成一个整体，之后可以用 `network.select('critic')(...)` 这种方式按名字取出某一个网络来调用，而它们的参数全部存在**同一个** `network.params` 字典树里，共用**同一个** optimizer（`network_tx`）。这个设计直接决定了第 5 章训练代码的形态：所有 loss 项加在一起，一次 `jax.grad` 调用同时算出各网络的梯度，再一次性更新。
