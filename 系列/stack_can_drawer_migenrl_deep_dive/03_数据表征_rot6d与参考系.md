# 第 03 章：数据表征：rot6d 与 target_object_frame

> 前情提要：第 02 章确定了三层配置合并后 `action_representation: target_object_frame`、`action_group: rot6d_processed_actions` 这些字段的最终值。本章开始解析这些表征转换的具体数学形式——`miGenRL` 的环境接口给出的动作是"末端执行器的绝对位姿"（3 维位置 + 旋转），本章要回答的是这个位姿具体用什么数学形式表示、相对哪个坐标系表示。这是整条链路里最容易被忽视、却最直接影响训练效果的两个设计选择。

## 1. 一个位姿需要几个数字来描述

机器人末端执行器（手腕）的位姿包含两部分：**位置**（3 个数：x, y, z）和**朝向**（旋转）。位置没有争议——3 维笛卡尔坐标就够了。但"朝向"要用几个数字表示、用什么数学结构表示，是一个远比看起来复杂的问题，因为它直接决定了神经网络能不能顺利学到正确的旋转输出。

配置里的这一行揭示了答案：

```yaml
action_group: rot6d_processed_actions
```

`rot6d` 指的是一种用 **6 个数字**表示三维旋转的方法。为什么不用更直觉的三个数字（欧拉角，比如"绕 x 轴转多少度，绕 y 轴转多少度……"），也不用工业界常见的四元数（4 个数字）？

## 2. 欧拉角和四元数各自的问题

**欧拉角（3 个数）的问题**：万向锁（Gimbal Lock）。当某个旋转轴的角度接近 90° 时，另外两个轴的旋转会互相耦合，出现自由度损失——直观地说，在某些姿态下，不同的角度组合会对应到相同或者极其接近的实际朝向，这个映射在局部变得不连续。对神经网络来说，这意味着损失函数的地形（loss landscape）在这些区域会出现陡峭的悬崖或者平坦的高原，梯度下降在这里会变得不稳定。

**四元数（4 个数）的问题**：双重覆盖（double cover）。单位四元数 $q$ 和 $-q$ 表示的是**完全相同**的旋转——这是四元数数学结构本身的性质（四元数群是 SO(3) 旋转群的一个双重覆盖）。这意味着同一个目标旋转在网络的输出空间里对应着两个相距很远的点（$q$ 和 $-q$ 在四维空间里几乎是相反的方向）。如果训练数据里同一段轨迹的相邻两帧分别被记录成了 $q$ 和 $-q$（这在实践中很容易发生，取决于四元数计算库的符号约定），网络看到的目标输出会在训练数据里突然翻转符号，形成一个虚假的"不连续跳变"，网络会试图去拟合这个不存在的跳变，反而学坏了。

**这两个问题的共同数学根源**：Zhou et al. 在 2019 年的论文 *On the Continuity of Rotation Representations in Neural Networks* 中证明了一个结论——从三维旋转群 SO(3) 到欧几里得空间 $\mathbb{R}^n$ 的**连续**映射，要求 $n \geq 5$。3 维（欧拉角）和 4 维（四元数）都不满足这个下界，所以它们都无法找到一个处处连续、处处光滑的表示方式；而 6 维正好越过了这条下界，是一种既满足连续性又足够紧凑的选择。

## 3. rot6d 是什么

rot6d 的构造非常直接：一个旋转可以用一个 $3\times3$ 的**旋转矩阵** $R$ 完整表示（矩阵的三列分别是旋转后坐标系三个轴的方向向量）。rot6d 只取这个矩阵的**前两列**，丢掉第三列，得到 6 个数字：

$$
\text{rot6d} = [R_{:,0},\ R_{:,1}] = [r_{00}, r_{10}, r_{20},\ r_{01}, r_{11}, r_{21}]
$$

**这个公式在做什么**：把一个完整的 $3\times3$ 旋转矩阵（9 个数，但受正交约束只有 3 个自由度）压缩成 6 个数字，作为网络的实际输出目标。

**逐项拆解**：

| 符号 | 含义 | 维度 |
|---|---|---|
| $R$ | 完整的旋转矩阵，$R \in SO(3)$ | $3 \times 3$ |
| $R_{:,0}$ | $R$ 的第一列，即旋转后局部坐标系 x 轴在世界坐标系下的方向 | 3 维向量 |
| $R_{:,1}$ | $R$ 的第二列，局部坐标系 y 轴的方向 | 3 维向量 |
| $\text{rot6d}$ | 拼接后的 6 维输出 | 6 维向量 |

被丢掉的第三列 $R_{:,2}$（局部 z 轴方向）不是丢失信息——因为旋转矩阵三列必须两两正交且都是单位向量，只要知道前两列，第三列可以通过叉乘唯一确定（在右手坐标系约定下）：$R_{:,2} = R_{:,0} \times R_{:,1}$。

### 3.1 从 rot6d 还原成旋转矩阵：Gram-Schmidt 正交化

网络输出的 6 个数字，在训练刚开始、还没学好的时候，并不保证真的构成一组正交单位向量（毕竟这是网络自由输出的实数，没有约束）。所以从 rot6d 还原回合法旋转矩阵，需要显式做一次正交化：

$$
b_1 = \frac{a_1}{\lVert a_1 \rVert}, \qquad
b_2 = \frac{a_2 - (b_1 \cdot a_2)\, b_1}{\lVert a_2 - (b_1 \cdot a_2)\, b_1 \rVert}, \qquad
b_3 = b_1 \times b_2
$$

**这个公式在做什么**：Gram-Schmidt 正交化——把两个不一定正交、不一定单位长度的向量 $a_1, a_2$（网络的原始输出），修正成一组合法的正交归一基 $b_1, b_2, b_3$，拼成一个真正的旋转矩阵。

**逐项拆解**：

| 符号 | 含义 | 几何直觉 |
|---|---|---|
| $a_1, a_2$ | rot6d 的前 3 个数和后 3 个数，即网络的原始输出 | 不保证正交、不保证单位长度 |
| $b_1$ | 把 $a_1$ 归一化得到的第一个基向量 | 直接定方向、只调长度 |
| $b_1 \cdot a_2$ | $a_2$ 在 $b_1$ 方向上的投影长度 | 度量 $a_2$ 里有多少成分和 $b_1$ 重复 |
| $a_2 - (b_1\cdot a_2)b_1$ | 从 $a_2$ 中减去与 $b_1$ 平行的部分，只留下与 $b_1$ 垂直的部分 | 强制正交化的核心步骤 |
| $b_2$ | 上一步结果再归一化 | 与 $b_1$ 垂直的单位向量 |
| $b_3$ | $b_1$ 与 $b_2$ 的叉积 | 自动垂直于前两者，补齐右手坐标系第三轴 |

**代入数字**：假设网络输出 $a_1 = (1, 1, 0)$，$a_2 = (0, 1, 1)$（未归一化、不正交）：

- $\lVert a_1 \rVert = \sqrt{2}$，所以 $b_1 = (1/\sqrt2,\ 1/\sqrt2,\ 0) \approx (0.707, 0.707, 0)$
- $b_1 \cdot a_2 = 0.707 \times 0 + 0.707 \times 1 + 0 \times 1 = 0.707$
- $a_2 - 0.707 \times b_1 = (0,1,1) - (0.5, 0.5, 0) = (-0.5, 0.5, 1)$
- 归一化：$\lVert(-0.5,0.5,1)\rVert = \sqrt{0.25+0.25+1} = \sqrt{1.5}\approx1.225$，所以 $b_2 \approx (-0.408, 0.408, 0.816)$
- $b_3 = b_1 \times b_2$：按叉积公式算出与 $b_1, b_2$ 都垂直的第三个单位向量

最终 $[b_1, b_2, b_3]$ 拼成一个合法的旋转矩阵，再通过标准公式转换为四元数（供仿真侧的 IK 控制器使用）。

**为什么允许网络输出"不完美"的 6 个数、再靠后处理修正**，而不是直接约束网络输出合法的旋转矩阵：这正是 rot6d 相比其他表示方式的优势所在——网络的输出层可以是一个完全自由的线性层（不需要任何特殊的归一化激活函数），训练时只需要让损失函数（第 06 章会讲到的加权 L1 loss）鼓励网络输出的 $a_1, a_2$ 接近训练数据里记录的真实值，Gram-Schmidt 正交化只在**使用**这个输出时（转换回四元数喂给 IK 控制器）才发生，不参与梯度计算的核心路径（虽然它本身是可导的，可以参与训练，但推理时的正交化步骤保证了即使网络输出有轻微误差，最终得到的仍然是一个合法的旋转）。

代码层面，这两个转换函数在 `source/core/miUtils/miUtils/utils/rot6d.py` 里对称地实现：

```python
def quat_to_rot6d(quat: torch.Tensor) -> torch.Tensor:
    """(..., 4) [x,y,z,w] → (..., 6)"""
    quat = quat / quat.norm(dim=-1, keepdim=True).clamp_min(eps)
    rot_mat = matrix_from_quat(quat)                  # (..., 3, 3)
    return torch.cat([rot_mat[..., :, 0], rot_mat[..., :, 1]], dim=-1)

def rot6d_to_quat(rot6d: torch.Tensor) -> torch.Tensor:
    """(..., 6) → (..., 4) [x,y,z,w]"""
    a1, a2 = rot6d[..., :3], rot6d[..., 3:]
    b1 = a1 / a1.norm(dim=-1, keepdim=True)
    b2 = a2 - (b1 * a2).sum(-1, keepdim=True) * b1
    b2 = b2 / b2.norm(dim=-1, keepdim=True)
    b3 = torch.cross(b1, b2, dim=-1)
    rot_mat = torch.stack([b1, b2, b3], dim=-1)
    return quat_from_matrix(rot_mat)
```

这一组函数在整条链路里被大量复用：观测记录阶段把仿真给出的四元数转成 rot6d 存进 HDF5，训练阶段网络直接以 rot6d 作为回归目标，rollout 阶段把网络输出的 rot6d 转回四元数喂给 IK 控制器。位姿级别的封装函数把位置和旋转打包在一起转换：

```python
def pose_quat_to_rot6d(pose):    # (..., 7)[pos3+quat4] → (..., 9)[pos3+rot6d6]
    return torch.cat([pose[..., :3], quat_to_rot6d(pose[..., 3:])], dim=-1)

def pose_rot6d_to_quat(pose_rot6d):  # (..., 9) → (..., 7)
    return torch.cat([pose_rot6d[..., :3], rot6d_to_quat(pose_rot6d[..., 3:])], dim=-1)
```

## 4. 位姿要相对哪个坐标系表示

解决了"用什么数学形式表示旋转"，接下来是一个同样重要、却经常被忽视的问题：这个位置和朝向，是相对哪个坐标系测量的？配置里另一行揭示了答案：

```yaml
action_representation: target_object_frame
qpos_representation: target_object_frame
```

### 4.1 为什么不能直接用世界坐标系

最直接的想法是：把手腕在仿真世界坐标系（world frame）下的绝对位置和朝向，直接喂给网络。这样做的问题在于**泛化性**——环境侧在每次 episode 开始时会对罐子和抽屉的位置做随机扰动（这是仿真环境自己的域随机化逻辑，不属于 `miGenRL`，本系列不展开），也就是说同一个任务在不同 episode 里，物体的绝对位置是不一样的。如果策略学到的是"手腕应该移动到世界坐标 (0.34, 0.0, 0.35)"这种绝对坐标，那么一旦物体被挪到了别的位置，这条学到的绝对坐标轨迹完全不适用。

`target_object_frame` 的解法是：**把手腕的位姿表达成"相对于当前任务目标物体的初始位姿"的相对位姿**。直觉上，无论罐子被随机放在桌面的哪个角落，"手从罐子右前方 5 厘米处靠近、下降 3 厘米、抓住"这套相对运动模式是不变的。把这套不变的相对模式作为学习目标，策略就自动获得了对物体位置变化的鲁棒性——这是 `miGenRL` 表征层主动配合环境侧随机化设计出来的解法。

### 4.2 坐标系转换的数学形式

**从世界坐标转换到 target_object_frame**（观测记录阶段使用）：

$$
(\mathbf{p}_{\text{rel}}, \mathbf{q}_{\text{rel}}) = T_{\text{frame}}^{-1} \cdot T_{\text{gripper}}
$$

**这个公式在做什么**：把手腕在世界坐标系下的位姿 $T_{\text{gripper}}$，转换成"以目标物体坐标系为参照"的相对位姿。

**逐项拆解**：

| 符号 | 含义 | 本例中的具体值 |
|---|---|---|
| $T_{\text{gripper}}$ | 手腕在世界坐标系下的完整位姿（位置+朝向） | 仿真每步实时读出 |
| $T_{\text{frame}}$ | 参考物体（本例中是 can 或 drawer）在**episode 开始那一刻**的世界位姿 | 缓存值，episode 内不变 |
| $T_{\text{frame}}^{-1}$ | 参考物体位姿的逆变换 | 把"物体在世界里的位置"转换成"世界在物体局部坐标系里的位置" |
| $(\mathbf{p}_{\text{rel}}, \mathbf{q}_{\text{rel}})$ | 手腕在物体局部坐标系下的相对位置和朝向 | 这是网络实际看到/输出的量 |

代码实现直接调用 Isaac Lab 提供的工具函数：

```python
from isaaclab.utils.math import subtract_frame_transforms

rel_pos, rel_quat = subtract_frame_transforms(
    target_frame_pose_w[:, :3], target_frame_pose_w[:, 3:],   # T_frame
    gripper_pos_w, gripper_quat_w,                              # T_gripper
)
```

**从 target_object_frame 转换回世界坐标**（动作执行阶段使用，方向相反）：

$$
T_{\text{world}} = T_{\text{frame}} \cdot T_{\text{rel}}
$$

**逐项拆解**：这是上面公式的逆运算——网络输出的相对位姿 $T_{\text{rel}}$，需要重新组合上参考物体的世界位姿 $T_{\text{frame}}$，才能得到 IK 控制器需要的世界坐标目标：

```python
from isaaclab.utils.math import combine_frame_transforms

left_pos_w, left_quat_w = combine_frame_transforms(
    target_frame_pose_w[:, :3], target_frame_pose_w[:, 3:],   # T_frame
    left_pose_target[:, :3], left_pose_target[:, 3:],          # T_rel（网络输出）
)
```

**为什么用物体的"初始"位姿而不是"当前"位姿作参考系**：这是一个关键的设计细节。如果参考系跟随物体实时移动（比如罐子被抓起来之后，参考系也跟着罐子一起移动），那么"手相对罐子的位置"在抓取完成后会突然变成一个恒定值（手抓住了罐子，两者相对静止），这对训练没有意义，而且更麻烦的是——如果这个物体本身在移动，参考系就变成了一个运动的坐标系，观测里记录的相对位姿会包含物体自身运动带来的噪声，让学习目标变得不稳定。用**初始位姿**（`initial_object_pose_w`，在 episode 开始时缓存一次，全程不变）作参考系，相当于把"桌面上物体摆放的具体位置"这个变量从整条轨迹里完全消掉，只保留"手应该怎么运动"这一件事，而这件事恰恰是策略真正需要学习的内容。

## 5. 小结与下一章

这一章确立了两个基础设计：

1. **rot6d**——用旋转矩阵的前两列（6 个数）表示朝向，通过 Gram-Schmidt 正交化还原成合法旋转矩阵。相比欧拉角（万向锁）和四元数（双重覆盖不连续），rot6d 满足 SO(3) 到欧几里得空间连续映射所需的最小维度（$n\geq5$），对神经网络回归更友好。
2. **target_object_frame**——用目标物体的**初始**世界位姿作参考系，把手腕的绝对位姿转换成相对位姿。这让策略学到的是"相对目标物体应该怎么运动"而不是"应该移动到哪个绝对坐标"，天然兼容环境侧的随机化设计。

但这里留下一个没有回答的问题：这个任务分几个阶段（先抓取、后放置），"目标物体"在不同阶段是不同的——参考系要怎么随着任务推进而切换？这正是下一章 `policy_frame_id` 机制要解决的问题，同时下一章还会讲另一个独立的表征问题：22 维的手指关节要怎么压缩成更紧凑的表示。
