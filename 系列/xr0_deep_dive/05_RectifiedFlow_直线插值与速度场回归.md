# 第五章：Rectified Flow —— 直线插值、速度场回归与 Beta 时间步采样

> 本章目标：理解 XR0 训练动作头所用的 Rectified Flow 算法的完整数学细节——训练目标怎么构造、为什么用 Beta 分布而不是均匀分布采样时间步，以及推理时 Euler 积分具体怎么执行。

**前情提要**：第 4 章讲完了 DiT 内部结构——它本质上是一个函数 $v_\theta(z_t, t) \to \text{速度}$。本章讲这个函数具体怎么被训练出来、怎么被用来生成动作。

## 一、Rectified Flow 是 Flow Matching 的一个特例

[Flow Matching 与连续归一化流](/前置知识/000g_前置知识_Flow_Matching与连续归一化流) 已经完整推导了"用直线插值构造训练目标"这套通用理论。Rectified Flow 正是 Flow Matching 家族里最简单的一种具体实现——路径选择直线插值，目标是常数速度场。XR0 的代码里这套逻辑集中在三个方法：`_sample_timestep`（怎么采样 $t$）、`_flow_interpolate`（怎么构造带噪样本）、`_flow_velocity_target`（训练目标是什么）。本章聚焦在这三个方法的具体设计和 XR0 特有的取舍。

## 二、训练目标：直线插值 + 速度场回归

### 2.1 构造带噪动作

```python
@torch.no_grad()
def _flow_interpolate(self, x0, x1, t):
    return (1 - t) * x0 + t * x1
```

**为什么需要这个公式**：训练时我们已经知道真实动作 $x_1$（数据集里的标注），需要人为构造一系列"部分去噪的中间状态"，让网络学会在任意噪声程度下都能正确判断去噪方向。直线插值是构造这些中间状态最简单的方式。

$$
z_t = (1-t) x_0 + t x_1, \qquad x_0 \sim \mathcal{N}(0, I),\ t \in [0, 1]
$$

> **一句话**：在纯噪声 $x_0$ 和真实动作 $x_1$ 之间画一条直线，$t$ 是这条线上的位置——$t=0$ 是纯噪声，$t=1$ 是真实动作。

**逐项拆解**：

| 符号 | 含义 | 在 XR0 中具体是什么 |
|------|------|-----------|
| $x_0$ | 噪声样本 | `torch.randn_like(action)`，形状 `[B, 30, 32]` |
| $x_1$ | 真实动作 | 数据集里的标注动作，已经过归一化（均值方差标准化，见 [第 9 章](./09_数据管线_JSON标注与相对动作计算)） |
| $t$ | 插值系数 | 形状 `[B, 1, 1]`，每个 batch 样本独立采样一个标量，广播到整个动作块 |
| $z_t$ | 带噪动作 | 喂给 DiT 的实际输入，形状 `[B, 30, 32]` |

**数值例子**：取动作维度里的某一维，$x_0 = 2.0$（噪声），$x_1 = -0.5$（真实动作，归一化后的值）。分别看 $t=0.2$ 和 $t=0.8$：

- $t=0.2$：$z_{0.2} = 0.8\times2.0 + 0.2\times(-0.5) = 1.6 - 0.1 = 1.5$（更接近噪声）
- $t=0.8$：$z_{0.8} = 0.2\times2.0 + 0.8\times(-0.5) = 0.4 - 0.4 = 0.0$（更接近真实动作）

**为什么是这个形式**：直线插值对应的速度场是常数（不随 $t$ 变化），这让训练目标最简单——下一节具体展开。

### 2.2 速度场目标

```python
@torch.no_grad()
def _flow_velocity_target(self, x0, x1):
    return x1 - x0
```

**为什么需要这个公式**：网络 $v_\theta(z_t, t)$ 要学习的是"在当前带噪状态 $z_t$、当前时刻 $t$，应该往哪个方向移动才能走向真实数据"。对直线插值路径 $z_t = (1-t)x_0+tx_1$ 求关于 $t$ 的导数，就能精确得到这条路径上每一点的瞬时速度——这正是网络的回归目标。

$$
v_{\text{target}} = \frac{\mathrm{d} z_t}{\mathrm{d} t} = \frac{\mathrm{d}}{\mathrm{d}t}\big[(1-t)x_0+tx_1\big] = x_1 - x_0
$$

> **一句话**：不管当前处在插值路径的哪个位置，正确的移动方向永远是"从起点指向终点"这一个固定方向。

**逐项拆解**：

| 符号 | 含义 | 具体是什么 |
|------|------|-----------|
| $x_1 - x_0$ | 速度场目标 | 真实动作减噪声，形状 `[B, 30, 32]`，和 $t$ 无关的常向量 |
| $v_\theta(z_t, t)$ | 网络预测 | DiT 的输出，同样形状 `[B, 30, 32]` |

**数值例子**：接上例，$x_0=2.0$，$x_1=-0.5$，速度目标 $=x_1-x_0=-2.5$。不管 $t=0.2$ 还是 $t=0.8$，只要 $x_0, x_1$ 不变，目标速度**永远是 $-2.5$**——这是直线插值路径的关键性质：常速直线，梯度方向不随位置改变。

**为什么是这个形式（为什么不用别的插值路径）**：如果选用非直线路径（比如某种曲线），速度场会随 $t$ 变化，网络需要同时学会"当前在哪个位置"和"这个位置对应的曲率该怎么修正方向"，训练目标的复杂度显著提高。直线插值把这个复杂度降到最低——网络只需要学会一件事：给定 $(z_t, t)$，判断噪声混合比例并预测出"拉直"到真实数据需要的固定方向。

### 2.3 完整训练 Loss：加权 MSE

真正用于反向传播的 Loss 在 `compute_loss` 里计算：

$$
\mathcal{L} = 0.5 \times \underbrace{\Big(\big\|v_\theta(z_t,t) - (x_1-x_0)\big\|^2 \odot w\Big)_{\text{action\_mask}}}_{\text{加权 MSE 项，记为 } \mathcal{L}_{\text{mse}}} + \lambda_{\text{freq}} \times \mathcal{L}_{\text{freq}}
$$

**为什么需要这个公式**：单纯的均方误差会平等对待动作块里的每一个时间步、每一个维度，但实际训练中有两个额外需求：（1）某些时间步的预测难度不同，需要动态加权（详见 [第 8 章](./08_异步训练_Prefix条件化与加权Loss)的异步训练场景）（2）某些维度是 padding（比如动作空间里的保留维度），不应该参与梯度计算，需要用 `action_mask` 屏蔽。

> **一句话**：让预测速度尽量贴近真实速度，用 mask 屏蔽掉不该学的维度，用权重让重要的时间步获得更大的梯度。

**逐项拆解**：

| 符号 | 含义 | 具体是什么 |
|------|------|-----------|
| $v_\theta(z_t,t)$ | 网络预测速度 | DiT 输出，`[B,30,32]` |
| $x_1-x_0$ | 真实速度目标 | 同上 |
| `action_mask` | 有效位置掩码 | `[B,30,32]` 的 0/1 掩码，屏蔽 padding 帧和无效维度 |
| $w$ | 逐元素权重 | 同步训练时恒为 1；异步训练时由 no-grad 推理误差决定（第 8 章） |
| $\lambda_{\text{freq}}$ | 频域损失系数 | `enable_freq=True` 时为 1.0，否则为 0（默认关闭） |

**代码里权重归一化的细节**：

```python
with torch.no_grad():
    masked_weight = weight[action_mask]
    weight = weight.clone()
    weight[action_mask] = weight[action_mask] / masked_weight.mean()
    weight = torch.clamp(weight, min=0.5, max=5.0)
loss_mse = (F.mse_loss(pred, target, reduction="none") * weight)[action_mask].mean()
```

**这一步在做什么**：先把权重除以有效区域的均值，让权重的平均效果保持在 1 附近（不改变整体 loss 的数量级，只调整不同样本之间的相对重要性），再用 `clamp` 限制权重范围在 $[0.5, 5.0]$，防止某些异常大或异常小的权重把梯度带偏。

**为什么用 $0.5\times$ 而不是直接用 MSE**：这是一个常见的约定（对应高斯分布负对数似然里方差项的系数），不影响优化方向，只是让 loss 的数值尺度更符合传统惯例，方便和其他扩散模型的 loss 数值做对比。

## 三、时间步采样：为什么用 Beta 分布而不是均匀分布

### 3.1 三种可选的采样方式

```python
@torch.no_grad()
def _sample_timestep(self, batch_size, dtype=torch.bfloat16, device="cpu"):
    if self.flow_sampling == "logit_normal":
        u = self.logistic_normal.sample((batch_size,))[:, 0].to(device)
    elif self.flow_sampling == "beta":
        u = self.beta.sample((batch_size,)).to(device)
        u = (1 - u) * 0.999
    else:
        u = torch.rand(size=(batch_size,), device=device)
    return u.to(dtype)
```

XR0 默认使用 `flow_sampling="beta"`，用的是 `Beta(1.5, 1.0)` 分布。

### 3.2 Beta(1.5, 1.0) 的形状与变换

**为什么需要这个公式**：如果均匀地从 $[0,1]$ 采样 $t$，网络在训练时看到的"带噪程度"是均匀分布的——一半的训练样本 $t>0.5$（比较接近真实数据，去噪任务相对容易），一半 $t<0.5$（比较接近纯噪声，去噪任务更难）。但推理时的 Euler 积分从 $t=0$ 开始走到 $t=1$，恰恰是**从最难的区间开始**——如果训练时对高噪声区间的采样不够充分，模型在推理起点的表现会打折扣。

$$
u \sim \text{Beta}(1.5, 1.0), \qquad t = (1-u) \times 0.999
$$

> **一句话**：故意让训练时采样到的时间步更多地落在"低 $t$"（高噪声）区间，让模型在最难的起始阶段得到更充分的训练。

**逐项拆解**：

| 符号 | 含义 | 具体是什么 |
|------|------|-----------|
| $\text{Beta}(1.5, 1.0)$ | Beta 分布的两个形状参数 $\alpha=1.5, \beta=1.0$ | 概率密度函数 $\propto u^{0.5}(1-u)^{0}=u^{0.5}$，在 $u$ 接近 1 时密度更高 |
| $u$ | Beta 分布采样值 | 取值范围 $[0,1]$，偏向靠近 1 |
| $(1-u)$ | 翻转 | 让偏向 1 的分布变成偏向 0 的分布 |
| $\times 0.999$ | 数值稳定处理 | 避免 $t$ 精确等于 1（导致后续计算里出现 $1-t=0$ 之类的边界问题） |

**数值例子**：Beta(1.5, 1.0) 的期望值是 $\alpha/(\alpha+\beta) = 1.5/2.5 = 0.6$，意味着 $u$ 平均取值在 0.6 附近，偏向较大的值。经过 $(1-u)\times 0.999$ 变换后，$t$ 的期望约为 $(1-0.6)\times0.999 \approx 0.4$，比均匀分布的期望 0.5 更偏向低值区间（高噪声区间）。具体分布形态：

| $u$ 的取值区间 | Beta(1.5,1.0) 密度相对大小 | 对应 $t=(1-u)\times0.999$ 区间 |
|------|------|------|
| $u$ 接近 1（如 0.9-1.0） | 密度较高 | $t$ 接近 0（高噪声区间，采样更密集） |
| $u$ 接近 0（如 0-0.1） | 密度较低 | $t$ 接近 1（接近真实数据，采样更稀疏） |

**为什么是这个形式**：这个设计直接对应"训练分布要覆盖推理时实际会遇到的分布"这个原则——推理从 $t=0$ 出发做 Euler 积分，第一步的预测质量直接影响后续所有步骤（误差会累积传播），所以有必要让训练时在 $t$ 接近 0 的区间采样更密集、训练更充分。这和很多扩散模型论文里提到的"重要性采样时间步"思路是一致的。

## 四、推理：5 步 Euler 积分

```python
@torch.no_grad()
def _flow_generate(self, x0, dit_kwargs):
    dt = 1.0 / self.num_steps
    z = x0.clone()
    for step in range(self.num_steps):
        t = torch.ones((z.shape[0], 1, 1), device=z.device, dtype=z.dtype) * step / self.num_steps
        v = self.dit_forward(z, t, **dit_kwargs)
        z = z + v * dt
    return z
```

**为什么需要这个公式**：训练学到的是"瞬时速度场" $v_\theta(z,t)$，要从这个速度场恢复出实际的动作轨迹，需要做数值积分——把无穷小的瞬时移动累加成有限的总位移。Euler 方法是最简单的数值积分方式：把连续的积分过程离散成有限步，每一步假设速度在这一小段区间内不变，直接用"速度 × 步长"更新位置。

$$
z_{\text{step}+1} = z_{\text{step}} + v_\theta(z_{\text{step}}, t_{\text{step}}) \cdot \Delta t, \qquad \Delta t = \frac{1}{N},\ N=5
$$

**逐项拆解**：

| 符号 | 含义 | 具体是什么 |
|------|------|-----------|
| $N$ | 积分步数 | XR0 里 `num_steps=5` |
| $\Delta t$ | 每步的时间跨度 | $1/5=0.2$ |
| $t_{\text{step}} = \text{step}/N$ | 当前时刻 | 依次取 $0, 0.2, 0.4, 0.6, 0.8$ |
| $z_0$ | 积分起点 | 纯噪声 `torch.randn_like(action)` |
| $z_5$ | 积分终点 | 最终输出的动作块预测 |

**完整数值走查**（取动作某一维，假设网络预测总是"完美"地给出真实速度 $-2.5$，也就是理想情况）：

| step | $t_{\text{step}}$ | $z_{\text{step}}$ | $v=v_\theta(z,t)$ | $z_{\text{step}+1}=z+v\times0.2$ |
|------|------|------|------|------|
| 0 | 0.0 | 2.0（初始噪声） | $-2.5$ | $2.0+(-2.5)\times0.2=1.5$ |
| 1 | 0.2 | 1.5 | $-2.5$ | $1.5-0.5=1.0$ |
| 2 | 0.4 | 1.0 | $-2.5$ | $1.0-0.5=0.5$ |
| 3 | 0.6 | 0.5 | $-2.5$ | $0.5-0.5=0.0$ |
| 4 | 0.8 | 0.0 | $-2.5$ | $0.0-0.5=-0.5$ |

5 步之后 $z_5=-0.5$，恰好等于真实动作 $x_1=-0.5$——因为这个例子里速度场是理想的常数（直线插值路径的真实性质），Euler 积分能精确复原。实际训练出的网络预测不会完全精确，会有一定误差，但 5 步通常已经足够让误差控制在可接受范围内。

**为什么 5 步就够**：Rectified Flow 相比标准 DDPM（往往需要几十到上百步）能用更少的积分步数达到可用质量，本质原因是训练目标本身就是"拉直"路径的常速直线——路径越直，用越少的线段就能逼近得越准确，这也是"Rectified"（矫正、拉直）这个名字的来源。相关的数值积分误差分析见 [Flow Matching 前置知识 第 3.5 节](/前置知识/000g_前置知识_Flow_Matching与连续归一化流#3.5-推理过程)。

## 五、本章小结

| 阶段 | 关键操作 | 目的 |
|------|---------|------|
| 训练：采样 | Beta(1.5,1.0) 采样 $t$，翻转偏向低值 | 让训练分布覆盖推理起点的高噪声区间 |
| 训练：构造输入 | 直线插值 $z_t=(1-t)x_0+tx_1$ | 构造任意噪声程度的训练样本 |
| 训练：构造目标 | $v_{\text{target}}=x_1-x_0$ | 常速直线的解析速度场，训练目标最简单 |
| 训练：Loss | 加权 MSE（+ 可选频域项） | 让网络预测逼近目标速度，同时支持异步训练的权重机制 |
| 推理：积分 | 5 步 Euler 积分，从纯噪声出发 | 把速度场"还原"成具体的动作轨迹 |
