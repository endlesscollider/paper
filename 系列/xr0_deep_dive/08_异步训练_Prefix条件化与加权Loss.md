## 一、为什么需要 Prefix Conditioning：真实部署中的延迟问题

### 1.1 同步执行的问题

想象一个真实的部署场景：机器人执行完一个 30 步的动作块之后，需要请求下一个动作块。如果严格按照"执行完当前块 → 请求下一块 → 等待模型推理完成 → 才能继续执行"的方式运行，机器人在等待模型推理的这段时间里会**卡顿**——即使 XR0 只需要 5 步 Euler 积分，一次完整的 VLM 前向 + DiT 5 步迭代仍然需要几十到上百毫秒，这段延迟会打断动作的连续性。

### 1.2 异步执行的思路：提前请求，用前缀衔接

一个自然的解决方案是：不等当前动作块完全执行完，而是在还剩若干步未执行完时，就提前发起下一次推理请求。但这样会带来一个新问题——新生成的动作块，起点应该和"当前动作块还没执行完的那部分"平滑衔接，不能有突兀的跳变。

XR0 的解法是：**把还没执行完的那部分历史动作，作为"前缀"喂给模型，让模型在生成新动作块时以这个前缀为条件**，保证新生成的动作块开头几步和这个前缀保持一致——这样机器人在切换到新动作块时，动作轨迹是连续的,不会因为衔接不当产生突变或抖动。这正是 `prefix_length` 参数存在的意义。具体部署时怎么使用这个机制，详见 [第 12 章](./12_推理与部署_同步异步执行模式)。

## 二、训练时怎么"教"模型学会前缀条件化

### 2.1 随机决定是否使用前缀

```python
if self.training:
    prefix_length = 0
    if self.async_train and random.random() < 0.5:
        prefix_length = random.randint(1, min(6, action_length))
```

**这一步在做什么**：只有开启 `async_train=True` 时，训练才会涉及前缀条件化；即使开启了，也只有 50% 的概率真正使用非零前缀（另外 50% 仍然走标准的从零开始生成路径）。前缀长度本身也是随机的，从 1 到 6 步之间均匀采样。

**为什么要随机化**：真实部署中，"提前多少步开始请求下一个动作块"是一个可调的策略参数（对应部署文档里提到的 $k$，"剩余步数少于 $k$ 时开始推理下一块"）。训练时没有必要固定死某一个前缀长度，而是让模型在推理时能应对**不同长度**的前缀条件——用一个范围内的随机采样覆盖多种可能的部署场景,这是提高模型鲁棒性的常见做法。

### 2.2 前缀部分直接复用真实动作，不做任何去噪

```python
prefix = action[:, :prefix_length]
```

**这一步在做什么**：`prefix` 直接取自训练数据里的真实动作（已经归一化），代表"已经确定、不需要再去噪的历史步骤"。它会被拼接在带噪动作序列的最前面：

```python
pred = self.dit_forward(
    torch.cat([prefix, noisy_action[:, prefix_length:]], dim=1),
    t, action_mask, state_embed, position_embeds, past_key_values, attn_mask,
    prefix_length=prefix_length,
)[:, prefix_length:]
```

也就是说，DiT 看到的动作部分输入是"**真实的**前 `prefix_length` 步 + **带噪的**剩余步骤"，而不是整段都带噪。这模拟了真实部署时的情形：前缀部分是机器人刚刚执行过的真实动作轨迹（完全已知，不存在噪声），只有还没执行的那部分需要模型去噪生成。

### 2.3 DiT 内部怎么处理前缀：输出强制清零

回到第四章看过的 `dit_forward` 方法末尾：

```python
output = self.action_output_layer(hidden_states)
if prefix_length > 0:
    output[:, :prefix_length] = 0.0
return output
```

**这一步在做什么**：DiT 仍然会对前缀对应的位置计算出一个输出，但这个输出被强制置零——因为前缀部分不需要预测速度（它已经是真实值，不需要被"修正"），把它的输出清零可以确保：（1）这部分不会对 Loss 产生贡献（下面会看到 Loss 计算时会切掉前缀部分）（2）即使某些计算路径里意外使用了这部分输出，也不会引入错误的数值。

前缀部分的 token 仍然参与 Attention 计算（其他动作 token 可以关注它、从它获取信息），只是它自己的"预测输出"部分没有意义,故置零；这和第六章讲的"局部因果掩码"是两件不同的事——掩码控制的是"谁能看到谁"，这里控制的是"谁的输出需要被使用"。

## 三、动态权重：用 no-grad 推理误差衡量"这一步有多难"

这是异步训练里最精巧的一步。回到第七章跳过的分支：

```python
if prefix_length > 0:
    with torch.no_grad():
        pred_prefix = self._flow_generate(
            torch.cat([prefix, noise[:, prefix_length:]], dim=1),
            dict(action_mask=action_mask, state_embed=state_embed, position_embeds=position_embeds,
                 past_key_values=past_key_values, attn_mask=attn_mask, prefix_length=prefix_length),
        )
    weight = (pred_prefix[:, prefix_length:] - action[:, prefix_length:]).abs()
else:
    weight = torch.ones_like(pred)
```

**为什么需要这个机制**：标准训练路径（第七章）里，每个时间步、每个维度的 Loss 权重都是均匀的 1。但在前缀条件化场景下，不同的非前缀时间步"难度"可能差异很大——比如刚好紧接在前缀后面的第一步，因为有真实前缀信息可以参考，模型应该比较容易预测准确；而距离前缀较远的步骤，缺少更多上下文支持，预测难度天然更高。**如果这些步骤的预测误差本身就更大，简单地用均匀权重训练，可能没有把足够的梯度信号分配给这些"更难"、更需要改进的步骤。**

**具体做法**：先用当前模型（不计算梯度，`torch.no_grad()`）完整跑一次推理式的 `_flow_generate`（也就是第五章讲的 5 步 Euler 积分），得到一个"当前模型在这个前缀条件下能生成什么样的动作"的预测 `pred_prefix`。然后用这个推理结果和真实动作的**绝对误差**，作为后续正式（带梯度）训练的逐元素权重。

> **一句话**：先"试跑"一次看模型现在哪里预测得差，再针对预测得差的地方加大训练权重。

**逐项拆解**：

| 符号 | 含义 | 具体是什么 |
|------|------|-----------|
| `pred_prefix` | 无梯度推理预测 | 完整 5 步 Euler 积分的输出，形状 `[B,30,32]` |
| `action` | 真实动作 | 同上 |
| `weight = |pred_prefix - action|` | 逐元素绝对误差 | 误差越大，权重越大 |

**数值例子**：假设某个时间步、某个维度上，`pred_prefix` 给出的预测值是 $0.3$，真实值 `action` 是 $2.0$，则该位置权重 $=|0.3-2.0|=1.7$；另一个位置预测值 $1.9$，真实值 $2.0$，权重 $=0.1$。第一个位置的权重明显更大——意味着后续正式训练时，这个位置的 MSE 项会被乘以更大的系数，梯度贡献也更大。

这个权重最终会经过第五章讲过的归一化和 clamp 处理（除以均值、限制在 $[0.5, 5.0]$），避免某个异常大的误差把整体训练不稳定地放大。

**为什么这样设计是合理的**：这是一种**自适应难度加权**的思路，类似于 Hard Example Mining（难样本挖掘）在其他机器学习任务里的应用——让模型把更多的学习"注意力"放在自己当前表现较差的地方，而不是对所有样本/位置平等对待。额外的计算代价是需要多跑一次完整的 5 步推理（用 `torch.no_grad()`，不需要反向传播，相对开销可控），换来的是更有效的梯度分配。

## 四、局部因果掩码上的额外随机遮盖

回顾第六章末尾提到的 `_random_mask_prefix`：

```python
if self.training and prefix_length > 2:
    causal_mask = self._random_mask_prefix(causal_mask, prefix_length, state_length)
```

只有在异步训练且 `prefix_length > 2` 时才会触发。它的作用是让**正在被去噪的动作 token**，以一定概率看不到前缀中间的某些步骤（但始终保留前缀最后 2 步可见）。结合本章的主题，这进一步增强了模型的鲁棒性：即使前缀信息不完整（比如真实部署时因为通信延迟或状态估计误差，前缀的某些步骤不完全可靠），模型依然要能生成合理的后续动作，而不是过度依赖"前缀必须完整可靠"这个假设。

## 五、本章小结：异步训练比同步训练多出的三件事

| 环节 | 同步训练（第 7 章） | 异步训练额外增加的部分 |
|------|---------------------|----------------------|
| Prefix 长度 | 恒为 0 | 50% 概率随机采样 1-6 步 |
| DiT 输入 | 全部带噪 | 前缀部分用真实值，其余带噪 |
| DiT 输出 | 全部有效 | 前缀部分输出强制清零 |
| Loss 权重 | 均匀为 1 | 用 no-grad 推理误差动态加权 |
| 局部因果掩码 | 标准局部因果 | 前缀中间部分随机遮盖（保留末尾） |
