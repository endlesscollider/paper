## 贯穿本章的例子

> **场景**：一台 Unitree G1 人形机器人（29 个可控关节）。我们想让它学会走路、下蹲、爬行等各种全身动作，最终这些动作技能会被 GR00T VLA 主干在执行具体任务（比如"走到桌子那边把苹果放到盘子上"）时调用。本章要解决的问题是：**这个 29 维关节角度的控制策略，是怎么训练出来的？**

## 一、为什么人形机器人运动控制"难以扩展"

### 1.1 传统做法：每个任务手工设计奖励

在 SONIC 之前，训练人形机器人运动技能的主流做法是：针对每一种具体行为（走路、跳跃、从地上站起来），手工设计一套专属的奖励函数，然后用 RL（通常也是 PPO）训练一个小型策略网络（往往只是几百万参数的 3 层 MLP），在单张 GPU 上训练几天。

这种做法有一个根本性的扩展障碍：**奖励工程不可复用**。"自然地向前走"这个奖励函数,对"跳舞"这个新技能几乎没有任何指导意义;"从地上站起来"又需要一套完全不同的奖励设计。每新增一种能力，就要重新设计一整套奖励——这意味着训练规模没法像语言模型那样通过简单地"堆数据、堆参数、堆算力"来提升，因为问题不在数据或算力，而在于"目标本身"没有一个统一的、可扩展的定义。

### 1.2 SONIC 的核心洞察：把"运动控制"重新定义成"运动追踪"

SONIC（Supersizing mOtion tracking for Natural humanoId Control，来自 [arXiv:2511.07820](https://arxiv.org/abs/2511.07820)）提出的解法是：**不要针对每个行为设计奖励，而是把整个问题重新表述成"精确追踪人类动作捕捉数据"**。

这个转换带来的好处是：
- **奖励函数变得统一且简单**：不管是走路、跳舞、下蹲还是爬行，奖励永远是"当前机器人姿态和参考动作捕捉数据的姿态差多少"——不需要为每个新动作重新设计
- **训练数据可以直接复用现成的动作捕捉数据库**：人类动作捕捉领域已经积累了几十年的数据（如 AMASS 数据集），SONIC 用了 170 个人类被试者、700 小时、超过 1 亿帧的动作数据，不需要重新采集
- **监督信号是稠密的**：动作捕捉数据的每一帧都能提供明确的"目标姿态"，不像稀疏奖励任务那样"做完整件事才有一次反馈"

一句话直觉：**追踪任务本身自带监督信号，不需要人工设计"好不好"的标准——参考动作捕捉数据本身就是标准**。

## 二、Motion Tracking 的 MDP 形式化

### 2.1 为什么要重新定义状态和动作

要把"运动追踪"变成一个 RL 问题，第一步是明确定义状态空间、动作空间和奖励函数。SONIC 采用标准的 MDP 形式化 $\mathcal{M} = \langle \mathcal{S}, \mathcal{A}, \mathcal{T}, \mathcal{R}, \gamma \rangle$，用 PPO 训练策略最大化累积折扣回报 $\mathbb{E}\left[\sum_{t=1}^T \gamma^{t-1} r_t\right]$。

**为什么需要这个公式**：这是所有 RL 问题的通用起点，但这里的关键不在公式本身（这部分见 [策略梯度与 PPO](/前置知识/000a_前置知识_策略梯度与PPO)），而在于**状态和动作具体指什么**——这才是让"运动追踪"能落地成一个可训练问题的关键设计。

### 2.2 状态：本体感知 + 运动指令

状态 $\boldsymbol{s}_t$ 由两部分组成：

$$
\boldsymbol{s}_t^p \triangleq (\boldsymbol{q}_t, \dot{\boldsymbol{q}}_t, \boldsymbol{\omega}_t, \boldsymbol{\psi}_t, \boldsymbol{a}_{t-1})
$$

**逐项拆解**：

| 符号 | 含义 | 直觉 |
|------|------|------|
| $\boldsymbol{q}_t$ | 关节角度（29 维） | "身体现在每个关节弯曲到什么角度" |
| $\dot{\boldsymbol{q}}_t$ | 关节角速度 | "每个关节现在转动多快" |
| $\boldsymbol{\omega}_t$ | 根部（骨盆）角速度 | "整个身体现在转动多快" |
| $\boldsymbol{\psi}_t$ | 根部坐标系下的重力方向向量 | "身体现在是不是歪了，往哪个方向歪" |
| $\boldsymbol{a}_{t-1}$ | 上一步的动作 | "上一步准备往哪个方向动"，帮助平滑连续性 |

另一部分是运动指令 $\boldsymbol{s}_t^g$，它有三种类型：机器人动作指令 $\boldsymbol{g}^r$（直接是机器人关节轨迹目标）、人类动作指令 $\boldsymbol{g}^h$（人类动作捕捉的 3D 关节位置目标）、混合动作指令 $\boldsymbol{g}^m$（上半身用稀疏关键点、下半身用机器人动作目标）。这三种指令类型分别对应第 3 章要讲的三个不同编码器——本章先把它们当作"来自不同来源的目标姿态"来理解即可。

**为什么要把状态全部表示在"根部局部坐标系"下**：所有状态量都相对于机器人自身骨盆的朝向来表示，而不是相对于世界坐标系。这保证了策略学到的是"旋转不变"的行为——不管机器人现在面朝哪个方向，只要相对身体的姿态关系相同，策略就应该输出相同的动作。这避免了策略被"绝对朝向"这个和任务本身无关的量干扰。

### 2.3 动作：PD 控制器的目标关节角

$$
\boldsymbol{a}_t = \pi(\boldsymbol{s}_t) \quad \text{（目标关节位置）}
$$

策略网络的输出不是直接的关节力矩，而是"目标关节位置"，这个目标位置再交给一个比例-微分（PD）控制器去实际驱动电机。

**为什么不直接输出力矩**：直接学习力矩输出对策略网络的要求极高（需要隐式学到整套动力学模型），而且力矩输出的策略天然更容易产生高频振荡（这是 [动作平滑性正则化 CAPS](/前置知识/000i_前置知识_动作平滑性正则化CAPS) 一文讨论的一类通用问题）。让策略只负责"想去哪个姿态"，把"怎么用力去到那个姿态"这个更底层、更需要精细时间尺度响应的问题交给传统的 PD 控制器，是机器人控制领域一个久经验证的分工方式——策略网络负责"意图"，经典控制器负责"执行细节"。

### 2.4 奖励：追踪误差 + 惩罚项

$$
r_t = \mathcal{R}(\boldsymbol{s}_t^p, \boldsymbol{s}_t^g) + \mathcal{P}(\boldsymbol{s}_t^p, \boldsymbol{a}_t)
$$

**为什么需要这个公式**：这个式子把奖励拆成两大块——追踪项 $\mathcal{R}$ 负责"鼓励尽量贴近参考动作"，惩罚项 $\mathcal{P}$ 负责"抑制不自然、不安全的行为"。两者合起来定义了"什么样的运动才算好"。

**追踪项的具体构成**（来自论文 Table 3）：

| 奖励项 | 公式 | 权重 | 直觉 |
|--------|------|------|------|
| 根部朝向 | $r^{\text{root}}_{\text{ori}}(t) = \exp(-\|\boldsymbol{o}_t^p - \boldsymbol{o}_t^g\|_2^2 / 0.4^2)$ | 0.5 | 骨盆朝向和参考朝向差多少 |
| 身体位置（相对） | $r^{\text{body}}_{\text{pos}}(t) = \exp\left(-\frac{1}{|\mathcal{B}|}\sum_{b\in\mathcal{B}} \|\boldsymbol{p}_{t,b}^{p,\text{rel}} - \boldsymbol{p}_{t,b}^{g,\text{rel}}\|_2^2 / 0.3^2\right)$ | 1.0 | 各身体部位（相对骨盆）的位置追踪误差 |
| 身体朝向（相对） | 同上结构，用朝向差 | 1.0 | 各身体部位朝向的追踪误差 |
| 身体线速度 | 同上结构，用速度差 | 1.0 | 各身体部位移动速度的追踪误差 |
| 身体角速度 | 同上结构，用角速度差 | 1.0 | 各身体部位转动速度的追踪误差 |

这五项都用了同一种数学形式：$\exp(-\text{误差}^2/\sigma^2)$。

**为什么是这个形式**：这是一种常见的"高斯核"奖励塑形——误差为 0 时奖励恰好是 1（满分），误差越大奖励呈指数级快速衰减到 0。相比直接用"负的误差值"作为奖励（比如 $r = -\|\boldsymbol{p}^p - \boldsymbol{p}^g\|^2$），指数形式的好处是奖励值被限制在 $(0, 1]$ 区间内，数值上更稳定，也让"追踪得很准"和"追踪得差一点"之间的奖励差异更平滑,不会因为误差量级不同（比如厘米级 vs 米级）而让某一项奖励在数值上主导整体优化方向。

**代入数字看一遍**：假设某个身体部位（比如右手腕）相对骨盆的参考位置是 $(0.3, 0.1, 0.2)$ 米，机器人实际位置是 $(0.32, 0.13, 0.18)$ 米，误差向量是 $(0.02, 0.03, -0.02)$，L2 范数平方 $\approx 0.02^2+0.03^2+0.02^2=0.0017$。代入 $\sigma=0.3$：

$$
r = \exp(-0.0017/0.09) = \exp(-0.0189) \approx 0.981
$$

这是一个接近 1 的高分——3 厘米左右的追踪误差，在这个奖励设计下几乎不扣分，符合直觉：人类肉眼很难分辨 3 厘米以内的姿态差异。

惩罚项则包括三项：动作变化率惩罚（$-0.1$ 权重，抑制动作突变）、关节超限惩罚（$-10.0$ 权重，严厉惩罚超出物理极限的关节角度）、非预期接触惩罚（$-0.1$ 权重，惩罚脚踝和手腕以外的部位触碰地面或物体）。这些惩罚项的权重远小于追踪项，因为它们的作用是"划定安全边界"，不是"定义任务目标"——绝大部分时候策略应该在追踪项的引导下运动，惩罚项只在越界时才生效。

## 三、领域随机化：让仿真训练出的策略能部署到真实机器人

### 3.1 为什么需要领域随机化

SONIC 完全在仿真（Isaac Lab）里训练，最终却要部署到真实的 G1 机器人上。仿真和真实世界之间必然存在差异（摩擦系数、执行器响应延迟、传感器噪声等），这种差异叫"仿真到真实的差距"（sim-to-real gap）。

**领域随机化的核心思路**：不去精确匹配仿真和真实世界的每一个物理参数，而是在训练时**故意大范围随机化**这些参数，让策略在训练阶段就经历各种可能的物理条件组合。这样训练出的策略天然对"参数具体是什么"不敏感，因为它已经在训练里见过了比真实世界更极端的情况。

### 3.2 具体随机化了什么

SONIC 随机化了三大类参数（详见论文 Table 4）：

**物理参数随机化**：静摩擦系数 $\mu_s \sim \mathcal{U}[0.3, 1.6]$、动摩擦系数 $\mu_d \sim \mathcal{U}[0.3, 1.2]$、恢复系数 $e \sim \mathcal{U}[0, 0.5]$、默认关节位置的微小偏移、质心位置偏移。

**根部速度扰动（模拟外部推力）**：随机施加线速度和角速度扰动，模拟"有人推了机器人一下"的场景，持续时间 $\sim \mathcal{U}[1,3]$ 秒。

**目标动作扰动**：给参考动作本身也加入抖动——目标位置抖动、目标朝向抖动、目标速度抖动等。

**为什么要扰动"目标动作"本身，而不只是扰动物理环境**：这是一个容易被忽略但很重要的设计。如果参考动作永远是"完美平滑"的，策略可能会过拟合到"输入永远是理想轨迹"这个假设上。而真实部署时，上层的运动规划模块给出的参考轨迹不会完美平滑（比如用户操纵摇杆的输入会有抖动，VLA 给出的高层指令切换时会有跳变）。给训练时的目标动作本身加入噪声，是在训练"策略对不完美指令的鲁棒性"，这一点直接决定了后续 GR00T VLA 主干接入 SONIC 时,即便上层指令不完美,SONIC 依然能稳定执行。

## 四、训练循环：标准 PPO，但有一处关键的自适应采样技巧

### 4.1 训练循环整体结构

SONIC 用标准的 PPO 训练循环（详见 [策略梯度与 PPO](/前置知识/000a_前置知识_策略梯度与PPO) 了解 PPO 的 clip 机制本身），大规模并行——单次实验在数千个并行仿真环境中同时收集数据，最大规模的实验用了 128 张 GPU、3 天时间处理超过 1 亿帧动作数据。

### 4.2 自适应动作采样：训练效率的关键工程细节

一个值得单独展开的细节是 SONIC 用了什么策略去决定"训练时从哪一段动作捕捉数据开始采样"。如果均匀随机地从整个数据集里选起始帧，会有一个问题：某些动作片段（比如复杂的舞蹈动作）远比另一些（比如平稳走路）更难学，如果采样概率一样，简单的片段会被"过度学习"，难的片段却得不到足够的训练信号。

SONIC 的解法是**基于失败率的分箱自适应采样**：

1. 把整个动作数据集切分成固定长度的时间"箱子"（bin）
2. 统计当前策略在每个箱子上的失败率 $f_i$
3. 为了避免采样过度集中到"极端难"甚至可能有数据问题的箱子上，把每个箱子的失败率上限截断为 $\beta \bar{f}$（$\bar{f}$ 是所有箱子的平均失败率，$\beta$ 是超参数）
4. 用截断后的失败率归一化得到初步采样权重 $\hat{p}_i$
5. 最终采样概率是 $p_i = \alpha \hat{p}_i + (1-\alpha)\frac{1}{N}$（$\alpha$ 是混合超参数，$N$ 是箱子总数）

**为什么需要这个公式**：这套机制要在"多训练难的片段"和"不要过度沉迷难的片段导致训练不稳定"之间找一个平衡点。纯粹按失败率采样（不做截断）可能会让训练一直卡在几个极端困难甚至质量有问题的动作片段上；纯粹均匀采样又会浪费大量算力在已经学会的简单片段上。

**逐项拆解**：

| 符号 | 含义 |
|------|------|
| $f_i$ | 箱子 $i$ 的当前失败率 |
| $\beta \bar{f}$ | 失败率的截断上限 |
| $\hat{p}_i$ | 截断后归一化得到的"倾向性"采样权重 |
| $\alpha$ | 混合系数，控制"倾向难例"和"均匀覆盖"之间的比例 |
| $\frac{1}{N}$ | 均匀采样项，保证所有箱子都有基础的被采样概率 |

这个设计模式和很多"课程学习"（curriculum learning）思路相通，但它不是预先设定一个从易到难的固定顺序，而是**动态地**根据当前策略的实际表现调整采样重点——本质上是一种自适应的重要性采样。

## 五、Critic 与 Actor 的规模：不是"小网络"了

### 5.1 网络规模对比

一个值得强调的对比是，SONIC 的网络规模远超传统的人形机器人 RL 策略。传统方法通常是几百万参数的 3 层 MLP，而 SONIC 的解码器（Decoder）用了 `[4096, 4096, 2048, 2048, 1024, 1024, 512, 512]` 这样的 8 层宽 MLP 结构，Critic 也采用同样规模的网络（详见论文 Table 1）。整体参数量从 1.2M 扩展到 42M。

### 5.2 为什么"更大的网络"本身就是一个值得验证的假设

论文专门做了对照实验（Figure 2），系统对比了在网络规模、数据量、算力（GPU 小时数）三个维度上分别扩大规模带来的效果：

| 扩展维度 | 对比设置 | 结论 |
|---------|---------|------|
| 数据量 | 0.4M 帧 vs 7.4M 帧 vs 100M 帧 | 数据量扩大带来的收益最显著 |
| 模型规模 | 1.2M vs 42M 参数 | 持续带来提升，但边际收益不如数据量 |
| GPU 小时数（并行度） | 8 GPU vs 32 GPU vs 128 GPU | 更多并行度不仅训练更快，**收敛后的最终性能也更好**（不是同样的最终效果只是更快达到） |

**为什么"更多 GPU 并行"会影响最终性能而不只是训练速度**：这一点略微反直觉——通常我们认为更多 GPU 只是加速收敛，收敛点应该是一样的。但 SONIC 的实验发现：用更少 GPU 训练到收敛的策略，渐近性能反而更差。一个合理的解释是：在这种大规模、多样化动作追踪的设定下，有效的探索/覆盖需要足够多的并行环境实例同时采集数据——环境数量不足会导致某些困难或稀有的动作模式在一次训练迭代里根本采样不到，即使训练更久也无法弥补这种"覆盖不足"的结构性缺陷,这和第四节里讨论的"自适应采样"要解决的问题本质上是同一类:训练信号的覆盖面比训练时长更关键。

这个发现印证了 GR00T 系列文档反复强调的一个工程原则:**在具身智能这个领域,数据的规模和多样性,往往比单纯堆砌算力或模型规模更能决定最终效果**——这也是为什么本章开头强调"运动追踪"这个任务设计的核心价值，正在于它能够直接复用现成的大规模人类动作捕捉数据。

| 核心方案 | 把控制问题重新表述为"运动追踪"，用统一的追踪误差作为奖励，直接复用人类动作捕捉数据 |
| RL 算法 | 标准 PPO，但网络规模远超传统方法（1.2M → 42M 参数） |
| 状态设计 | 本体感知（关节角/速度/朝向/上一步动作） + 运动指令（机器人/人类/混合三种来源） |
| 动作设计 | PD 控制器目标关节位置，不直接输出力矩 |
| 奖励设计 | 高斯核形式的多项追踪误差 + 少量惩罚项（动作突变/关节超限/意外接触） |
| 关键工程细节 | 基于失败率的分箱自适应采样、大范围领域随机化 |
| 在 GR00T 技术栈中的角色 | "System 1"快速反应式执行器，VLA 主干作为"System 2"负责决策，SONIC 负责让身体动起来 |
| 扩展规律 | 数据量 > 模型规模 ≈ 算力（GPU 并行度），三者都持续带来收益 |

## 下一章预告

本章讲清楚了 SONIC 的 MDP 定义、奖励设计和训练循环，但故意留了一个悬念：状态定义里提到"运动指令有机器人、人类、混合三种类型"，具体是怎么被编码进同一个策略网络的？下一章我们将深入 SONIC 的核心架构创新——**通用 Token 空间**，看它是怎么用 FSQ（有限标量量化）把三种完全不同形态的输入统一映射到同一个离散 token 空间，从而让一个模型同时支持机器人关节轨迹、VR 遥操作、人类动作捕捉这三种截然不同的控制接口。
