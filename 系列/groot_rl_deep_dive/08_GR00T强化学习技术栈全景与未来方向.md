## 一、四层技术的统一表格

在深入讨论共性和差异之前，先用一张更完整的表格把四层技术并排放在一起，作为全系列的"速查手册"：

| 维度 | Whole-Body RL (SONIC) | COMPASS | RTC | AQC 离线 RL 增强 |
|------|------------------------|---------|-----|-------------------|
| 所属层级 | 第一层：底层运动控制 | 第二层：导航泛化 | 第三层：推理时序控制 | 第四层：VLA 后训练增强 |
| 官方/学术界 | 官方（NVIDIA GEAR） | 官方（NVIDIA） | 官方采用/学术界原创（Physical Intelligence） | 学术界独立工作 |
| 核心算法 | PPO（从零训练） | Residual PPO + KL 蒸馏 | Flow matching 条件化（train-time）/ 伪逆引导（test-time） | 多尺度 Actor-Critic 离线 RL |
| 训练规模 | 100M+ 动作帧，最高 128 GPU | 每具身体 1000 episode，2×L40 GPU | 8000 步微调（真实场景） | 24k 专家演示 + 300 rollout/任务 |
| 探索难题的解法 | 追踪人类动作捕捉数据提供稠密监督 | 冻结 IL 基础模型收窄探索空间 | 不涉及探索（非在线学习问题） | 复用离线数据 + best-of-N 采样 |
| 是否修改/重训 VLA 主干 | 不需要（独立训练） | 不需要（独立子系统） | 需要少量微调（train-time 版本） | 不需要（backbone 完全冻结） |
| 泛化目标 | 泛化到多样化运动模式 | 泛化到不同机器人形态 | 泛化到不同推理延迟场景 | 泛化到不同任务阶段所需的分块粒度 |

## 二、共同的设计哲学：围绕昂贵主干的外挂式增强

读完全部四层技术之后，一个反复出现的模式已经很明显了：**没有一层技术要求"重新训练或大幅修改 GR00T VLA 主干本身"**。

- SONIC 是完全独立训练的控制器，VLA 只需要学会"调用"它（通过输出速度指令或运动学参考帧）
- COMPASS 的 Residual RL 阶段明确冻结 IL 基础模型，只训练一个小的残差网络
- RTC 的 train-time 版本只需要三处轻量架构改动（不增加参数），test-time 版本完全不涉及训练
- AQC 明确"冻结整个 backbone，只训练外挂的 Critic head"

**为什么整个生态圈会收敛到同一种设计哲学**：VLA 主干（Cosmos-Reason2 + AlternateVLDiT）的预训练成本极高——GR00T N1.6 用了 300K 步、全局 batch size 16384 的预训练规模。在这个成本量级下，任何需要"顺便重新训练整个主干"的增强方案，在工程实践里都不现实——每一次迭代验证一个新想法，都要承担重新预训练的天价成本。所以整个社区（不管官方还是学术界）不约而同地走向了同一个方向：**把新增的能力都设计成外挂式的、轻量级的子系统或修正层，只在主干"之外"或"之上"工作**。

这个原则甚至可以往前追溯到本系列之外——[GR00T N1.7 深度解析系列](/系列/groot_n1d7_deep_dive/) 第 6-8 章讨论的"骨干层截断"（只用 VLM 的前若干层）本质上也是同一种"控制昂贵主干的介入程度"的思路，只是应用在预训练阶段而不是后训练阶段。

## 三、共同的第二个模式：用先验/结构性约束替代纯粹探索

四层技术的第二个共同点是：**几乎都在想办法避免"让策略从零开始、在稀疏奖励下盲目探索"这种最昂贵的学习方式**。

- SONIC 没有用手工设计的任务奖励让机器人"自己摸索"怎么走路，而是直接给了稠密的追踪监督信号（人类动作捕捉数据）
- COMPASS 没有让 Residual RL 从零探索导航空间，而是先用 IL 学一个"大致靠谱"的基础策略，把探索范围收窄到基础动作附近的小范围修正
- AQC 处理的是**离线**RL 场景本身——直接利用已有的、次优的 rollout 数据，而不需要在真实机器人上做大量在线试错

**这背后的一个更宏观的观察**：在真实机器人（而不是低成本仿真游戏环境）上做纯粹的、无结构的强化学习探索，代价极其高昂——不仅是训练时间，还有真实设备的损耗风险和安全问题。整个 GR00T 技术栈里的 RL 系统设计，实际上都在回答同一个问题：**"怎么用尽可能少的、结构化的先验信息，替代掉尽可能多的盲目探索？"** SONIC 用的是"人类已经会做这些动作"这个先验，COMPASS 用的是"已经有一个能在简单机器人上工作的基础策略"这个先验，AQC 用的是"已经有大量专家演示和次优 rollout 数据"这个先验。

## 四、四层技术各自遗留的开放问题

### 4.1 Whole-Body RL (SONIC) 的开放问题

论文自己在讨论部分承认：**安全性、能耗效率、长时间部署的正式化处理**目前还没有系统解决；此外，模型对训练时没有"仔细覆盖"的噪声输入（比如真实传感器的异常数据）的鲁棒性也还需要进一步研究。SONIC 论文明确把"VLA 指令的全身移动操作任务"（VLA-instructed whole-body locomanipulation）列为未来方向——目前 SONIC 和 VLA 的结合（第 3 章末尾提到的 apple-to-plate 实验）只是一个概念验证性质的实验（95% 成功率、20 次试验），论文明确说"这只是为了证明兼容性，不是为了展示广泛的泛化能力"。

### 4.2 COMPASS 的开放问题

论文讨论部分列出了几个方向：目前的具身体嵌入是简单的**独热编码**，对于未曾见过的、全新形态的机器人不具备零样本泛化能力——一个可学习的、更连续的嵌入空间可能是更好的方向；策略蒸馏本身存在"跨具身体平均化"的效应，可能导致某些具身体特定的细微性能差异；此外，长 horizon、需要复杂路线规划的场景（比如多货架仓库里的路径规划）目前表现相对较弱，论文提出**分层导航栈**（结合基于图的路线规划器）是一个值得探索的改进方向。

### 4.3 RTC 的开放问题

Train-time RTC 论文自己指出的核心局限是：它只支持对一段"硬"前缀的条件化，不像 test-time 方法那样可以用"软掩码"处理前缀之外的重叠区域；而且训练时需要提前设定一个延迟分布来采样，如果真实部署时的延迟分布和训练时假设的不匹配，性能可能打折扣。论文明确期待未来工作能把两种方法的优点结合起来——既有训练时方法的低开销和高延迟鲁棒性，又有推理时方法处理任意、未见过延迟模式的灵活性。

### 4.4 AQC 的开放问题

AQC 论文（第七章第一节详细讨论过）承认候选尺度集合 $\mathcal{K}$ 仍然是**人工设计的离散集合**，没能从数据里自动学出最优的粒度划分；即便选中了 $k^*=1$（最细粒度），策略在这一步内部依然继承了行为策略 $\pi_\beta$（本身是在 $h$ 步分布上训练的）固有的反应能力上限——如果任务需要真正逐步的闭环反馈，动作分块这个框架本身存在天然局限；此外，Critic 训练开销随候选集合大小 $|\mathcal{K}|$ 线性增长，虽然论文报告说实践中影响可控。

### 4.5 一个共同的开放问题：能不能让这些外挂系统"互相知道对方的存在"

一个跨越四层的、目前没有被任何一篇论文直接讨论的问题是：**这四套系统目前基本上是独立设计、独立验证的**——SONIC 不知道 RTC 的存在，COMPASS 训练时也没有考虑到未来可能被 AQC 一类的离线 RL 后训练增强。如果这些外挂系统能"感知"到彼此的存在（比如 AQC 的分块长度选择,能不能同时考虑到 SONIC 执行不同长度指令时的物理稳定性差异？），理论上应该有更大的联合优化空间。但这需要打破"各自独立、互不干扰"的当前设计哲学,可能带来更复杂的训练流程和调试难度——这大概解释了为什么目前没有人这么做。

## 五、回顾全系列：一句话总结每一章

| 章节 | 一句话总结 |
|------|-----------|
| 第 1 章 | GR00T 生态里的 RL 分四层：Whole-Body RL、COMPASS、RTC、AQC，各自独立、各自解决不同问题，"GR00T 集成 AQC"是个误解 |
| 第 2 章 | SONIC 把人形机器人运动控制重新定义成"追踪人类动作捕捉数据"，用 PPO 训练，网络规模远超传统方法 |
| 第 3 章 | SONIC 用 FSQ 把机器人/人类/混合三种输入模态统一到同一个离散 token 空间，重定向能力是训练的自然涌现 |
| 第 4 章 | COMPASS 用"IL 打底 + Residual RL 修正 + 策略蒸馏合并"三阶段流程，把导航能力泛化到多种机器人形态 |
| 第 5 章 | RTC 把"动作块衔接不连贯"问题重新表述成图像修复问题，有推理时（伪逆引导）和训练时（前缀条件化）两种解法 |
| 第 6 章 | Q-Chunking 用分块 Critic 消除 TD 学习的 off-policy 偏差，AQC 用折扣归一化 advantage 解决"分块长度该多长"的自适应选择问题 |
| 第 7 章 | AQC 论文用冻结的 GR00T N1.6 + 外挂 Critic head，在 RoboCasa-GR1 的 24 个任务上验证了离线 RL 后训练增强的有效性 |
| 第 8 章（本章） | 四层技术共享"围绕昂贵主干的外挂式增强"和"用先验替代盲目探索"两个设计哲学，各自仍有明确的开放问题 |
