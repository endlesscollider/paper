# 后训练对齐：Embodiment Alignment + Instruction Alignment

> **前情提要**：上一章完整拆解了 Rectified Flow 训练目标和频率域 Loss。本章进入 Stage 2——预训练出来的通用模型如何通过后训练对齐到具体机器人和自然语言指令。

- 前代对照：[XR-0 数据管线](/系列/xr0_deep_dive/09_数据管线_JSON标注与相对动作计算)

## 1. 后训练要做什么

预训练完成后，模型具备了这些能力：
- ✅ 从画面理解场景布局和物体关系
- ✅ 理解"状态转换描述"（如"夹爪从 A 移到 B"）
- ✅ 生成实现转换所需的末端动作序列
- ❌ 不知道具体机器人有哪些关节、怎么控制
- ❌ 不理解自然语言任务指令（如"帮我倒水"）
- ❌ 没见过多视角输入（预训练只用了 UMI 单路 ego 相机）

后训练的目标就是补齐这三个缺失。

## 2. 两轴对齐

### 2.1 Embodiment Alignment（体态对齐）

把"末端 6DoF 动作"映射到"具体机器人的完整动作空间"。

以 XR-1 目标平台（小米双臂移动机器人）为例：
- 预训练动作：末端 6DoF + 夹爪 ≈ 7 维
- 后训练动作：60 维（左臂 EE 7d + 右臂 EE 7d + 腰 1d + 底盘 3d + reserved）

体态对齐通过在**跨体态数据**上继续训练实现：
1. 模型看到多视角图像 + 指令
2. 输出完整 60 维动作
3. Loss 计算时用 `action_mask` 只在该机器人有效的维度上监督

`action_mask` 的设计让不同体态的数据可以混合训练——比如只有单臂的数据，其右臂维度的 mask 就是 0，loss 不在这些维度上计算。

### 2.2 Instruction Alignment（指令对齐）

把"状态转换描述"理解能力切换为"自然语言指令"理解能力。

预训练时的文本输入形如：
> "The gripper moves from the left side of the table to above the cup and closes"

后训练时替换为：
> "Pick up the red cup"

这两种文本在语义层面有本质区别：
- 状态描述是**事实性的**（描述发生了什么）
- 任务指令是**意图性的**（描述要做什么）

但由于 VLM 骨干（Qwen3-VL）本身就理解自然语言，切换的代价不大——VLM 已经知道"pick up the red cup"意味着什么，只需要学会把这种理解连接到动作生成即可。

## 3. 后训练数据来源

后训练用了三类数据（总计 1 万+ 小时）：

| 数据来源 | 量级 | 特点 |
|---------|------|------|
| 小米真机遥操作 | 主体 | 双臂 60 维完整动作，三路相机 |
| 开源数据集（过滤） | 补充 | 来自 Open X-Embodiment 等，质量筛选后使用 |
| 标注 UMI 数据 | 补充 | 部分 UMI 轨迹人工添加指令标注 |

### 3.1 数据混合策略

不同来源的数据在后训练中按比例混合，关键原则：
- 真机数据权重最高（体态对齐的核心来源）
- 开源数据只取通过质量过滤的子集
- UMI 标注数据作为预训练→后训练的"桥梁"——它的视觉输入和预训练一致，但文本换成了指令

### 3.2 多视角输入的引入

预训练只用了 UMI 单路 ego 相机。后训练引入三路相机：

| 相机 | 视角 | 作用 |
|------|------|------|
| Ego | 头部/机身正前方 | 全局场景理解 |
| Wrist Left | 左手腕 | 左臂精细操作的近距离观测 |
| Wrist Right | 右手腕 | 右臂精细操作的近距离观测 |

VLM 的 prompt 模板在后训练中变为：

```
The following observations are captured from multiple views.
# Ego View
<image>
# Left-Wrist View
<image>
# Right-Wrist View
<image>
Generate robot actions for the task:
{instruction}
```

每个 `<image>` placeholder 对应一路相机的当前帧。

## 4. 后训练的具体配置

从 `configs/data/load_washer.yaml` 可以看到后训练的完整配置：

| 参数 | 值 | 说明 |
|------|-----|------|
| batch_size | 48 | 单 GPU |
| action_length | 30 | 动作块步数 |
| paths | JSON 文件列表 | 每个 JSON 描述一个 episode |
| mean/std | [30, 60] | 每步每维的归一化统计量 |
| q01/q99 | [1, 60] | 状态的分位数归一化 |
| max_steps | 10000 | 默认总训练步数 |

关键：`mean` 和 `std` 都是 **per-step** 的——即第 1 步有自己的 mean/std，第 30 步有自己的 mean/std。这是因为动作是**累积相对量**：越往后的步骤，累积的偏移越大，方差也越大。

## 5. 后训练和预训练用同一个模型架构

一个重要的工程特点：**后训练和预训练用完全相同的模型架构和 loss 函数**。

唯一的区别是：
1. 输入文本从"状态描述"变为"任务指令"
2. 输入图像从单路变为三路
3. 动作维度从 UMI 的 7d 扩展到具体机器人的 60d
4. 加载预训练权重后继续训练（`pretrained="pretrained_ckpt/model_states.pt"`）

这种设计的好处：
- 不需要为后训练设计专门的 adapter 或额外模块
- 预训练学到的所有权重（VLM + DiT + Projectors）都参与后训练
- 架构一致性让 Scaling 行为更可预测

## 6. 后训练的 Scaling 行为

XR-1 论文的一个核心发现：**预训练数据量的增加，能可靠地通过后训练传递到下游任务性能。**

这意味着：
- 用 10K 小时预训练 → 后训练性能 X
- 用 50K 小时预训练 → 后训练性能 Y > X
- 用 100K 小时预训练 → 后训练性能 Z > Y

且 **没有饱和迹象**——曲线仍在上升。

这和 LLM 的 Scaling Law 完全一致：更多预训练数据 → 更强的后训练基础 → 下游任务更好的表现。这是 XR-1 最重要的实验结论之一。

## 7. 数据高效适配的实际含义

后训练完成后的模型已经具备泛化能力。针对新任务的微调只需要极少数据：

- **< 10 小时/任务**就能达到平均 75% 成功率
- 对比 π0.5 的 40%，差距巨大

这说明预训练阶段学到的通用操作知识确实有效——模型已经"知道"怎么抓取、推动、放置，只需要少量数据告诉它"在这个具体场景中怎么做"。

## 8. 本章小结

后训练是将预训练能力"落地"的关键步骤：

1. **Embodiment Alignment**：通过 60 维动作空间 + action_mask，让模型适配具体机器人
2. **Instruction Alignment**：通过文本切换（描述→指令），让模型理解人类意图
3. **数据混合**：真机 + 开源 + 标注 UMI，三路互补
4. **架构不变**：同一个模型架构端到端训练，预训练权重完全复用
5. **Scaling 传递**：预训练规模的增加能可靠提升后训练性能
