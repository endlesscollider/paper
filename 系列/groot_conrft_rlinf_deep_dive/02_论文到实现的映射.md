## 1. 论文的两阶段结构

ConRFT 论文（arXiv:2502.05450）的方法叫 **Cal-ConRFT + HIL-ConRFT**，是一个两阶段方案。为了后面对照方便，先把论文的形状用一张表固定下来（详细解读见 [ConRFT 论文精读](/论文综述/010_ConRFT_一致性策略RL微调VLA)）：

| | 阶段一 Cal-ConRFT | 阶段二 HIL-ConRFT |
|---|---|---|
| 数据 | 少量离线演示（论文用 20~30 条） | 在线采集 + 人类干预纠正 |
| Critic | Cal-QL（CQL + MC 回报校准） | 标准 TD，无保守项 |
| Actor | 一致性策略蒸馏 loss + Q 项 | 一致性策略 loss + Q 项 + 行为约束 |
| 目的 | 用极少数据得到一个"能用"的 critic 和 policy | 在真实交互中提升成功率，同时不允许策略跑飞 |
| 安全机制 | 无需（不交互） | 人类可随时接管，接管数据进 buffer |

论文的核心论点有两条：

1. **离线阶段必须用 Cal-QL 而不是 CQL**：数据量太小（20 条演示），CQL 会把 Q 压得毫无尺度，切到在线阶段后策略立刻崩。Cal-QL 的 MC 回报下界让 Q 保持在可用量级。
2. **在线阶段必须有行为约束**：真机上策略跑飞会撞坏东西，所以 actor loss 里始终保留一个把策略拽回演示分布的项。

这两条论点决定了本链路必须保留什么。

## 2. 五处关键替换

本链路不是论文的复现，而是把论文方法搬到一个不同的模型、不同的环境、不同的框架上。一共有五处实质性替换。

### 2.1 策略骨架：一致性策略 → Flow Matching

**论文用的是什么**：Consistency Policy。一致性模型的特点是**一步生成**——训练时通过蒸馏让网络学会"从任意噪声水平直接跳到干净样本"，推理时一次前向出结果。这对真机很关键，因为推理延迟直接限制控制频率。

**本链路用的是什么**：GR00T N1.7 的 Flow Matching action head，4 步 Euler 积分。

**这个替换改变了什么**：

| | 一致性策略 | 本链路的 Flow Matching |
|---|---|---|
| 推理步数 | 1 | 4（`denoising_steps: 4`） |
| 动作对策略参数的梯度路径 | 一步，短 | 4 步链式，需要穿透去噪链 |
| 是否有解析的 $\log\pi(a\vert s)$ | 否 | 否（同样没有） |
| 梯度回传的可控性 | 天然可控 | 需要 `actor_backprop_steps` 控制回传几步 |

**为什么这个替换是可行的**：ConRFT 的 actor loss 里那个 Q 项需要的是 $\nabla_\phi Q(s, \pi_\phi(s))$，也就是**动作对策略参数可微**就够了，不需要 $\log\pi$ 的解析式。Flow Matching 的去噪链每一步都是可微的（见第 05 章），所以梯度能传回去。这是 ConRFT 能搬到 Flow Matching 上的根本原因。

**代价**：4 步去噪意味着一次 actor 前向的计算量是一致性策略的 4 倍，而且梯度要穿过 4 层 32 层 DiT 的链。本链路用 `actor_backprop_steps: 4` 表示全部 4 步都回传梯度。这也是第 01 章 9.7 提到的"两次策略前向"代价特别贵的原因。

### 2.2 动作粒度：单步动作 → 16 步 chunk

**论文的动作**：单步（或者短 chunk），MDP 是标准形式。

**本链路的动作**：$[16, 62]$ 的整个动作块。GR00T N1.7 一次推理产出 16 个控制步，全部执行完再做下一次推理（replan 周期 = chunk 长度）。

**为什么必须 chunk 化**：如果硬要按单步 MDP 做，会遇到三个问题：

1. GR00T 的 16 步是**联合**生成的，第 8 步的取值依赖同一次去噪过程里第 1 步的取值。拆成 16 个条件独立的单步分布就扔掉了模型最核心的结构。
2. 中间状态（执行完第 3 步之后的观测）策略从来没有在上面做过决策，给它估 $Q$ 值语义不明。
3. GR00T 一次前向要几十到上百毫秒，每步重新推理达不到控制频率。

所以定义：**一个"动作"就是整个 16 步序列**。这套思路的理论讨论见 [Q-Chunking 论文精读](/论文综述/071_QChunking_RL与动作分块)。

**这对 ConRFT 的每一项意味着什么**：

| ConRFT 的组件 | 单步版本 | chunk 版本 |
|---------------|----------|------------|
| $Q(s,a)$ | $a \in \mathbb{R}^{62}$ | $a \in \mathbb{R}^{16\times62}$，critic 把它展平成 992 维输入 |
| Bellman 折扣 | $\gamma$ | $\gamma^{16} = 0.851$ |
| 即时奖励 | 一个标量 | 16 步奖励序列，要先折扣求和成一个标量 |
| CQL 候选动作 | 采 $62$ 维向量 | 采 $16\times62$ 的矩阵 |
| BC loss | 单步动作的回归 | 整个 chunk 的 Flow Matching velocity 回归 |
| 行为约束 | 单步动作距离 | 整个 chunk 的 masked MSE |

**注意 CQL 候选那一行**：动作空间从 62 维变成 992 维。CQL 的保守正则本质上是"在动作空间里采样并压低 OOD 区域"，而 992 维空间里采 4 个均匀随机样本，覆盖率是可以忽略的。这是 chunk 化对 ConRFT 最不利的影响——**保守项的有效性随动作维度指数衰减**。本链路靠"候选里包含策略自己的采样"来部分弥补（见第 08 章），但这个问题在原理上没有被解决。

### 2.3 纠正数据来源：人类干预 → 仿真自动 reset

**论文的做法**：HIL（Human-in-the-Loop）。人类盯着机器人，一旦看到要出事就接管，接管期间的动作作为高质量纠正数据进 buffer。这既是安全机制，也是数据来源。

**本链路的做法**：仿真环境，`auto_reset: false` + `max_episode_steps: 350`，episode 跑完或失败就重置。没有人类干预，也不需要——仿真里撞坏东西没有代价。

**这个替换拿掉了什么**：

1. **纠正数据的质量下降**。论文的 buffer 里混着人类在关键时刻给出的"正确做法"，这是极强的监督信号。本链路的 buffer 里只有策略自己采的数据（成功和失败混在一起）加上离线的 BC 演示。
2. **在线阶段的 BC 项失去了"新鲜"的监督**。论文在线阶段的 BC 项可以用新采集的人类纠正数据；本链路的在线 BC 项用的是**固定的**离线 expert replay（`sample_expert`），从头到尾不变。

**这个替换加上了什么**：

1. **吞吐**。64 个并行环境不停跑，采样速度是真机的几个数量级。
2. **可重复性**。48 个固定 layout 的评测集可以精确复现（前提是评测被打开，见第 01 章 9.1）。
3. **不需要安全机制**，所以行为约束项的作用从"防止撞坏硬件"变成了纯粹的"防止策略分布崩塌"。

**后果**：论文里"行为约束项"和"人类纠正数据"是互补的两个安全网。本链路只剩前者，所以对它的依赖更重——这在权重上体现为 `w2_weight: 1.0` 和 `q_weight_online: 0.01` 的悬殊比例（见第 11 章）。

### 2.4 行为约束的具体形式：论文的 BC 项 → W2 masked MSE

论文在线阶段的行为约束是把策略拉向演示数据。本链路实现了**两个**约束，而不是一个：

| 项 | 参考对象 | 权重 | 数据 |
|---|---|---|---|
| BC 项 | 离线 expert replay 里的真实演示动作 | `bc_weight_online: 1.0` | expert batch |
| W2 项 | **冻结的预训练策略**在同一状态上的输出 | `w2_weight: 1.0` | 在线 replay batch |

第二项是本链路特有的，它利用了 Flow-G adapter 的结构。简单说：GR00T 的去噪速度场被冻结，RL 只训练一个乘性 gate。所以"关掉 gate 再跑一遍去噪"就能得到**原始 BC 策略在这个状态上会输出什么**——这个参考动作不需要额外的网络副本，也不需要额外的数据。

代码里对应 `sample_chunk_sac_action(..., return_bc_reference=True)`，实现细节在第 05 章。

**为什么要两个约束**：BC 项管的是"策略输出要像演示"，但演示只覆盖了状态空间的一小部分；W2 项管的是"在任意状态上，策略不要偏离原始 BC 模型太远"，覆盖的是在线 replay 里出现的所有状态。前者是分布层面的约束，后者是逐状态的 trust region。

### 2.5 框架：单机 SAC 循环 → RLinf 分布式异步

论文的实现是单机的：一个进程里跑环境交互 + 训练。本链路是 RLinf 的三组 worker，跨两个物理节点：

| Worker | 位置 | 数量 | 职责 |
|--------|------|------|------|
| env | 4090 节点 GPU 0-3 | 4 | 64 个 Isaac Sim 环境的物理仿真 |
| rollout | H20 GPU 0-3 | 4 | GR00T 推理，产出 16 步动作块 |
| actor | H20 GPU 4-7 | 4 | FSDP 训练，critic + actor 更新 |

这个替换带来的**唯一算法层面的改变**是**策略滞后**：rollout worker 用的权重最多比 actor 落后 50 秒（`weight_sync_interval_seconds: 50.0`）。也就是说 replay buffer 里的数据是由"稍旧的策略"采的。

对 off-policy 方法这是可接受的——replay buffer 本来就混着各个版本策略的数据。但它确实让"在线"的程度比论文低：论文每次更新之后策略立刻生效，本链路是每 50 秒生效一次。

## 3. 目标函数的逐项对照

把论文的公式和本链路的实现并排放。

### 3.1 阶段一 Critic

论文的 Cal-ConRFT critic 目标（省略符号细节，完整推导见 [Cal-QL 前置知识](/前置知识/002h_前置知识_CalQL校准保守Q学习)）：

$$
\mathcal{L}_{\text{critic}}^{\text{offline}} = \mathbb{E}\Big[\big(Q_\theta(s,a) - y\big)^2\Big] + \alpha \Big( \mathbb{E}_{a'}\big[\max\{Q_\theta(s,a'),\, G(s)\}\big]_{\text{LSE}} - Q_\theta(s,a) \Big)
$$

**Step 1：这个公式在做什么**

**它同时做两件事：让 $Q_\theta$ 满足 Bellman 方程（第一项），并且在数据动作和候选动作之间人为拉开一个被 MC 回报托底的间隙（第二项）。**

> **一句话直觉**：先把 Q 值算对，再把"策略想去但数据没覆盖的地方"的 Q 值压下去，但不许压到"人类演示实际拿到的分数"以下。

**逐符号拆解**：

| 符号 | 含义 | 本链路的对应 |
|------|------|--------------|
| $Q_\theta(s,a)$ | twin-Q critic 对一个 chunk 的估值 | `ChunkSACCritic`，`flat_absolute` 架构，两个 head |
| $y$ | Bellman target | `chunk_sac_td_target`，含 $\gamma^{16}$ bootstrap（第 06 章） |
| $\alpha$ | 保守强度 | `algorithm.conrft.cql_alpha: 0.1` |
| $a'$ | 候选动作 | 12 个：4 随机 + 4 当前策略 + 4 next-state 策略（第 08 章） |
| $G(s)$ | MC 回报下界 | `chunk_sac_mc_return`，由 `chunk_sac_bc.py` 预计算 |
| $[\cdot]_{\text{LSE}}$ | logsumexp 软最大 | `torch.logsumexp(candidates / tau, dim=1) * tau`，$\tau = 1.0$ |

**代入数字**：本链路的候选数是 12，再拼上数据动作本身共 13 项，$\tau = 1.0$，所以 logsumexp 的归一化常数是

$$
\tau \log K = 1.0 \times \log 13 = 2.565
$$

这个 $2.565$ 会在第 08 章反复出现——它是 `conservative_q_loss` 里 `normalizer` 的实际值。

**为什么是这个形式**：$\alpha = 0.1$ 相对 TD 项（量级 $10^{-2} \sim 10^{-1}$，因为 Q 值本身在 $[0,1]$）不算小。保守项的量级取决于候选 Q 值和数据 Q 值的差距，训练初期可能有几个单位，所以 $0.1 \times$ 之后和 TD 项同量级。这是一个合理的初值，但需要看 `conrft/cql_diff` 的实际曲线来确认。

**实现位置**：`EmbodiedConRFTFSDPPolicy.forward_critic` 调父类拿到 TD loss，然后加上 `self.conrft.cql_alpha * cql_scale * cql_loss`。第 08 章逐行拆。

### 3.2 阶段二 Critic

$$
\mathcal{L}_{\text{critic}}^{\text{online}} = \mathbb{E}\Big[\big(Q_\theta(s,a) - y\big)^2\Big]
$$

保守项直接消失。代码里是一个提前 return：

```python
def forward_critic(self, *args, **kwargs):
    output = super().forward_critic(*args, **kwargs)
    if not self._conrft_offline_stage:
        return output                      # ← 在线阶段到此为止，不加 CQL
    ...
```

**为什么在线要关掉**：保守项是为"数据固定、不能再探索"设计的。在线阶段新数据会持续修正 OOD 区域的 Q 值，保守项不再必要，而且会持续压低 Q 值、拖慢它爬升到真实尺度。这和论文一致。

### 3.3 Actor：两阶段的三项

$$
\mathcal{L}_{\text{actor}} = \underbrace{w_{\text{bc}} \cdot \mathcal{L}_{\text{BC}}}_{\text{像演示}} + \underbrace{w_q \cdot \big(-\bar{Q}\big)}_{\text{往高价值走}} + \underbrace{w_{\text{w2}} \cdot \mathcal{L}_{\text{W2}}}_{\text{别离开 BC 太远}}
$$

**Step 1：这个公式在做什么**

**它让策略同时满足三个互相拉扯的要求**：输出要能重建演示动作、要让 critic 给出高分、并且不能离原始 BC 策略太远。

> **一句话直觉**：三根绳子拉同一个策略——演示往这边拉、Q 值往那边拉、原始模型往回拽。

**每一项的梯度方向**（多项 loss 必须逐项说明"在拉什么往哪走"）：

- **$w_{\text{bc}} \cdot \mathcal{L}_{\text{BC}}$**：$\mathcal{L}_{\text{BC}}$ 是 Flow Matching 的 velocity 预测 MSE。梯度把策略的去噪速度场往"能重建演示动作"的方向拉。这一项**不看 Q 值**，是纯监督信号。
- **$w_q \cdot (-\bar{Q})$**：$\bar{Q} = \min_i Q_i(s, \pi_\phi(s))$（twin-Q 取小）。系数为负号，梯度下降会**增大** $\bar{Q}$，也就是把策略往 critic 认为好的动作推。这是唯一带来"超越演示"能力的项。
- **$w_{\text{w2}} \cdot \mathcal{L}_{\text{W2}}$**：$\mathcal{L}_{\text{W2}} = \|\pi_\phi(s) - \pi_{\text{BC}}(s)\|^2$（valid 掩码加权）。梯度把策略往冻结 BC 输出拉。这一项是 trust region，它**只在在线阶段存在**（离线阶段 $w_{\text{w2}}$ 那一项恒为 0，见下文）。

**三者的博弈**：BC 项和 W2 项都是"往回拉"，Q 项是"往前推"。如果 $w_q$ 太小，策略永远不动；如果 $w_q$ 太大，策略会追逐 critic 的估值误差跑飞。ConRFT 选择了极度偏向安全的一侧。

**权重表**（来自 `algorithm.conrft`，两个阶段的配置里数值完全相同）：

| 权重 | 离线阶段 | 在线阶段 | 配置键 |
|------|----------|----------|--------|
| $w_{\text{bc}}$ | 1.0 | 1.0 | `bc_weight_offline` / `bc_weight_online` |
| $w_q$ | 0.01 | 0.01 | `q_weight_offline` / `q_weight_online` |
| $w_{\text{w2}}$ | — | 1.0 | `w2_weight` |

**代入数字看比例**：假设某一步 $\mathcal{L}_{\text{BC}} = 0.35$，$\bar{Q} = 0.42$，$\mathcal{L}_{\text{W2}} = 0.008$。在线阶段的总 loss：

$$
\mathcal{L}_{\text{actor}} = 1.0 \times 0.35 + 0.01 \times (-0.42) + 1.0 \times 0.008 = 0.35 - 0.0042 + 0.008 = 0.3538
$$

Q 项贡献 $-0.0042$，占总量的 $1.2\%$。**Q 值要变化 100 倍才能对总 loss 产生和 BC 项同量级的影响。** 这就是第 01 章 9.2 里说"50 次更新等于没训练"的算术基础——不只是更新次数少，每次更新里 RL 信号的份额也只有 1%。

**离线阶段 W2 为什么是 0**：代码里

```python
w2_loss = policy_q.new_zeros(())
if not self.offline_stage:
    ...  # 只有在线阶段才真正计算 W2
```

离线阶段直接用零张量。原因是离线阶段 actor 训在 expert batch 上，BC 项已经把策略钉在演示动作上了，再加一个"不要离 BC 太远"的约束是冗余的。

## 4. 哪些论文结论还成立，哪些不再成立

这是本章最重要的一张表。

| 论文的结论 | 在本链路是否成立 | 理由 |
|------------|------------------|------|
| 离线阶段必须用 Cal-QL 而非 CQL | **成立**，而且更重要 | 动作维度从 62 涨到 992，CQL 的压低更没有尺度参考 |
| 在线阶段必须保留行为约束 | **成立**，但作用变了 | 仿真里不需要保护硬件，约束的唯一作用是防止策略分布崩塌 |
| 少量演示（20~30 条）就够 | **未验证** | 本链路的 BC 数据集规模不同，且 chunk 采样是每 episode 256 个 |
| 人类干预是关键的数据来源 | **不适用** | 被仿真自动 reset 替换，纠正数据的质量下降 |
| 一步生成对真机部署是必要的 | **不适用** | 仿真里推理延迟不是硬约束，用了 4 步去噪 |
| Q 项权重可以很小（0.01）也有效 | **存疑** | 论文的在线交互次数远大于本链路的 50 次更新；小权重 + 少更新 = 几乎不更新 |
| Cal-QL 的 MC 下界能保证平稳交接 | **部分成立** | `terminal_success` 奖励下失败样本的 $G_t \equiv 0$，下界很松（第 01 章 9.10） |

最后两行是这条链路最需要警惕的地方。论文的 $w_q = 0.01$ 是在"在线交互几千步、每步都更新"的前提下选的；本链路只有 50 次更新，同样的权重不可能产生同样的效果。**要么放大 $w_q$，要么放大更新次数，两者必须动一个。**

## 5. 与另一个 ConRFT 实现的差异

这个知识库里还有一个 ConRFT 实现的拆解：[LeRobot-VLARL](/系列/lerobot_vlarl_deep_dive/03_ConRFT与SACQC_VLA加Critic的RL策略融合)。本链路的 `ConRFTConfig` 注释里明确写了 "LeRobot-aligned ConRFT settings"，`conrft/objectives.py` 的文件头也写了 "Tensor-only conservative objective adapted from Apache-2.0 LeRobot ConRFT"。也就是说**目标函数是对齐 LeRobot 实现的**，不是直接从论文重写的。

主要差异：

| 维度 | LeRobot-VLARL | 本链路 |
|------|---------------|--------|
| 框架 | 单机多进程 + gRPC | RLinf Ray + Channel |
| 策略 | GR00T + 自己的 SAC head | GR00T N1.7 + Chunk-SAC head + Flow-G adapter |
| chunk 长度 | 可配 | 强制 16（`config.py` 里硬断言） |
| Critic 架构 | VLA 特征 + MLP | 同思路，但强制 `flat_absolute` twin-Q |
| BC 参考动作 | 需要单独的冻结模型副本 | 复用 Flow-G 的 `apply_flow_g=False` 通路，零额外显存 |
| same-state pair TD | 无 | **有实现但被强制禁用**（见第 04 章） |

最后一行值得说明：本链路的 Chunk-SAC 基类支持 same-state pair TD（让两个仿真环境从完全相同的物理状态出发各执行一个动作，用差分训练 critic），但 ConRFT 把它**明确禁掉**了，而且是三重禁止：

```python
if self.conrft.require_same_state_td:
    raise ValueError("LeRobot-aligned ConRFT does not use same-state TD")
if same_state_td_enabled:
    raise ValueError("LeRobot-aligned ConRFT does not use same-state TD")
```

加上配置里 `same_state_ranking.enabled: false` 和 `same_state_td.enabled: false`，以及 `rlinf/config.py` 里独立的一条断言。这不是"没配"，是"故意排除"——目的是让 ConRFT 的结果能干净地和 LeRobot 侧对比，不引入本仓库特有的改动。

## 6. 小结

| 替换 | 论文 | 本链路 | 性质改变 |
|------|------|--------|----------|
| 策略骨架 | 一致性策略（1 步） | Flow Matching（4 步） | 计算量 $\times 4$，方法有效性不变 |
| 动作粒度 | 单步 62 维 | 16 步 chunk，992 维 | **CQL 保守项的覆盖率大幅下降** |
| 纠正数据 | 人类干预 | 仿真自动 reset | 数据质量下降，吞吐大幅提升 |
| 行为约束 | 一个 BC 项 | BC 项 + W2 项 | 约束更强，W2 复用 Flow-G 结构零成本 |
| 框架 | 单机 | RLinf 异步分布式 | 引入最多 50 秒的策略滞后 |

**一句话**：本链路是 ConRFT 的**保守版**——保留了论文的全部安全机制，并且额外加了一个 W2 trust region，但把动作维度提高了 16 倍、把在线更新预算压到了 50 次。前者削弱了 Cal-QL 的保守项，后者削弱了 Q 项的作用。
