# SAC_FLOW_G 完全解剖：GR00T VLA 在线强化学习链路的工程实现

> 一个已经用行为克隆训好的 GR00T VLA，在仿真里"会做但做不稳"。SAC_FLOW_G 是把它接进 chunk 级 SAC 继续在线训练的一整套工程实现。这个系列从数据流讲到判定标准，把这条链路每一个环节拆开。

## 系列简介

SAC_FLOW_G 不是一篇论文，而是一条**真实在跑的训练链路**：四类进程分布在两台机器上，一边在 Isaac Sim 里让 96 个环境同时跑机器人，一边把产生的轨迹喂给一个 chunk 级 SAC 更新 Critic 和策略。它的配置族从 `miarena_r1_sac_flow_g_adapter_gr00t_n1d7` 起，经过若干层继承，长成了一串正式实验。

这条链路里有大量"看起来像超参、其实是设计决策"的东西：策略为什么只学一个门控而不是整个网络、奖励为什么必须等 episode 结束才能写、为什么要造两个处在同一物理状态的环境、为什么 Critic 要有一道自己的"体检门禁"、为什么固定 96 个布局的评测结果会自己抖动 5 个点。这个系列的目标是把这些全部讲清楚，并且讲到能自己判断"这条 run 是训不出来还是还没开始训"的程度。

**适合读者**

- 想理解一条真实的 VLA 在线 RL 链路从数据到梯度到底怎么流动的工程师
- 需要接手、复现或修改这类分布式 RL 训练系统的人
- 对"动作分块 + Flow 策略 + off-policy RL"这套组合的工程细节感兴趣的研究者

**你将获得**

- 对整条链路数据流的完整认知：每份数据在哪产生、存到哪、结构长什么样、什么时候被谁消费、消费完是否放回
- 对策略侧 Flow-G、Critic 侧 BC-relative 分解、同状态双动作差分三个核心设计的理解
- 对更新调度、安全门禁、评测协议这些"决定实验成败但不写在论文里"的部分的掌握
- 一套可执行的诊断方法：从曲线判断问题出在信号、预算还是测量
